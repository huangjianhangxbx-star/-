# CB-02｜双人动作体力状态机＋PPT 原位绿色体力条

性质：**下一正式功能任务专项计划草稿**，承接 `UI-01C`；若 P1 EN-BAL01 执行，则以其**实际提交 SHA**作为本阶段新基准。请不要按旧快照直接覆盖。

## 1. 玩法目标与已确定规则

1. 正式探索两位在场本体各有独立的体力资源（Stamina）；**普通 WASD 移动不耗体力**。
2. 已有可施放动作的大部分需在接受前有统一体力资格查询：基本攻击、RMB副动作、Shift机动、E已有主动；准备未来 Q/E/R，不能本轮虚构尚未存在的技能。
3. 技能需同时满足原有 CD/弹药/霜寒/动作窗和体力，不允许先消费体力再返回其他条件失败；资源拒绝应反馈可读原因。
4. 手动主控与离手 AI 消费**同一核心权威规则**；Z切人不能共用另一人的体力或重置条。
5. 体力状态机与 PPT 布局同步交付：`game/src/exploration-hud.ts` 现有 `.duo-stamina` 左上/左下绿条从占位变为真实资源，**严禁改动 UI-01C 六区锚点、阿尔头像**。
6. 体力是己方角色机制；**怪物不自动套用玩家体力**。前轮高压试验伤害只作为另一项可切换环境条件。

## 2. 真实工程导航

- 权威 Unit/Time：`game/src/core/types.ts` `GameState/Unit`、`game/src/core/engine.ts` `step/tick`。
- 普攻：`basic-chain.ts` 请求/排队；`basic-runtime.ts` `startBasicAction` Accept、Hit/AttackReady/Finish；谨防同一按住输入重复支付。
- 猎人：`hunter-combat.ts` `hunterInput` guard/dodge/active；原方向盾、闪避无敌和霜寒资源时序保持。
- 阿尔：`al-combat.ts` `alInput` shot/roll/rocket；原弹药真实支付仍在 Hit、CD与快慢动作时序保持，不能用扣体力代码改变其事件时间。
- AI：`companion-combat.ts`、`basic-chain.ts` 的自动 Basic 路径及 G/F/Z 输入仲裁。
- 状态边界：`world-session.ts` 离区保留 Unit 与模拟钟、合法继续不会免费恢复；篝火 `campfire.ts` 仍为独立交互消费者。
- UI-01C 基准：`game/src/exploration-hud.ts`、`game/src/geometry-hud.css`、`docs/tasks/UI-01C/validation/layout-measurement.json`，阿尔用户头像 `game/public/assets/ui/portraits/al-user.png`。

## 3. 推荐 SAMPLE 初值（不是用户永久决定）

建议 CB-02 先用**清楚标记为 SAMPLE 的可调参数表**实现体验：

| 行为 | 体力成本 / 恢复 | 本轮建议 |
|---|---|---|
| 两人最大体力 | 100 | 各自独立，不受 Z 切人影响 |
| 普通 WASD | 0 | 战斗/脱战均不因单纯移动收费 |
| LMB 普攻 | 每个真实接收段 10 | 排队中的下一段被取消，只有实际 Accept 才扣费 |
| 阿尔 RMB 射击 | 每次有效开枪指令 15 | 弹药仍按原 Hit 时点扣，不重复扣费 |
| 猎人 RMB 方向盾 | 成功举盾 8；持续举盾每模拟秒 6 | 体力耗尽时安全解除盾并显示原因；保留现有成功格挡的 HP=0、减半架势 |
| Shift 闪避/翻滚 | 22 | 不改原 0.13 s 等无敌时点与动作轨迹 |
| E 现有主动 | 28 | 不能绕过原霜寒/CD/弹药/动作窗门槛 |
| 体力恢复 | 暂定约每模拟秒 20；付费后约 0.5 s 延迟 | 不在动作忙碌/持续举盾期间强行恢复；离区时间冻结 |

上述费用与恢复数值由 Codex 视真实角色连段、盾持续时长与高压试验组实测保留 SAMPLE 标签及可调整表；**不允许为了测试轻松而重调黄金动作**。若发现必须由用户作新的玩法决定（例如举盾时体力耗尽到底如何卸盾、篝火是否立刻补满体力），优先采用不引入新资源/新视觉的明确临时策略并在交接中列为待用户审核，不能伪装为已确认规则。建议体力耗尽使持续盾终止，篝火补满作为可比较的 SAMPLE，不触碰 Y 回血瓶。

## 4. 统一资格/支付实现合同

**先校验所有原资格→再原子接收并支付→再开始动作**。不允许 HUD、键盘回调与 AI 分别扣费。

- 体力查询返回 `{ok, reason, cost, available}`，支持 UI 和 AI 的只读资格查询；真正支付与 ActionContext 接收拥有唯一 authority。
- 对 `BasicRequest`：在 `requestBasic`/`startBasicAction` 之间明确唯一支付门，覆盖玩家连段、AI普通攻击、已确认按键缓冲；rejected/重复/失焦取消/无实际 acceptedId 时不得扣款。一个动作段只支付一次。
- `HunterInput/AlInput`：先经过 CD、当前动作窗、弹药/霜寒等原合法条件，再在接受点一次扣体力；原射击弹药仍在 Hit，原格挡霜寒仍在成功防御时处理；预备/Charge/子弹实体不重复扣。
- 举盾持续消耗基于 `s.time` 的模拟钟，按 dt 一次推进，真实暂停、G轮盘慢速、失焦不可产生后台扣费；反复抬起盾需真实重付。
- 状态归属不应复制到 `h.mp`、`al.ammo`、旧体力镜像，新增核心 Unit 的 stamina/current/max 与 spend metadata；已有 maxHp、maxPosture 绝不更改。
- 受控/死亡/离区/继续时真实资源可保留或按已批准边界更新；不能因为 UI 重新 mount、Z切人、切换装备或 G轮盘重置体力。新世界的明确 restart 才创建初始值。
- 敌人 `high-pressure-v1` 的命中照常可能打断玩家动作，**已接受动作的体力不因受击取消而退费**（该策略为 SAMPLE，可在用户反馈后单独讨论）；拒绝的动作不得发生任何损耗。

## 5. 游戏 HUD 与输入反馈

- 绿条使用已有 `.duo-stamina` 子树和选定几何 base/frame/fill 的渲染逻辑；条内显示“实际数值/max”或易读的极短数值，不占用新的角落、无需新增素材。当生命/架势/体力共同显示时保留 UI-01C PPT 顺序和 1920 像素位置，1440/1280 自动缩放。
- 中下热键 1–0、Tab、Y、未来 Q/R/V、被动三级仍保持真实**不可操作预留**；仅现阶段实际实现的 LMB/RMB/Shift/E 显示可用/不足反馈。
- 体力不足用现有 notice 或按钮 hint，提供简短、可访问、有限频的反馈；按住输入不得每帧刷同样的错误。避免 modal/指针穿透或点击预留触发攻击。
- 不改阿尔用户头像路径、肖像尺寸、游戏画面可操作中区以及 G轮盘/F选路/Z切人本体身份。

## 6. 推荐实现分段与 Gate

- **S0 对账/RED**：冻结最新 HEAD、UI01C量测、两角色动作时钟、正常/高压敌人场、NR离区、现有库存；为“输入拒绝不扣费、受理一次只扣一次、Z双人体力不串、HUD真实一致”添加失败测试。
- **S1 核心 Stamina**：核心字段、独立费用表、只读资格、原子支付、模拟恢复/延迟；测试负余额、NaN、边界精度、暂停和重开。
- **S2 接受链**：Hunter/Al与合法其他伙伴 Basic/RMB/Shift/E，受击取消、连续缓冲、阿尔扣弹/装填、猎人方向盾/闪避与原能力/CD检查。AI同权威费用。仅原能力可执行，不能实现未批准的 Q/R 技能。
- **S3 世界/生命**：Z/G/F、待恢复动作、离区（不计时）、继续（不全满）、无效时区间、篝火既有消费者（若采用 SAMPLE 恢复要标），旧两人生命流程不要偷重写 LT01。
- **S4 原位 HUD**：把真绿条、拒绝反馈接到已有六区的同一可渲染状态，不迁移布局。绑定 Hunter 与 Al 的真实 stamina，不把 HP/架势条当成资源。
- **S5 回归**：定向核心（支付唯一性、取消、AI、战术、重进、全量技能）、`npm run build`、`npm run build:action-lab`、`npm run test`；Playwright 真实鼠标键盘 1920×1080/1440×900/1280×720，至少两次 Z 切人、不同角色各消耗/恢复、连续基本连段、举盾资源耗尽、阿尔四发装弹与火箭、敌人高压基准对照、世界离区继续。
- **S6 交付**：设计系数表、成本/支付生命周期、真实 HUD 截图与量测 JSON、测试前后、残留 SAMPLE、玩家试玩路径，选择性提交 GitHub main（有效授权前提）。停在用户体感 Gate，**不自动启动 LT-01**。

## 7. 一定不要做的事情

- 不能为了适配高压敌人而降低原黄金动作威力/格挡/闪避，或在 UI 里造固定 100% 绿条。正常受伤数据必须来自真正 Unit。
- 不新增怪物体力，不顺便重做敌人/队友战术、不改 QST-01A 流程/原持续世界时钟。
- 不实施 LT-01死亡重生、Y瓶/背包/农业、QER技能库/V注入、EQ双形态、3级被动/睡眠冷启动；这批均为以后任务。
- 不借新增体力之名变更 PPT 中左上/左下/右上/右下/中下的几何位置和尺寸；视觉若有不一致，请记录为待 UI-01D 用户明确反馈项。

## 8. 交付必须包含的量化结果

- 初值/恢复/费用实测，分别针对猎人、阿尔及至少一个通用合法伙伴（如当前版本可选）；显示和真实 GameState 相等。
- 每次接受动作的 `actionId`/体力差唯一追踪；`Trace OFF` 不改变支付结果。
- `baseline` 与 `high-pressure-v1` 敌人压力下，盾挡、闪避、体力耗尽时动作合法拒绝和接收行为正常。
- UI01C 六个集群保持已冻结锚点、阿尔头像实际 `currentSrc` 是 user 图且无头像替换回退，三视口无可点击区域穿透。
- 自动 Gate 与主观 Gate 分开；数值成本始终标为本轮 **SAMPLE**，不是用户最终认可的体力平衡。
