# 星骸回廊：探索主战斗升级任务清单 v0.1

> 日期：2026-10-05  
> 性质：长期判断锚点，不是一次性实施计划。  
> 当前核对基准：GitHub `main@f5fb4bb13e5ecb667ec38a49196a9d4515a93c1c`。  
> 固定流程：**选中一个清单项 → 单独出计划 → Codex 执行 → 用户试玩验收 → 再决定下一项。**  
> 本文件仅在聊天中生成，尚未写入仓库。

## 0. 总方向

后续设计优先级调整为：

> **探索 / 双人即时冒险 RPG 为主玩法；塔防缩为兼容玩法、特殊遭遇或挑战。**

当探索手感与塔防规则发生冲突时，优先保证探索，再通过独立 ruleset / 参数兼容塔防。

共享底层仍包括：角色、职业/武器、技能构筑、HP/架势/虚血、伤害与状态、影庭、资源、空间和碰撞。

塔防独立保留：战斗锚点、小半径自治、多人部署、波次、防线、塔防移动倍率。

### 角色数量策略

当前强方向是：正式游戏可能只保留几个伙伴，甚至只有**猎人 + 1位核心伙伴**。

因此从现在起，不再为了“未来大量可玩角色”而故意削减单角色设计量。允许把更多成本投入到：

- 更多技能和更深技能树；
- 角色专属 AI；
- 专属动作与闪避；
- 独特 Break / 控制反应；
- 独特伙伴指令；
- 双人组合语义；
- 专属资源和成长。

不优先建设面向 20 个角色的大型通用框架。  
但底层战斗语言仍尽量共享：Telegraph、Hit Resolve、Posture/Break、Forced Movement、Wall Impact、Direction/Weakpoint、Ability Tags、输入与动作仲裁。

# 2. EC-01：双人副本与探索节奏基线

## 目的
先把当前“多人碾压少量脆怪”的环境改成真实可判断的双人战斗实验场。

## 内容
- 探索固定猎人 + 1名伙伴。
- 开局从当前可用伙伴中选 1 名同行；其余本次不出场。
- 若未来最终只保留一个伙伴，这套入口可自然简化为固定双人。
- 探索移动速度与塔防彻底解耦。
- 首轮建议玩家探索速度从 1.70 提到约 2.3～2.5 起测；敌人约 1.8～2.0 起测。
- 探索敌人 HP 先统一约 ×2。
- 遭遇数量提高：小遭遇 3～4，普通 4～6，强遭遇 5～8，可含远程/Heavy。
- 保留空房、移动、篝火、战斗的节奏起伏。

## 不做
不改三技能、闪避、弱点、新AI、切人。

## 试玩闸门
- 双人是否比多人更好读？
- 中型地图移动是否仍慢？
- 敌人是否还太脆？
- 遭遇是否开始需要认真操作？
- 不同伙伴是否已经明显改变副本体验？

# 3. EC-02：双角色直接控制模型

## 目的
正式建立“玩家在玩两个人”，而不是“猎人 + 跟宠”。

## 内容
- 任意时刻只有一个 DirectActor，另一人由 AI 接管。
- 快捷键快速切换猎人 ↔ 伙伴。
- 切换不开菜单、不重置技能、不重置攻击周期、不重新入战。
- 切走后 AI 无缝接管当前角色，不突然回旧锚点。
- 镜头偏向当前操作者，但双人距离合理时尽量同时保留在画面中。

## 试玩闸门
重点验证：
> 猎人制造机会 → 切伙伴兑现 → 再切猎人  
是否足够流畅。

# 4. EC-03：探索动作基础——闪避、移动、走A

## 目的
让主操角色即使暂时不放技能，也有足够操作密度。

## 全角色基础闪避
所有直接可控角色拥有角色化的翻滚/踏步/滑步/后撤。  
猎人的瞬影仍是更强的特殊机动能力。

首版不做复杂体力条，建议先试：
> 2次闪避储层 + 自动恢复。

## 走A
普攻拆为：
> 前摇 → 命中/出手点 → 后摇

- 前摇移动取消：这次攻击失败。
- 出手后：允许移动取消后摇。
- 真实最小攻击周期仍存在。
- 禁止“移一步直接清空攻击CD”的无限攻速方案。

## 试玩闸门
- 近战粘人是否舒服？
- 远程边走边射是否有节奏？
- 闪避是否主要靠真实位移而不是纯无敌帧？
- 操作空窗是否明显减少？

# 5. EC-04：Telegraph 与严谨命中

## 目的
建立“看懂范围 → 走出去就真的能躲”的可靠规则。

一次敌方攻击拆为：
1. Telegraph：显示圆、扇、长条、环、冲锋路径等危险区。
2. Lock：发动前锁定区域/方向，不无限追踪玩家。
3. Resolve：结算时严格检查碰撞体是否仍在攻击区。

基础闪避主要依赖实际离开危险区。  
可以保留极短容错 i-frame，但不是主要玩法。

形成通用：
- AttackTelegraph
- AttackCommit
- HitArea
- ResolveTime

以后敌我技能共享这套语言。

# 6. EC-05：架势 Break 2.0 与强制位移

## 目的
把当前架势从硬直条升级成双人协作核心。

## 内容
架势归零进入 Break 窗口。破势目标更容易受到：
- 大硬直；
- 击退；
- 击倒；
- 打断；
- 钉墙；
- 弱点暴露。

攻击增加独立参数：
- PostureDamage
- ImpactForce
- BreakReaction

加入重量：
- Light
- Medium
- Heavy
- Boss/Immovable

建立 Forced Movement：
- 推、拉、击飞、冲撞。

建立 WallImpact：
- 额外伤害/架势；
- 眩晕；
- Pin；
- 分支效果。

目标体验：
> 猎人打空架势 → 阿尔强化箭击退 → 撞墙钉住 → 输出窗口

规则必须是通用组合，不是写死角色脚本。

---

# 7. EC-06：方向、背击与弱点基础

## 目的
让包夹、绕后、吸引朝向成为双人策略。

## 内容
首版只做：
- Front
- Side
- Back

按攻击者与目标 facing 的相对方向判断。

不做统一“背后伤害×1.5”。

不同敌人定义不同方向价值，例如：
- 盾兵：正面强防，侧后正常。
- 大型怪：背部弱点。
- 敏捷怪：背面攻击能力少。
- 施法怪：背击更容易打断。

## 试玩闸门
两人是否自然产生：
> 一人吸引正面，另一人找侧后  
而不是继续围着怪平A。

---

# 8. EC-07：三技能槽与独立技能运行时

## 目的
解除“同一时间只有一个技能激活”的探索主战斗限制。

## 推荐
每个角色 3 个主动技能槽，技能各自维护：
- 时间CD；
- 长充能；
- 攻击次数；
- 受击次数；
- 造成伤害；
- 架势条件；
- 自动触发；
- Toggle；
- 持续状态。

构筑仍保留：
- 局外解锁与默认配置；
- 副本内从低培养开始；
- 生命力购买进阶/分支。

只是 Build 从“唯一技能”升级成“主动技能组”。

## 暂不锁死
实施这一项时再决定：
- 战斗中是否允许换技能；
- 是否要求脱战；
- 换技读条；
- 换入是否空充能；
- 是否有换技锁。

# 9. EC-08：敌人战斗能力升级

## 目的
玩家会加速、闪避、多技能后，敌人不能继续只追上来普攻。

## 普通敌人
建议：
> 普攻 + 1个主动能力 + 1个反应行为

例如：
- 重击 + 后撤；
- 投射物 + 侧闪；
- 突进 + 格挡。

## 精英
> 普攻 + 2～3能力 + 闪避/格挡/反击

## Boss
可以更完整。

## 原则
敌人反应必须受：
- 视野；
- 反应延迟；
- CD；
- 架势；
- 当前动作；
- 性格
限制。

禁止“读取玩家按键后同帧完美闪避”。

同种敌人允许少量可识别 Build Template，但视觉上必须可读。

# 10. EC-09：探索伙伴 AI 2.0

## 目的
探索伙伴不再被塔防的 Anchor + Activity Radius 束缚。

## 塔防
继续保留现有锚点AI。

## 探索
进入战斗后，伙伴可在当前 Encounter 范围自由移动。

限制对象从：
> 距锚点不能超过2米

改为：
> 不离开当前战斗区域，不追怪跨半张地图，不误触下一个Encounter。

伙伴AI可具有：
- engage
- flank
- retreat
- support
- peel
- evade
- setup
- payoff
- regroup

由于最终伙伴可能很少，允许角色专属AI，不强求所有角色共用同一个浅模板。

# 11. EC-10：简易战术指令轮盘

## 目的
玩家不切人也能快速改变伙伴行为。

首版推荐只有：
- 集合
- 自由行动
- 集火我的目标
- 保守

如果四项已经够用，不继续扩。

按住 Command 键出现轮盘。  
游戏不完全暂停，可以进入 0.1× 战术慢速。

# 12. EC-11：技能行为标签与双人协同

## 目的
让AI理解技能，同时让玩家主动打出更高上限的组合。

技能数据拥有行为标签，例如：

阿尔强化箭：
- finisher
- prefersBroken
- prefersRear
- prefersWallBehind

盾击：
- peel
- protectAlly
- knockback

治疗：
- support
- lowHp
- cluster

技能AI使用权：
- AUTO：正常使用
- RESERVE：只在高价值条件使用
- MANUAL：AI绝不主动交掉

建立通用 Setup：
- Broken
- Rooted
- Frozen
- WallPinned
- Exposed
- ArmorDown
- BackExposed

以及 Payoff：
- 对 Broken 强化
- 对 Rooted 强化
- 对 Back 强化
- 对 WallPinned 强化

目标：
> AI能偶尔打出聪明配合是惊喜；玩家主动制造组合才是上限。

# 13. EC-12：怪物知识与弱点锁定

## 目的
让击杀和培养增加“理解敌人”的能力，而不仅是加伤害。

弱点从第一次遇到就真实存在，但低知识等级UI不告诉玩家。

示例：
- Lv0：情报有限。
- Lv1：名字和模糊弱点提示。
- Lv2：抗性、架势特征、主要能力名。
- Lv3：显示弱点区，允许辅助锁定。
- Lv4：显示部分攻击后摇/特殊Break反应。

玩家第一次碰巧打中真实弱点，依然获得收益。

# 14. EC-13：卡牌系统降级/转型

## 目的
实时战斗拥有普攻、闪避、3技能、切人、指令后，卡牌不再承担“填技能空窗”的职责。

推荐转成：
- 战术消耗品：应急护盾、架势恢复、治疗、位移、下一技能强化；
- Run Modifier：本副本持续改变规则；
- 探索资源：开门、陷阱、篝火强化、事件选择。

暂时不急着删卡牌UI。  
等 EC-07 三技能实装后再判断剩余价值。

# 15. EC-14：猎人 + 核心伙伴深度重制

## 目的
底层战斗语法稳定以后，再真正重做角色完整Kit。

## 猎人
从“塔防救场角色”升级成：
- 主角操作核心；
- 高机动；
- Setup制造者；
- 可以通过职业/技能改变协作方式。

## 核心伙伴
如果最终只有一位正式伙伴，可以按“第二主角”级别投入：
- 3技能；
- 专属闪避；
- AI；
- 独特资源；
- Break反应；
- 专属Combo；
- 成长；
- 情境反馈。

如果仍保留伊内丝/阿尔/菲奥蕾多个候选，也不同时全部重做。  
先选一名最能验证双人战斗的角色做完整样板，再决定其余角色保留、合并、NPC化或删除。

# 16. EC-15：敌人原型集与 Encounter 设计

第一批只需4～5种：

- 普通近战：验证移动/普攻/Break；
- 盾兵：验证正面防御和绕后；
- 远程：验证追击和切入；
- 敏捷敌人：验证闪避和反应延迟；
- Heavy：验证重量、WallImpact、大Telegraph。

Encounter 组合：
- 近战+远程；
- 盾兵+施法；
- Heavy+小怪；
- 狭窄可撞墙空间；
- 开阔包夹空间。

不靠纯数量堆怪。

# 17. EC-16：第一段主玩法垂直切片

## 目的
回答：
> 新的《星骸回廊》核心战斗到底好不好玩？

## 内容
一段中等长度副本：
入口 → 小遭遇 → 路线选择 → 普通遭遇 → 篝火 → 强遭遇 → 精英/小Boss → 出口

只需要：
- 猎人；
- 1位深度伙伴；
- 4～5种敌人；
- 3技能；
- 闪避；
- 双角色切换；
- 指令轮盘；
- Break/击退/撞墙；
- Telegraph；
- 方向弱点；
- 基础怪物知识。

## 验收重点
1. 玩家会不会主动切人？
2. 能不能主动制造双人组合？
3. AI聪明配合有没有惊喜？
4. 闪避和范围判定是否可信？
5. Break有没有真正创造窗口？
6. 绕后值不值得？
7. 三技能是丰富还是混乱？
8. 卡牌还有没有必要占主操作层？
9. 一位伙伴是否足以支撑整款游戏？
10. 打完以后是否想继续？

EC-16成立后，才值得大量填地图、敌人、技能、关卡、剧情、美术和UI。

# 18. 暂时不要删的旧系统

- 塔防：保留为Build测试器、特殊防守事件/挑战。
- Anchor AI：继续给塔防使用。
- 卡牌：先降优先级，不立即删除。
- 现有多个角色资料：暂不删除，等核心伙伴样板后再决定最终Roster。

# 19. 不再继续限制探索的新设计旧假设

以下不再作为探索主玩法默认约束：
- 探索必须和塔防共用移动手感；
- 探索队友必须围绕固定锚点；
- 玩家主要只操作猎人；
- 一个角色只能有一个实时技能；
- 卡牌必须填战斗空窗；
- 为未来大量伙伴而压低单角色复杂度；
- 每个伙伴必须严格套同一种AI模板；
- 每个技能都必须适配多人塔防部署。

如果其中某条以后还值得保留，需要重新证明，而不是自动继承。

# 20. 推荐第一份实施计划

清单之后，第一份真正交给 Codex 的计划只做 **EC-01：双人副本与探索节奏基线**。

范围：
- 探索固定猎人 + 1伙伴；
- 出发前选择同行；
- 其余本体不进入该副本；
- 探索己方/敌方速度独立提高；
- 探索敌人HP约×2；
- 调整暗牢随机敌群数量和房间遭遇密度；
- 现有技能、AI、单技能、卡牌、架势暂时不改；
- 塔防完全不改；
- 直接使用当前独立暗牢实际试玩。

理由：

> **先制造正确的“双人战斗实验环境”，再判断切人、闪避、Break 2.0、三技能到底应该怎么做。**

---

# 21. 清单不是死顺序

如果 EC-01 试玩后发现闪避比切人更急，可以改成：

> EC-01 → EC-03 → EC-02

如果发现单技能制已经严重妨碍测试，可以提前 EC-07。

唯一固定原则：

> **一次只改一个足以独立验收的层级，不同时重做控制、AI、技能、敌人、弱点和卡牌。**

# 22. 当前置信度

## 高置信度
- 探索成为主玩法；
