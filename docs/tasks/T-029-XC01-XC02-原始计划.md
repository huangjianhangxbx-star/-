# 3. XC-02 Canonical State：最小状态，不制造重复真相

## 3.1 `controlledBodyId` 继续作为 DirectActor 权威

当前大量系统已经读取：

```text
GameState.controlledBodyId
```

本轮不为了改名字进行大迁移。

语义正式明确：

> `controlledBodyId === DirectActorId`

---

## 3.2 新增 ExplorationControlState

建议：

```ts
type ExplorationAimKind =
  | 'path'
  | 'skill'
  | 'mobility'

type ExplorationAimSession = {
  kind: ExplorationAimKind
  actorId: string
}

type ExplorationControlState = {
  commandFocusId: string | null
  aim?: ExplorationAimSession
}
```

GameState：

```ts
explorationControl?: ExplorationControlState
```

---

## 3.3 本阶段 Aim 只建立接口，不产生实际Session

XC-01 + XC-02阶段：

```text
aim === undefined
```

是正常状态。

不要提前实现：
- PathAim；
- SkillAim；
- MobilityAim。

但结构要为后续保留。

---

## 3.4 ControlMode 建议派生，而不是再保存一份

不要同时存：

```text
mode='command'
commandFocusId=null
```

制造非法组合。

建议：

```ts
controlMode(s):
  commandFocus有效 → 'command'
  否则 → 'direct'
```

所以：

> Command / Direct 是由Canonical State推导出的状态。

---

# 4. CommandFocus 的合法对象

只允许：

- Standalone Exploration；
- 当前Party original body；
- `life==='active'`；
- 非 `shadowResident`；
- 非 Clone；
- 且不是当前DirectActor。

---

## 4.1 点击当前DirectActor

含义：

> 返回/保持Direct。

如果当前有CommandFocus：

```text
clear CommandFocus
```

不重新触发Direct handoff。

---

## 4.2 CommandFocus失效

以下情况自动清除：

- downed；
- dead；
- rescued；
- withdrawn；
- shadowResident；
- 离开Party；
- 它因为其他合法原因已经成为DirectActor。

不得自动把另一个角色切成CommandFocus。

---

# 5. 推荐 Core API

建议 `core/exploration-control.ts` 提供类似：

```ts
usesExplorationControl(s): boolean

directActor(s): Unit | null

commandFocus(s): Unit | null

controlMode(s): 'direct' | 'command'

queryCommandFocus(s,id): CommandResult

setCommandFocus(s,id): CommandResult

clearCommandFocus(s): void

promoteCommandFocus(s): CommandResult

ensureExplorationControl(s): void
```

命名可按实际工程风格调整。

---

# 6. Command 层接口

建议新增：

```ts
{ type:'commandFocus', id:string|null }
```

现有：

```ts
{ type:'controlBody', id:string }
```

语义正式缩窄为：

> **真正改变DirectActor。**

它不再代表：

> “玩家只是点了一下这个角色”。

---

# 7. `switchControlledBody()` 职责收窄

当前实际：

```ts
switchControlledBody(s,id,manual=true)
```

会：

- release旧Direct；
- acquire新Direct；
- `manual`时直接启动TacticalFocus。

这个职责需要拆开。

---

## 7.1 新语义

`switchControlledBody()`：

> 只负责DirectActor handoff。

不要决定：

- CommandFocus；
- Tactical Focus；
- 玩家是怎么表达切换意图的。

---

## 7.2 Tactical Focus 改由 CommandFocus 入口创建

```text
setCommandFocus(otherBody)
→ tacticalFocus = {elapsed:0}
```

真正晋升Direct时：

```text
promoteCommandFocus
→ switchControlledBody
→ clear CommandFocus
→ tacticalFocus = undefined
```

所以：

> **思考窗口属于Command，而不是属于DirectActor切换。**

---

## 7.3 自动Fallback永远不创建Tactical Focus

例如：

- 当前DirectActor downed；
- DirectActor非法；
- 系统自动把控制权交给另一名存活本体。

结果：

> 正常Direct fallback。

不得产生：

> “系统自己切了人，突然给玩家1.5秒慢动作”。

- AI不会因为“被看了一眼”原地停止。

> Command Reservation / AI逐层让权。

```text

```

# 12. Command → Direct 晋升入口

本阶段先接入已经存在的三类直接动作。

---

## 12.1 WASD

如果：

```text
CommandFocus = Al
DirectActor = Hunter
```

玩家按W：

同一次keydown必须：

```text
1. promote Al to DirectActor
2. clear CommandFocus
3. end TacticalFocus
4. apply W movement to Al
```

不能要求第二次按键。

---

## 12.2 Skill Hotkey

E / R / T：

同一次输入：

```text
promote CommandFocus
→ 对新DirectActor执行对应slot skill
```

如果Skill本身拒绝：

> Direct takeover是否已经成立？

推荐：

> **成立。**

因为玩家已经用动作快捷键明确表达：

> “我要直接操作这个角色。”

技能因为CD/动作状态失败：

> 不应该把玩家又弹回Command。

---

## 12.3 Mobility Hotkey

Shift：

同一次输入：

```text
promote
→ 调新DirectActor真实Blink/Evade
```

如果机动因为：
- 无charge；
- 被阻挡；
- stagger；

而失败：

推荐同Skill：

> **Direct takeover仍成立。**

玩家表达的Direct意图已经明确。
