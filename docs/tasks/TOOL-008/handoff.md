# TOOL-008 交接

## A 包已实施

- 项目、场景、资产可在项目页重命名；新资产有可识别的默认名称。
- 保存资产和场景使用带哈希校验的回收区；被实例引用的资产先提示引用数量，可显式移除实例；可恢复，永久删除有二次确认。旧发布目录不参与回收。
- 最近成功打开的项目保存在本机 Electron 用户数据中；支持一键重开、路径失效提示、重新定位、忘记记录。切项目时处理未保存修改。
- 项目页提供卡片/列表、搜索、排序与资产缩略图；在三种桌面窗口尺寸做了截图检查。

原有模块笔刷、场景装配、发布历史、Blender/Unity 交换代码保留。本包新增 UI 不改变 v1 文档 schema；回收区属于受管项目文件。新建项目/场景/资产尚沿用 v1 场景私有资产结构，不能误称资产优先模型已经完成。回退时可通过本包提交回退应用代码；已有 `.workshop-trash` 必须先经 UI 恢复或另行备份，不能仅回退代码后直接丢弃回收文件。

技术验证见 [validation.md](validation.md)。用户对 A 包的实际手感尚未验收；B/C 的实施和边界见下节。

## B/C 增量实现状态（2026-10-19）

新建项目默认采用 v2：原生资产存于项目级 `assets/`，试摆场景只记资产 ID 与 Transform；同源多实例、多场景共享，独立化则新建资产并单实例改指。保存生成持久资产预览和试摆平面概览。公共库原生资产首次拖入复制成一个项目资产，后续拖入引用同一项目副本。旧 v1 项目继续可打开，并有「备份并转换副本」到新目录入口。模块编辑直接选择文件名/目录输出单件 FBX，Blender 5.1.2 实际转换并保留材质旁车；v2 普通导航不再提供整场景发布。

本次改动未碰 Unity、游戏、2D 工坊或旧发布格式。便携目录已在隔离工作树重新打包，源码提交不会上传 ignored 的 EXE；要在用户机器上体验新版本，应使用该目录的 EXE，不能继续启动先前旧包。技术验证见 [validation.md](validation.md)。

**仍待用户手感与后续优化：**试摆缩略图目前是平面位置概览，不是完整三维场景截图。长期大工程、全部历史项目和用户制作手感未验。新项目副本只复制当前有效资产与试摆草稿，不带回收区；同名 FBX 只有用户选择「备份并覆盖」时才会替换，旧版备份路径明确显示。
