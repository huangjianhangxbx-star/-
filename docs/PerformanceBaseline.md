# 性能基线：同屏敌人数量

2026-09-28 诊断当前 2D Spine Canvas 到 Three.js CanvasTexture 的渲染桥接。独立夹具使用 NVIDIA GeForce RTX 4080 SUPER（ANGLE / D3D11），加载完整静态场景后模拟 5、15、30 个敌人；每组预热 3 帧，连续更新/提交 20 帧。

| 敌人数 | 场景更新时间均值 | 角色更新部分 | 渲染提交部分 | 60 次纯战斗 step 均值 |
|---:|---:|---:|---:|---:|
| 5 | 6.99 ms | 3.46 ms | 3.50 ms | 0.12 ms |
| 15 | 52.83 ms | 8.17 ms | 44.63 ms | 0.21 ms |
| 30 | 110.48 ms | 15.44 ms | 95.01 ms | 0.43 ms |

初步结论：该设备上的战斗逻辑计算较小；角色画布重绘和动态纹理提交是主要调查方向。连续渲染提交会产生 GPU 排队与回压，因此表中耗时不能直接当作稳定游戏 FPS，也不能据此推断 Three.js 本身的性能上限。

建议：评估可复用的 Spine 帧缓存/共享贴图或 GPU 骨骼渲染，再用目标机器和真实玩法场景复测。继续保留平滑动画和独立战斗计时。
