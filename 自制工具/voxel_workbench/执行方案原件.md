## 1. 产品选择与首版完成标准

### 1.1 推荐路线

做 **Blender 内的体块资产工作台**，不做独立建模软件，不做完整可破坏体素引擎，也不把“体块风格”限制成世界中的每个物体必须等尺寸立方体。

首版围绕静态、可复用的场景资产：墙段、台阶、石柱、断拱、树冠、树干、碎石和装饰面片。已有 Blender 视口、网格编辑、文件与渲染能力作为基础；插件负责统一规范并缩短反复操作。

**不把“内部有 AI 聊天框”当作 agent 支持。** AI 可以运行在 Codex 或其他已授权 agent 中；插件提供受约束、可查询、可重复调用的工具，不自己维护模型账户、密钥和云端生成服务。

### 1.2 首版必须形成的两个完整流程

**人工流程：**选项目规范 → 选基板或预设 → 选颜色 → 在视口像画画一样铺放／堆叠 → 局部修改 → 显式保存为预设 → 导出 GLB／FBX → 在独立查看器检查。

**Agent 流程：**读取能力、规范与预设目录 → 生成结构化建模请求 → 预检 → 调用插件搭建新资产或修改已有资产 → 校验 → 渲染至少一个可读角度 → 根据结果局部修正 → 输出可编辑文件及导出模型。

**接力流程：**agent 制作的模型，用户能继续涂色、删改和保存；用户制作的预设，agent 能查到并复用。交付不能只有一次性脚本，也不能只有不可继续编辑的合并网格。

## 2. 开工先核实的事项：不把技术探测变成长问卷

| 事项 | 优先自行核对 | 需要询问的情形 |
|---|---|---|
| Blender 版本与执行方式 | 本机 `blender --version`、实际可执行文件、Python API、导出器；现有已授权连接是否能执行 Python／取图 | 安装多个版本且目标不明、现有连接不可访问、需要安装或升级 |
| 文件范围 | 当前工作目录、已有体素实验、项目 AGENTS、允许输出和预设库路径、未保存内容 | 找不到用户所指实验，或新建工具目录／持久预设库位置未获确认 |
| 比例与色板 | 从那轮用户认可的模型读取实际尺寸、单位、基础材质和视角；仅用作候选规范 | 多份样例矛盾、未提供可读模型，或需要把候选提升为全项目规范 |
| 首版策略 | 采用本方案的基板、标准材质与色板贴图、受限首版笔刷和 agent 共用接口 | 用户不接受范围或某项默认交互会影响已有习惯 |

本方案不硬锁“最新 Blender”，也不宣称同时支持全部旧版和 5.x。先针对用户实际使用的一个版本制作安装包和验证；其他版本单独列为未测。网页所查官方资料支持设计思路，不代替本机 API 与导出器核验。

建议先由 Codex 汇报一页环境／规范确认表。环境能读出的内容不要再问用户；缺少的美术尺度、保存位置等关键项集中确认。确定后再连续推进，不在每个普通实现细节上重新请求批准。

## 4. 最重要的架构：人和 agent 共用建模核心

```text
人工视口／笔刷 ─→ 操作适配器 ─┐
                              ├─→ 公共建模服务 → Blender 中的可编辑资产
Agent JSON／Python ────────────┘          ├→ 校验／查询／预览渲染
                                        └→ 非破坏性编译与导出
```

这不是让 AI 模拟点击几十个面板，也不是给 AI 另写一套会绕过色板和尺度规则的建模脚本。

### 4.1 建议职责

| 层 | 职责与限制 |
|---|---|
| 纯数据与计算 | 规范、recipe、离散格位置、锚点变换、笔划采样、命名与校验；尽量不依赖 `bpy`，可单元测试 |
| Blender 建模服务 | 显式接收目标资产、模板和配置，通过数据 API 创建／更新；不依赖鼠标当前悬停区域、任意选中对象或编辑模式 |
| 人工操作器 | 采集鼠标／键盘；调用公共服务；一次笔划或一次显式编辑形成一次可撤销操作 |
| Agent 入口 | 验证结构化请求、限定作用域和数量，调用相同服务；返回结构化结果与可检查的文件 |
| 存储与导出 | 版本化预设与规范；副本上合并／转换；文件原子写入与失败清理 |

Blender 官方说明 Operator 可以从 Python 调用，但其上下文依赖会使脚本调用失败。因此主建模逻辑不应只有依赖视口状态的 `bpy.ops` 实现；Operator 留在交互、撤销、导出等必要边界。[B1]

## 5. 规范、预设与可编辑性

### 5.1 不把美术体块步长等同于游戏地格

一个游戏逻辑地格可以由若干美术体块组成。插件的 `grid_step` 是建模规格，不自行修改游戏地格、寻路或身体占地。

项目规范保存唯一ID与版本，至少包括单位、格步长、允许的尺寸步进、轴向、旋转步进、默认锚点、平面单双面策略、色板版本。示例初值可以由 Codex 提议，但不能把示例米数当成用户已认可的游戏尺寸。

格点计算以离散索引为基础，真正放置时再转换到 Blender 坐标。明确网格原点、锚点与边界包含规则，测试负坐标、非单位尺寸和半格中心，避免在不同工具中混用四舍五入造成接缝。

修改项目步长不自动缩放已有模型；提供显式迁移预览或仅对新资产生效，并保留旧资产所引用的规范版本。

### 5.2 基板和预设不是一回事

**基板**是方体／薄板／面片的参数模板；保存默认尺寸和锚点。**预设**是用户明确保存的一组模型，可由多个基板组成，也可以纳入用户在 Blender 中整理过的静态网格。

首版锚点包括底部中心、几何中心、指定面中心与一个可编辑自定义局部锚点。旋转和镜像围绕所选锚点进行，镜像后的法线和导出方向必须正确。暂不做自动推断所有模型接口的语义连接系统。

预设应保存：稳定ID、版本、局部变换、包围范围、规范ID、基板或静态网格依赖、语义色板引用、缩略图和兼容说明。实例固定引用预设版本；修改预设创建新版本，不静默改变场中所有已放置实例。

对于任意原生网格，保存为 **静态网格预设**，支持整体铺放、旋转、配色和导出；不谎称能逆推出最初的体块配方。复杂节点、驱动、外部依赖和脚本不在首版无损承诺内，保存前报告。

### 5.3 `.blend`、recipe 与人工修改的关系

`.blend` 中的实际模型及插件持久元数据构成当前资产状态；recipe 是可重建的建模请求／配方和变更记录，不与当前场景维持两套互相覆盖的“真相”。

人工操作通过插件时同步实例ID和元数据。用户使用 Blender 原生编辑功能修改托管网格后，要检测状态变化：允许显式采用为静态预设，或解除其参数化关系；不自动从旧 recipe 重建并抹掉人工修改。

Agent 修改前使用 `inspect` 获取当前版本／指纹，提交时携带预期版本。不同则拒绝陈旧修改，先重新读取。导出的可编辑交付应能重新打开，不依赖一次 Python 会话里的全局字典。

## 6. 像画画一样搭建：交互规格

### 6.1 三种放置模式

**锁平面：**在 XY／YZ／XZ 指定高度或深度上铺地面、墙或顶面。开始笔划时冻结工作平面，不因射线命中新生成的块而自动越画越高。

**轴向表面：**从已有方体的面选择一次放置平面及外法线，沿该面铺放；本笔划不把新生成表面当新目标。更换承载面后再开始下一笔。首版不承诺沿曲面连续滚动贴合。

**显式堆叠：**主动切换层／深度或重新选面，再铺下一层。需要时可以点选预设的自定义锚点吸附，但不做隐式无限堆高。

单点、线段、矩形填充、连续笔刷与橡皮擦共用落点生成／校验逻辑。预设大于单块时，笔刷间距按预设足迹或显式配置，不把大拱门每隔一个小体素重叠铺满。

### 6.2 连续铺放与重叠策略

鼠标采样之间在工作平面的离散格网上补全路径，不能只按鼠标事件次数放物件。悬停不重复生成；同笔划的相同位置、预设及朝向去重。

首版默认不在已有相同实例上重复叠放。允许接触但不重复实体占位；组合预设按其子块占地判定，不能用整个包围盒把拱门内部空洞也当实体。任意静态网格使用保守边界检查并标识限制。

橡皮擦默认删被命中的**放置实例**，不是无边界地删除场景任意网格。组合预设默认作为整体，用户显式拆开后才能逐子块删除。不在首版加入通用几何切割。

### 6.3 撤销与恢复

一次按下—拖动—释放是一笔，一次 Ctrl+Z 撤销整笔；线段／矩形同理。Esc 在提交前取消，必须恢复到笔划前状态，不留下半笔物件、材质或缓存。

遵守 Blender Operator 撤销机制；不能把返回 `CANCELLED` 当作自动回滚已经发生的数据修改。官方明确指出，修改数据的 Operator 应正确参与 Undo，取消返回不会自动创建撤销步骤。[B2]

切换文件、退出模式、失焦、禁用插件和发生异常时清理预览、计时器与绘制回调。撤销、重做和文件重载后重建运行缓存，不持有已失效的 Blender 对象引用。

**场景撤销不等于磁盘文件撤销。** 保存预设、导出模型为显式持久操作；通过不可变版本和文件备份处理，界面不承诺 Ctrl+Z 能删回已保存的外部文件。

### 6.4 上色与共享数据

支持选择色板后新建、给选中块／实例涂色，以及选定面涂色。全局换色必须明确作用于“当前资产”还是“本项目该色板角色的全部使用者”。同一RGB不代表同一语义角色或同一金属度，不可盲目合并。

共享网格实例的局部面涂色需要写时复制或适当的局部覆盖；不能因为改了一块石头而无意修改全部同网格物体。全局色板更新则应有预期地更新该作用域内的引用。

## 7. 材质和导出：保留常规工作流

### 7.1 制作时采用色板＋共享标准材质

建议首版使用简单 Principled BSDF，基色、粗糙度、金属度、必要的发光与单双面参数均明确。颜色角色用稳定 ID，如 `stone.base`、`stone.dark`、`leaf.dry`；显示名称可改，ID不随显示名改变。

色板文件可以保存 sRGB 色值，转换到 Blender／glTF 所需数值时显式处理色彩空间，避免重复或漏做转换。颜色管理与光照会影响最终画面；标准材质中的基础色不要求依赖游戏运行时的材质名识别才能显示。[B3][B4]

限定的是基础色，不是最终屏幕颜色。首版不强制像素限色，不烘入柔和阴影或雾，不承诺不同引擎的光照／色调映射逐像素一致。

### 7.2 两条导出路径都交付，不把“输出贴图”悄悄删掉

| 路径 | 行为 | 首版验证 |
|---|---|---|
| 标准颜色材质 | 使用共享标准材质保存颜色及基本表面参数，无强制贴图 | GLB 导出后不依赖插件或自定义赋色脚本即可正确显示 |
| 自动色板贴图 | 根据使用的色板建立小 PNG，把每面 UV 放到对应颜色区；不要求人工展开 | GLB 和 FBX 贴图路径、颜色、UV、单双面及尺度均测试 |

色板贴图不是烘焙最终灯光。仅可把表面参数兼容的颜色合进一个材质族；金属、发光、透明和单双面差异不能为追求“一个材质”而丢掉。首版优先不透明材质；不同参数分组，必要时多材质，不强塞复杂通道烘焙。

采样策略明确：色块中心采样、适当填充，首版色板采用最近采样并避免混合调色板的 mip；检查导出和加载后的实际 sampler。不能只说“贴图很小”或“有padding”就保证任意距离永不串色。若接收端改了采样策略，必须暴露并验证。

色板路径正确设置基础色乘数，避免图片颜色再乘一次原有颜色。用多种明显不同的测试色，验证颜色通道和色彩空间转换。

### 7.3 非破坏性整理

导出时复制到临时集合／场景，在副本上应用变换、转为网格、必要三角化、按资产／块区整理材质和网格。不能为了合批永久合并源模型，不能顺手清空当前场景。

制作时共享网格／材质有助于减少重复数据，但不等于目标引擎必然一个 draw call。导出记录实际对象、三角面、材质、材质分组及文件大小；不把“顶点少”当成充分性能证据。[B4]

首版不以复杂自动布尔和重拓扑作为前置。能证明安全的相邻轴对齐共面内部面可移除；任意重叠网格不盲目删面。暂未优化的内部面应报告，不伪装成已经做了外壳提取。

### 7.4 格式与兼容性

GLB 为首个完整验收格式，FBX 为必要的通用交换输出。优先调用实际版本已有导出器，不自写 FBX 二进制编码器。不保证任意 Blender 节点原样传递；插件内部主动使用有限、可验证材质集合。[U1][C1]

验证零厚度面片正反面、法线、镜像、单位、原点、锚点、负缩放和纹理依赖。Blender 轴向与导出坐标转换只做一次，以非对称三轴标尺和已知长度检查；不要把艺术网格单位误改为游戏格单位。

GLB 至少进入一个独立于 Blender 的查看器（例如现有 Three.js 依赖构成的隔离查看页），截图和数值检查都保留。不修改游戏地图或核心模拟来接模型。

FBX 至少完成导出＋新文件重新导入，贴图随包可用；再使用本机实际可用的目标接收端验证。只有 Blender 往返时标“Blender往返已测，外部引擎未测”，不能报告团结／Godot均已验收。

## 8. Agent 原生支持：首版就能实际调用

### 8.1 最小 API 合同

以下是拟实现名称和职责，不是已存在可运行的 API。实现后以 `capabilities` 返回的正式合同为准。

| 能力 | 接口职责 |
|---|---|
| `capabilities` | 工具/API版本、支持的基板／操作／导出、运行模式、资源上限 |
| `get_profile` / `list_presets` | 当前尺度、色板、默认值、预设ID和固定版本，不让 agent 猜名字 |
| `inspect_asset` | 托管资产实例、变换、颜色、包围范围、警告和当前修订号 |
| `validate_recipe` | 执行前检查格式、数量、路径、引用、网格、颜色、重复与冲突，返回拟变更摘要 |
| `apply_recipe` | 成批创建／排列／删除／变换／换色，作用于指定资产根；事务提交 |
| `save_preset` | 显式保存选定托管资产为新预设／新版本；不自动发布所有临时生成物 |
| `validate_asset` | 检查实际场景和导出副本，不只检查请求JSON |
| `render_preview` | 设定的正交角度／中性环境和可选氛围图，返回文件路径 |
| `export_asset` | 经明确选择的材质方案导出，返回产物清单和检查结果 |

### 8.2 能做新模型，不只会搬已有预设

Agent 可调用方体／薄板／面片，使用阵列、线段、区域填充和显式子件组合做出新的墙段、台阶、断拱等，再请求保存为预设。不能把“agent可以列出和摆放旧预设”当作全部能力。

首版提供基础确定性构造，不要求包办所有树木、雕塑、废墟的艺术自动设计。agent 仍负责选择形体和构图，用户负责接受或修正；工具负责让尺寸、颜色和文件流程可控。

### 8.3 请求示意

```json
{
  "schema_version": "0.1",
  "request_id": "demo-wall-create-001",
  "asset_id": "draft.ruin_wall_01",
  "expected_revision": 0,
  "profile_id": "project.demo",
  "profile_revision": 1,
  "operations": [
    {
      "op": "place_array",
      "id_prefix": "wall",
      "template_id": "base.cube",
      "origin_cells": [0, 0, 0],
      "size_cells": [1, 1, 1],
      "count": [8, 1, 3],
      "spacing_cells": [1, 1, 1],
      "color_id": "stone.base"
    }
  ]
}
```

这仅规定“一排八块、三层高”的请求形态和定位思路，不是艺术成品，也不固定真实色板／物理米数。原点按规范定义为格边界参考，模板锚点转换由核心负责。正式 schema 应拒绝未知字段、无效尺寸、NaN、负数组数量、未知颜色和不可读预设。

禁止在 recipe 内 `eval`／`exec`、shell命令、任意URL或载入并自动执行 `.blend` 文本脚本。可信的 Blender Python 适配器负责解释有限操作；JSON是数据，不是代码。

### 8.4 安全、重复调用与人工接管

Agent 默认只能操作指定资产根及获准输出／预设库路径，不清空场景，不改原素材。不允许路径穿越；文件量、操作数和展开后的实例数有上限。

请求使用稳定ID。相同 `request_id` 与相同请求不重复建一份；同ID不同内容返回冲突。重试状态随目标资产持久化，并与撤销／重做同步，不仅保存在当前 Python 进程内。

修改带 `expected_revision`；与用户最新改动不一致时报告冲突，不能“以recipe为准”覆写。所有写请求先验证，失败恢复本事务新建/修改的数据；外部文件先临时写入，成功再提交。超时或中断返回已知状态，不猜成功。

这限制的是插件入口，不是隔离任意外部 Python 的安全沙箱。有权直接运行其他 Blender 脚本的 agent 仍可能绕过插件，因此还要有工作目录限制、明确任务范围和使用说明，不能宣称单靠API就防止一切错误。

### 8.5 三种接线方式

**必做：Blender 内 Python API。** 人工可在脚本控制台验证，现有已授权 Blender 连接也可以调用。复杂构造不依赖模拟 UI 点击。

**必做：后台 CLI。** 使用实际 Blender 可执行文件运行插件附带脚本，传 recipe、输入／输出路径，返回 JSON 报告与渲染图片。Blender 官方提供后台运行、执行 Python 脚本及错误退出码等参数。[B5]

```powershell
# 以下是未来应实现的调用形式，路径和脚本并非当前已有安装。
& $BlenderExe --background --factory-startup --python-exit-code 1 `
  --python "$ToolRoot/scripts/run_recipe.py" -- `
  --recipe "$RecipePath" --output-dir "$ApprovedOutputDir"
```

脚本需要可靠加载该次打包的插件模块。Blender Extensions 安装后的模块命名空间可能不同，不能硬编码一台电脑的 `bl_ext` 仓库路径。输出和错误语义也由合同明确。

**条件接入：现有实时连接／MCP。** 若用户已有连接且能执行 Python，做薄适配器调用同一个 API，并实际在当前 Blender 会话验一次。若没有，先交付CLI完整流程，不为此新建公网服务或要求重装现有连接。

后台 Blender 进程不会自动修改用户正打开的那一份场景；结果需要明确保存、打开或导入。不得把后台渲染成功说成“已更新当前视口”。

任何桥接都不能从后台网络线程直接修改 `bpy`。Blender 官方明确警告其 Python 集成的线程安全问题；复用现有合法调度或在主线程处理数据变更，耗时计算分开。[B6]

### 8.6 “以后 agent 会使用”的交付

除了 API，提供 `AGENT_GUIDE.md` 和经过实际执行端验证的配套 Skill：何时使用、如何查规范、如何生成／校验、如何局部修改、何时询问、如何输出 `.blend`／模型／图片。

Skill 是使用流程，API／CLI才是执行能力。OpenAI 官方将这两者明确区分，Skill 也可以在无需 MCP 的情况下组织打包资源和流程。[B7] 不把“创建了一个 SKILL.md 文件”说成已经注册或之后所有 agent 都必然自动调用。

获得明确配置授权后，在目标 Codex 的实际发现目录注册并用新会话测试。需要项目入口提示时，只在批准位置增加简短指引，不修改开发细则。对不支持 Skill 的 agent，显式提供 `AGENT_GUIDE.md` 也应能工作。

验收至少包括：自然语言要求符合规范的新模型 → agent 发现并调用插件 → 产物有真实API日志；再要求局部修改 → 没有绕过工具重写整个模型。

## 9. 性能与批量生产

不要默认每个小体块一套独立网格、一套独立材质，也不要每次鼠标移动重建整场景。复用相同几何／材质、预览与已提交数据分开；按笔划和脏区域批量更新，预设缩略图缓存按内容版本失效。

编辑表示与导出表示可不同：编辑保留块／实例身份；最终按资产或适当区域整理。若实测独立对象数量造成明显瓶颈，再对纯规则块采用分块网格与面到源实例的映射；不能为了优化使用户失去橡皮擦和局部换色能力。

首版性能样例建议为 1,000 基础块的常规交互、10,000 基础块的压力场景，以及 100 个复合预设实例。它们是测试工作负载建议，不是已验证容量，也不能把一个包含数千面的预设与一个立方体等价计数。

在用户硬件上记录笔划更新延迟、视口帧率、撤销时间、内存、保存／导出时间、三角数和材质分组。先协商可接受门槛再测，不无依据承诺“百万体素流畅”。采用与未开笔刷时相同的视口、着色和场景作比较。

批量生成不能只报告生成速度；报告生成、校验、修正、导出后的完整成本。先用少量资产测试人工干预量，再扩大到大批量。

## 10. 实施顺序：完成一个可用工具，不堆孤立功能

### P0｜环境和规范锁定

确认第2节，检查已有体素实验与目标目录，读取真实 Skill 和对应版本API；备份但不覆盖既有 `.blend`。确定一套初始尺度、基础色板、首版镜像／旋转步进和保存路径。

产物：环境报告、规范样例、有效范围。必须缺失时才问用户；本机已可检测信息由执行者核对。

### P1｜公共核心与最小双入口链路

建立安装骨架、基板、稳定ID、规范校验、共享材质和API。用相同参数从人工按钮与后台脚本各创建一个带色方体，完成 `.blend` 保存、重开和一个GLB输出。

产物：第一份真正可运行安装包和结构化调用记录，不是空面板。两入口结果比较几何、色板ID、尺度、锚点，不要求二进制文件字节相同。

### P2｜预设和可复用资产数据

完成组合保存、缩略图、标签／搜索、锚点、版本、新场景载入、静态网格预设、拆开编辑和配色映射。同步API，使agent能创建新组合并显式保存候选预设。

产物：从人工和agent分别制作的预设可相互调用，重启后不失效，升级插件不丢库。

### P3｜笔刷与上色完整体验

完成三种首版放置模式、连续补点、线段、矩形、擦除、旋转／镜像、实例／面涂色、落点预览、单笔撤销和Esc回滚。测小场景中的实际操作，不仅模拟算法输出。

产物：能够顺畅画墙、铺台阶、堆树冠；录屏证明快划、停留、越过面边界和取消时符合预期。

### P4｜Agent批量、修改和验证闭环

完成正式 schema、能力查询、预检、数组／区域等批操作、修订号、重复请求处理、错误报告、局部修改、标准预览渲染及CLI包装。现有连接可用时做薄适配；否则交付后台路径并准确标识状态。

产物：不是预设搬运脚本，而是能由新参数构造新的模型；用户继续改、agent读到更新后继续改。

### P5｜导出完整化与性能收束

完成自动色板PNG与UV、GLB两条材质路线、FBX和依赖打包、非破坏性合并、计数报告、独立查看及轴向测试。处理实测对象／材质瓶颈，不扩成完整体素引擎。

产物：真实可导入的模型及颜色结果；明确被测版本和未测接收端。

### P6｜实用样例、Skill和交付

做一组验证资产：墙段、台阶、石柱、断拱、树冠／树干组合、面片装饰，拼成小型遗迹展示场景。场景仅用于工具验证，不是游戏新地图交付。

其中至少一件人工用笔刷制作，一件agent从基板生成并保存预设，一件从用户已有预设批量组合。完成下一节验收、打包、安装／禁用／重启验证及最小教学视频。

获得配置授权后注册agent使用入口；执行新会话的自然语言建模、局部修正、导出测试。模块完成以前不先做内置聊天、云库或任意图片一键转模型。
