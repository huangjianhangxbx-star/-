# 星骸回廊：T-026 / EC-08 敌人战斗能力升级实施计划 v0.1

> 日期：2026-10-06  
> 当前核对基准：GitHub `main@9d9b59a5de3e3974855a1fef16ae316354e83fe2`。  
> 前置：EC-01～EC-07 已实现；用户确认最新版已上传并可进入下一阶段。  
> 状态：计划草稿，尚未实施、未写入仓库。

## 1. 本阶段目标

当前玩家侧已经拥有双角色切换、走A、主动闪避、3技能槽、Telegraph规避、Break/Impact/WallPin、方向与Weakpoint。

但敌人仍主要是：
```text
发现玩家 → 接近/保持射程 → 基础攻击
```

EC-08 的目标是：

> **让普通敌人第一次拥有 Combat Kit：Basic Attack + 1 Active Ability + 1 Reaction。**

共享玩家已经建立好的战斗语法，但不直接复用玩家 SkillProfile/三槽/技能树。

---

## 2. 本阶段范围

只做：
- Enemy Combat Kit 数据与运行时；
- 三类现有敌人各1主动能力+1临场反应；
- Ability复用AttackIntent/AttackArea；
- Reaction delay/cooldown；
- 敌方主动回避的第一版；
- Break打断Ability；
- 与方向/Weakpoint联动；
- 多敌人同屏可读性验证。

不做：
- 新敌人种类；
- 精英/Boss完整技能组；
- Companion AI 2.0；
- 指令轮盘；
- 怪物知识；
- 卡牌转型；
- Encounter正式重做；
- 新美术资产。

---

## 3. 共享战斗语法，不复制玩家技能系统

敌人共享：
- AttackArea；
- Telegraph → Lock → Resolve；
- HP/Posture；
- Break；
- Impact；
- Active Avoidance；
- Direction；
- Status。

但敌人不使用：
- 玩家SkillId；
- SkillProfile；
- 3槽UI；
- 技能培养。

建议建立：
```text
EnemyCombatKit
EnemyAbility
EnemyReaction
EnemyCombatState
```

---

## 4. 敌人复杂度上限

首版每个普通敌人：
```text
Basic
+ 1 Active
+ 1 Reaction
```

不做多技能Boss式复杂度。

---

## 5. 首版Combat Kit

### Melee
```text
Basic
+ 裂阵重斩
+ Counter Step
```

### Ranged
```text
Basic
+ 蓄力穿射
+ Backstep Evade
```

### Heavy
```text
Basic
+ 震地重击
+ Front Brace
```

名字是原型标签。

---

## 6. EnemyAbilityId独立

不要塞进玩家 `SkillId`。

建议：
```ts
type EnemyAbilityId =
  | 'melee-heavy-cleave'
  | 'ranged-power-shot'
  | 'heavy-ground-slam'
```

AttackIntent / CombatEvent 可记录：
```text
enemyAbilityId
```

---

## 7. EnemyCombatState

建议：
```ts
type EnemyCombatState = {
  kitId: EnemyKitId
  abilityReadyAt: number
  reactionReadyAt: number
  reaction?: EnemyReactionAction
}
```

能力开始时立刻进入cooldown。

如果随后被Break打断：
> cooldown不退款。

---

## 8. 不使用裸随机

不允许每帧：
```text
Math.random() < x
```

决定闪不闪或放不放技能。

行为由：
- 条件；
- 冷却；
- deterministic id/seed offset

决定。

---

## 9. 避免同步施法

同类敌人首次Ability Ready时间加入：
```text
0～1.2s
```
的确定性offset。

后续按各自cooldown。

---

## 10. Ability复用AttackIntent

扩展AttackIntent：
```text
kind: basic | ability
enemyAbilityId?
label?
```

Ability继续使用：
- Tracking
- Locked
- Resolve
- AttackArea

Renderer不能另造第二套伤害几何。

---

## 11. 决策优先级

```text
Reaction pending/active
→ existing AttackIntent
→ ready Ability
→ Basic
→ movement
```

Reaction不打断已经成立的Intent/ForcedMotion/stagger等动作。

---

## 12. Reaction公平规则

Reaction不能读：
- keydown；
- mouse；
- “玩家刚按E”；
- 控制权切换。

只能读已经进入Simulation的状态，例如：
- 真实受击；
- 已提交Windup；
- 距离；
- Posture；
- Facing；
- CombatEvent。

必须有delay和cooldown。

# 13. Melee：裂阵重斩

建议：
```text
Shape: Sector
Range: 1.35U
Arc: 140°
Total: 0.85s
Lock: 0.50s
Cooldown: 5.0s

HP Damage: basic ×1.35
Posture: basic ×1.60
Break Impact: 0.65U
WallPin: false
```

使用条件：
- target ≤1.25U；
- 同层；
- LOS合法；
- ability ready；
- 当前可行动。

---

## 14. Melee Reaction：Counter Step

触发：
> 受到一次真实 direct / non-derived 玩家命中后。

条件：
- 非Broken；
- 非stagger；
- 无Intent；
- reaction ready。

参数：
```text
delay: 0.15s
distance: 0.55U
duration: ~0.15–0.18s
cooldown: 4.0s
```

没有无敌帧。

方向选择：
- 根据攻击来源；
- 检查左右合法空间；
- 选择更可用一侧；
- 相同时用enemy id稳定决定。

---

# 15. Ranged：蓄力穿射

```text
Shape: Capsule

Half width: 0.16U
Total: 1.05s
Lock: 0.65s
Cooldown: 6.0s

HP Damage: basic ×1.60
Posture: basic ×1.40
```

使用条件：
```text
target distance 2.2～6.0U
LOS合法
ability ready
```

---

## 16. Ranged Reaction：Backstep Evade

触发：
> 任一可见Party Body进入1.60U近身威胁区。

不是读输入。

参数：
```text
delay: 0.15s
distance: 0.90U
duration: 0.18s
avoidance window: 0.08s
cooldown: 5.0s
```

方向：
> 远离最近威胁。

这用于验证：
> 敌人也能使用与玩家相同的主动回避语法。

---

## 17. 通用Avoidance

建议抽象：
```text
activeAvoidanceWindow(s,u)
```

玩家伙伴Evasion和Ranged Backstep共同消费。

但：
- 玩家仍用charges；
- 敌人Reaction只用cooldown。

共享命中语法，不要求外围资源规则一致。

---

# 18. Heavy：震地重击

建议：
```text
Shape: Circle
Radius: 1.75U
Center: Heavy当前位置
Total: 1.15s
Lock: 0.75s
Cooldown: 7.0s

HP Damage: basic ×1.40
Posture: basic ×2.00
Break Impact: 1.15U
WallPin: false
```

至少一个Party Body在范围内即可考虑使用。

---

## 19. Heavy Reaction：Front Brace

触发：
> Heavy受到一次真实 Front direct hit后。

条件：
- posture >0；
- 非Broken/stagger；
- 无Intent；
- reaction ready。

参数：
```text
delay: 0.15s
active: 0.65s
cooldown: 6.0s
```

Brace期间额外：
```text
Front HP ×0.70
Front Posture ×0.70
```

Side/Back不吃Brace。

Broken立即取消Brace。

---

## 20. Brace与EC-06联动

Heavy原本已有：
```text
Front HP×0.65 / Posture×0.70
Back HP×1.25 / Posture×1.35
```

Brace只进一步强化Front。

因此玩家看到架防后：
> 更应该切人绕侧后，而不是正面硬打。

---

## 21. Ability视觉

Ability Telegraph与Basic共享同一Area，但视觉可区分：

### Basic
沿EC-04现有样式。

### Ability
- 边界更粗或双线；
- Source头顶短显示能力名；
- 不只靠颜色区分。

不增加敌人HUD技能条。

---

## 22. Reaction Tell

Counter Step / Backstep / Brace 都需要约0.15s预备反馈。

不能瞬发。

建议：
- Counter Step：轻微侧向提示；
- Backstep：后撤方向短标记；
- Brace：正面护盾弧形成。

Reduced Motion仍可读。

---

## 23. Ability与Break

Ability Tracking/Locked期间触发真正Break：
- Intent取消；
- 不Resolve；
- cooldown保持。

这是玩家主动打断“大招”的奖励。

---

## 24. Reaction与Break

Reaction Pending/Active期间被真正Break：
> Reaction取消，ForcedMotion/WallPin优先。

---

## 25. Ability与玩家闪避

所有Ability仍走统一 `resolveHit()`：

- 走出Area → Position Avoid；
- Area内Active Evade → Miss。

不做第二套免伤。

---

## 26. Reaction移动碰撞

Counter Step / Backstep：
- 连续移动；
- 不穿墙；
- 不跨层；
- 不出地图；
- 不穿active body；
- 不超出8U leash。

建议抽取玩家EC-03连续采样底层为：
```text
combat-step.ts
```

只共享安全短位移，不改玩家charges规则。

---

## 27. Combat Kit分配

Standalone：
```text
melee  → melee-v1
ranged → ranged-v1
heavy  → heavy-v1
```

本轮固定，不随机Variant。

EC-15再做同Role多Kit。

---

## 28. 不改EC-01基础数值

本轮不同时调整：
- enemy HP；
- enemy speed；
- Encounter count；
- basic damage。

Ability只使用倍率。

这样可以单独判断：
> 行为复杂度是否让战斗更好玩。

---

## 29. Posture威胁

Ability的Posture倍率比HP更明显：

```text
Cleave      ×1.60
Power Shot  ×1.40
Ground Slam ×2.00
```

这样会真正利用EC-05 Broken风险。

---

## 30. EnemyCombat与探索AI职责分离

`updateExplorationEnemy()`仍负责：
- 感知；
- 追击；
- patrol；
- leash；
- return。

EnemyCombat只负责：
> 已进入交战后的局部攻击/反应选择。

本轮不是AI2重写。

---

## 31. Debug

Debug显示：


普通玩家不显示CD数字。

# 34. 用户试玩重点

### A. 三类敌人是否终于有性格
- melee是否像近战压迫者；
- ranged是否真的在控距；
- heavy是否像区域压制和正面硬防。

### B. 是否可学习
玩家能否逐渐知道：
- ranged贴脸会后撤；
- Heavy架防应绕后；
- melee重斩要提前离开。

如果像随机作弊，EC-08未通过。

### C. Reaction频率
重点看：
- melee是否一直抖；
- ranged是否永远追不上；
- Heavy是否正面过硬。

优先调trigger/cooldown，而不是直接删除反应。

### D. Telegraph拥挤
Normal Encounter中多个敌人同时行动时是否仍能读。

### E. Break打断价值
玩家是否开始主动想：
> “它在放能力，赶快Break。”

### F. 三技能价值
敌人复杂以后，玩家是否更愿意使用多个技能应对不同情况。

# 35. EC-08 通过标准

1. 普通敌人不再只有Basic；
2. 三Role有明显不同Combat Kit；
3. 每类至少1 Active +1 Reaction；
4. Ability复用Telegraph/Area；
5. Reaction有delay/cooldown且不读玩家原始输入；
6. Ranged真实验证敌方主动闪避；
7. Heavy Brace鼓励侧后攻击；
8. Break可打断Ability且cooldown保留；
9. 多敌人同屏不整齐同步刷满Telegraph；
10. 玩家觉得敌人可学习而非AI作弊；
11. Tower/旧庭院不被污染。
