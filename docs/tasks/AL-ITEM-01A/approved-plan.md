## 0. 本轮为什么要这样拆

当前 FARM-01 已完成两个安全田块的开垦→播种→成熟→收获循环；`INV-01A` 有当前世界统一库存、Tab 背包和数字 1–0 农用快捷栏；`INV-01B` 让阿尔原有自由槽可拖放/绑定，但**目前它只存 `itemId` 引用，并不会主动使用，更没有阿尔自己持有的后备库存**。

用户最新解释了三个方向：

1. **自由道具栏 = 玩家即时优先意图。** 比如给炸弹，希望阿尔更积极寻找合适投掷时机；给缓慢回血药，希望阿尔需要时主动关注队伍治疗。优先考虑不等于必然施放，也不等于禁止她使用其他后备道具。
2. **阿尔以后有自己的后备道具栏，容量大约五格。** 玩家可以给她，道具 AI 将来也能自己放入；AI 根据实际局势选择可用物品。**“约五格”尚非永久容量定案。**
3. **同一物品交互体系将来还要接赠礼、普通交付，以及直接把物品拖到阿尔角色模型。** 所以不能从一开始把自由栏硬编码成“物品专属自动施放器”，也不能把所有赠予都当作消耗物。

**本轮目标：** 让玩家实际把一份物品交到阿尔手中、在约五格后备栏看到独立数量、设为自由栏优先项，并看到**一种真实的阿尔 AI 自动使用样板（缓慢回血药）**。这足以检验“物品归属→玩家意图→AI资格→真实使用”的基础。炸弹战术投掷、礼物剧情和直接拖到角色模型是后续专项，不能因接口预留而假装已实现。

## 3. 权威设计：后备物品与自由栏必须分离

### 3.1 数量归属

- 当前 `WorldSession.backpack.stacks` 是当前世界玩家/队伍背包数量的唯一来源；`WorldSession.backpack.hotbar` 是它的十格**引用**，不能储物。
- 建议在**同一世界道具权威**下，为固定 `ranger` 建立 `alReserve`（暂定 5 格，槽内为 `itemId + quantity`，并有 `revision/serial`）。**玩家背包→阿尔后备**是原子物品转移：玩家数量减少、阿尔持有数量增加，总量不变；撤回则逆向，库存溢出/满格/无货整体拒绝。不得既保留原包可用数量又给阿尔凭空增加同量。
- 自由栏 `companionFreeItem` 应变为**优先意图引用**，指向阿尔持有的某种物品（或具体有效后备格），**不能是第二份数量**。同一项可在阿尔后备与自由栏中同时显示，但总计只能消费/转移一次。
- 必须对旧 INV-01B 已有 `companionFreeItem.itemId` 的**会话兼容/行为变化**做显式处理和测试：此前它仅指向队伍 `stacks`。不能静默变成“已经交给阿尔的实体道具”。允许在真实用户交付时从背包转入后备并设为优先，或者清楚提示需完成交付；请选一种最小一致路径，记录成 S​AMPLE 与 UI 提示，不生成免费物品。
- 当前世界里阿尔自己拾取道具以后必须走同一转移/收入接口；**本轮没有拾取 AI**，不要伪装她已经能自动收纳。

### 3.2 统一物品分类，不把全部物品视作消耗品

建议定义可拓展的、**本轮最小**物品语义：

- `farm`（现有种子、农具、实验收成）：保持 FARM-01 指定的玩家农田消费者。即使由玩家交给阿尔，**本轮也没有自动种田或自动使用**。
- `usable`（本轮仅新增实验缓回药）：允许阿尔 AI 在满足真实条件时消耗，具有唯一效果消费者。
- `gift` / `material` / `handoff`：**先作为以后交互协议的类型/未支持意图边界**。没有正式物品样本时，不必伪造好感、对白或商店；明确返回“赠礼/交付行为待专项接入”，不能默默消耗或当作战斗道具使用。

给物品的请求应包含 `worldId`、`visit`、`ownerId:'ranger'`、`source`、`itemId`、`amount`、`expectedRevision`。操作的入口可标记来自背包/未来角色模型/阿尔后备；**接收后的核心语义不得由 DOM 坐标自行决定**。需要意图不明时先停在可确认状态，不自动判作赠礼。不要现在凭空接入角色好感系统。

### 3.3 玩家可以得到的直观操作

本轮推荐的 UI 行为（SAMPLE，用户试玩后可调整）：

1. `Tab` 打开背包，在现有面板内新增一个**阿尔后备**小区域，先展示 5 格（不是重排主 HUD 的第七块）。拖/点物品指定数量 → 阿尔后备；初始简单处理为**每次交付 1 个**，重复操作可交多份。若用户看到批量交付困难，后轮再加入数量选择，不作永久约束。
2. 在后备区域选中一个有库存的物品，点击“设为优先”或拖到现有阿尔自由栏；原位自由栏显示名称、阿尔持有量与状态：`优先考虑 / 等待时机 / 条件不符 / 耗尽`。可清除偏好但**不销毁阿尔手中库存**。
3. **兼容旧习惯：**玩家从队伍背包直接拖到阿尔自由栏，应有可见提示，原子完成“给阿尔 1 件 + 设为优先”，如果阿尔后备满、道具无货等，完整拒绝、不出现假绑定。
4. 从后备撤回队伍背包，数量在双方同步变化；优先项的库存耗尽时，保留意图但显示不可使用（或经明确解绑），不得偷偷补货。
5. 已选的数字农用快捷栏仍只用**队伍背包剩余数量**，Y 瓶与左手炸弹继续各有自己的权威；不要把左手装备的炸弹实例转换成“阿尔背包里的炸弹”。

键盘/拖拽、失焦/模态、变更访问代次与库存损坏都必须纯拒绝或取消。保留 1920/1280 原 HUD 六区、阿尔用户头像、自由栏坐标及外框；后备页可以局部滚动，不能遮住槽导致无法完成拖放。

## 4. 首个真实 AI 竖切：缓慢回血药

### 4.1 数据与实际效果（全部为试验样板）

- 新增一个明确标记 `SAMPLE` 的 `sample-al-regen`（暂名“实验缓回药”），初始给**队伍背包** 2 个用于试玩；原 FARM-01 `seed5/tool1/crop0` 不变。药未交付阿尔时，阿尔绝不能凭空使用。
- 推荐效果：对一个**当前存活的猎人或阿尔**施加 `regen`，**每模拟秒恢复 4 HP，持续 5 模拟秒**（总量最多 20，按真实缺血与HP上限截断）。实际效果沿现有 `healHealth` 和 `Status.kind='regen'` 结算，不要直接重写 HP、灰血和 DOT 规则。
- 推荐条件：目标 HP 比例不高于 65%；目标与阿尔同层、有效距离不超过 3 单位、必要的视线/墙阻合法；目标尚无有效同类缓回效果，或当前总恢复不会浪费。在高威胁动作、受击硬直、已接收攻击等危险状态不插队、不同步偷取消黄金 Basic/RMB/E。
- 实验初期 **阿尔离手由 AI 控制时**才自动使用；玩家 `Z` 直接控制阿尔时，AI 不替玩家偷偷使用。暂不加入阿尔道具特殊动作/新的正式 Spine 资产；使用成功至少具备清楚的小范围光效/状态读数/日志，不能只改后台数值。
- 推荐取舍：有自由栏优先的可用治疗药时，较普通后备更积极考虑；如果自由栏物品没有合法时机或已耗尽，仍可考虑后备中其他合适的可用物品。**“优先”不等于“强制立即使用”或“只允许使用该物品”。**

### 4.2 唯一决策与唯一消费

- 写纯查询 `queryAlItemCandidates`：先确认正式普通世界/固定阿尔原始本体/当前非实控/生命/未被强制行动、可见合法目标、后备库存、类别消费者、冷却/防重复和空间条件。为每个候选记录 `itemId / target / reason / prioritySource`；不得在查询时扣库存、变更 AI 或发 FX。
- 加 `advanceAlItemDecision` 的受控轮询（例如 0.2 模拟秒，仅 SAMPLE），与原 `advanceCompanionCombat`/现有动作资格协调。优先偏好只影响评分及尝试倾向，合法性与身体锁优先；不替换旧阿尔追敌/翻滚/基本攻击计划；**不要为了喝药自动位移、穿墙或瞬移**。
- 真正接受使用 `acceptAlItemUse` 必须由世界/后备库存的唯一事务扣 **1**，绑定 `worldId + visit + itemId + ownerId + instance/usage serial`，确保一次只扣一次、重复请求、退出/新世界旧事件均不能多次使用。再走唯一 `regen` Status 消费者；Trace 关闭也必须一致。
- 正在作用的 regen 是世界本体状态，不因 `Z` 切人、自由栏换意图或离区被第二次付款；时间推进严格遵循现有模拟钟/World 生命周期，不得无意给永久治疗。死亡归零/重生保留或清除即时状态沿 LT-01 **现有规则**，不免费恢复药。
- 只能以真实已交付的物品作为 Al 使用来源；当前队伍背包里的同类药、农田收成、数字槽和左手装备均不构成阿尔的免费可用后备物品。

### 4.3 验收时必须能实际观察到

自然试玩流程：进入世界 → Tab 给阿尔交付实验缓回药 → 将药标为自由栏优先 → 让阿尔离手同行 → 真正被怪物打伤时她在合法时机对对应队友施加缓回 → 阿尔后备数量-1，队伍背包已在交付时-1 → HP 随模拟时间上涨，暂停/离区停止 → 无需按“使用药”快捷键。

负例：满血、无合法目标、所有人太远、遮挡、当前动作不安全、阿尔死亡、直接主控阿尔、自由栏是种子/农具/收成、后备库存为零、重复决策、失效代次等均不允许凭空消耗；如果暂时不能使用，应显示简短原因，不重复刷屏。

## 6. 推荐的 Codex 实施顺序

### A. 先写失败测试（RED）

- 物品从队伍背包到阿尔后备的真正数量守恒；容量 5、每次一份的可逆转移；陈旧 `visit`、`worldId`、revision、非法数量、满仓、负数/重复stack/溢出全部原子拒绝。
- 原自由栏是意图指针：更换、清除、耗尽均不复制/销毁物品；旧 INV01B 参考绑定不允许偷偷变成已给阿尔的实体库存。
- AI 不可在库存未交付、类别 farm/gift、直接控制阿尔、无医疗需求、身体锁定或无合法距离/LOS 时使用；查询前后纯净。
- 真正自动缓回的一次消费、`regen` 真实模拟推进，目标上限/灰血夹紧；切人/死亡/暂停/同世界继续/新世界不会重付或免费补货。

### B. 最小建模与世界生命周期（GREEN）

- 推荐独立模块如 `game/src/core/al-items.ts`（意图/后备/原子交付）与 `game/src/core/al-item-ai.ts`（资格、候选、评分、唯一使用）。实际模块可按源码约束改名，避免将赠礼类型硬塞 `world-inventory` 所有逻辑。
- 最小扩展 `world-inventory` 的已登记物品和安全数量接口，`WorldSession` 初始化/继续/重建，`engine` 分发和模拟步推进；不要并列新增第二个当前世界经济权威。
- 在 `companion-combat` 与独立 Al AI 的资格层对接，避免第二个未经协调的自动行动循环；保留主控身份和同伴既有追敌目标策略。

### C. UI/输入

- `BackpackPanel` 中小型阿尔后备 5 格与原子交付/撤回控制；原位自由槽只显示优先意图，不另起华丽装备屏；复用已验证的拖拽取消/模态屏蔽。
- 用户点击给阿尔时区分**交付动作**与**设置优先意图**，每次更新真实队伍和阿尔数量。提示“目前实验物品，阿尔只会自动使用缓回药”；不给样板种子/农具虚构自主使用能力。
- 已提交的赠礼/普通交付请求在未实现时显示具体“当前尚不可作为礼物/交付互动”提示，不自动吞物品；将来角色模型入口应复用同一 Core 语义，而不是再写一个随意消耗组件。

### D. B 级定向验证

- Vitest：本任务新测试 + `world-inventory`、INV01B、FARM01、Y瓶、LT01、NR01 的实际受影响小集。先小范围，产品真实失败再扩测。
- `tsc --noEmit`、主探索 Vite 构建；触及共享内容则对 Action Lab 执行轻量构建/烟测，不跑全部退休系统。
- Playwright/Edge 真实键鼠 **3～5 条短故事**：1920 交付/设优先/双库存数量，1280 拖拽/解绑/满仓/取消，真实自然受伤→阿尔离手自动缓回，Z 主控抑制自动用药，同世界继续/新世界重置（生命周期可辅以核心夹具）。**不得注入 HP、库存、位置或内部 command 冒充自然使用。**
- 重点记录自动用药开始前后的库存、HP 随真实模拟钟的变化、目标状态、同伴实控身份、原 E/RMB 与 AI 追敌能否继续。必要时只读诊断字段，关闭可选 Trace 时结果相同。
