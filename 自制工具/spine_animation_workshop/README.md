# 星骸 Spine 动画工坊

桌面工坊默认打开 **Spine → Spine**：直接选择两个角色的 `.spine` 工程，记录异名骨骼和控制器的对应关系，预览迁移动作，自动准备目标工程副本及动画导入文件。最后在 Spine 中确认“动画”导入即可，不需要手动导出 JSON 或解包。原有 **GLB 模式**可从右上角进入。Windows 便携包制作见 [packaging.md](packaging.md)。

## 准备素材

1. 本机须安装并授权 Spine **4.3.26**。工坊自动查找本机 Spine；未找到时会让你选择 `Spine.com` 或 `Spine.exe`，以后记住此位置。旧版工程由官方编辑器后台读取，不修改原文件版本。
2. 保留工程原有的图片目录，确保工程在 Spine 中能正常显示图片。工坊会读取工程配置的图片路径，不要求你准备 JSON、atlas 或解包图片。
3. 启动便携包中的 `星骸 Spine 动画工坊.exe`；源码启动依次运行 `pnpm install --frozen-lockfile`、`pnpm build`、`pnpm start`。

## Spine → Spine 工作流

1. 点击“载入源 .spine”“载入目标 .spine”。工坊在后台读取动作和图片；多骨架工程会提示选择本次使用的骨架。文件选择器仍兼容旧版 JSON 输入。
2. 选择源动作、源/目标皮肤，方向备注可留空；它用于记录当前画法方向，不会自动变换视角。
3. 新载入的一对工程自动采样并建立可靠映射；切换动作时更新分析。也可点击“自动分析并映射”重新分析。已有配置与人工编辑保留；载入配置或手动编辑后，切换动作只沿用已有映射，需要补充时再点分析按钮。对模糊的骨骼候选选择目标后点“确认对应”，并检查侧别、父链和驱动。依赖列表只列该动作实际打键的通道；无法移植的通道须明确标记为跳过并审阅原因。
4. 需要时在当前动作内加入局部旋转或平移修正。完整片段保留原关键时间和曲线；当前尚不能保证精确截取的片段会被阻止生成。
5. 选择输出目录，生成候选，逐时点对照两侧动作及报告。**显式跳过的通道不构成已迁移内容；需目标校准的键仍须审阅。**点击“准备导入到 Spine”，工坊生成独立的 `SPW-02_.../` 目录并打开目标工程副本。此时界面明确显示“尚未导入”。
6. 保存映射配置。下次重新载入来源、目标工程及配置即可复用。换来源、目标或参数后必须重新生成。新动画使用填写的名称；重名时自动编号，不自动覆盖旧动作。

追加第二条动作时，完成下节导入并保存后，将包含第一条新动作的 `.spine` 作为下一轮目标，复用配置即可。每轮都保留原输入文件，生成新的工作副本。

本轮真实样本 `rhiny → rozeul` 使用同一份角色映射验证 `city/interact` 与 `common/talk1`。前者 12 条、后者 13 条通道需目标校准；174/175 条分别明确跳过。两条均为**部分迁移候选**，不能直接当作完整成品动作。试选的 `run` 已淘汰，不属于正式验收。配置、报告和样本位置及逐项结论见 [SPW-02 验证记录](../../docs/tasks/SPW-02/validation.md)。

## 自动采样与映射（0.2.2）

采样与映射计算在本机完成，不调用网络服务，不上传角色。Spine 首次授权、安装或版本下载另依赖官方启动器。加载本地工程后，runtime 沿当前完整动作均匀取 25 帧，记录骨骼世界坐标和朝向的变化；零时长动作取 1 帧。运动幅度用于优先排列待确认骨骼。映射根据名称、侧别、父链及设置姿势下的归一化位置/长度推断；这不是基于画面识别的通用人体语义模型，也没有实现不同绑定之间的整段世界轨迹重定向。

唯一同名/规范化名称，以及严格单一子链的高分对应会自动加入。分支骨骼仅靠位置接近不足以自动确定，不同侧别排除，IK 驱动不兼容的候选保留检查。评分不是正确率。确认后的对象映射可保存复用；附件仍需皮肤/槽上下文，不能仅凭骨名推断。

内置本机历史校准的 rhiny → rozeul 35 项对应，只有两端骨架指纹和皮肤完全匹配才复用；界面会显示其来源。不会把旧动作的跳过策略、修正或层序键套到新动作。当前 atk1 无配置实测自动得到 41 项对象对应，仍有 167 根打键骨骼待确认；324 条通道中 292 条待处理，仍不能直接生成可交付的攻击动作。自动映射只是迁移准备的一步，不等于所有通道已兼容。

## 导回可编辑工程

1. 工坊自动打开的目标工程位于 `target-project/`，是原 `.spine` 的逐字节副本。相对图片路径会自动整理；原工程使用绝对路径的资源仍引用原位置。
2. 点击工坊“复制导入文件地址”。在 Spine 主菜单选择 **Import Project / 导入项目 → Animation / 动画**，粘贴地址，按工坊提示选择来源骨架、目标骨架和本次动画，确认导入。不要选择“骨架”。导入文件只含这次新动画。
3. 在 Spine 保存，然后回工坊点击“校验导回结果”。只有新动画存在、所有骨架和原有动画的导出数据核对一致，才会显示通过。未导入、未保存或误导入整个骨架会被拒绝。
4. 最终使用 `target-project/` 内的 `.spine`。`_internal/`、JSON 和图集是自动生成的中间文件，无需处理。每轮目录另有 `导入说明.txt`，可离开工坊查看；本次任务的校验按钮需保持工坊窗口开启。

若仍使用旧 JSON 作为目标，保存按钮保持旧的 JSON 输出方式；直接 `.spine` 流程请在两端选择原工程文件。操作说明见 [Spine 官方导入说明](https://en.esotericsoftware.com/spine-import)。

## 当前能力边界

Spine → Spine 模式接受 `.spine` 和 Spine 4.3 JSON。最后的动画导入由用户在 Spine 确认；工坊不会自动控制鼠标，也不重建目标工程。校验覆盖可导出的骨架和动画，不是对全部编辑器内部信息的逐字段证明。不自动重绑、移植不同拓扑网格 deform、重建其他方向或修复不兼容 IK/附件。`GLB 模式`保留 SPW-01 流程，其地面原地化和俯角参数不作用于 Spine 来源。
