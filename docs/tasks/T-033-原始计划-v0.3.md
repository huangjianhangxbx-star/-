> 本轮仍是 XC-06 输入与权限收口 + XC-07。相比 v0.2 新增“指令期间防御托管”子项及其整合验收，不重排整条 XC 路线。具体行为阈值属于本计划建议的首轮参数；XC-08继续打磨动作时间线、起手、软锁定与职业参数。

## 0. 本次修订摘要与依据

本次用户补充：

> “在切另一个角色的指令模式时，当前的实操角色虽然无法执行普攻，但是要由ai接管基本的移动或者闪避的使用决策，不能因为玩家注意力在另一个角色的指令模式上就让没被操作的角色站桩挨打。”

本文件保留 v0.2 的纯手动普攻、手动续段、单条预输入、持续订单与输入优先级，只明确替换“原 DirectActor 在 CommandFocus 期间不新增自主移动”的限制。

| 项目 | v0.2 | v0.3 |
| --- | --- | --- |
| 实控起手及续段 | 每段需要玩家输入 | 保留；防御托管不能恢复自动普攻 |
| 指挥队友期间的原 DirectActor | 维持已提交动作，不新增自主移动 | 仍保留 Direct 身份，开放受限防御移动／真实 Evade 或 Blink |
| 临时自保是否等于完整伙伴 AI | 没有定义 | 否；不能追敌、绕后输出、集火或主动释放手动技能 |
| 正在被瞄准的 CommandFocus 角色 | Reservation 阻止新自主动作 | 保留；防御托管只保护另一名原 DirectActor |
| Tactical Focus 自然结束 | CommandFocus 保留 | 保留；防御授权跟随有效 CommandFocus，不跟随 1.5 秒慢动作计时 |
| 旧 MoveOrder | 自动动作暂停，玩家成功新意图才取消 | 保留；防御 AI 行为属于自动动作，不能被误判为玩家新意图 |
| 同一帧控制切换／防御动作 | 未覆盖 | 新增逐角色动作裁决、旧路径清理、真实机动资源去重 |

依据分类：
- **用户要求**：实控普攻纯手动；指挥另一角色时原主控可以自保。
- **已有确认继续有效**：DirectActor ≠ CommandFocus；仅 Focus 不冻结被关注队友；被关注队友进入 Aim 时 Reservation 生效；普攻不值得消耗 AI 闪避；技能危险先走位、必要时才用真实机动；订单目标持久。
- **本计划建议**：将此能力限定为 Defensive Assist（防御托管），只做短距离避险、避免近身围困与紧急机动；提取现有危险判断和安全位置查询，不给 DirectActor 开启整套 Companion AI。
- **代码现状**：本次 GitHub main 仍为 `70823a2fce45a2e4fd4a1dff5e22a62e4dab1d4d`。当前 AI 循环跳过 DirectActor；当前 `evadeAI` 资格也排除 DirectActor。因此此能力尚未覆盖，不能只改文案或只放开一个布尔值。

**“已有躲技能算法”不等于“原实控角色在指令期间已经能自保”。本文件是待实施规格，不是实现或验收报告。**

## 1. 目标

旧版目标：

```text
LMB一次 → A1 → 系统自动A2/A3
```

新版目标：

```text
LMB一次 → A1
没有下一次攻击输入 → 不出A2

再次LMB，且处于合法续段时机 → A2
再次LMB，且处于合法续段时机 → A3
```

**禁用的是实控角色的自动起手和自动续段，不是删除Basic Chain。**

连段系统仍记住当前阶段；决定“是否打下一段”的权力属于玩家，而不是目标仍在范围这一条件。

## 2. XC-06继续并入本轮

已存在的DirectActor / CommandFocus、Tactical Focus、W/E/R/T/Shift同输入接管、MoveOrder成功动作取消等机制继续作为基础。

本轮接通剩余入口：

```text
Hunter Direct
→ Command Al
→ 非UI、非Aim确认的战场LMB
→ 同一次点击让Al成为DirectActor
→ 同一次点击请求Al的A1
```

不为这次设计变更另外安排一轮XC-06重写；但仍需回归原主控、Aim、命令和控制权交接，不能仅因旧任务通过就假定所有组合正确。

## 3. 实控角色禁自动普攻的范围

只要角色是当前DirectActor，下列情况都不得由自动逻辑发起新的普攻阶段：

- 站在敌人旁边，攻击间隔已经结束；
- A1打完，目标仍在范围；
- 玩家松开鼠标；
- 正在执行自己此前确认的MoveOrder；
- 原本由AI控制，刚刚被玩家接管；
- 玩家暂时CommandFocus另一角色，但本角色仍是DirectActor。

特别注意：判断应基于**当前角色身份**，不能只检查界面的`controlMode === 'direct'`。玩家指挥阿尔时，猎人仍可能是DirectActor；不能因界面进入Command就恢复猎人的自动普攻。

## 4. 不扩展成“关闭一切自动行为”

本次新增第 21 节防御托管的权限与接线，但不借此改写下列机制本身：

- 离手队友自主选择何时攻击；
- 敌人的Basic与Combat Kit；
- 已有合法Auto / Background技能；
- 技能CD、受击计数、普攻触发的派生效果；
- 伤害、架势、硬直、击退、闪避的既有结算；
- 离手队友MoveOrder途中的合法局部自动战斗。

例如Rain、Reap等按当前技能规则触发的行为，不因“禁自动普攻”被一并删除。它们是否需要改变手控触发方式，属于另一项技能设计决定。

本轮应拆出**普攻专用的自动请求权限**，不要简单把所有DirectActor的`localAutoCombatAllowed`总开关关掉。

## 5. BasicChain Runtime

建议新增单职责模块：

```text
game/src/core/basic-chain.ts
```

保留每角色独立的连段状态，建议表达：

```ts
type BasicRequestSource = 'player-input' | 'companion-ai' | 'order-auto';

type BasicChainRuntime = {
  stageIndex: number;
  targetId?: string;
  stageStartedAt: number;
  nextStageAllowedAt: number;
  continuationExpiresAt: number;
  // 仅为表达建议，不要求照搬字段名。
};
```

实际攻击请求应记录actor、输入方向、来源和唯一标识。玩家预输入另用最多一项的缓冲表示，不能由一个常驻`autoContinue=true`驱动实控续段。

**来源是追溯信息，不是永久权限。** 不能因为某条Chain最初由AI建立，就在角色已经变成DirectActor后继续自动出A2。

`attackPending`仍可承担单段前摇/命中，避免本轮同时重写整个伤害系统。

## 6. 职业分段Profile保留

继续用数据描述：

```text
BasicChain = [A1, A2, A3, ...]
```

不同职业可有不同段数。首轮至少用真实两段验证手动A1→A2，测试结构还应证明可以扩展到三段及以上。

不需要现在为全部职业编写最终连招内容，也不要求新动画。当前A1/A2复用现有动画仍可接受。

## 7. 本轮必须有最小手动续段时序

旧版把全部Combo Window留到XC-08；纯手动续段之后，这一边界需要小幅调整。

本轮至少实现：
- 当前段什么时候允许下一段开始；
- 下一次点击什么时候视为续段、什么时候视为新A1；
- 没有新输入时如何结束连段上下文；
- 高频点击不能提前命中或绕过恢复时间。

这些是手动连段能工作的最低要求，不是完整动作手感重制。最终逐职业Windup / Recovery / ComboOpen / ComboClose细调仍在XC-08。

**任何重开A1、换目标或重新点击，都不能清零原本仍有效的攻击恢复限制。**

## 8. LMB输入优先级

保留：

```text
Modal
→ Aim Confirm
→ 明确场景交互 / 角色焦点操作
→ Direct Basic
```

- PathAim中的LMB只确认路径。
- 点击己方角色仍走原有聚焦/清焦点语义。
- 篝火、出口等明确交互继续优先。
- UI按钮、拖拽、卡牌、背包和构筑操作不得透传成攻击。
- 其余合法战场LMB才请求普攻。

同一次物理点击不能被`pointerdown`、`pointerup`和`click`重复消费成A1+A2。选择一个真实输入入口，其他事件不得再生成第二份攻击请求。

## 9. Command→Direct的LMB入口

保留同输入接管：

```text
CommandFocus = Al
→ 非UI、非Aim的战场LMB
→ Promote Al
→ 清CommandFocus / TacticalFocus
→ 请求Al的一段普攻
```

这次点击只提供**一段**攻击输入，不附带自动完成整套连段的授权。

## 10. 攻击失败与控制权

保持T-029、T-032已确认的分离：

- 动作级输入可以先完成Direct takeover。
- 后续攻击因为当前动作状态不允许而失败，Direct身份仍保留。
- 失败攻击没有Commit，不因此取消旧MoveOrder。

攻击资格复用现行规则，不借“禁自动普攻”新增架势规则。特别是旧计划把“Broken”概括为不能起手的示例，不应被当成新增“架势为0必定禁止原地普攻”的批准；实施时以已确认的架势/硬直契约分别判断。

## 11. 成功手动攻击取消MoveOrder

手动A1真正获准启动时，取消该角色旧MoveOrder。

挥空A1也属于成功执行的攻击动作，因此同样取消。

预输入仅仅进入缓冲、攻击还没有真正启动时，不应伪装成已经Commit。失败、过期、被更高优先级输入替换的请求不消费攻击、不误删订单。

## 12. 挥空保留

没有合法敌人时，玩家仍可主动发动A1：
- 按鼠标方向起手；
- 运行真实攻击时序；
- 没有真实命中就不造成伤害、不产生假命中反馈；
- 不自动找敌人、不自动续段。

本轮可沿用旧计划的最小边界：无目标A1正常收尾，后续新点击按合法恢复条件重新请求攻击；空挥能否继续复杂连段留XC-08再细化。

实现必须处理空目标集合，不能无条件读取`targets[0]`生成命中或特效。

## 13. 最小瞄准策略保留

本轮继续记录鼠标世界方向，使用现有攻击几何选取该方向的合法目标，允许无目标。

不要求精准点中敌人模型，也不完全忽略方向只攻击最近敌人。连续方向和Soft Target Assist仍在XC-08。

每次真实玩家点击可以表达新的方向；不能用旧AI目标覆盖玩家的新方向输入。

## 14. 普攻Command与请求去重

可以沿用拟新增接口：

```ts
{ type: 'basic', id: string, aim: Pos }
```

或等价设计。核心只接受当前DirectActor的玩家攻击命令；控制权转换仍由集中控制入口处理。

建议给输入请求增加可追溯标识或等价去重机制：
- 一次点击最多请求一个阶段；
- 一个缓存请求最多消费一次；
- 一段可以有技能规定的多个合法命中，但不能把同一次输入重复解释为多段普攻；
- 鼠标按住不通过逐帧轮询自动生成无限攻击。

## 15. 命中仍在Release时检查

起手时选中目标不等于必中。出手时继续检查真实范围、LOS、目标状态及当前攻击规则。

目标移动出范围：
> 该次攻击按原规则挥空或失效。

这条不因手动输入而放宽。

## 16. A2/A3由新的玩家输入请求

建议首版采用：

```text
一次有效点击请求一段。
```

A1之后新的点击：
- 在合法续段窗口内，且当前连段目标/状态符合规则：请求A2；
- 已结束或超过窗口：等待恢复合法后请求新的A1；
- 无新点击：不发起任何新段。

“处于连段窗口”只代表**允许接段**，不是系统会自动接段。

同一目标仍在范围只是合法性条件，不是攻击触发器。

## 17. 目标变化不触发自动攻击

旧版“不自动换目标”保留，但不能误写成“玩家也不能主动换目标”。

- 目标死亡或离开后，不自动转火。
- 玩家后来再点击另一个方向，可以明确选择新目标。
- 本轮可保守采用：旧目标失效则结束旧链，新的玩家请求从A1开始；仍遵守剩余恢复时间。
- 已失效目标对应的旧缓冲不得悄悄改投旁边敌人。

跨目标不断段等更细动作设计留XC-08，不在本轮扩展。

## 18. 建议加入短窗口、单条预输入

这是为手动手感提出的实施建议，不是用户额外要求一个复杂输入系统。

目的：玩家不用恰好卡到某一帧才能接A2。

```text
A1接近允许续段的时点
→ 玩家稍早点击一次
→ 记录一条短期请求
→ 到合法时点执行A2
```

首轮建议：
- 最多缓存一条下一段输入；
- 只在接近合法执行时点的短窗口接收，初始候选约0.10～0.15模拟秒，集中配置；
- 过早输入不积攒，窗口外/过期请求不在很久以后突然执行；
- 不建立无限输入队列；
- 按住左键不默认变为持续连打；
- 当前段结束后若没有真实有效输入，停止。

**预输入不是自动攻击：A2仍然来自玩家确实按过的第二次点击。**

若测试表明现有时序需要不同窗口，以明确记录的候选参数调整；不宣称该初值就是最终手感。

## 19. 高优先动作与预输入

成功WASD、技能、机动、新MoveOrder、武器或其他明确身体命令，按已有取消规则终止连段并清理待续段输入。

进入新的Aim、进入另一角色的CommandFocus／防御托管、发生真正实控归属变化、暂停/失焦，以及硬直或角色失效等会使旧攻击预输入不再可信的情况，应清理未消费输入，防止玩家正在指挥另一个人时原主控迟到补刀。已经实际提交的当前段不因此回滚。

清理预输入不等于回滚已经提交的攻击，也不等于取消MoveOrder；各自沿明确生命周期处理。

## 20. 进入Aim

玩家进入PathAim等更高优先级瞄准：
- 不再接受普通LMB作为攻击；
- 清理未消费普攻预输入；
- 已提交的当前攻击按原动作规则完成/允许的取消规则处理；
- Aim取消后不会凭空补A2。

不把“退出Aim”视为新的攻击输入。

## 21. Command 期间原 DirectActor 的防御托管

本节完整替换 v0.2 第 21 节中“不新增自主战术移动”的绝对限制。新规则仍不是把原主控交给完整 Companion AI，而是只移交**自保移动与基础机动决策**。

### 21.1 身份、注意力、行动权限分开

典型状态：

```text
DirectActor = Hunter
CommandFocus = Al
```

Hunter 仍是名义主控、相机主参考和返回实控的角色；玩家注意力在 Al，Hunter 获得有限防御托管。不得为了绕过旧 AI 限制临时改 controlledBodyId、设置为 null，或伪装成另一名 AI 身份。

| 场景 | Hunter／原 DirectActor | Al／CommandFocus |
| --- | --- | --- |
| 正常实控 Hunter，没有其他 CommandFocus | 玩家负责移动、机动与普攻；无新增防御托管 | 按既有离手 AI 规则 |
| Command Al，仅关注，尚无 Aim | 仅防御移动／紧急机动；无自动普攻 | 既有完整离手 AI，可继续原行动 |
| Command Al，正在 Path／Skill／Mobility Aim | 仍可防御托管；不能因全局有 Aim 就一起冻结 | Reservation，禁止新自主走位、普攻与 AI 闪避 |
| Al 的 Aim 取消，但仍关注 Al | Hunter 防御托管继续 | Al 按订单／自由 AI 恢复 |
| 清除 CommandFocus，返回 Hunter | 立即停止新增防御决策，回到玩家操作 | Al 按既有离手 AI／订单继续 |
| 在 Command Al 中输入 W／技能键／机动键／合法 Basic LMB | Al 真正成为 DirectActor，Hunter 才进入完整离手 AI | Al 由玩家接管，不继承防御或 AI 自动出刀权限 |

这里的“仅防御”限制的是本次新增控制器。已经合法存在的 Auto／Background 技能、持续世界效果及其时钟仍按原规则执行；防御控制器不主动按任何手动技能。

### 21.2 启用与结束条件

推荐派生 `defensiveAssistEligible(state, actor)`，语义为：

```text
Standalone + 正在探索交战
且 actor 是当前有效 DirectActor 本体
且存在另一名有效 CommandFocus
且当前 actor 不是 AimActor
```

之后再按实际动作、生命与资源限制判断“此刻能否启动一次防御动作”。不要把角色暂时硬直等状态误解释为模式身份改变。

授权持续到 CommandFocus 被清除、改变为非法目标、玩家真正交换 DirectActor、离开探索战斗或角色失效。**Tactical Focus 的 1.5 秒慢动作到期，不终止防御授权。**

只打开背包／构筑等界面不自动获得此能力；不能把“没有按 WASD”或“玩家似乎没操作”当作全局托管开关。模态阻止的是玩家输入，是否推进世界仍沿现有时间规则；有其他角色 CommandFocus 时，也不能仅因面板或另一个角色有 Aim 就错误关闭原主控的自保。

### 21.3 防御范围：只脱离危险，不替玩家进攻

允许：
- 技能危险区内做短距离避让，优先选择足够安全且位移小的位置；
- 在可见、已交战敌人贴身压迫或局部围困时，小幅侧移／后退到更安全站位；
- 普通走位来不及且技能威胁达到现行阈值时，调用真实 Evade／Hunter Blink。

禁止：
- 自主 A1、A2、自动转火或为了输出追敌；
- 为弱点绕后、冲到敌人正面、主动 Peel 或整房间找攻击位置；
- 主动释放手动技能、消耗卡牌或治疗道具；
- 为赶路使用 Blink／Evade；
- 自主开启新 Encounter、传送脱困、穿墙或绕过硬直。

普通近身压力的避让只使用可见敌人的位置、朝向和距离等可观察状态，不能读取不可见 Basic 的锁定/命中时点当作完美闪避提示。**Basic 不触发消耗型 AI Evade／Blink**，沿用此前明确决定。

### 21.4 优先走，危险高且走不及时再闪

优先复用现有 `visibleHazards`、`abilityThreat`、安全路径与机动落点查询。

```text
发现当前或即将进入的危险
→ 经过现行反应延迟
→ 现有路径本来就能及时脱险？继续，不无谓改路
→ 能用短普通移动避开？短移动
→ 走不及、能力威胁达阈值、有资源且动作允许？Evade／Blink
→ 否则按现行规则承受伤害，不作弊
```

反应与判断间隔优先沿现行 `COMBAT_AI`，首轮不要另建随机反应概率。近身压力的普通移动采用间隔、最小收益与方向稳定规则，避免持续左右抖动。

候选点优先复用当前小范围采样；安全后停在**新的安全位置**，不为了归位重新走回刚才危险点。只有原本存在未完成 MoveOrder 时，才在危险动作结束后从当前位置恢复那个玩家目标。

### 21.5 可行性：有算法底座，缺的是专属权限与动作接线

本次固定提交核对到：
- `companion-combat.ts` 的 `advanceCompanionCombat()` 对当前 DirectActor 直接清理／跳过；其 `owned()` 同样把当前实控角色判为不可由伙伴 AI 接管。
- 同文件已有 `visibleHazards()`、`abilityThreat()` 及 `avoidHazard()`，支持可见 Ability、真实反应延迟、安全点、先走后闪。
- `evasion.ts` 的 `queryEvade(..., ai=true)` 排除当前 DirectActor；玩家入口则要求 DirectActor。不能假装防御托管就是玩家按了 Shift。
- `exploration-control.ts` 已分离 `tacticalAutonomyAllowed` 与 `localAutoCombatAllowed`，但尚无“仍是 DirectActor、仅有防御权限”的入口。
- `move-order.ts` 目前会在无暂停原因且路径为空时恢复订单，因此新防御路径必须有明确的动作所有权和暂停原因。

推荐最小工程拆分：

```text
共享防御查询：危险、路径、可达安全点、机动资源、动作限制
           ├─ 现有离手 Companion AI
           └─ Command Defensive Assist（只服务原 DirectActor）

普攻请求权限：单独处理，DirectActor永远不接受自动Basic请求
完整战术AI：仍只服务合法离手角色
```

不要把整套 `advanceCompanionCombat` 对 DirectActor 放行。现有 `avoidHazard` 同时包含查询与修改 path/attackPending 等副作用；提取时应将**评估候选**与**真正提交动作**分开，不能只导出函数就算完成。

### 21.6 机动资格与请求来源

新增明确来源，例如 `command-defense`，与 `player-input`、`companion-ai` 区分。名称可调整，但必须能追溯真实来源。

机动执行仍复用现有物理、储层、冷却、碰撞与命中窗口。资格建议拆为：
- 动作/资源/路径是否允许；
- 当前请求者是否有权控制该角色的机动。

`command-defense` 只在上述限定上下文拥有权限；不能变成任意调用者都能让 DirectActor 自动闪避的后门。

尤其不能通过切换 ai 布尔值、临时改 controlledBodyId 或伪造玩家 Command 绕过校验。Hunter Blink 当前会清动作／中断技能，因此自动防御的调用方必须先检查已有原子动作与不可取消前台技能，不能借 Blink 的底层宽权限取消它们。

### 21.7 和正在执行的攻击／技能的关系

进入 CommandFocus 另一角色：
- 清理原 DirectActor 尚未消费的手动普攻预输入；
- 已经真实提交的当前攻击沿现行时间线完成，不能回滚已经射出的箭或已结算伤害；
- 需要防御时，只能按已有取消规则中断可取消普攻前摇；成功提交防御动作后才执行相应取消，不能因为“看见红区”就盲清攻击；
- 不新增 A2，不恢复任何自动普攻；
- 不可取消 Foreground、Crossing、技能落位、已有 Evade、ForcedMotion 等仍按原子生命周期完成。

因此“不能站桩挨打”表示具备受限自保能力，不表示硬直、无路、资源不足时也保证无伤。

### 21.8 和 MoveOrder 的关系

防御动作不是玩家的新命令，因此不能调用“成功玩家 Intent → Cancel Order”的通路。

有旧 MoveOrder 时：
1. 保留原 id、destination、source；
2. 若确实需要防御避让，暂时 Suspend，并记录防御原因／动作所有者；
3. 普通防御路径或 Evade 完成后，从新位置重新规划原目标；
4. 危险结束但没有订单时停在新的安全位置，不恢复旧防御路线，也不自动跟随 CommandFocus。

`advanceMoveOrders` 不得同一帧把防御路径改回订单路径，也不能因为防御路径走完就误报玩家目标已完成。暂停逻辑不能每帧用无所有权的 clearRoute 把正在执行的防御路径清掉。

玩家后来成功 WASD／手动技能／手动机动／Basic，仍按 v0.2 取消旧订单；失败命令保留。

### 21.9 归还控制、按键与同一帧仲裁

回到原 DirectActor：
- 点击原本体、C/数字键或 Escape 按当前层级清 CommandFocus；
- 立刻停止产生新的防御决策；
- 只清该防御控制器拥有的普通移动路径，不清玩家刚建立的新路线；
- 已启动 Evade／跨层等不能粗暴中断的动作按原规则安全完成；不在动作结束后补走旧防御路径。

Command Al 时按 W，仍按已确认规则**接管 Al**，不是让 Hunter 移动。Hunter 因真正成为离手角色才交给完整 AI；原防御控制器必须先交还所有权，不能与完整 AI 同帧写两条路径或扣两次机动资源。

输入优先处理、资格随后重新核验，保证某角色同一时刻只有一个移动／机动动作写入者。不能为此要求玩家多按一次键。

### 21.10 Tactical Focus、相机与瞄准稳定

防御托管不改变 DirectActor，不重新创建或延长 Tactical Focus。AI 防御移动不能被误判为“玩家主动位移”而结束玩家正使用的判断窗口。

被关注角色的 Path／Skill／Mobility Aim 仍以该角色为 origin。另一个角色正在自保，不得更换 Aim.actorId、目标或消费当前鼠标确认输入。

原 DirectActor 的局部移动可能触发现有镜头跟随；本轮需验证：鼠标未产生新的瞄准操作时，防御引起的镜头位移不会悄悄把已预览的世界位置改成另一个确认点。优先稳定世界目标／对象快照或采用现有相机的短期稳定策略，不做全新镜头系统。确认时仍重新验证真实可达性。

### 21.11 不是一行开关，也不需要重写AI

这是一个有现成危险判断可复用的**控制权限与动作生命周期整合项**。本轮新增工作主要在：权限入口、共享防御查询、机动授权、路径所有权、订单暂停恢复、输入交接及组合测试。

应拆成可验证的小步骤，不承诺具体工时或性能提升，也不为此提前引入 EC-10 轮盘、EC-11 技能 AI 或完整伙伴性格系统。

## 22. 真正接管与交出控制

### AI角色变成DirectActor
- 允许当前已经提交、按原规则不能粗暴取消的攻击完成；
- 清理AI尚未执行的续段请求；
- 后续A2/A3必须有玩家输入；
- 不能因为`chain.source`最初是AI就继续自动连打。

### DirectActor变成离手AI
- 清理尚未消费的玩家预输入，避免输入被带到新的控制会话；
- 当前已提交攻击不被凭空吞掉；
- 后续是否攻击由该角色此刻合法的AI策略、订单与Reservation决定；
- 不把玩家刚才的一次点击解释成授权AI无限打完。

每次发起新阶段都重新查询**当前控制归属与权限**，而不是只在A1开始时检查一次。防御托管只修改移动／机动权限，不改变实控身份和普攻请求来源限制。真正交出角色前，先清理原防御移动所有权，再交给离手 AI。

## 23. 玩家与AI仍共用动作执行层

不必复制两份普攻实现。

```text
玩家真实攻击输入 ─┐
                 ├→ 同一BasicStage执行、命中、恢复与表现
合法AI攻击请求 ──┘
```

共享的是如何执行一段攻击；不同的是谁能请求这一段。

离手AI可以保留自己的起手/续段决策，仍受Reservation、动作占用、战术和局部自动规则限制。敌人现有攻击系统不在本轮强制迁移。

## 24. MoveOrder必须按当前实控归属区分

现行T-032契约允许MoveOrder期间的局部自动Basic；本次只替换其中**角色当前是DirectActor**的部分。

| 当前角色 | MoveOrder途中是否自动普攻 | 玩家手动攻击成功后的订单 |
| --- | --- | --- |
| DirectActor | 禁止，不能因路过敌人自动停下来打 | 取消旧订单 |
| Off-Control AI | 保留已确认的合法局部自动Basic；不追怪、不改最终目标 | 玩家若先接管并成功攻击，取消旧订单 |
| Command Reservation中的角色 | 禁止新的自动起手 | 沿Aim确认/取消规则处理 |

**不能用`MoveOrder.source`判断当前能否自动攻击。** `source`只保留原路径安全策略：
- 原来Command签发的Order，角色后来变成Direct：不能自动Basic；
- 原来Direct签发的Order，角色后来交给AI：可在现行规则允许时局部自动Basic；
- 仍是Direct但正在Command防御托管：只可自保并暂停/恢复订单，不能因托管而局部自动Basic；
- 两种情况都不擅自改变订单的路径安全策略和目的地。

## 25. 攻击时序不能靠点击次数重置

移除Auto Continue并不意味着每次点击都能马上命中。

实现必须保证：
- 当前段的最早Release时间不能因重复点击提前；
- 续段不得抢占尚未开放的恢复/衔接阶段；
- 重开A1和换目标不能跳过已有恢复限制；
- 没有有效玩家输入，即使间隔结束也不启动新段；
- 一条预输入只执行一次，不连带后续多段。

最小窗口与恢复边界本轮就要明确；最终职业手感继续下一轮打磨。

## 29. 生命周期

继续维护：
- 伤害已结算不回滚；
- 角色死亡/倒地/离场清理运行时与预输入；
- 硬直、强制位移、技能接管等遵守现有中断规则；
- 结束后DirectActor等待新玩家输入，不自动补下一刀；
- 离手AI按当前权限重新决策；
- 普攻派生效果与已有自动技能不因普攻权限修订被无故删除。
- 防御托管开始/退出不回滚已提交动作；角色失效、交出实控或退出Command上下文时清理防御运行状态。
- 没有有效CommandFocus时，防御控制器不得继续接管正常实控输入。

## 30. 移动与攻击的交接

保留灵敏操作目标：
- 有合法手动攻击请求时，普通移动能按规则让权；
- 新WASD能按现行可取消规则中断前摇/连段；
- W按着的时候点击攻击不能被下一帧旧held状态无条件立刻抹掉；
- 若实现输入锁存，应区分“攻击之前已按住的移动键”和“攻击后新的移动意图”。

本轮至少保证不会吞合法攻击或产生幽灵移动；连续方向、精细取消窗口和最终手感交由XC-08继续。

## 36. 通过标准

1. 实控起手和每一段续段都能追溯到真实玩家输入。
2. 单次输入最多授权一个普攻阶段，不自动A2/A3。
3. 没输入、长按未新增输入、目标靠近、CD恢复均不能触发实控新段。
4. 最小预输入可改善接段容错，但不积攒长队列、不重复消费。
5. 狂点、换目标、重开A1不跳过合法恢复。
6. Command LMB同输入接管保留。
7. Aim、UI、交互和拖拽不误触攻击。
8. 当前DirectActor拥有MoveOrder时也没有自动Basic。
9. 离手AI和离手MoveOrder局部战斗仍成立。
10. 实控归属变化不继承旧AI自动续段权限。
11. 已提交攻击、现行Auto技能、伤害/架势/物理生命周期不被粗暴破坏。
12. 新版测试明确替换旧Auto Continue实控断言，而非与其并行生效。
13. 有其他角色CommandFocus时，原Direct仅获得防御权限，身份与自动普攻禁令不变。
14. 原Direct为猎人或伙伴时都能复用对应机动，不能写死Hunter。
15. CommandFocus进入Aim时，原Direct自保与AimActor的Reservation可同时成立。
16. 自保优先短移动，危险高且走不及时才花真实机动，不为Basic交机动。
17. 防御不会篡改MoveOrder目标、误触玩家成功Intent取消、拉新敌人或偷放手动技能。
18. 返回玩家操作/真正交换角色时，不双写路径、不双扣资源、不恢复旧防御动作。
19. 防御持续时间依赖Command上下文，不误绑1.5秒Focus；不因AI移动关闭判断窗口。
20. 相机跟随原主控的避险移动时，不破坏被关注角色的明确Aim目标。
