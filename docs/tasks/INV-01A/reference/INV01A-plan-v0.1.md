## 0. 为什么下一轮做这个

ITEM-Y01 已实现正式世界的 Y 共享回血瓶、篝火刷新；最近用户反馈“似乎没问题”，允许继续主轴，但不等于所有 SAMPLE 数值和交互永久定稿。

用户已明确过以下方向：

- `Tab` 打开背包。
- `1/2/3/4/5/6/7/8/9/0` 是底部种田系统道具快捷栏。
- 由**背包拖拽物品到对应插槽**来指定数字键的内容。
- 阿尔左下角的“自由道具”今后由玩家拖拽赋予，供 AI 使用，但本轮暂不实现其 AI 消费。
- Y 回血瓶是特殊的**主角专属显示槽 / 双人共享效果**，不占数字栏，也不作为普通背包即时治疗物品。
- 右手 Q/E/R 与左手 RMB 是独立战斗系统；装备炸弹是左手装备样板而非背包消耗品。
- 武器升级方案暂缓：保留现有 SK-02 V 弹窗/共享激活试验，不重构、不扩 SK-03/04/SV-01，不为背包建立成长适配。

**目标：**完成真实可交互、可拖拽绑定的 Tab 背包与数字栏基础。**不以空白十格 + 静态图片冒充已完成背包；也不提前声称种田、制作、种植、生长、收获已实现。**

## 3. 建议技术模型（可按实际代码收敛，不以命名绑定实现）

建议新增 `game/src/core/world-inventory.ts`（或同职责唯一模块）：

```ts
// 仅示意接口；具体命名和合法性以现有风格核对
interface PrototypeItemDef {
  id: string;
  name: string;
  category: 'farming';
  // 可用物品后续通过显式 consumer 注册；现阶段没有虚构的 use()。
}
interface WorldInventory {
  stacks: { itemId: string; quantity: number }[];
  hotbar: (string | null)[]; // 长度严格10；索引0..9对应1..0
  selectedSlot: number | null;
}
```

- 持久权威：当前 `WorldSession` 的 `inventory` / 更明确的 `farmingInventory`，不要与旧 `GameState.inventory` 同名混淆。
- `itemId` 是稳定**定义 ID**，不是当前角色/世界实体 ID；数量只有一个来源。
- `hotbar` 存 itemId 的**引用**，不持有复制的物品数量。背包归零或源失效后应显示失效/空，不能给无限使用能力。
- 只有正数、有限、安全整数数量；只允许本轮已登记 farming 类物品；非法 ID、负数/NaN、非 0–9 槽索引、旧世界请求均原子拒绝。
- 对外分别提供**纯读查询**与**真实提交**：`queryAssignHotbar`、`assignHotbar`、`clearHotbar`、`queryActivateHotbar`、`activateHotbar`；不要在 UI 点击事件里直接改数组/数值。
- 若有请求身份，应受当前 world ID 和 visit/generation 的当前性约束；重复/迟到操作不得跨重启新世界污染数据。
- `selectedSlot` 用于可观察的数字键选择状态；有注册效果后才能执行实际消耗。未注册效果只更新合法选择与提示，**不减库存、不给奖励、不可绕过掉落来源唯一性**。
- 同一种物品是否允许配置在多个键位，建议首版**允许引用重复但共用同一数量**（SAMPLE）；后续可根据使用体验调整，不写成永久规则。

### G2｜Tab 背包（可实际操作）

1. 在 `game/src/exploration-app.ts` 接 `Tab`；正式战场开启/切换背包，`Esc` 关闭；打开时适用现有模态输入隔离，冻结模拟时间作为**暂定 SAMPLE**，防止边整理物品边无意操纵角色。
2. 建议 `game/src/backpack-panel.ts`：黑底细边几何 UI，列出实际物品名、拥有数量、类别、是否可在数字栏配置及当前绑定位置。没有 items 时显示真实空状态。
3. 实现**鼠标从背包物品拖到数字栏对应槽**；拖动预览跟随指针，合法目标高亮，不合法目标和取消路径说明原因；取消或松到场景空白不得误触发 LMB 普攻/移动。
4. 增加键盘可达的替代配置：选定背包物品 → 按数字槽对应键或点击目标槽绑定；确保 `Tab`/`Esc` 与操作说明清楚，不能因画面拖拽支持而无法键盘操作。
5. 允许右键/清除按钮解绑，但**解绑不删除物品**。不实现丢弃、分堆、整理排序、物品贸易、制作等未批准玩法。
6. 已绑定 UI 从真实权威反映数量；数据不变时不每帧重建 DOM 中的拖拽节点；视口变化保持可读和焦点。
7. 注意 `Tab` 打开/关闭后焦点还原，失焦、Z 自动接管、死亡、世界离区或重启后清除临时 drag/held 状态，避免迟到提交污染新 world。

### G3｜1～0 快捷栏与核心请求

1. 保留 PPT 中下方 Tab 与 10 格外框的**原位置、长宽比例、边距**，只让格子从预留变为显示真实绑定数据，数字 1～0 原顺序不变。
2. `Digit1 ... Digit0` 输入映射 10 个槽；`repeat` 不重复提交。小键盘可按兼容性提供 `Numpad1...Numpad0`，但不得误将快捷键当数字输入框输入。
3. 背包打开时数字键服务**绑定**，不在后台释放物品；关闭背包时数字键服务**选择／尝试使用**。是否当前战斗可使用由核心返回，而非仅 UI 禁用。
4. 点击数字栏格子亦走同一核心接口。若注册了真实道具 consumer，将来由此执行；本轮两个实验物品均提示“种田使用尚未接入”，不假动作、不假消耗。
5. G 轮盘、F 选路、Q/E/R 技能、C 形态、Z 切人、Shift、左右键、Y 瓶和 V 实验窗拥有原先输入优先级；相应模态/失焦/页面隐藏时数字键不得穿透或重复操作。
6. 游戏内说明准确写清“**已可整理绑定，但种田实用行为待 FARM-01**”。不要把空槽按键提示伪造为拥有物品。
