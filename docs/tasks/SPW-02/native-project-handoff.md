# SPW-02 直接载入 .spine — 0.2.1

## 用户决定

2026-10-25 用户要求两端直接载入 `.spine`，迁移后向目标工程追加动作，不能用 JSON 重建的角色工程替代原工程。经说明官方 CLI 缺少 animation-only import 接口，用户明确选择“自动准备，在 Spine 确认导入”。本版按此交付，最终在 Spine 的确认操作由用户完成，不自动控制鼠标。

## 启动与使用

程序：`E:\SPW-02-release\xinghai-spine-animation-workshop-0.2.1-native-win-x64\星骸 Spine 动画工坊.exe`。

1. 在工坊选择来源与目标 `.spine`；官方 Spine 4.3.26 自动读取动作与图片，多骨架时选择本次骨架。
2. 载入原有映射配置，选择动作、预览、生成；选择输出目录。
3. 点击“准备导入到 Spine”。自动整理资源并打开 `target-project` 内的原工程副本。这里尚未写入新动画。
4. 点击“复制导入文件地址”，在 Spine 选择 **Import Project → Animation**，粘贴地址，按工坊提示选骨架和本次动作，导入并保存。
5. 回工坊点击“校验导回结果”；通过后使用上述 `.spine`。无需手工 JSON 导出、导入或图集解包。

原工程保持不变。目标副本初始字节与原工程相同；临时 animation.spine 仅包含本次新增动画，供官方编辑器导入关键帧，不是最终目标工程。新动画重名会自动编号，不自动替换旧动画。相对路径图片（及有声音事件时的音频）随工程复制，绝对路径仍引用原位置。校验按钮依赖当前工坊会话，完成确认前保持工坊打开；导入说明另写在每次输出的 `导入说明.txt`。

## 限制

仍为部分动作迁移，映射、跳过通道和动作观感边界沿用 SPW-02，不因改成原生文件输入而提升动作完整度。校验覆盖可导出的骨架/皮肤/约束/动画，不能证明全部不可导出编辑器信息逐字段相同；保留原工程并经官方动画导入来避免重建损失。此版不宣称后台全自动写入原 `.spine`。
