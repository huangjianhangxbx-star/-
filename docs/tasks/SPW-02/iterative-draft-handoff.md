# 迭代草稿预览与新增动画（0.2.4）

## 用户流程

按用户本轮明确要求，将全通道兼容作为预览门槛改为：本地自动分析 → 优先输出身体草稿 → 双侧同步查看 → 修改映射/局部修正 → 自动或手动刷新 → 满意后确认迁移 → Spine 确认动画导入并继续改键。不要求衣服头发等全部匹配。

便携程序：E:\SPW-02-release\xinghai-spine-animation-workshop-0.2.4-iterative-final-win-x64\星骸 Spine 动画工坊.exe。旧版本保留。resources/app/dist/spine-app.js SHA-256：FA4EC2AB0E7BC81ADCC5516B30A626609E169B81B8567CBC2C3C15BAE65008FE。

## 实现

- createSpineDraft 独立包装严格迁移器，保留真实逐通道审计；UI 不再用 report.blocked 阻断整段预览。已兼容通道复制，不兼容项略过；完全无映射也能看空草稿，明确 copied=0。
- 默认身体骨骼优先，不要求槽、附件、deform、层序、来源约束/事件。可选择全部已映射通道。不修改用户原有映射或把草稿略过策略写回共享配置。
- FK 动作实际进入草稿后，只在该新动画里为相关目标 IK 写入 time0 mix=0，避免 solver 覆盖新手脚键；源/目标骨架设置不改。此为可调草稿，不是通用世界轨迹或 IK 重定向。
- 载入/选动作自动生成草稿，映射和修正变更默认防抖刷新。可关自动刷新后手动点刷新；过期预览不能确认，旧异步结果不能提交。保存使用本次生成时的配置快照；选择保存目录期间改映射会中止旧确认。
- 同一目标原快照上反复刷新同一动画名，不增加多条新动画；非空旧动作从不覆盖。可显式选择目标中的严格 {} 空动画填入，名字须一致；duration=0 不作为判空条件。仅此模式最后导入要勾 Replace existing animations。已有空占位且结果仍为 {} 时保留预览但不可确认，原生准备接口也拒绝此无操作状态，防止未导入就误报成功。
- 默认收起更多未匹配骨骼，主要映射直接编辑，定位可标出两侧骨骼，驱动可选不迁移。报告区分已迁移、待调、略过，提示不等于失败。
- 确认前不创建输出目录；确认时可再选保存位置。最终目标是完整 .spine 工程，单动画载体只用于官方编辑器导入。

## 实测

最终 EXE 直接加载 rhiny.spine→rozeul.spine，无外部映射配置，选择 atk1，自动分析得到41项对应。草稿实际复制40条来源通道，略过284条，其中30条进入草稿但需局部校准；3个目标IK在新动画中写入mix0。来源和目标在0、0.7、1.416秒同步预览，runtime能解码且主要身体骨会运动。40不等于40条完全兼容的成品内容，画面仍须人工调动作和轨迹。

真实隐藏 renderer 验证：自动草稿出现；不预选目录也能确认；把 hips7→chest 改为 hips7→body 制造冲突后仍能刷新其他通道；旧预览确认禁用；还原后自动刷新；草稿名始终 spw02_atk1；最终确认准备完整工程与动画导入来源。回执 work/SPW-02/proofs/iterative-v8/result.json，截图位于该回执 savedPath/iterative-preview.png。没有占用鼠标。

最终原生载体经官方4.3.26独立重导，新动画键与预览一致；移除新增动画后，候选的全部旧目标数据保持一致；原 .spine 哈希及完整工程副本逐字节检查通过。证据 work/SPW-02/proofs/iterative-v8/native-proof.json。真正向目标副本导入并保存仍由用户在 Spine 最后确认；本轮没有再次进行前台 GUI 导入。填空动画 Replace 选项由官方资料确认支持，当前4.3.26 GUI替换未实测，最后工坊会独立重导检查实际结果。
