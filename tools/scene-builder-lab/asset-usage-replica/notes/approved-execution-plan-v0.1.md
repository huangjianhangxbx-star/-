## 1 本轮要解决的实际问题

### 1.1 用户明确目标

- 希望做一次 Tiny Glade 的素材使用复刻，查明原作实际怎样用素材。
- 搭建工具需要“可以绘制”，不满足于通过滑块改变固定桥形。
- 需要由验证结果确定今后的建模供给策略：应制作什么母件、遵守什么标准、如何组成目标建筑。
- 沿用工坊制作素材的生产方向。原作资源服务本次本地对照研究，生产验证最终使用自有工坊件。

### 1.2 本计划提出的实施选择

以下是本轮建议，用户授权执行本文件后在本轮采用，不自动成为全项目永久规则：

- 先限定桥梁、台阶、落脚平台、栏杆及其局部支撑／开口。
- 先实现折线路线与转角平台，保留连续落笔输入；任意平滑曲桥后续另验。
- 先证明同一接口族内更换造型可行，再决定是否扩展尺寸族。
- 复用 SB-03 的有效基础，在现有研究工程增加后续切片；不重建整个工坊。
- 主体造型来源与允许生成的区域逐项登记。沿用 SB-03 墙芯属于兼容现状，不自动成为未来建筑统一方案。

### 1.3 完成后用户应能做什么

用户打开样机，画一条带转折的桥／阶梯线路，拖动中间节点与局部高度，看到构件联动；再按图解规范制作一组新母件，登记后替换到同一线路，得到新造型。

用户应能提前知道：哪些造型会原样保留，哪些通过重复适应尺寸，哪些允许裁切或局部变形，接头和端面由谁提供。仅交付一张现有九件的尺寸表，不算完成供给策略验证。

## 6 R1 原作素材识别与数据保真

### 6.1 选择最小研究对象

优先使用已有 `04-small-bridge` 和台阶素材线索，追查约 2—4 种关键角色：踏步／铺面、栏杆或边缘，以及一个连接或支撑部位。文件名必须从实际目录取得；`stair_step` 等旧名只作为搜索线索。

不要先假定这些角色均由磁盘中的完整模型承担。允许结论为“纹理＋生成几何”“局部网格＋程序补面”“未找到对应源”，但必须有依据或明确未知。

### 6.2 每个候选件记录什么

- 原文件相对路径、版本／指纹、文件格式。
- 单件正交／透视预览，坐标朝向、枢轴、实际包围盒。
- 顶点与索引、UV、顶点颜色及其他数据通道是否存在。
- 材质与可识别的着色器依赖，哪些字段已经理解、哪些仍未知。
- 原作中的候选使用位置；未经实验确认的标注为候选。

保留原始文件和必要属性。转换为研究格式前后检查必要通道与尺度；不能丢弃未理解的通道后称“完整原版素材”。普通 GLB 摆件导入成功不算建筑母件消费证据。

### 6.3 素材使用对照板

每项至少呈现：**原件单独展示 → 建筑中同编号位置 → 已知数据与使用限制**。先形成可读的候选板，R2 后再写入确认结论。

此阶段可使用中性材质。研究重点是结构与使用方式，不以缺少原作灯光作为模型识别失败，也不把相似的最终外观作为消费方式一致的证明。

## 7 R2 在原作中确认素材怎样被使用

### 7.1 实验环境与方法

优先按官方支持建立独立 Mod 和测试存档，不覆盖原安装文件或用户作品。核对当前工具和桌面授权后执行；已有授权足够时直接继续。不能后台操作的步骤，应明确使用前台窗口，不虚称后台完成。

一次实验只改变一个因素。固定原作版本、测试存档、主要视角与其他参数，保留原件、替换件、操作步骤和恢复方法。实验后恢复测试状态，不能留下影响用户其他作品的全局替换。

给候选模型增加可辨认且不破坏基本接口的几何特征，或改变一个明确的数据字段。颜色替换能帮助定位，但**只有变色不能证明几何的重复、缩放或裁切方式**；至少一条核心结论需要几何或等价数据证据。

### 7.2 最小操作矩阵

下表列出要观察的问题，不预设原作答案。可以合并操作和证据，但不能用另一个版本、另一个素材或不同存档冒充单因素对照。

| 编号 | 操作 | 观察问题 |
|---|---|---|
| O1 | 原件与带识别特征的替换件对照 | 哪些实例实际由该源件产生？是否还有其他源件承担相邻区域？ |
| O2 | 同一路段变短／变长，包含一个不容易整除的长度 | 数量是否变化，是否拉伸、裁切或在端部消化余量？ |
| O3 | 改变宽度 | 整件横向缩放、增加铺设列，还是使用其他规格？边缘如何处理？ |
| O4 | 改变一个节点高度 | 哪些段成为台阶／平台，支撑如何变化，源件如何转向？ |
| O5 | 增加一个转折或接到平台，随后续接／断开 | 是否新增接头、换端件、裁切或补面？ |
| O6 | 调整一个原作实际支持的桥下开口／支撑状态 | 什么部位被重排，什么空间被保护，是否与墙体／地形宿主有关？ |

如果原作不支持某种操作，明确记录实际边界，不伪造对应按钮或人为修改存档来冒充正常用户操作。只补测本轮依赖项，不扩回完整 Tiny Glade 研究。

### 7.3 证据与结论

每条结论记录：问题、版本、源件、唯一变化、操作、结果、证据位置、结论等级及仍存在的解释。原作存档差分可补充说明节点关系，但不能单独证明最终网格来自哪件素材。

结论等级统一为：

- **原文件事实：**能直接从文件或数据读取。
- **原作实测：**正常操作或受控替换所确认。
- **推断：**当前现象支持，但未排除其他解释。
- **我方实现：**为达到观察到的行为采用的工程方案。
- **未确认：**证据不足或环境未完成。

拿到资产、理解可观察行为与拿到源码是三件事。不得称“已复原原作完整算法”，除非有相应直接证据；本轮目标不要求完整源码恢复。

**G1：**至少两种关键角色能建立原件与建筑部位的对应记录；其中至少一条与桥／阶梯直接相关的几何消费链通过受控替换确认，并覆盖长度、宽度、局部高度或连接中的至少两类变化。其余角色及规则的证据等级清楚，足以选择小样机的确定范围。

如果核心源件或依赖始终无法确认，保留失败证据和具体原因；完成可做的静态工作后报告该缺口，不能将新造方块或仅变色展示写成 G1 通过。

## 8 R3 原作参考消费与有限绘制样机

### 8.1 先建立可对照的消费路径

在隔离研究模式中接入已定位的原作源件，复现 R2 已确认的少量消费行为，再接入工坊套件模式。两者使用相同的线路输入和结构描述，可以各自有格式适配，不得各写一座无关联的演示桥来宣称换件成功。

保留有效数据与来源映射；因着色器专用数据而需要的替代处理必须写明。无需移植完整原作渲染，几何对照可采用中性材质。原作素材保留本机研究范围，分享源码和交付生产样机时使用自有件及可复现说明。

至少展示两组与 R2 对应的操作前后：原作如何改变，我方参考模式如何消费源件，已一致和未一致的项目各是什么。未经确认的部分采用有明确标签的我方规则，不补写“原作就是这样”。

### 8.2 可编辑输入

首轮输入限定为**连续落笔形成的有限折线路线＋可拖动节点**：

- 按住左键绘制时实时看到路线及有效结构预览；可以对采样简化和吸附，保留明显的中间转折。
- 松手形成一个可编辑的线路作者，不能每帧多放一座桥。
- 可移动中间节点、改一个节点标高、续接一段和删除一段。
- 转角采用落脚平台／专用过渡，暂不承诺任意平滑曲线。
- 对过短路段、过急转角、自交、缺件和不可容纳的开口给出具体提示，保留上一个有效结果。

有效尺寸与角度由本轮接口族决定并在 UI 中表达，不用大量隐藏约束让用户试错。滑块可以保留为精确调整入口。

### 8.3 数据与职责

沿用项目现有作者模式；以下是需要表达的最小语义，不强制照抄类名：

| 数据 | 作用 |
|---|---|
| 稳定的线路、节点和路段 ID | 保存关系、局部修改、稳定分配构件与变体。 |
| 节点位置／标高与路段连接 | 真实保留中间路线。 |
| 宽度、结构选项、局部覆盖 | 表达本轮允许的编辑；不创建第二套隐藏参数权威。 |
| 套件、配方和来源版本 | 确定如何消费素材，保存重开不偷偷换版本。 |
| 生成结果的来源映射 | 可反查构件源、角色、所属路段和实际处理。 |

显示网格与碰撞由作者数据派生；合并显示不能丢掉反查所需的逻辑映射。烘焙结果与可编辑作者保存分开。

### 8.4 结构规则的有限范围

- 水平段安排铺面，有高差的段按已声明步高／进深安排踏步，转角预留平台。
- 栏杆、边缘和端头依据路段与连接派生，接上新段时正确处理原端件。
- 支撑首轮使用明确的水平基准或已存在的只读采样能力；不扩复杂地形求解。
- 桥下开口只放在本轮能处理的合法直线路段，几何和碰撞均留空；不要求拱洞跨越折角。
- 保持 A 地貌与独立物件的所有权；地形挡住洞口时明确提示，不自动挖 A。
- 局部编辑不重新洗牌其他路段的变体；优先复用无变化区域，不提前引入无必要的大型调度框架。

### 8.5 来源与生成区域

每类可见部位登记为：固定母件、重复中段、连接／端件、允许加工的母件，或明确的规则生成区域。

SB-03 现有墙芯另列为兼容对照。研究后必须说明其后续供给选择：继续使用已明确的生成规则，还是由工坊提供专用构件、截面或模板。模板方案只有实际提供、消费并验证后才可称工坊驱动；不能把纯代码墙芯改一个名字就算工坊来源。

**G2：**相同起点与终点的直线路线和带中间转折的路线得到不同且对应的结构；移动中间节点、改局部标高、续接／删除均成立；保存重开仍可编辑节点。仅改变整桥长度／朝向，不通过。

## 9 R4 母件制作规范与第二套独立供给

### 9.1 规范分成两层

**工坊通用约定：**单位、坐标、枢轴、导出、材质、原生源文件、版本登记与预览。

**桥梁／阶梯接口族：**角色、占位、连接、允许加工、端头、转角、规格变化和组合限制。

本轮只冻结经过验证的接口族。不能把桥梁的一组尺寸写成所有建筑的统一标准；也不要求实现任意模型、任意数量、任意尺寸都可用的通用求解器。

### 9.2 每类母件必须有的说明

| 项目 | 应说明的内容 |
|---|---|
| 角色 | 重复中段、踏步、端头、转角、接头、支撑或装饰的具体用途。 |
| 逻辑占位与实际轮廓 | 排列按什么尺寸，哪些凸起、鼻口和破损可以外扩。 |
| 连接位置与方向 | 接口中心、剖面或明确对齐基准，允许旋转与镜像范围。 |
| 尺寸适配 | 固定规格、增减重复数量、专门短件、局部伸缩或裁切分别允许到哪里。 |
| 保护区域 | 必须原样保留的鼻口、柱头、帽沿、端部等。 |
| 接缝与切口 | 收边、补面、端盖和转角由哪个源件或明确规则负责。 |
| 材质与 UV | 重复或加工后怎样保持密度，新增切面怎样着色。 |
| 变体与来源 | 同角色变体如何登记，套件版本怎样采用和回退。 |

每类件附正面／侧面／俯视中必要的视图，标出枢轴、逻辑占位、接口、可外扩范围与禁止改变的部位，并给出至少一个合格与不合格例子。示意图应由真实模型或精确图解产生，不能以概念图冒充资产验证。

### 9.3 接入工作流

应让用户能完成：**工坊制作 → 导出 → 登记角色／规格 → 检查 → 预览替换 → 采用或取消 → 保存**。

来源指纹由工具或脚本计算。明确哪些配置可调整，避免让用户修改 C#、反推内部常量或手填哈希。接口不兼容时指出具体项，不静默使用默认方块补齐。

允许保留专用桥梁配方。需要配置驱动的是本轮声明可变的素材选择、变体和尺寸；不可变的结构限制也应公开说明。不能一面宣称步高可配置，一面仍按旧 `.25` 常量布局。

### 9.4 两套母件验证

**第一套：**复用或补齐现有工坊件，形成能跑通所有本轮样例的兼容套件。

**第二套：**在相同接口族内改变真实几何造型，如踏步鼻口、栏杆结构、端柱轮廓或压顶层次；仅改颜色不够。至少覆盖重复铺面／踏步、连接／端件和栏杆／边缘三类本轮实际使用的角色。无需为了凑“全套”重做无关角色。

第二套优先由独立执行者或独立制作步骤完成：提供规范、必要外观参考、工坊入口和空白接口模板，不依赖阅读生成器内部代码来猜正确形状。记录制作中的歧义，用于修订规范。

换件验收开始前，记录生成器代码基线和规范版本。保持同一线路、标高、开口、主要视角及组合规则，只更换源文件、角色映射和已声明合法的配置。

- 固定接口族：必须证明不同造型的替换成立。
- 可配置尺寸族：若本轮宣称支持，必须再验证至少一项合法尺寸变化确实驱动排布；否则明确“本轮不支持改变接口尺寸”。
- 新结构类型：不纳入本轮的通用承诺。

若发现消费接口缺陷，可以修复后建立新的基线，再重新完成独立换件测试；不能在同一次测试里偷偷改生成器，仍声称第二套直接兼容。

**G3：**第二套按规范独立制作，并仅通过素材与合法配置替换成功；接缝、端头、洞口、材质及保存继续编辑仍成立。用户能获得足以复现的制作与接入说明。

## 10 R5 验证等级与最终验收

### 10.1 验证等级

研究阶段只做结论所依赖的检查；实现阶段采用开发细则 **B 级模块验证**。最终验证按约 10—25 分钟安排初始预算，不含素材制作与必要原作实验；这是预算参考，不是掩盖失败的硬截止。

优先运行相关小集与少量真实操作。只有出现具体剩余风险才扩大验证，不全量回放无关系统、不冻结数千无关文件、不为低影响文案或布局建立永久测试。

### 10.2 最小验收表

| 编号 | 验收项 | 通过证据 |
|---|---|---|
| A1 | 原作真实素材被使用 | 原件、单因素替换、同操作前后结果与版本记录。 |
| A2 | 消费方式可解释 | 对重复、余量、缩放／加工或连接中的已测部分有依据，未知分开。 |
| A3 | 原作参考模式可对照 | 至少两组已确认操作能与研究样机逐项比较，不混用原创猜测。 |
| A4 | 真正保留中间路线 | 同起终点直线与转折两例，生成结果不同，作者数据亦不同。 |
| A5 | 局部修改联动 | 移中间节点、改局部高度后踏步、栏杆与相关支撑正确更新。 |
| A6 | 连接与删除 | 续接／删除处理端头、平台和收边，无遗留重复件或悬空切口。 |
| A7 | 开口与失败保护 | 几何／碰撞净空一致；非法尺寸或缺件保留上个有效结果。 |
| A8 | 编辑生命周期 | 一次手势一次撤销；取消、重做、松手导航行为可预期。 |
| A9 | 可编辑保存 | 关闭重开仍保留线路、源版本和局部信息，可继续修改；烘焙单独验。 |
| A10 | 第二套供给 | 固定代码基线，独立制作的不同几何只换素材／合法配置成功。 |
| A11 | 所有权与旧数据 | 旧 SB-03 桥可读或有明确迁移；A 与独立物件不被误改。 |
| A12 | 用户可复现 | 明确实际入口，最短操作能完成绘制、编辑、换件和重开。 |

性能只记录代表性小样例的构件数、显示块、网格量、重建成本与实际操作表现。没有实际测量时不报告屏幕 FPS；不把后台构建耗时写成界面流畅度。

### 10.3 必要的真实操作

至少一次以执行环境允许的实际鼠标／键盘入口完成“画折线—拖中间点—局部抬高—换套件—保存重开”。合成事件和后台渲染用于补充对应检查，不替代这一条。

如果原作或研究工程的实际窗口当前不可用，先完成可做部分，记录哪个步骤未执行。不能把不可用扩大为所有工作停工，也不能删掉硬验收。最终手感与美术由用户试玩验收，技术通过不代替用户认可。

## 11 交付方式

交付应精简且能直接使用，不以大量报告数量代替成果。

1. **一个审阅入口。** 可用已有 HTML 素材板扩展：原件、原作位置、替换实验、样机位置和两套工坊对照按相同编号连接；几何来源可反查。
2. **一个可运行的研究切片。** 登记真实工程、场景和菜单入口；复用现有工程，提供最短操作。
3. **两套工坊来源与配置。** 保留原生源、导出件、必要材质与可复现制作过程；区分本机原作参考数据。
4. **一份图解母件规范。** 写清已认证接口族、制作自由度、限制、错误示例及接入流程。
5. **一份精简交接。** 任务范围、代码基线、G1—G4、验收表、未完成项与下一步。其他机器数据直接链接，不复制全文。

任务文件与项目状态沿现有职责维护。只在发生真实设计或实现差异时更新相应对账，不自动回填人工原稿。

为用户提供的最短操作至少说明：从哪里打开 → 怎样连续画线路 → 怎样改中间点和高度 → 怎样选择第二套 → 怎样保存并继续编辑 → 如何反查母件。

## 12 工作量控制与中断恢复

- R0 优先在一个短检查段完成；已有同版资料可以复用，不重新全文扫描。
- R1 只围绕约 2—4 个关键角色；R2 只完成表中与所选切片相关的操作，尽量在同一测试存档连续进行。
- 原作工具链单点排障约 20—30 分钟仍没有新证据时，先记录具体阻塞与已尝试方法，转做独立工作；不要无限扩大到全游戏逆向。此时间窗不是自动放弃必要实证。
- R3、R4 分别形成可恢复的工作节点。阶段通过即连续推进，不为了阶段名重复要求用户批准。
- 每完成一个有意义节点，简短报告已确认事实、仍缺的证据与下一步；耗时增加时说明实际原因。
- 中断交接只需记录版本、当前阶段、实际路径、可复现命令／操作、下一步和保护范围。不要靠上一段聊天的“做完了”恢复状态。

## 13 结束时必须回答的六个问题

1. 原作哪几件真实素材参与了所研究的建筑部位，证据是什么？
2. 长、宽、高和连接变化时，哪些处理已经确认，哪些仍是推断？
3. 当前样机能绘制哪些形状，哪些明确不能？
4. 用户应该制作哪几类母件，每类具体要遵守什么接口与处理约定？
5. 第二套是否在不修改生成器的验收基线下成功？若失败，缺的是规范、素材还是程序？
6. 哪些几何来自工坊，哪些来自规则生成；用户下一批正式建模可以开始做什么？

**只有原作素材使用证据、有限绘制与第二套供给三条均完成，才可将本轮整体标为完成。** 可以分别交付已通过部分，但必须准确写出缺口。下一轮方向应由这些结果决定，不自动进入整屋或大规模资产生产。
