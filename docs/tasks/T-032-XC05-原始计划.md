# 星骸回廊：XC-05 持续 MoveOrder 实施计划 v0.1

> 日期：2026-10-06  
> 当前基准：`main@e81087073a8824b96823b80285a421098007d40c`  
> 前置：T-031 / XC-04 已实现并提交。  
> 状态：详细实施计划，尚未实施、尚未写入仓库。

## 1. 本阶段目标

把现在：

```text
PathAim → Confirm → 一条当前path
```

升级成：

```text
PathAim → Confirm → MoveOrder(destination)
```

以后 `Unit.path` 只是执行 MoveOrder 的临时路线；即使自动Basic、Auto Skill、ForcedMotion、Evasion、临时碰撞或重新寻路把当前path清掉，玩家的最终目的地仍然保留。

核心体验：

```text
命令Al去右侧
→ 途中顺手攻击
→ 攻击结束
→ 从当前位置重新寻路
→ 继续去右侧
```

## 2. Destination 是命令，Path 不是命令

玩家真正表达的是：

> “最终去那里。”

而不是：

> “必须永远沿这串导航节点走。”

因此必须建立独立 MoveOrder 状态。

推荐：

```ts
type MoveOrderState =
  | 'moving'
  | 'suspended'
  | 'blocked'

type MoveOrderSuspendReason =
  | 'aim'
  | 'basic'
  | 'skill'
  | 'mobility'
  | 'forced'
  | 'stagger'
  | 'temporary-block'

type ExplorationMoveOrder = {
  id: number
  actorId: string
  destination: Pos
  source: 'command' | 'direct'
  issuedAt: number
  state: MoveOrderState
  suspendReason?: MoveOrderSuspendReason
  lastRepathAt?: number
}
```

建议存放在：

```ts
ExplorationControlState.moveOrders
```

按 actorId 独立保存。

这样 Hunter 和伙伴可以同时拥有各自MoveOrder。

## 3. 保留 source

MoveOrder必须记住：

```text
command
```

还是：

```text
direct
```

原因：

- Command Path每次repath仍需避免主动穿过未激活Encounter感知区；
- Direct Path允许玩家主动闯入下一Encounter。

第一次规划安全、后续repath也必须保持相同策略。

## 4. PathAim Confirm 改为创建/替换 Order

当前XC-04：

```text
confirmPathAim → move
```

本轮改为：

```text
confirmPathAim
→ issueMoveOrder(actor,destination,source)
→ 生成第一条临时route
→ cancelAim
```

同一角色最多一个active MoveOrder。

新目的地确认后：

> 旧Order被替换。

不同角色的Order互不覆盖。

## 5. 已有Order时重新进入PathAim

这是本阶段的重要行为。

```text
Order A active
→ F
→ PathAim
```

此时：

> A不取消，只是 `suspended: aim`。

### RMB / Escape取消Aim

```text
Aim结束
→ Order A恢复
→ 从当前位置重新去A
```

### Confirm B

```text
A被替换
→ 新Order B开始
```

这落实此前确认的：

> 进入指令/瞄准但没有真正提交新指令，不取消旧目标。

因此XC-03中“已有legacy move时禁止Begin Aim”的临时限制，需要在MoveOrder建立后解除。

## 6. MoveOrder 高于 Tactical AI

角色有MoveOrder时：

> Companion Tactical AI不能改写最终目标。

禁止：
- Flank改变Destination；
- Regroup改变Destination；
- Peel改变Destination；
- Retreat永久改目标；
- Follow覆盖玩家目标。

但是允许：

> Low-level Auto Combat暂时打断身体动作。

新的权限层应明确成：

```text
Player Direct Input
↓
MoveOrder
↓
Low-level Auto Combat / Survival
↓
Companion Tactical AI
```

## 7. AI权限建议拆成两层

XC-03现有 `autonomousBodyStartAllowed` 不再足够，因为MoveOrder不是“AI全关”。

建议拆成等价的：

```ts
tacticalAutonomyAllowed(s,u)
localAutoCombatAllowed(s,u)
```

语义：

### Command Reservation
```text
tactical = false
localAuto = false
```

### MoveOrder
```text
tactical = false
localAuto = true
```

### 普通AI
```text
tactical = true
localAuto = true
```

用于：
- Companion AI；
- Follow；
- Basic；
- Auto Skill。

不要再次回到“一个Boolean同时控制所有自动行为”。

## 8. Local Basic Interrupt

当前引擎有path时不会开始Basic。

XC-05允许非常有限的：

> Local Combat Interrupt。

建议条件：
- explorationBattle；
- 敌人属于Active Encounter；
- 目标已知/已交战；
- 当前角色此刻已经能 `canHit`；
- attackTimer ready；
- local auto允许；
- 没有更高优先动作。

满足时：

```text
MoveOrder suspended: basic
→ 暂停当前route
→ 允许现有Basic创建并Resolve
→ MoveOrder仍然存在
→ Basic结束后立即repath
```

### 不允许自动追怪

MoveOrder不是“路上看到怪就变成自由战斗”。

敌人离开攻击范围：

> 不追。

马上恢复原MoveOrder。

### 不必等完整attack CD

Basic真正结束后，只要身体没有其它动作：

> 立即继续走。

不要站在原地等attackTimer归零。

## 9. Auto / Background Skill

### Background
例如：
- Snipe模式；
- Poison；
- Dance状态；
- CD / charge；

继续运行，不因MoveOrder消失。

### Foreground Auto
如果当前Auto机制合法产生实际身体动作：

```text
MoveOrder suspended: skill
```

技能结束：

> 从当前位置继续Order。

自动技能不能永久改写MoveOrder.destination。

## 10. Evasion / ForcedMotion / Stagger

以下都不取消MoveOrder：

- Evasion；
- Blink；
- ForcedMotion；
- WallImpact；
- WallPin；
- Stagger。

动作结束后：

> 从新位置重新寻路。

本轮重点是“Order能存活”，不是复制一套MoveOrder专属Hazard AI。

## 11. Crossing

如果Crossing属于当前MoveOrder路线：

> 它是Order执行的一部分。

不要在跨层中途重算把角色拉回。

落位以后再继续判断。

## 12. 临时受阻

如果Destination本身仍合法，但当前找不到route：

```text
MoveOrder.state = blocked
```

建议约每：

```text
0.20～0.30s
```

重试。

适合：
- 身体暂时挡路；
- 队友经过；
- 战斗站位改变。

如果Destination本身已经真正非法：

- 变成障碍；
- 不在地图；
- 不可停留；
- Command安全策略永久无合法路径；

则：

> Cancel Order并记录reason。

不要无限卡住。

## 13. 到达目标

真正满足：

```text
near(actor.pos, MoveOrder.destination)
```

且没有未完成Crossing：

```text
MoveOrder Complete
```

然后清Order。

### Off-Control
恢复：
- Companion AI；
- Follow。

### DirectActor
保持Direct，等待玩家输入。

## 14. 什么会取消 MoveOrder

继续采用已经确认的原则：

> **新的Player Intent成功Commit才取消。**

成功后取消：
- WASD/direct；
- 手动Skill；
- Evade；
- Blink；
- Weapon / SwitchWeapon；
- Recall / Collect / Rescue / Extract；
- 被角色接受的 H/B Party Command。

新Path Confirm：
> Replace，而不是普通Cancel。

## 15. 失败动作不取消

例如：
- Skill在CD；
- 没有Evade charge；
- Blink方向被阻挡；
- 其它动作命令失败；

MoveOrder：

> 保留并继续。

因为新的Player Intent没有真正Commit。

## 16. CommandFocus变化不取消

以下都不取消：
- C/1/2切CommandFocus；
- 点击进入Command；
- Clear CommandFocus；
- 切去关注另一角色；
- Begin Aim后RMB取消。

这让玩家可以真正：

> 一边让Al执行命令，一边重新关注Hunter。

## 17. DirectActor变化本身不自动取消

纯粹控制身份变化不等于动作。

真正通过：
- W；
- Skill；
- Mobility；

完成Promote后，成功动作再取消旧Order。

## 18. 推荐新增模块

建议新增：

```text
game/src/core/move-order.ts
```

负责：
- `moveOrder`
- `hasMoveOrder`
- `issueMoveOrder`
- `replaceMoveOrder`
- `cancelMoveOrder`
- `completeMoveOrder`
- `suspendMoveOrder`
- `advanceMoveOrders`
- `queryMoveOrderRoute`

不要把全部逻辑堆进 `main.ts` / `engine.ts` / `autonomy.ts`。

## 19. Navigation继续复用

repath继续使用：
- `navigate`
- `canStop`
- `radius`
- `pathSafeFromInactiveEncounters`

不写第二套寻路。

## 20. `ai.command='move'` 不再是长期目的地真相

可以暂时保留作为：
- legacy兼容；
- 当前低层移动ownership；
- command grace。

但：

> `ai.command`被清、path被清，都不能表示玩家MoveOrder已经结束。

MoveOrder才是Standalone玩家移动命令的权威。

## 21. `completePlayerMove()` 必须重审

当前低层逻辑会在path结束时清player move状态。

XC-05以后：

> 当前path结束 ≠ 整个MoveOrder完成。

只有：

```text
真正到达MoveOrder.destination
```

才Complete。

## 22. `playerOwns()` 必须认识 MoveOrder

即使当前path被Basic/ForcedMotion临时清空：

> active MoveOrder仍代表高层Player Ownership。

Companion Tactical AI不能趁这个空档接管角色。

## 27. 用户试玩重点

### 1. “去那里”是否终于是真命令
途中发生战斗后，角色最终仍去那里。

### 2. 自动战斗是否只是插曲
应该是：

```text
走 → 顺手打一刀 → 继续走
```

而不是：

```text
走 → 看到怪 → 忘了命令
```

### 3. 重新选路是否符合直觉
看新位置后取消：
> 继续旧目标。

确认新位置：
> 替换旧目标。

### 4. 主动接管是否彻底Cancel
玩家W以后：
> 绝不能松手后又自动回旧目的地。

### 5. 被击退后是否记得目标
被Heavy打飞再起身：
> 继续执行原命令。
