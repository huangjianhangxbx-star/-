## 0. 要交付什么

用户反馈：新版本独立贴图绘制模式明显卡顿，希望定位吃性能的部分并优化。

本轮交付是一版可运行的便携工坊、可重复的同条件前后性能对比，以及必要的正确性证据。优先消除鼠标移动、笔画预览和确认流程中的重复全量计算，不降低模型／贴图规格，不删掉刚增加的工具。

目标体验：笔头悬停跟手；拖动长笔画不越画越迟钝；16/32px 笔刷和对称能连续工作；松手确认不会反复闪回旧图或触发无关网格重建；大选区和填充可响应、可取消；已经绘画较多的模型仍能正常观察。

**性质区分：**下文热点是源码证据支持的优化候选，不是已经测定的耗时排名；毫秒目标是本计划提出的工程目标，不是当前成绩或性能承诺。

## 3. 不得牺牲的行为

1. 保持 64px/m、三种体素精度、方／圆笔刷、1px像素完美、直线／折线／矩形／椭圆、填充、选区、吸色及两套对称能力。性能测试期间不得以关工具／关选择边界／降低DPR作为同条件优化成绩。
2. 当前物体／画布权限、锁定、隐藏、外露面、门洞后墙遮挡、镜像不可见外表面的显式选择不变。不删可见性检查来提速。
3. 一笔一个原子历史；左右镜像一起撤销；擦除只改绘画而不删几何。原像素完美或输入算法若有正确性缺陷，先单列失败案例，不用更快但错误的旧结果作新标准。
4. 已确认源、在途笔触、待发笔触、活动草稿彼此隔离。不丢第二笔、不乱序、不重复确认、不因ACK回到旧画面。保存／撤销／关闭遵守排队和草稿合同。
5. 主会话仍为唯一写入者；子窗不获得文件或通用工程API。租约、修订、owner、面／像素预算、同ID同内容去重、失败恢复不削弱。
6. 不靠缩短现有撤销深度、清空旧贴图、减少可保存内容、降低颜色精度或跳过校验获得性能改善。不擅自改变4笔待确认上限、32MiB队列／消息限界及现有源预算。
7. 原件不变；导出和重开保持作者数据语义一致。显示缓存、性能计数、视口偏好不污染源文件或dirty状态。

## 4. R0：先建可重复的性能基线

### 4.1 版本和场景

核对实际运行EXE的功能提交／sourceFingerprint及本地工作树。保留原便携目录，优化版另建目录进行A/B。若远端已推进，以最新相关变更为起点并记录差异，不重置用户工作树。

优先定位用户当前门洞的本地源，复制后使用；若只能看到截图、找不到原资产，明确标为“用户模型未测”，用原创结构相近夹具推进，不声称已复现该资产。沿用 TOOL-015 原创练习模型，不因性能任务扫描全部模型。

另准备一个约3千至6千格的门洞／平板和一个约1万至4万格的组合模型；准确记录实际格数、绘画面数、绘画像素、物体／画布数量及规格。大模型夹具要避免无意触发源预算而测成错误处理速度。

重点分开三种数据状态：未绘画、少数面画得很满、大量面各画少量像素。后二者即使总像素接近，渲染对象数量也可能不同；不能只报体素数。

### 4.2 实测方式

详见 `BENCHMARK_PROTOCOL.md`，只用少量代表场景，不做全部参数的笛卡尔积。覆盖悬停、长笔、连续短笔、32px对称、大选区、填充、旋转、关闭重开。

同时观察独立绘画renderer、主工坊renderer与Electron主进程。主进程、主会话所在renderer、子窗口renderer必须区分，不能都称为“主线程”。[E1][E2]

用轻量计数和有限环形采样记录，不逐像素打印日志，不在计时中逐帧截图／强制GC／GPU同步读回。按需采集一段DevTools CPU/Performance trace定位调用栈；最终A/B时两版使用同样采集方式，另做关闭重型采样的复测。[E3]

### 4.3 必须记录的指标

| 指标 | 口径 |
|---|---|
| 输入同步耗时 | pointer事件回调开始至结束；异步分片执行时间另记，不能仅缩短入口函数 |
| 首次预览延迟 | 输入事件到包含该变化的下一次render提交；仅为软件侧近似，不称为真实屏幕出光时间 |
| 预览计算耗时 | 新像素生成、镜像／范围／可见性、缓存合成、纹理刷新分别计数／计时 |
| 一笔确认延迟 | 抬笔/完成→主会话接受→子窗接收ACK→呈现；分出排队等待和实际处理 |
| 活跃帧间隔 | 实际可见窗口交互期间的rAF分布；不拿隐藏窗口或空闲按需渲染的低帧率作结论 |
| 计算次数 | owner集合构建、全源clone、整笔重放、meshMap、绘画域构建、选区轮廓重算、raycast |
| 资源与渲染 | texture／geometry／material创建与销毁、变化面／图集页数、上传估算、整帧draw calls |
| 数据与内存 | IPC实际字节、队列长度／差量字节、历史量、JS堆与各进程内存、资源数量的趋势 |
| 正确性 | 最终规范化paintSource/几何摘要、笔数与确认数、回滚与导出结果 |

`renderer.info` 是绘制调用和资源数量等诊断信息，不是GPU用时或显存字节。使用后处理时按完整逻辑帧汇总，记录reset位置；对照当前实际r186实现，不只取最后一次render的计数。[E4]

## 5. R1：高频状态读取变成轻量只读

### 5.1 缓存目标与成员

将绘画所需的asset/object/canvas身份、step、origin、owner集合、空间索引与对称中心分开。`target()` 不再为了读取origin或spec而筛选全体cells；owner使用预先建立的Set或索引。

固定几何时，目标数据按进入绘画／目标更换／几何或归属改变生成一次。缓存的几何范围可在按下“重置中心”时重算，但普通鼠标移动和关闭对称时不能重复构建。吸取作者色用已有坐标索引，不在每个候选像素中对 `cells.find()` 线性查找。

### 5.2 稳定的乐观源

把 `queue.source()` 从“调用就clone和重放全部队列”变成“只读当前已合成版本”。只有确认源变更、入队／出队、失败／重试／放弃时更新乐观合成缓存。

缓存返回只读引用，所有写入必须显式copy-on-write到本次变化面；不得把缓存对象直接交给可变笔刷而修改确认源或历史。只读状态查询不分配与全部绘画像素数量成比例的数据。

### 5.3 分类失效，不滥用总revision

运行时维护明确的代际／变更类别，名称由实施决定，不写入资产格式：

| 发生的变化 | 需要失效 | 应保留 |
|---|---|---|
| 纯手绘笔触／纯手绘UndoRedo | 对应像素/面合成与纹理，必要dirty信息 | 几何、owner索引、可见性几何索引、对称中心 |
| 相机/投影/视口尺寸改变 | 可见性投影与相机相关辅助显示 | 作者绘画源、几何、owner索引 |
| 画布位置／尺寸或物体几何/归属改变 | 相关空间索引、目标、面映射、几何 | 未受影响的其他资产缓存 |
| 可见/锁定/目标/选区改变 | 相应权限、可拾取集合或选区缓存 | 无关像素/几何；选择不标脏 |
| palette/sideColor/faceTone改变 | 相关作者颜色、材质／贴图合成 | 几何是否可复用需按合面依赖判断，不盲目复用 |
| 显示预设/背景/灯光改变 | 显示材质和渲染请求 | 作者源、历史、冻结草稿 |
| 租约结束、资产关闭、项目切换 | 对应缓存和待执行任务全部清理 | 已确认主会话源 |

不能每像素拼接相机矩阵字符串，也不能每帧JSON.stringify整个资产用于判断变化。未知变更或完整重同步可安全全量重建，但须计数和记录原因，不能让普通笔触频繁落到回退路径。

**R1验收：**固定场景重复悬停，owner/几何索引不重建，全绘画源clone不随事件数增长；显示与选择切换无错误旧缓存。

## 6. R2：笔触增量计算，预览按帧合并

### 6.1 输入与显示分离

所有有效采样按顺序进入手势路径；处理相邻段，不从笔头起点反复重放。高频事件可收集后在下一帧处理；只保留最后一个事件而丢弃折线弯折、越洞路径或末尾点不可接受。

同一显示帧中合并新像素与变化面，正常连续笔触最多一次统一预览刷新；pointerup/Enter/保存前允许必要的最终flush。正在处理一帧不表示可以丢掉后续输入。处理积压需有有限内存和明确反馈，不能无上限排队。

形状预览采用前后覆盖范围的差集：新增部分写入、撤回部分恢复笔前值；几何形状很大时可分片，但最终掩码和预算检查完整。自由画笔与形状不要强行共用每次全量重放的实现。

### 6.2 稀疏草稿

每笔保存稳定基线、首次覆盖位置的原值，以及当前有效增删量。只复制本笔触及的面／像素容器；预算用变化计数递增维护，提交边界仍做完整合法性验证或等价权威校验。

普通累积笔画只镜像和验证新候选；已经加入的像素去重。擦除必须记住“原本无笔触”与“原本有某色”，恢复不能一律写底色。改变颜色／尺寸等笔中行为沿用当前约定，不偷偷改变笔触输出。

### 6.3 像素完美与边界

优先让像素完美只修整受影响的尾段并维护交叉点/重访计数。只有证明与已批准规则等价时才替换；不能假定随意固定三点窗口能解决全部交叉／回描。保留reference计算作离线差分，不放回高频路径。

同平面跨体素无接缝；真正拐面／空洞分段；首尾点、转角、重复落点和镜像中线完整。选择裁剪和遮挡检查发生在同一明确流水线上，不能把被裁掉的像素错误恢复回来。

### 6.4 手势结束与并发ACK

抬笔前flush所有待处理采样，冻结本笔差量后入队；开始下一笔不复用上一笔可变草稿。

旧笔ACK到达时，将其从待确认集合移入确认源，不能把当前活动草稿覆盖掉。取消仅取消活动草稿；已结束排队笔按既有合同等待确认。切换对象／退出项目必须通过已有租约与关闭流程。

**R2验收：**同一输入轨迹经旧reference/新实现得到相同结果；20笔连续短笔顺序完整；长笔每一段的计算成本不随已画路径无界增长。最后一次移动后立即松手仍包含终点。

## 7. R3：只更新变化纹理，复用资源

### 7.1 必做的低风险路径

绘画面第一次出现时创建显示资源；此后只改颜色时复用已有Canvas/Texture/Material/BufferGeometry，不再 `remove → dispose → new`。

由笔触差量明确传入变化面集合；不为改一个面重新建立所有画布cells索引、枚举所有paint.faces并序列化每一面。变化来源包括手绘、底色、暗面、UndoRedo，全部通过一致失效路径。

一次刷新把同一纹理多次颜色修改合并，再标记更新。CanvasTexture支持复用与更新，但“CPU只改了几个像素”不自动证明GPU只上传那几个像素；记录实际使用的上传策略。[E5]

最后一个笔触像素被擦除时，正确移除或回收相应显示覆盖，露出当前底色和暗面。空白面回收／资源池须有上限，不能用永不释放换速度。

基础模型与彩绘仍统一接受四种显示预设；纹理、alpha/不透明度、面朝向、z偏移、sRGB、隐藏/锁定、灰模等不得改变。绘画面不重复进入普通拾取导致Z偏移误命中。

### 7.2 按需渲染与父窗口成本

静止、无草稿／ACK／相机／显示变化时不需持续全量刷新显示管理；按需请求帧。相机操作、笔头/选区变化、纹理脏、窗口resize和上下文恢复均触发重绘。

**失去焦点不等于不可见。** 父窗口可能在另一显示器仍可见，应按确认变化刷新它；最小化/隐藏可停止无意义绘制，但队列、保存、关闭回执不可暂停。不能将帧率降低到不跟手再说CPU下降。

结构边线与材质派生缓存只在必要时失效。色轮等UI空闲无变化不循环重建；若发现viewport轮询或全场景遍历为重要热点，再局部改为变更驱动，不重做整套渲染器。

### 7.3 条件分支：分块／分页合批

当高绘画面数样本在资源复用后仍主要受draw calls、对象遍历或上传限制，则在本轮继续实现编辑显示用的稳定图集页／分块网格。

图块位置稳定，只更新脏页／脏区；避免每笔全模型重排UV或整张巨图重打包。按画布可见性、显示透明度与材质需要合理分组；不强求整个资产一个Mesh。

图集页大小先试验选择，不用超大页把一次小改变成大上传。若当前Three.js版本没有可用的精确局部上传路径，可用较小页和整页上传并实测；不得虚构API或长期依赖未经维护的renderer私有字段。

保持Nearest、无无意插值、图块padding与六面朝向；首版图集只为编辑显示，作者稀疏面源及导出器保持原契约。必须验证paint材质／显示控制器适配，不只是替换网格后原色能看。

**R3验收：**在同一已存在绘画面反复落笔，geometry/material/texture创建销毁数不随每次采样增加；未变化面不反复刷新。新增绘画面允许首次分配。高面数场景资源量有明确解释和上限。

## 8. R4：纯绘画ACK快路径与主会话成本

### 8.1 必做：颜色确认不重建几何

识别纯paint/paint undo/paint redo回执，更新源与paint revision后保持CanvasSession、绘画域、几何查询和mesh。运行时采用可靠的变更类别／协议元信息，不能只对总revision做大小判断，更不能为了分类每笔再深比完整几何。

主工坊收到已确认笔触也只更新相关显示／作者数据；源保存、dirty和历史仍正常。审查 `PaintWindowController.changed()`、`WorkshopSession.sync()`、主窗口refresh链，避免仅优化子窗、父窗仍全量同步重建。

无几何变化的笔触，在两端预热后的常规确认路径里 `meshMap()` 与几何域重建计数应为0；首次打开、真几何改变、未知完整重同步除外并独立统计。

### 8.2 必做：减少重复复制，保留安全边界

排队差量合成、发送、校验、主会话提交、历史快照、回执分别计时。源读取不复制；未变化结构不要在多个中间步骤重复复制。允许在权威提交／完整快照边界保留确有必要的安全拷贝，不把“所有clone都是错的”当目标。

`CanvasSession` 历史中原有模型对象并非已证明全面不可变；未经审计不得简单让全部历史共享可变cells数组。优化共享结构必须有明确所有权和写时复制规则，且通过后续几何修改再Undo/Redo的验证。

不能另建一个只在子窗有效的撤销栈，不能丢失主会话的选择／几何联合历史及绘画租约的history边界。不能通过减少历史条数达到内存指标。

### 8.3 条件分支：内部差量通信／历史

若R1–R3后确认延迟、IPC大小或历史快照仍是主要瓶颈，允许为内部绘画会话增加版本化差量命令／精简回执，不改磁盘作者格式，不放宽IPC授权。

入站必须继续验证租约、对象/画布身份、baseRevision、合法面键和像素坐标、颜色、写入范围、预算、当前源。按差量计算预算必须覆盖覆盖/新增/删除/重复键，输入有一个非法项则整笔拒绝。

同一已发送命令失败重试：同ID同内容；不能重基底后沿用旧ID。只有未发送笔触可按新确认源重放。重复或迟到ACK以lease/sequence/revision核验，不错误覆盖较新源；冲突时明确重同步，不伪装成功。

历史若改差量，记录旧值/新值与不存在值，支持检查点和现有权威history协议。此项风险高于缓存修正，只有实测必要才做，实施后加严R6数据和失败回归。

**R4验收：**确认不会重建几何；强制延迟／失败／重试与四笔队列仍有序；主窗口关闭等待排空，已确认和已结束应保留的笔触全部保留。

## 9. R5：遮挡、选区与大操作

### 9.1 拾取和可见性

缓存可拾取网格集合，几何不变不遍历整场景重新收集。相机投影、相机矩阵、viewport尺寸与DPR等形成一次状态代际，避免每个像素重新字符串化矩阵及重复读取DOM布局。

按需建立体素分块／空间索引或其他适用加速结构；先测现有raycast占比再决定实现，不能为了优化无条件引入大型依赖。

共面笔刷可以复用已证明的可见区域，但粗粒度“这一面中心可见”不等于整个面都可见。门洞边、细柱遮挡、台阶、其他物体／画布挡住部分面时必须细化或回退逐像素精确检查。

保留普通可见绘制与显式“镜像到不可见外表面”的区别；隐藏/锁定目标不因缓存被绕过。相机/视图或遮挡几何变化后立即失效相关缓存。缓存需受预算控制，关闭窗口清理。

### 9.2 选区与笔头辅助显示

选区范围和轮廓按 selectionRevision 缓存；鼠标悬停只更新笔头。长笔轮廓可更新新增/撤回边，不重建全部旧轮廓。优先复用BufferGeometry和材质；容量增长时再分配，不每次dispose。

轮廓可计算外边界并减少冗余共线段，但不能任意抽稀丢掉边角、只画前N个像素或因追求速度显示错误范围。绘画结果仍以完整掩码计算，显示简化与作者写入不能混用。

### 9.3 填充／大形状

已有像素预算不变。有效域、颜色/owner索引复用；避免每个访问像素线性搜索整个cells。大操作先规划、校验，再一次提交；没有完成不能先写到预算就停。

纯计算工作超出交互预算时可合作式分片或Worker。必须携带目标/租约/源代际，取消或目标变更后晚到结果作废；主会话最终仍校验。不能仅将整个大模型频繁复制给Worker，转移热点而不减少总成本。

预览、进度或取消提示是真实状态。关闭窗口/保存/切工具与计算中的草稿如何结束沿用已有安全流程，不出现UI可以操作但后台还悄悄写入的情况。

**R5验收：**门洞后墙不被染、部分遮挡正确、选区外不写；相机旋转后无过期可见性；大操作可取消且取消零写入。

## 10. 工程指标与升级分支

### 10.1 硬性结构指标

| 项目 | 要求 |
|---|---|
| 固定目标悬停 | 无整模型成员扫描／owner集合重建；无全paint源clone |
| 普通长笔 | 计算主要随新增/撤回像素增长，不每子采样重放全部累计笔触 |
| 常规预览 | 一显示帧最多一次合并刷新，明确列出final flush例外 |
| 纯paint确认 | 预热后父/子常规路径不重建作者几何与PaintSurfaceDomain |
| 修改已有绘画面 | 无逐采样geometry/material/texture销毁重建 |
| 固定选区悬停 | 不重算选区完整掩码／轮廓 |
| 结果与边界 | 不丢笔、不多写、不越权、不缩减历史和源预算 |

### 10.2 建议的响应目标

在R0登记的参考机器、可见窗口、固定显示配置和标准门洞夹具上，建议采用下列初始目标；硬件、刷新率与真实资产未知，R0可提出有依据的调整，但不能测试后为过关默默放宽。

- 悬停输入同步处理 p95 ≤8ms；绘画CPU任务分片 p95 ≤8ms，并同时检查总处理量和积压，不能只把工作挪到定时器隐藏耗时。
- 普通1px/16px绘画的软件侧首次预览 p95 ≤33ms；32px加对称目标 ≤50ms。
- 无人工故障延迟的标准短笔确认 p95 争取 ≤100ms，持续短笔队列不长期积压至上限。
- 标准交互片段不应持续出现 >50ms 的计算阻塞；大填充可作为标记的大操作，但需要即时反馈、可取消，耗时单列。
- 对原先明显慢的同场景，主要输入／预览指标建议至少改善50%；若原版已经低于目标，改用“不回退+结构指标通过”，不硬凑倍数。

这些数值不等于承诺所有模型60FPS。若标准场景未达标，列出未达指标与实测根因，继续适用的R3/R4/R5分支或诚实标记部分完成；不能只用平均FPS掩盖p95卡顿。

### 10.3 不扩张为无限重构

| 优化后剩余问题 | 下一步 | 不应该做 |
|---|---|---|
| 热路径目标/复制仍多 | 完成R1/R2 | 先调暗灯光或换渲染器 |
| 颜色确认仍停顿 | 分析R4主会话/历史/IPC分段，再做必要差量 | 直接关历史、取消校验 |
| 旋转/静止慢且绘画对象数高 | R3稳定分页合批和显示缓存 | 合并作者物体、减贴图精度 |
| 大笔刷/选择/填充慢且raycast主导 | R5精确加速与分片 | 跳过遮挡或截断掩码 |
| GPU后处理明确主导 | 在相同质量下优化或另给可选质量档，基线分别标注 | 默认关SSAO后宣称完整同条件优化 |
| 原有问题在本机无法复现 | 保留源码确定冗余的修正，交付采样入口与缺测说明 | 写“用户问题已解决” |

## 11. R6：性能复测与正确性回归

### 11.1 验证级别和样本

按B级做本模块和受影响共享逻辑的定向验证。涉及IPC差量或历史结构的分支扩大相应安全/数据用例，不机械跑全部游戏、Spine、2D工坊和退休模式。

基线版与优化版采用相同资产副本、相机、窗口内容尺寸、页面缩放/DPR、显示预设、笔刷参数、选区和输入轨迹。每个代表场景预热一次、测三次；分别记录每次p50/p95/max与样本数，不用“最快一次”代表整体。

细节见 `BENCHMARK_PROTOCOL.md`。性能标准依赖真正可见的打包Electron窗口；隐藏/offscreen测试可用于逻辑和差分，但不能作为桌面流畅度的全部证据。

### 11.2 必测正确性矩阵

| 范围 | 至少覆盖 |
|---|---|
| 空闲与目标 | 关对称悬停不dirty；颜色变化不改变几何；切换目标/锁定不会用旧缓存 |
| 笔刷 | 1/16/32px、方圆、长笔、多次回描、负坐标、共面跨格、拐面/漏空 |
| 像素完美 | 端点、角、交叉、重复访问、撤回恢复原笔触；新旧reference差分 |
| 图形 | 直线跨门洞、折线Enter、形状回缩、最后采样后立即抬笔、Esc取消 |
| 对称 | X及组合、中线去重、固定中心、缺对应面、显式隐藏镜像、三精度 |
| 选区与填充 | 加减/反选/清除、像素选择而非几何删除、容差、部分遮挡、预算拒绝与取消 |
| 历史与源 | 一笔一历史、20笔有序确认、UndoRedo、返回建模后旧历史与后续几何修改 |
| 队列与生命周期 | 800ms故障注入、4笔积压、ACK丢失后同ID重试、乱序旧ACK/失效租约、失败冻结/放弃/关闭 |
| 外观与导出 | 底色+手绘+faceTone、两种吸色、六面UV、三精度、显示切换、GLB/FBX+PNG回读 |
| 长用与资源 | 连续复画/擦除、5次开关窗口、缓存与资源回收、不会每次都线性增长 |

保存／关闭期间已结束队列必须保留，活动草稿按既有合同处理；已提交效果不因ACK显示跳变。记录人工故障延迟与正常性能结果，不能混算。

### 11.3 结果等价，不只看截图

对相同合法输入比较规范化作者源、几何、owner、Root、palette、sideColor、faceTone和paintSource。归一化只能排除约定允许变化的revision/测试ID，不能删除实质字段掩盖差异。

压缩／打包顺序或GLB字节不稳定时，解析后比较几何/UV/材质/最终PNG像素语义；不能仅以文件大小或截图相近判等。编辑显示图集合批不需要改变导出图集分配。

保留一次真实Blender回读，优先复用 `tests/paint-toolkit-export.test.cjs` 及现有已验证导出故事（先核对本地真实路径）。团结接收器未改时不强制重跑所有引擎流程；若改了导出材质契约则扩大验证并明确说明。

### 11.4 实际命令与打包

在 `自制工具/map_editor` 使用真实脚本。已登记的构建命令为 `npm run build`；单测按当前Node支持和现有约定选择受影响的 `tests/*.test.ts` 文件。类型检查与便携打包读取实际配置／脚本，不虚构npm脚本名。
