# 2DW-TILE-02 · 工坊 0.4.0

双击工坊目录的 `启动工坊.cmd`，选择 **样品到联通生产**。工坊离线工作；导出的任务 ZIP 交给有图像能力的 ChatGPT/Codex/其他执行者，返回 PNG 后再导入。程序本身不联网调用 AI。

1. **锁定格式**：选择草地或石质边界、逻辑格边长、PPU 和用途。默认新候选是多贴片与手绘轮廓，128px/100PPU 对应 1.28 世界单位。任务 ID 自动生成。新候选格边最大256px，经典四区保留原范围。
2. **少量样品**：按需添加内容/风格参考，导出 `sample-task`。只要求四个代表形态，不要求47态。返回样品用文件或 PNG 剪贴板导入；64–2048px边长、4MP/32MB预算，原始字节保存。
3. **风格收口**：选中准确版本，填写这次希望调整的内容，导出 `style-refine-task`。包内包含该原图及 SHA、保持项和允许编辑项。返回图须保留父版本尺寸和透明语义，作为新版本保存。内容是否一致仍需看图。
4. **人工定稿**：可用 Photoshop 等软件修改后点击“导入我的修改”，或粘贴 PNG。比较父版本/当前版本，点击批准并在确认窗口检查实际图、版本、规格和 SHA。只有这个准确版本获得当前任务批准；测试夹具始终注明不是用户美术认可。
5. **正式制作**：导出正式包，包含实际批准图和固定绘制画板。新候选须返回 `materials.png`（4c×2c）与 `contour.png`（2c×c）；c 为逻辑格边。可分次导入，两层齐全才编译。精确尺寸、通道或相位不符会拒绝并归档失败原件，不自动拉伸、补画或代入缺层。
6. **编译验收**：实际生成47种状态、188个变体及 atlas。检查九张地图、3×3邻居、底层、Alpha、Pivot、越格和排序对照。点击地图格或问题项，可以追到 mask、具体 PNG、源贴片坐标和批准样品。导出结果前须结构检查通过，保存后重新核验 SHA 和真实源像素。

新修订、修改格式/模板/PPU、撤销批准或替换正式源，会使旧正式任务和产出陈旧。旧原图和历史记录保留；重新批准以后仍要重新导入当前正式源。取消选择/保存不丢工程，同名 ZIP 不覆盖。

本机工程自动保存于 `.cache/asset-task-2d-profile/tile-workflow/`，也可“另存工程包”。同机原样工程可以恢复本机批准；新环境能打开所有原件和记录，但旧批准不自动授信，需要明确重新批准。密钥留本机，不进入工程或任务 ZIP。工程包为 `2dw-tile-session/1`，64MB/512条目预算。

工程参考栏显示将进入任务包的实际 PNG、角色、唯一 ID 和完整 SHA。重新选择参考会在下一次导出替换保存列表；清空按钮同时清添加区及持久参考，不删除用户源图。图片最多8张，每张4MB。只有明确选入的图片随包发送。

旧 **普通任务** 与 **经典联通母版** 入口保留。打开旧 v5 任务包会核验后明确提示使用经典入口，当前工程保留；不会把旧“编译过”升级成“样品已批准”。

程序的结构通过、用户对样品的批准、美术最终合格和 Unity 集成是不同结论。石质边界仍是厚度候选，Unity cap/body/underlay 遮挡与排序未验证。真实 AI 样品暂未获得用户批准，手修分钟数未测。
