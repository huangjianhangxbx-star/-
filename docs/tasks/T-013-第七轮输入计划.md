## 3. 本轮唯一交付目标与非目标

### 3.1 交付目标

在现有原型中提供一个可从正常副本流程进入的、有限规模的手工探索节点：玩家带队推进，借共享视野发现地形与敌人，触发和退出本体队伍战斗，使用个体及全队命令；在不清光全图敌人的前提下，按出口规则提前离开或完成目标离开；重入后敌人重置，目标、机关、地图记忆与奖励领取记录正确保留。

**完成单位是这整个探索循环，不是“先做跟随，下一轮再做真正的出口和重入”。** 可以分步骤提交，但不转去其他模块，把本轮主流程留下一半。

### 3.2 纳入范围

| 子范围 | 交付要求 |
|---|---|
| 正常探索入口及有限内容 | 手工探索地图、明确入口与出口、预设敌人、主要目标及一次性资源点；内容规模需 R7-B1 采用 |
| 发现、追击和队伍状态 | 视野发现而非全图找人；本体队伍统一入战／脱战；探索接敌容量与复制体例外 |
| 非战斗跟随 | 猎人固定领队，松散线性跟随，手动接管与恢复，遇敌停跟随，不自动排阵 |
| 全队召回／集结 | 战斗与探索非战斗两套已确认执行形式；含塔防中的同一命令，不只在探索生效 |
| 视野与场景反馈 | 未知／当前可见／已探索记忆；共享本体及复制体视野；目标选择与实时信息不穿透迷雾 |
| 探索镜头 | 默认关注队伍，选人偏移、取消回归；同步校正拾取、HUD 投影与范围表现 |
| 出口及死亡衔接 | 正常资格检查；濒死救援或明确放弃；不自动远程救回，不错误按塔防扣重试 |
| 同副本重入与新副本重置 | 敌人恢复满血和初始行为；机关／目标／记忆／奖励保留；正确重置技能、瞬影、计价与复制体 |
| 与已做系统联调 | 战斗、构筑、影体、资源、卡牌、塔防回归及正常资源循环证据 |

### 3.3 不纳入范围

不增加第五位出战角色或新职业技能，不重定现有培养及经济价格，不设计新牌池，不新增复制体距离衰减／数量上限，不把“类魂”扩成体力、翻滚无敌或死亡捡资源。

不制作完整巢穴生态、程序生成地图、多张大地图、复杂任务对话、商店或装备交易；不制作任意地形几何、体素地形编辑器、桥上桥下等新空间体系。允许用现有地面／高台／墙规格制作本轮小地图，不要求主体美术永久保持方块外形。

不迁移 Godot／团结，不新增刷新存档、断线恢复、联机或正式发布流程。只保证当前页面运行会话中的已批准状态寿命，不把“副本外库存”误写成已完成磁盘永久存档。

## 4. 已确认的设计：实施时不得重新发明

| 主题 | 已确认规则 | 依据 |
|---|---|---|
| 模式定位 | 探索由队伍主动推进，不以水晶为目标，也不先走塔防预告路线再攻击队伍 | S03 §1；S04 F.1—F.2 |
| 入战 | 敌人开始追击或攻击任一本体使全队入战；只是看见远处敌人不入战 | S03 §9.1 |
| 脱战 | 无敌人继续追击／攻击在场本体，并连续一段时间无本体对敌攻击或被敌方攻击；具体等待时长待定 | S04 F.3 |
| 复制体例外 | 其战斗不触发／维持本体队伍战斗，不让敌人定向报复；仍可被范围及环境效果波及 | S03 §3.3、§9.1 |
| 容量 | 未被接纳的探索敌人仍可攻击最近合法本体；已有接敌遵守锁定，不是伤害仇恨排名 | S03 §3.1、§3.3 |
| 跟随 | 非战斗猎人固定领队；手动移动其他本体暂离跟随；遇敌停跟随、原地展开战斗，不自动重排 | S03 §1、§9.1；S04 F.4—F.5 |
| 全队命令对象 | 仅在场可行动的非猎人本体；不带出未部署者，不包含濒死者或复制体 | S03 §9.1 |
| 全队执行 | 战斗中接近猎人并读条；召回进影庭，集结重现于猎人附近合法位置；探索非战斗即时执行 | S03 §9.1；S04 F.8 |
| 集结不是恢复 | 不治疗，不刷新技能或部署等待；位置不足者留原处并提示，不能消失丢失 | S03 §9.1 |
| 探索部署 | 本体／新影体落点要在猎人附近，仍要完整占地合法；部署半径独立于收纳半径 | S03 §2.1 |
| 视野 | 未知区域隐藏地形；记忆区域暗化、不显示实时敌人；本体和复制体共享有效视野 | S03 §9.2 |
| 离开 | 非战斗、猎人在出口、其他本体入影庭或在出口附近即可申请，不要求杀光全图 | S03 §9.2 |
| 通关与提前离开 | 主要目标完成才算通关；提前离开保留进展和随身资源，不发通关奖励 | S03 §9.2 |
| 濒死 | 必须先救回或明确放弃救援并按角色死亡规则处理；出口不自动救援；死者不挡离开 | S03 §9.2 |
| 场内状态寿命 | 入战／脱战不清影、不重置技能或抽价；允许脱战配置默认技能，不允许洗已选分支 | S03 §5、§9.3 |
| 重入 | 重布敌人全部满血、回初始／巡逻位置，不延续追击；技能空条、瞬影满层 | S03 §9.3 |
| 进度与收益 | 同副本机关、目标、探索记忆保留；已领物品与奖励不再发；新副本重新生成 | S03 §9.3 |
| 资源边界 | 回副本地图不入库；只能由已有合法安全离开／副本完成进行唯一结算 | S03 §7—8；S05 T-011 |
| 时间与身份 | 继续采用默认 1×／2×、临时 0.1×、暂停优先；保留猎人／菲奥蕾特殊身份和第二轮个体救援 | S05 T-008、T-004 |

“未决”仅指本稿第 7 节列出的实施组合及内容，不表示上述规则重新回到讨论起点。

| `engagement.ts:updateEngagement` | 探索未锁定目标时从所有可接近本体中取最近者；没有完整发现／失视条件 | 先通过探索感知资格，再选择追击目标；接敌容量是另一层判断 |

| `engine.ts:step / tick` | 战斗模拟由 phase 驱动；探索状态开发切换不是完整队伍状态机；仍有水晶等塔防判断 | 探索非战斗也继续模拟；运行阶段和队伍遭遇状态分开，塔防逻辑严格按节点类型执行 |
| `personal.ts:requestRecall / protectRecall` | 健康回收会进入影庭并重设始动；有效回收的致死保护已有专门顺序 | 群体召回复用个体契约；集结必须有不同完成分支，不能回收后 deploy 来冒充 |
| `main.ts:select / cancel / pickTile` | 鼠标提交可自动退选，右键不撤销已提交命令；没有完整跟随的控制权归属 | 记录移动的发起者及手动接管，不让每帧跟随重发命令吞掉玩家移动、救援或换装 |
| `scene.ts:resize / project / pick` | 相机按全战场适配；拾取和所有世界UI使用相机投影；场景建筑可批处理 | 增加探索镜头策略，并保证雾区与动态信息过滤、相机移动时的投影一致 |
| `economy.ts / cards.ts` | 已有唯一副本结算、奖励键、节点 visit 计价契约及手牌寿命 | 复用其账本，给探索敌人／资源／目标建立稳定预设身份；不创建第二套钱 |

## 6. 状态寿命必须分层

| 事件 | 应保留 | 应改变／清理 |
|---|---|---|
| 探索入战／脱战 | 同一次访问、敌人实时血量、影体、技能进度、构筑、手牌、抽价、随身资源 | 队伍战斗状态、跟随资格、配置权限；不执行场景结算 |
| 本体健康个体／全队回收 | 构筑、伤势、武器耐久及有效技能政策 | 按既有规则入影庭、设置始动等待；菲奥蕾特例保留 |
| 全队集结 | 伤势、构筑、CD、计数和部署等待按已确认语义保留 | 合法位置变化；有限动作如何中断见 R7-B4，不能提供隐含回血／满充 |
| 探索节点提前离开 | 随身资源、培养、已领账本、目标／机关、探索记忆 | 清影与跨场效果、关闭本次 visit；不标通关、不入库、不套塔防失败扣次 |
| 完成目标后合法离开 | 同上，并记录已完成目标／节点状态 | 通关奖励至多一次；发放时点及内容待 R7-B1 采用；本节点不是自动副本完成 |
| 同副本重入 | 培养、长期损耗、目标／机关／地图记忆、领取状态 | 所有重布敌人满血并重新初始化；新 visit、抽价初始；技能空条、瞬影满层；旧影不复原 |
| 安全离开整个副本／副本完成 | 局外库存与长期角色状态 | 由已有唯一结算带出余额；清本副本培养和手牌，不重复入库 |
| 放弃整个副本 | 未携入库存及其他既有长期状态 | 由既有失败结算清随身资源，不假装安全撤离 |
| 开始新副本 | 身份、默认偏好、已解锁上限、账户和既有长期损耗 | 清探索记忆／机关／目标／领取周期；重新提交携入，不赠送启动资金 |

获救者重入同一节点是否解除禁用、节点外临时效果及特殊复生的探索落点，不能由上表自行补全，须完成 R7-B5。

## 7. 正式开工前需要采用的五组边界

以下均为**待确认补充或 AI 建议**。执行者先查本轮之后是否已有更具体批准；已有答案直接采用，不要求用户重复。可以先确认一组再推进下一组，但未确认内容不能写成定案。

### R7-B1：探索样本、接入位置和目标内容

**建议采用的最小完整样本：**保留节点 1→休息 2→节点 3 的原塔防主线，在节点 1 完成后开放一个独立、可重复进入的探索支路节点。编号由现有节点目录决定，不假定已存在“节点4”。支路不强制替代休息节点或长关，也不因完成支路自动结束整个副本。

制作一张约 28×20 逻辑单位的小型手工地图作为起点，含入口安全区、2—3 个遭遇区域、一条短巡逻、一个主要机关目标、一处可一次领取的资源点、一处可提前离开的出口。规模和敌人数在内容表中明确；不同时开发巢穴刷怪或生态系统。使用现有角色、敌人及地格美术，地图面积不是正式关卡规格。

**需要采用：**支路开放条件、精确内容规模、目标交互方式、主要目标是否在激活时标记完成，以及通关奖励发放时点。建议目标激活立即保存进度，合法离开时才发一次通关奖励；提前离开不发。资源点及通关奖励按内容配置给出小额随身生命力，具体数量留在本轮内容表，不修改培养／召影／抽牌价格。

必须能够在目标未完成且仍有敌人的情况下合法离开，再回同节点完成目标；不能只做一张“杀光敌人自动过关”的探索皮肤。

### R7-B2：敌人发现、失去目标与脱战

**已确认的核心不变：**看见远敌不入战；敌人追击／攻击本体入战；复制体不引发报复或维持战斗。具体视野与返程是 v0.2 明确保留的专题。

**建议方案供采用：**敌人用独立发现距离和实体遮挡判断本体，先做全向发现，不增加潜行方向角。失视允许短暂追往最后可知位置；持续失视、超出活动范围或目标失效后停止追击并返回自身初始／巡逻区域，不回塔防水晶，不在同次访问中免费回血。返程途中重新发现本体是否再追、何时允许再接敌须明确，不能直接照搬塔防“返程绝不重新接敌”当成已批准探索规则。

可调起点建议：敌人发现半径 5、脱战等待 3 模拟秒、失视宽限 1.5 秒、离开初始活动区的追击上限 8。它们不是现行数值，也不能与攻击／接敌半径混为一谈。

需要同时收束：

- 本体在敌人正常视距外先手攻击，敌人怎样发现攻击者、入战从哪个事件开始。建议真实本体攻击产生战斗活动并由敌人响应，不以选中、瞄准或未发动技能触发；准确规则须采用。
- “本体攻击”以真实出手还是命中为活动；闪避、持续伤害、延迟派生及无来源环境伤害怎样影响等待。建议记录事件来源和真实模拟时刻，不靠累积击杀数或上一帧是否有伤害猜测。
- 濒死、始动、跨层等“不能接纳敌人”与“不能被发现／追击”是否有差别。已确认跨层可受击，不得借资格查询增加无敌。
- 返程不是继续追击本体；正确清理追击标记，使脱战等待有机会结束。只有复制体仍在战斗时不能永久锁住全队。

### R7-B3：可见性、光照和雾区操作

**建议：**将“当前可见”和“曾探索”作为两层数据；小样本用配置化水平视距加实体高度遮挡，不把攻击射程当视距。先不增加昼夜／天气；现有黑暗塔防不改。

本体与复制体都贡献共享视野；道具提灯按既有资格接入。探索里的基础视距、提灯是否独立揭示地形、失去全部在场本体但仍有影体时的视野，以及墙和高台分别怎样遮挡，须明确采用。可从本体／影体视距 5 的试验值起步，具体身份差异留内容配置，不冒充旧 light 数值已获统一改写。

建议未知地面暂不提供精确落点指令，玩家以直接移动推进视野，或向已探索地面提交指令；记忆区域的目标及路径预览不得暴露未见的实时单位。未知区域是否允许长距离点击导航，以及技能对不可见单位的作用，须确认后统一接入。不得未经采用便删除旧卡牌能力或赋予全部范围技能穿雾精确索敌。

隐藏必须覆盖敌人模型、血条、状态、选中拾取、技能锁定预览、实时事件标记及会泄露位置的表现；不能只有地面一层黑色贴片，墙顶、实时敌人或描边仍从上方露出。记忆中的机关外观只在有效观察或明确交互后更新，不无条件展示不可见区的动态变化。

### R7-B4：跟随、全队命令和镜头

**跟随建议：**不做强制阵型，使用合法路径和松散目标区，带停走阈值与限频重规划；不能靠瞬移追赶，不能穿敌或取消普通跨层。具体跟随距离、所有本体同速的计算方式，以及负重／减速是否影响统一巡行速度，须采用；不顺便重调塔防移速。

手动控制、已提交鼠标移动、回收、救援、换装、技能与自动跟随必须有明确优先级。建议自动跟随最低；鼠标提交自动退选不等于抹掉这条已提交移动。右键仍不撤销已提交命令，恢复跟随资格后，跟随只能在命令允许交接时接管。进入战斗只停止自动跟随，不一刀切取消所有玩家指令；跨层与回镰中断仍遵循其已有规则。

**全队入口建议：**提供 UI 按钮和 H／B 两个键，分别召回／集结；这两个键仍需本轮采用。对象在提交时按已确认资格选取；各角色独立执行，失败不得让别的角色消失。重复按键不能反复重置读条，新明确角色命令可以覆盖该角色任务。

建议已提交的战斗型任务在脱战后继续原过程，不偷偷跳过读条；若用户重新发非战斗即时命令，再按当时状态执行。相反，即时命令只在同一提交检查仍为非战斗时成立，敌人刚入战不能沿过期资格全队瞬移。

集结在真正迁移前重新校验并预留每个落点，位置不足者保持当前位置；不先入影庭再尝试部署。集结过程不提供死亡保护。建议集结读条中濒死则取消该角色集结、保留濒死并提示救援；全队召回沿已有有效回收的致死保护规则。两种动作的差别须确认，不把共用读条误做成共用救援特权。

有限技能、无限模式、回镰、普通跨层和猎人移动／失能对群体任务的中断政策须列成小表；尤其集结不能因复用健康回收而重设始动、满充或回血。

**镜头建议：**探索默认跟随猎人作为队伍参考；观察选定者时向目标适度偏移，取消后平滑回归。偏移上限、跟随速度及是否在直接操控其他本体时继续关注该本体作为可调值；塔防选人不移动镜头。无目标朝向建议保留最后有效朝向。镜头缓动使用不改变模拟规则的显示时间策略，并适配减少动态效果偏好；暂停时可否继续缓动须明确。

### R7-B5：出口、特殊生命状态与重入边界

**出口已确认门槛不变。**需采用出口范围、其他本体“在出口附近”的距离和交互方式。建议实际按钮／地面交互采用同一资格查询；点击提交时复查，不能只有 HUD 禁用而核心命令仍可跳过战斗／濒死检查。

存在濒死者时先救援，或逐项显示姓名与死亡后果，由玩家明确确认放弃；取消不造成死亡。建议一次完整提交先校验剩余离开条件再改变生命状态，避免出口失效却先把人判死。采用后的同刻顺序要与既有回收保护和濒死超时约定对齐。

以下语义仍需核查并收束：

- “获救者本节点禁用、下节点 1 HP”在探索提前离开后重入同一节点是否仍禁用。不能仅因为旧塔防 enter 重建 life 就自动决定。建议优先按节点身份记录限制，防止出门再进同门当场复活；这是建议，须核对后续批准。
- 出口附近但未入影庭的健康本体，离开与下一次进入如何安置。建议正常节点转移收队，不算免费治疗，不触发额外资源，也不把集结／出门伪装成新死亡。
- 猎人在探索中复生的合法落点。保留既有特殊身份与计时，不再硬编码塔防起点；建议优先在规则允许的菲奥蕾附近或当前探索入口找合法地面，失败则等合法落点，不在未知墙内生成。
- 没有水晶时不沿用水晶失败条件，也不自行新增“全队倒地即扣塔防次数”。猎人等待复生、无可行动跟随者及出口不可用时须有明确反馈。
- 路障的旧“不能封死通路”在无水晶地图中的适用对象。建议用入口／出口／目标连接的本轮查询适配，不改卡牌机制，不直接禁牌或继续对虚构水晶寻路。
- 玩家放置的路障、提灯、未完成回收和临时状态在节点离开时的清理，以及固定机关与关卡记忆的保留要分开。建议临时战场布置清理，不把它们误当永久机关；采用后记录。

这五组全部收束后，再形成正式开工版。无需在第七轮前补完全部世界观、全部地图或巢穴设计。

## 8. 执行顺序：在同一探索模块内闭环

### R7-00：核对、批准、内容表和真实基线

执行者核对目标提交与本地未提交差异，读取本轮之后的有效决定、适用 AGENTS 及真实 Skill。只澄清 R7-B1—B5 未回答部分；给出采用后的内容表、状态中断表和验收映射。

获准实施后，先备份测试可能改写的历史证据，记录固定代码的逻辑／类型／构建及浏览器基线。不要在基线测试仍运行时修改游戏，然后把混合结果称作干净基线。

**结束条件：**每个会改变玩法的建议有明确采用或暂缓；本轮无悬而未决的核心出口／跟随／视野机制。任务编号由执行端查看登记后分配。

### R7-01：探索定义、正常入口与状态归属

建立有限手工地图定义、敌人／目标／资源稳定预设 ID、本次访问状态与本副本节点记忆。正常节点页面能进入和重入该节点，塔防节点仍使用原有波次路径。

在内部区分节点类型、场景运行阶段、本体队伍战斗状态、访问序号与副本周期。不要把探索非战斗复用成静止的 briefing/result；也不要把 `setContext` 调试切换当玩家流程。

入口重置按第 6 节执行，保留真实生命、耐久、构筑和携入账本，不把旧 1500 HP 交战夹具搬成正常内容。

**先测试：**正常入口／重复提交、稳定预设 ID、探索不刷塔防批次、不依赖水晶值、普通塔防不受影响。

### R7-02：感知、敌人行为与本体队伍入战／脱战

实现已批准的发现、追击、失视、返程／巡逻和目标释放；未接纳敌人仍能攻击本体。独立记录真实战斗事件来源与时刻，区分本体、影体、范围波及和延迟事件。

队伍状态影响配置权限、跟随和全队命令，但不停止探索模拟，不触发结算／清影／重置价格。连接正常样本中的守卫与巡逻敌人，不只是纯函数测试。

**先测试：**远处可见不入战、首次合法发现、复制体独立作战、满容量攻击、失视后真正可脱战、重新交战延后脱战，以及慢速／暂停／步长变化。

### R7-03：非战斗跟随与全队命令

接入控制权和自动任务归属。实现非战斗同速松散跟随、手动接管、恢复跟随、入战停止自动跟随。避免每个渲染帧重发 move 导致技能或救援被反复中断。

实现群体召回和群体集结的区别、战斗读条与非战斗即时形式、独立失败与落点预留。复用个体能力但不复用错误的完成状态。UI／快捷键同步接入；在塔防里验证战斗版本，不把这部分留给“以后补兼容”。

**先测试：**不移动复制体、不召出未部署者、不救回濒死者；集结不改变 HP/CD/始动；位置不足保持可见；施法／跨层／回镰／猎人失能／同刻濒死组合与明确命令覆盖。

### R7-04：迷雾、可见性消费和探索镜头

接入当前可见与历史探索掩码，在实际三维场景中隐藏未知地形及实时信息。将索敌、点击拾取、技能预览、角色血条与状态、事件交互、范围和路线展示接到各自允许的可见性查询。

实现探索跟随／偏移／回归，保留塔防全图镜头。镜头移动后鼠标地面落点、角色选择、读条、技能按钮、伤害／掉落反馈继续对准；不以固定屏幕坐标假设验证点击。

**先测试：**未知与记忆区别、影体共享、墙后及高差、离开视野的移动敌人不泄露、镜头与 world UI 投影、紧凑窗口和减少动态。

### R7-05：目标、资源点与合法出口

实现内容表中的机关目标、资源领取、出口提示和不要求全清的退出。区分节点目标完成、节点离开和副本结算；沿用已有账本，不创建平行余额。

玩家出口命令先检查当前战斗、猎人、其他本体与濒死者；显式死亡确认和最终提交防重复。开发清理函数可以保留，但正常出口不能调用绕过资格的裸命令；调试入口也不能被当作正常验证证据。

**先测试：**提前离开保留进度无通关奖；仍有敌人可离开；战斗／远离出口／队友不合格时拒绝；濒死不自动救援；重复激活、资源领取和离开不重复发奖。

### R7-06：真实重入、特殊生命状态和资源循环

重入恢复机关／目标／记忆／领取记录，但重新生成所有敌人满血及初始行为。重置访问计价、战斗技能与瞬影，旧影不复原。玩家伤势／耐久与本副本培养保留，获救限制按本轮已采用语义执行。

将探索支路与既有地图、安全撤离、放弃副本及塔防节点衔接。检查从探索出来再进塔防，和从塔防再回探索时，ruleset/context、地图、镜头、波次状态、索敌与计价都不串场。

**先测试：**同敌新运行 ID 不再领奖、新敌首次领奖；机关及目标不丢、旧敌伤势不留；安全副本结算才入库；新副本重新生成；猎人复生及普通获救状态无刷复活漏洞。

### R7-07：完整正常试玩回放、回归和交接

完成第 9 节验收；所有核心操作均通过正常 UI 或公开游戏命令执行。边界夹具可以直接安排状态，但与正常资源回放分开记录。

至少完成：正常进入→遇敌→脱战→全队命令→提前离开→重入→完成目标→再次离开→合法副本结算；并完成濒死不能直接走、单独救援或明确放弃的独立分支，以及塔防群体命令回归。

先冻结游戏代码，再执行完整回归；修改后只把确实覆盖的新结果记入验收，不用历史成功冒充。按本次有效授权保存任务、规则对账、状态及受影响导航；确认没有改保护区或覆盖别人的工作，发布另按授权。

**本轮结束条件：**正常入口能完整走通上述流程；不是只有 `setContext` 和清理按钮能调用。不得宣称已完成所有探索内容、正式平衡或最终性能。

## 10. 工程实施约束与可能的文件落点

### 10.1 建议的责任分区

- 探索节点配置与同副本记忆：定义稳定内容、访问重建与进度保留。
- 探索感知与队伍状态：提供可见性／发现和真实入战／脱战，不依赖渲染可见布尔值作玩法依据。
- 跟随及群体任务：明确控制权、逐对象执行、集结合法落点与失败反馈。
- 探索表现：雾区、目标、出口和镜头；只消费核心状态，不在动画完成回调里决定死亡保护或资源入账。

可以按实际代码新增例如 `core/exploration.ts`、`core/exploration-content.ts`、`core/party.ts`、`core/visibility.ts`；这些是**建议的新文件名**，当前仓库并不存在这些已完成模块，不要求为满足数量机械拆分。

### 10.2 必须核对的现有调用链

`engine.ts` 的初始化、step、目标查询、节点命令和终结；`engagement.ts` 的锁定和返程；`personal.ts` 的个体回收、直接控制与保护；`clones.ts` 的清理；`progression.ts`／`loadout.ts` 的配置权限与状态保留；`economy.ts`／`cards.ts` 的访问计价、收益和实例清理。

UI 范围包括 `main.ts`、`interaction.ts`、`ui.ts`、`build-ui.ts`、`economy-ui.ts`、`style.css`、`view/scene.ts`，以及受相机和可见性影响的范围、技能区域、世界反馈和掉落反馈调用方。只修改被本轮真实影响的地方，不重做全部界面皮肤或战斗技能。
