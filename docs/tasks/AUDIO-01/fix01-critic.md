## 先查问题

检查真实 diff 后，没有发现以下硬门槛仍可复现：同曲规则变化导致重建；普通对话替换原曲；对话结束从零播放；旧加载回调复活无效会话。

首轮审查指出三个验证缺口，已在本轮闭合：原真实对话测试仅覆盖打开瞬间，后补 8 秒停留及正常结束录音；30 秒模拟起初使用诊断音乐，后改为正式真实 home；补充取消/目标失效/F10、交战权威和新有效世界情境与旧加载的竞争。它们是证据补强，不是另开第二轮完整评分。

M06 完整集曾出现 calm 超时；真实追击最初只是推测，不能作根因。独立读取随后保存的 `combat-failure.json`：10 条采样中游戏 time 从 `.6083` 增至 `3.1083`，lastActivity 始终 `.2083`，scale 始终 1，单位中没有敌人；最后一次距离活动仅约 **2.9 游戏秒**，尚未达到生产代码的 3 秒 calm，因此这些观测不构成“达到脱战条件却未脱战”的证据。此前 8 秒墙钟等待预算不足以覆盖该轮实际游戏进度；具体软件渲染/资源负载的性能占比未做 profile，不作断言。仅将夹具等待预算扩至 20 秒、单测预算 45 秒，保留原游戏时钟与规则断言，最终完整集已通过。

夹具通过鼠标空挥进入既有交战权威、等待既有 calm、按 Z 切人，再次空挥入战，没有注入 context 或 lastActivity，也没有修改生产交战规则。单项连续三次和 M04+M06 小集通过不代替最终完整集；无敌人夹具也不能描述为实际敌人遭遇战全流程。

## 代码与状态证据

- `music-content.ts` 按素材、版本、段落和 loop 规格构造内容 key；`explore` 与 `explore-far` 共用真实 home 描述。`refreshMusic()` 在相同 key 时只更新规则/原因/必要强度，保留 source、epoch、transport；不同合法段落仍更换 transport。
- 普通 `dialogue` 已从自动选曲规则移除。既有 `dialogue-focus` 仍按 token 获得/释放，music .45；不会覆盖用户音乐音量或另一快照。对话输入与世界时间的生产代码没有被本轮修改。
- 交战曲意图来自 `state.context === 'explorationBattle'`。音频不再用实控角色 8U 可见敌人边界猜测交战，不改玩法进入/退出规则。
- 加载完成只填缓存。实际播放重新解析当前目标并受 disposed、explicit stop、world target validity 守卫；当前曲不同或新有效情境不会被旧请求强制覆盖。明确停止后 tick、普通上下文更新不会自行复活音乐。
- 强度更新以 `max(now, node.start)` 保留未来起播 envelope；F10 关闭时无覆盖的同 key 分支不会重新 start。有限历史最多 64 条，当前/待播/淡出/stinger 分列。

已独立读取 ignored `work/AUDIO-01/FIX01/home-continuity.json`，并用 FFmpeg 解码 `home-music-only.webm` 与 `home-master.webm`；没有人耳或模型试听。
