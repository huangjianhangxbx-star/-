## 0. 一页执行结论

**用户的明确需求只有一个：**

> 我手里只有**一张人工修好、我愿意采用的石砖 PNG**。工坊应该接受它作为正式美术基准，然后把它、已经定好的联通结构格式、项目风格规则一起打包给 AI，让 AI 负责扩展完整联通资产。**我不想自己画完整母版，更不想先绘制 47 张独立图。**

这不是重新建设一套 2D 工坊。**先复用 0.4.1 已有的“样品版本 → 人工批准 → 正式母版任务包 → 47 态编译”基础设施**，修补“单张样品入口”和“单张样品→可联通正式图”的真实生产缺口。

### 首版理想用户体验

```text
打开 2D 工坊
  → 选择「从一张已修好的 PNG 开始」
  → 粘贴 Ctrl+V / 选择 PNG（即使没有 AI 初稿记录也能开始）
  → 选择「平面石砖联通 / 草地边缘联通 / 石质高差边界联通」之一
  → 系统自动加载对应拓扑、视角、尺寸/PPU、风格规则
  → 用户预览该 PNG，点击「定为本任务样品」
  → 系统生成「依据此样品扩展完整联通资产」任务 ZIP
  → 外部 AI/Agent 读取 ZIP，在固定模板内制作正式原稿；有工具时完成精确素材编排
  → 将正式图/层返回工坊，执行严格编译与接缝检查
  → 浏览 3×3 / 8×8 / 16×16 及47态图集；有问题局部返工
```

**用户最多必须做的美术操作是修好一张样品 PNG、确认一张图和目标格式。** 技术上不可避免的导入、编译、检查尽量自动化或预设化，不能再要求用户手动编辑完整 PNG 图集、绘制数值轮廓控制层或者逐张填写任务 ID/标题。

### 三个不可混淆的概念

1. **样品定稿图（用户一张 PNG）**：画风、线条、砖块组织、主次、用色、材质表达的**最高优先级视觉基准**。它不是完整联通结构的证明，也不要求是可切割母版。
2. **联通结构模板（工坊既有数据）**：负责 47 种条件八邻状态的拓扑、边角、透明区域、格子、Pivot、世界单位等。**一张漂亮的石砖图无法推导全部掩码形态，必须由模板提供缺失的结构信息。**
3. **正式可编译图源（AI/Agent 制作）**：在保留样品绘画语言的前提下，服从模板产生连续材质与边缘，经过本地程序真实切割、回拼与验证。**不等于把一张样品简单复制47次再套不同透明蒙版。**

### 1.3 用户图片与文件事实的区别

本轮聊天里的“人工修改图”和“AI 原图”以**屏幕截图**形式出现；截图可能含灰色预览背景、截图边缘、浏览器缩放，不能直接冒充用户保存的最终素材 PNG。Codex 的测试必须以**用户实际选择/剪贴板提供的 PNG 字节**为准，显示分辨率、Alpha 类别、透明范围和来源 SHA；任何裁掉背景、抠透明、校正色域操作都须获得明确操作授权并产生新版本，不得静默更改用户原件。

## 2. 任务范围及已经决定的原则

### 2.1 必做（P0）

- **单张修正版 PNG 直入**：接受一个真实 PNG，没有最初 AI 原图、没有四形态 sheet、没有既有父版本也可以开始。
- **极简工作台入口**：单张 PNG + 目标资产类别/结构模板 + 默认规格/风格，任务 ID/标题自动；不让用户重复填表或做无意义选择题。
- **准确的用户定稿**：用户直接预览并确认同一 SHA 的样品为本任务视觉权威；保存来源、说明、样品身份；其他参考不得抢占优先级。
- **单张样品专属检查**：仅确认“资产用途、视角、是否可作为画风与结构主次参考、清晰度是否足够”；不冒称它展示了内外角和47状态。
- **一键正式制作包**：清楚标注“依据此样品**扩展**并制作联通”，包含真实 PNG、项目风格契约、所选拓扑/模板、返回物契约、连续绘制方法、检验/返工方法。
- **不改原有经典/四形态协议**：旧工程/任务包仍按旧版本解释与验证；新增显式协议、显式转换和回滚/兼容测试。
- **真实产出闭环**：使用一份可发布的**原创夹具单样品**完整演示从导入、批准、ZIP、正式原稿、47 态、回拼到 ZIP 验真；真实艺术结果另作验收。

### 2.2 力争（P1），可与主线分层实施

- 针对普通 Chat 生图难以满足数值控制图的问题，为支持脚本的 Codex/Agent 增加**可审核的技术转换步骤**；工坊可选的“生成技术 contour”应来源于明确的模板/可编辑控制，而非暗中伪造“AI 已画好”。
- 针对大面积石砖重复，提供中心变体与砖缝特征追踪、8×8/16×16 比较；保留画师对石砖组织的主次，而非只复制样品中的某块中央砖。
- 对旧“经典联通母版”页面中已有的单张内容参考，提供“发送到单样品入口”操作；数据安全校验通过时可复用已保存的 PNG 字节，不做不明来源路径直通。

### 2.3 明确不做

本轮不接入联网 AI API、不训练 LoRA、不创建 3D 工坊、不重构游戏/Unity 工程、不做全类别资产生产系统、不继续全面拆解《地心归途》、不建立“自动美术评分”假功能、不训练识别用户画风模型、不修改已批准场景 L0/L1/石材 L2、`design/开发细则.md` 或人工原稿。正式 Unity Sorting/遮挡仍是待验；本轮不凭编译器通过宣布可以直接用于 Unity 的复杂石墙。

### 2.4 样品只有一张时的正确生产哲学

- 单样品只锁定 **“如何画”**：石砖色域、形体分块、缝隙的黑线/黑块、暗部停止刻画、弱高光、破损密度、笔触密度。它并不能唯一决定所有联通状态的几何拓扑。
- 模板锁定 **“画在哪里、怎样拼、怎样切”**：中心、上下左右边、内外角、孔洞、连接和断口的工程规则。
- AI/Agent 负责 **“在模板上扩展同一种绘画语言”**：首先画出可延续的整体材质和边界，再考虑生成需要的各状态；不要让 AI 各自从零发明47块。
- 程序负责 **“真实编译并指出错误”**：不能在程序验证中把拓扑合法误读为画风合格；不偷偷填空、拉伸、镜像、旋转、模糊、随机涂抹补缝。

## 3. 新用户体验与页面设计

### 3.1 入口布局（优先 UI/操作最小化）

保留首页现有三个入口「普通素材任务」「经典联通母版」「样品到正式联通」，在**样品到正式联通**内放一个显著首选入口：

**「我已有一张手修定稿图 → 直接制作联通版」**

与之并列但次级保留「从头试制四形态样品」。不要在首页再堆一排五六个类似标签。

旧经典页面如检测到用户只在“内容参考”贴了一张图，还没有完整母版，应显示友好提示：

> “这页接收完整的结构母版，不接收单块定稿图。只有一张手修 PNG？点击『作为定稿样品开始联通生产』。”

点击按钮不能默默损失图片/任务信息；有可复用引用则保留源 SHA 与明确来源，没有则允许重新 Ctrl+V/选择图；切换和取消不覆盖原工程。

### 3.2 一页直入示意

```text
[从一张手修图开始]

已定稿图     [拖入 / Ctrl+V / 选择PNG] [预览原图]
文件        user-edited-stone.png · 384×384 (示意) · SHA 4c2…
身份        这张图是本任务【唯一主美术参考】[已选择]

要生产什么？ [平面石砖联通] [其他模板…]
规则        条件8邻 · 47态 · 格边128px（可改）· PPU100（可改）
视角        正俯视（模板固定，不能任意改变）
风格        标准（极端概括可选）

[确认这张图作为本次定稿]   [导出「扩展正式联通版」任务 ZIP]

下方：流程图与原图/形式模板预览 / 验收说明
```

这是需求示意，不是声称已完成 UI。项目当前是深色 Electron 桌面 UI，沿用既有样式及离线布局；避免大型重设计。

### 3.3 不强迫人工完成多项多余工作

- 任务 ID、标题、样品版本号全部自动生成。
- 不强制先走 “AI 少量试制” 或 “AI 第二轮风格收口”；**用户已经亲自手修好**，可直接作为起点，必要时才进一步压风格。
- 不强制把同一张图分别上传“内容参考”和“风格参考”：**主样品天然同时承载结构主次和画法语言**，在导出包中只存一份真实 PNG、带明确的双重作用声明。
- 不强制用户先把一张图拆成四形态，不要求自己画完整 mother sheet，也不要求手画 `contour.png`。
- 生成失败时给出当前阶段、失败原因以及**下一步可点击的按钮**，不只给 `schema` 或内部状态名。

## 4. 新数据契约与批准模型

### 4.1 原有规则不要硬套到单张样品

现行 v7 `formReview` 的 `sharedCamera` 与 `productionIntent` 实际面向 2×2 四形态。**不能让用户对着一张石砖单图，把“这四张共用相机”等不成立的项目逐个勾成真。**

提出新概念（命名可按既有代码风格微调）：

```json
{
  "sampleKind": "single-approved-reference",
  "sourceKind": "user-manual-final",
  "parentSampleId": null,
  "approvedImage": {"path":"input/approved-sample.png","sha256":"真实哈希","widthPx":384,"heightPx":384},
  "visualAuthority": {
    "priority": "highest-for-art-style-and-material-language",
    "uses": ["visual-structure-hierarchy","linework","color-blocks","surface-damage-density"],
    "notProofOf": ["conditional8-mask-coverage","seamless-all-edges","inner-corner-geometry"]
  },
  "targetGrammar": "selected-conditional8-template",
  "viewContract": "selected-fixed-form-id",
  "stylePressure": "standard",
  "artApprovalStatus": "user-approved-as-reference-for-current-task"
}
```

以上为数据语义示例，**不能照抄假 SHA**，`approvedImage` 真正的文件身份由现有本机 store 与输出协议确定。应该与现有 `sampleId/revision/specHash/SHA/approval` 体系复用；不得出现平行独立、不互认的批准数据库。

### 4.2 单样品专属人工检查（与四样检查区分）

新检查仅针对这一张图所能证明的内容：

| 检查项 | 用户实际要确认的事 |
| --- | --- |
| 目标类别 | 这张图是否可用作本次平面石砖/草地/石质边界的**绘画依据** |
| 固定视角 | 样品可见画法是否符合目标模板的视角；例如石砖顶视不应错选立体崖边 |
| 参考可用性 | 原图是否足够清晰地表达黑线、色块、裂缝、纹理密度及形体概括 |
| 定稿身份 | 用户是否明确选中**这张准确 PNG**作为本任务样品，不是其它父图/截图 |

- **不检查**“这张图包含四种邻接形态”或“整套联通无缝”，这些要在正式图阶段检查。
- 不接受 JSON 手改 `approved=true`、改变截图来源或替换文件绕过 Gate。
- 原图及修订原件依旧保留，导出不同规格时需重新建立批准身份；跨机器沿用当前可信边界。
- 可以记录“人工批准**单张视觉基准**”，不能把这一动作提升为“47态美术全部批准”。

### 4.3 版本/协议策略

旧任务 ZIP v1–v7、`spec 1.0–1.5` 都不改其原有意义。由于单张样品的检查语义与 v7 不同，**建议显式新增 `single-reference` 流程协议**（如 `spec 1.6.0 / 2dw-zip/8`，Codex 应先查当前统一解析器的真实版本管理约束，最终编号以未占用版本为准），**不能通过篡改 v7 `sharedCamera` 的名字而让历史签名/批准偷换含义**。

新协议需包含并严格验证：样品身份、来源字节、视觉权威、联通目标、真正批准的样品、标准/极端压力、固定视角、返回工序、失败诊断。所有派生 Markdown 与图示由权威结构重建验证，签名/哈希校验严格承袭前代；旧包不自动升级批准。

### 4.4 规格改变如何失效

- 改目标：平面石砖 → 崖边墙体，原批准至少必须重新确认“适用这类资产”。
- 改格边/PPU/连通模式/固定视角：旧正式包、编译结果陈旧；单样品字节可保留、但必须明确按新目标重新确认。
- 改风格档位：旧任务包陈旧，不自动复活批准。**若用户的本意只是正式生产阶段临时压风格，不得悄悄改写原样品的内容/审批身份；要明确区分样品获批与新生成策略。**
- 改修图 PNG：新 SHA → 新样品版本，旧源始终可追溯。
- 只是打开/关闭页面、取消保存：不丢工程，不覆盖原件。

## 5. 实际生产方案：外部 AI 怎样根据一张图扩展全套联通

### 5.1 不把拓扑难题交给一句“照这个风格扩展”

正式生产任务必须拆解为可执行顺序：

**步骤 A｜读取样品与提炼画法（AI）：**

- 找出主石砖形块、次结构、黑缝/接触暗块、主色/暗色、破损分布、禁止高光硬边及人工删减的特征。
- 提取可迁移的**设计方法**，不是要求复制同一颗石砖及同一条裂缝。
- 标记哪些是画风约束、哪些是本次具体内容、哪些是联通模板规则。不得从单张 PNG 猜测未画出的转角/深度。

**步骤 B｜构造连贯的绘制底层（AI）：**

- 先安排具有**跨格关系**的大块石砖/草面组织；规划连接边、开放边、外角/内角、底层和需要的厚度。
- 风格锚点维持不变，但不同状态的结构要**真正有差异**，不把中心砖面无脑粘贴到所有边角。
- 草地与石质高差必须各用各自正确的视角规则；平面石砖不能被绘制成 3D 岩台。

**步骤 C｜输出可用的艺术源图（AI/Agent）：**

- AI 负责绘画内容和必要的形体设计。默认不要求它独立出47张随机 JPEG/PNG。
- 对能操作文件与代码的 Codex/Agent，允许按已批准的绘制模板将绘画素材**确定性编排**成真正可编译的 PNG 图层；保留返回图与所有转换日志。
- 普通 ChatGPT 若只具有生图能力、不能精确输出数值控制层，必须如实停在“已产出绘画源图，尚待技术转换”，不能声称47态已完成。

**步骤 D｜技术映射/联通编译（工坊）：**

- 以固定模板和导入的原始绘画像素生产合法邻接状态，检查真实 Alpha、公共边、内外角、Pivot、相位与层级。
- 输出37/47或49/47时必须拒绝，**条件八邻合法状态数应由既有权威定义为47**；现有48索引不可与47个合法状态混淆。
- 导出用户可查看的所有状态、代表组合图与详细问题定位。

### 5.2 重要的技术现实：`contour.png` 不是让 AI 画的“黑线图”

现有 `art-directed` 编译要求：

- `materials.png`：`4c × 2c`，`surface-0…3`、`edge-0/1`、`underlay`、`dark`，均为 `c×c`；
- `contour.png`：`2c × c`，R=0–255，G=0–192，B=0，A=255，用于几何边缘缩进和暗部混合；
- edge-0/1 的共享两像素边框满足既有对应相位限制；
- `47` canonical / `188` variants 及九场景沿用现有编译/验收。

**禁止做法：**在提示词里让 ChatGPT “画出合法 RGB 控制图”，然后只检查文件尺寸就当通过。普通生图生成器并不保证编码颜色逐像素准确。

建议本轮做一次**可复核的生产可行性验证**：

1. 先用现行双层格式，从一张原创、经过人工批准的技术样品驱动真实 `materials.png`（绘画部分）和 `contour.png`（数值部分）生成。可由 Codex 编写**明确、版本化的确定性 contour 派生器**，参数来自合法几何模板/经确认的边界控制；其来源标记为程序生成，而不是 AI 手绘。
2. 检查这种方案能否保留画师设计出的关键外轮廓。如果只能套机械蒙版、导致变体都像同一块纹理，请把它列为**技术有效但艺术质量未达标**，不得将其宣传为满足用户目标。
3. 若真正的手绘边缘不能由现有两张正式图表达，可另加一个**可选的艺术轮廓工作层或控制层转换器**，让 AI 以人可见的黑白形态/外缘设计作画，再由程序映射到数值控制范围。不能不经验证就推翻已有成熟编译器；优先保持 v7 编译输出可复核，改动以独立候选策略隔离。
4. 技术转换器要记录来源、映射参数、变换前后 PNG SHA、有效像素取样范围；不能隐式缩放、镜像、旋转、模糊、抹边或使用空白占位。

**理想结果：**用户只修一张；AI 负责造出受样品约束的完整美术素材；Codex/工坊负责那些严格像素排列、掩码编码、校验和导出。这个分工与工坊“面向 Chat/Agent 的离线 ZIP”定位一致。

### 5.3 新的平面石砖模板不要误用“石质崖边”

用户当前单张图视觉上是**俯视石砖铺地**。当前 0.4.1 有 `XH-GRASS-8COND-01` 与 `XH-STONE-EDGE-8COND-01`，后者契约允许朝屏幕下方的前立面暗块。**不能让一张平面石砖强制适配有厚度的石质边界。**

推荐增加一个局部、原创、候选模板 `XH-STONE-FLOOR-8COND-01`（名称按现有注册表实际核对后确认）：

- 平面石砖、**严格正交俯视**，不允许崖边前立面；
- 逻辑上仍可采用现有条件八邻拓扑；但中心纹理连续与开放边形态的意义需在真实回拼中证明；
- 只抽取现有可复用的邻接/蒙版/拼接底座，不能借扩展新模板破坏石质高差边界的真实越格规则；
- 也明确区分“无须智能联通的随机平铺地面”：若此素材实际上更适合随机平铺，工坊可以告知用户，但在**用户选了联通目标**时不得自行替换其任务。

这是**本计划中的工程建议**，不是已经获批的第三套永久游戏美术规则。应以本轮一张石砖的真实试产结果决定是否长期保留。

### 5.4 风格生成原则：视觉主次比复制样品更重要

正式任务包必须对 AI 明确：

> 这张人工定稿图是本次素材唯一主要绘画语言来源：沿用其成熟二次元手绘的黑色结构线、接触暗块、大中小形体取舍与低密度破损；保留材质辨识但停止暗部精修。不要按相似性复制每块石砖的具体形状，更不要在边缘平均描高亮硬边。新构件必须先服从固定俯视和图块联通规则，再做同一风格的变化。图像尺寸、Alpha、Pivot、切割窗和拓扑以结构模板为权威，而不是以这张参考图的原始画布为权威。

采用 `off/standard/extreme` 当前已实现的规则。**极端模式仍是可选**；不用把项目所有场景永久限制为两种 RGB 色，也不取消石材已有 L0/L1/L2。

### 5.5 技术适配器能力等级（不能伪称所有 Chat 一样强）

| 执行者能力 | 允许完成的真实工作 | 不允许宣称 |
| --- | --- | --- |
| 纯文字 Chat | 读取规范、分析样品、输出制作指令与可行方案 | 已绘图、已生产正式文件 |
| 有生图能力的 Chat | 根据样品与模板制作绘画原稿/连续概念母图并返回真正 PNG | 自动成功产生合法数值 contour、精确切图与 Unity 正式可用 |
| 有图像与文件/代码能力的 Codex/Agent | 在合法工具能力下审阅样品、制作/整理图像、调用确定性转换和编译校验，交付受检 PNG | 图像质量自动通过人工审美、可以绕过人类批准 |

任务包应写清“能做多少做多少、欠缺能力时停在真实阶段并交代缺口”，不能让执行者仅靠模型自述就视为通过。

### M3｜单样品检查、批准和版本身份

- 允许直接手修图 `Ctrl+V / 打开PNG` 作为第一个版本，或者从已有四形态任务中将其中一张选择为“本次单样品视觉基准”（需要记录转换来源，绝不偷偷裁图）。
- 用户在准确文件、规格、版本、SHA 可见的确认窗口一键批准；无初始 AI 原图亦可。
- 换图、换目标、改硬格式、撤销、异机工程等事件让旧正式结果按现有策略陈旧；保留原始 PNG/历史记录。

**交付：**单图版审批状态与可复核负例；历史 v7 Gate 原样。

### M4｜新一代「批准样品 → 扩展联通」任务 ZIP

- 以权威 spec 生成新的单样品正式生产包（需要时使用新 spec/ZIP 显式版本），包中至少包括：
  1. `input/approved-sample.png`：用户准确批准 PNG 原始字节；
  2. `input/approval.json` 与 `input/sample-role.json`：单图审批与艺术权威声明；
  3. `asset-grammar/grammar.json` 与合法状态映射/测试场景；
  4. `guides/`：真实画布格式、固定视角、编排/切割图；
  5. `style/`：项目已批准的风格快照和可选压制；
  6. `prompts/`：外部 AI 的分析、正式绘制、技术编码/拼接步骤与禁止项；
  7. `manifest.json`：实际 SHA/长度、可核验的唯一权威路径。
- 明确“**直接按这张图的绘画方法扩展**”，不将单图当作已有 47态切片；不强制再次上传为风格参考。
- 包内返回协议能区分视觉成果与技术成果，允许继续在下一轮/另一个执行者补技术转换，而不伪称已完成。

**交付：**一个可供独立 Codex 不看聊天就理解的全新样例 ZIP；独立验包/篡改负例。

### M5｜AI 执行计划与绘制母版可行性验证（本轮最重要的研究性工程）

- 根据当前用户单样品与模板，输出最短必要的**有序执行步骤**：理解样品 → 绘制连续区域和边角关系 → 准备真正可编译图源 → 编译/诊断 → 返工。
- 先只验证一套**平面石砖**、一套**草地**的候选；利用原创样品，在 AI/Agent 的真实可用能力下至少做一次“单图扩展到多种边角”的实测；不能用已有 synthetic 夹具替代真实画风验证。
- 不预设“AI 肯定能准确绘制双层编码 PNG”，把失败具体记录为：结构错、画风走样、画布错、通道错、共享相位错、边角破损、重复明显等。
- 如果外部模型只能返回概念母图，让带工具的 Agent 将其转换成精确素材图，保留转换及缺口，不硬塞进编译器。

**交付：**`single-to-connected-feasibility.md`（成功/失败、产出截图、切割/编码真实证据、人工待验），不得宣称自动“零手修”。

### M6｜最小技术转换器与现有编译器接合

- **原则：**先沿用已经验证的 `grammar/art-directed.cjs`、`art-directed-validate.cjs`、`workflow/output.cjs`，如有必要建立独立 adapter，不改坏旧 canonical 输出。
- 将模型能够可靠绘制的艺术层与程序负责的技术图层区分，必要的 `contour.png` 由有来源/参数/版本的受限适配器生成；保留原图和结果双哈希。
- 数值控制转换要真正验证 R/G/B/A、共享边、拓扑、合法状态；材料必须来自实际绘画内容而非占位色块。无法保留艺术轮廓时只标技术可行，留候选改进项，**不在本轮悄悄把用户修出的手绘外缘变成统一数学外缘**。
- 禁止用无依据的自动平滑、复制中心、模糊补缝掩盖不连续。可选择性支持用户主动重试艺术源，不自动丢失已合格层。

**交付：**从一张原创单样品与真实生成艺术源制作的 47 canonical/188 variants；完整源追溯和失败保护。

### M7｜正式图回传、直观诊断和重试

- 工作台应直接显示：「当前批准单图」→「本次扩展任务 ZIP」→「返回正式美术图/技术层」→「47态检查」。用户不再需要理解“结构母版”按钮到底收什么。
- 导入返回图时显示其角色、应有尺寸、实测尺寸/Alpha/SHA、缺层和导致失败的具体位置。
- 大小不对不能默默拉伸; 假图、缺图、非法通道或变体身份不对一律拒绝，保留失败原件。
- 真实展示3×3、L/T/U、岛、洞、8×8、16×16，以及经典/新候选的对比（已有能力复用）。
- 提供「沿本次样品继续返工」入口，能携带失败列表、准确源文件和需要修改的区域，不要求重填全文。

**交付：**可实际演示的 GUI，能从问题格点追溯到具体图源/掩码/材料贴片与批准样品。

### M8｜面向真实用户当前案例的验收演练

**用户故事 U1：**用户有一张手修完的平面石砖 PNG（原始尺寸可不同于目标格边），没有最初 AI 生图记录。希望按条件八邻模板扩展成合格联通图；只做一次粘贴/导入，并明确批准样品。工坊生成一包给 Chat/Agent。用户不画完整母版。

**最低完整证据链：**

```text
一个真实 PNG 文件 → 本机入库 SHA → 单图形式/用途检查 → 明确批准
→ 新版正式制作 ZIP（包含完全相同的 PNG 字节） → 外部执行者理解说明
→ 真实绘画图源 / 合法技术图源 → 47态/188变体 → 组合图与人工待审
```

- 另用一张草地技术样品跑同一入口，确认没有把“石砖裂缝”写死为所有材质规则。
- **真实用户手修图**若本地已存在可供 Codex 使用，可以仅在 ignored 工作区做一次用户可操作演练；不能把用户原图复制进 GitHub 或标准技术夹具中。
- 若用户的最终 PNG 实际无 Alpha、带背景或低分辨率，应如实告知，不自动把截图边框当成游戏素材。

**交付：**一页用户可直接照做的操作说明和短屏录/截图（只包含原创夹具或经授权可展示部分）。

### M9｜测试矩阵、回归、性能与历史兼容

按第 7 节验收矩阵定向验证。要求至少：

- 单图起点/剪贴板/文件、无父图、审批/撤销、规格变化、异机恢复、恶意 spec/签名改写、任务 ZIP 验真；
- 新第三种模板和原草地/高差模板各有结构负例；
- 47/188、真实 PNG 重新编译验真、九场景、不透明/透明语义、全边接缝、角与洞、重复警告；

## 7. 可验收的具体条件（35项）

### A. 一张图即可开始（A01–A08）

- **A01**：新空工程在「从一张手修图开始」点击一次导入，即拥有一个可预览/可追溯的真实样品版本，不需要先跑任何 AI。
- **A02**：同一输入支持 PNG 文件、Ctrl+V 位图和已有可授权重用的工坊图片来源；分别核对字节或位图原始解码一致性，不混淆 OS 剪贴板重编码与文件不变。
- **A03**：原图可以不是目标逻辑格尺寸；目标格边默认128、PPU100，解释清楚二者区别。
- **A04**：图只有一个时不会要求四样共享相机、内外角成品或47态已经就绪。
- **A05**：不用人工填任务 ID、标题、引用优先级；用户定稿是唯一主要美术参考。
- **A06**：照片、截图、PNG 中真实图像与预览灰色背景不会被误认成已验证透明边界。
- **A07**：用户在旧经典页面误入时，可以看见明确转向入口，取消转向不丢当前工作。
- **A08**：无父版本的手工定稿能被批准；旧 manual-with-parent 版本仍正确记录亲缘。

### B. 模板/审批/协议（B01–B08）

- **B01**：平面石砖俯视与石质高差墙体为两个明确的模板语义，不能偷换。
- **B02**：输入 PNG 主体/材质/视角不合格时可拒绝并说明，不强迫勾选虚假的四样合格项。
- **B03**：批准绑定真实样品 ID、revision、SHA、规格及目标模板；替换图像导致旧批准失效。
- **B04**：压制 `off/standard/extreme` 继续可选，单样品使用时不强迫重复走 AI 收口。
- **B05**：更改目标联通类型、PPU、格尺寸、固定视角等硬规格会使正式任务/结果陈旧，不自动信任。
- **B06**：新 ZIP 直接携带原始获批 PNG，独立解析与返回文件身份准确；不需要另传一份同图“风格参考”。
- **B07**：旧 v1–v7 ZIP 原件与协议语义保持不变，旧工程不会被新版本自动授予批准。
- **B08**：篡改 spec/模板/截图路径/PNG 内容或重签 manifest 不能绕过权威规范及批准校验。

### C. 真实资产生产（C01–C09）

- **C01**：外部 Agent 不看聊天、只看 ZIP 就能说明这一张 PNG 是定稿基准，不是母版，知道应生产47态。
- **C02**：执行说明包含连续绘制思路/边角定位/材料来源与禁止的“逐格散画”，不只是“照参考风格出图”。
- **C03**：用户不必自己画完整母版或数值 contour；缺乏技术工具的 Chat 必须明确报告未完成的技术环节。
- **C04**：材料与数值图层分别校验，实际 PNG 来源与转换日志能追溯到获批样品及外部艺术原稿。
- **C05**：有效输入编译出47 canonical 和188实际变体；缺态、伪图、非法通道或相位都触发明确硬失败。
- **C06**：至少 3×3 邻居、L/T/U、孔洞、8×8/16×16 回拼图可视化，并能从问题格定位到源文件。
- **C07**：真实像素共享边和内外角接缝诊断仍执行；接缝通过不代表材质图案不重复。
- **C08**：用户手修图中的黑缝/大色块语言能在正式组合里明显被继承；程序不把它替换成与样品无关的数学边框而仍宣称“美术达标”。此项是**人工美术观察**，不能由测试伪造。
- **C09**：平面石砖不出现原契约禁止的自由斜透视/前崖立面；复杂石墙 Sorting 未在 Unity 验证时保持待验。

### D. 操作、保护、交付（D01–D10）

- **D01**：实际 Electron 窗口可完成一张图起步的全部用户操作，保存/重开工程后恢复，旧图不丢。
- **D02**：主界面在正确阶段只显示当前可执行按钮，技术术语可在高级区查看；不能强迫用户猜“母版返回图”的意思。
- **D03**：返回错误时明确告知是素材图、编码图、尺寸还是视觉问题，不允许虚假通过。
- **D04**：导出 ZIP 和结果为新文件，同名不覆盖；取消后仍可继续。
- **D05**：模拟测试批准始终标注 synthetic/test-only，不能代替用户亲自认可真实美术。
- **D06**：真实一张用户认可石砖的手修分钟数由用户后续试产记录，Codex 不编造“1–2分钟手修”。
- **D07**：旧工坊普通素材任务、经典联通及旧四形态入口保持可用。
- **D08**：所有需保护的正式风格规范/原稿/游戏源码和历史 ZIP 与接手版本相符。
- **D09**：GitHub 只包含白名单源码、原创示例与记录；用户 PNG、原作图、私有工程、密钥和真实 AI 试产不上传。
- **D10**：完整收尾必须同时报告**技术通过、美术待验、Unity待验**三个独立结论。

## 8. 优先级、验收闸门和开发成本控制

### 第一闸门（M0–M4）：交互与协议必须先有效

先证明**真的只需一张 PNG**，而且不再被四样检查卡住。这里通常比重造编译器更快，属于本轮最确定、最直接的改进。完成后即可向用户展示一次真实操作流程；不要还没走通入口就先搞多类别大架构。

### 第二闸门（M5–M6）：真实艺术源转换能否扩展成完整联通

这里是**全任务最大技术风险**。先在草地/石砖各做小规模试产，结果可能分为：

- `technical-and-art-candidate`：拓扑/像素校验通过，成图有可审阅的绘画扩展。
- `technical-only`：47态能编译，但纹理重复或外缘机械，仍需研究艺术表达。
- `artist-input-needed`：AI 原稿仅足够作为视觉概念，需要 Agent 进行明确技术加工；不让用户绘47张。
- `blocked`：图像/文件工具不足或现有格式无法表达；说明具体缺口，不造假图过关。

不要把一项真实困难静默变成“让用户自己制作结构母版”；如果无法完全自动，应交付可观察、可继续的半成品以及下一个**最小**需要自动化的操作。

### 第三闸门（M7–M10）：可视化验收与安全发布

不要只展示 JSON 写着 passed。必须打开真实 PNG 回拼图、局部边/角、连续大地图和对照，并保证用户能够指出某个失败位置返回对应源。技术确认后按授权发布，但**用户没有认定美术通过，就保持 `pending-human-review`**。

### 开发投入建议

优先做入口/协议、小规模真实编译和一份单样品任务包，避免立刻做所有素材家族的通用扩展器。若 `art-directed` 的两张技术图不支持保留想要的黑线形体，允许追加一个**隔离的艺术层转换候选**，但需要以可复现的实际错误驱动，不可大重写。

## 12. 本计划的最终判断

**这轮最有价值的不是再开发一条更长的提示词，也不是再画一张完美参考图。**

真正的成果是：你已经把**“我批准这一张手修 PNG”**变成了工坊可信、可继承的输入契约；工坊和外部 AI 在明确分工下把它扩展成**真正能联通**的正式素材，用户只需审美确认与必要的少量终修。

单张样品不能数学上唯一推导全部邻接状态，所以**严格联通必须来自结构模板，绘画语言必须来自这一张人工定稿**。这两者结合，才是《星骸回廊》想要的特化 2D 美术生产线。
