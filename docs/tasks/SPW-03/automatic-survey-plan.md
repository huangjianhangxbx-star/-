# SPW-03 0.3.2 自动骨架调查实施计划

用户纠正：需要先人工填方向入口、身体/脚底锚点、共享骨与尺寸链违背“程序采样—AI标定—回到工坊”目的。本轮修正默认产品流程，不以解释表单代替修复。

## 默认流程与边界

载入两端工程、选动作即可导出全骨架调查。调查保留全部方向/槽位/控制关系与动作采样，只提出局部候选，不把全局root当已确认身体中心，不猜相机视角。AI使用完整调查决定方向和身体参考，回传经实际工程身份及新选范围严格验证后显示映射候选；人工表单降为可选高级覆盖。依旧使用本机文件交换，不增加云端key或把本地规则描述成已经自动识别所有人体语义。

## 模块与次序

1. `rig-discovery.ts` 与测试：无用户selection的层级、槽位/加权附件、几何、运动与约束调查；保留多方向候选及root独立画片，程序不盲选第一个方向。
2. `ai-bundle/ai-contracts/ai-proposal/ai-session/spine-config` 与测试：automatic-survey manifest、discovery.json与新任务书；AI可从全调查选择真实参考，先严格验证原身份与数据字段，再重建精确分支并复用现行严格映射验证。保存原survey ID追溯。旧selected包和0.3.0/0.3.1配置兼容。
3. 桌面文件边界允许固定discovery.json、可选读取同目录manifest.json；UI首次直接生成，不再跳转人工填写；显示本地调查摘要，高级覆盖收起。调查阶段不改变现有映射或分支预览。
4. Electron真实用户路径先复现“零表单无法导出”，修复后验证零参考字段操作导出、导入AI确定参考、身体映射预览及配置重开。以rozeul→FREYCIA与截图rhiny→rozeul两对真实输入调查回传，未确定骨链保留未解决说明。
5. 类型/既有及新协议测试、构建、最终便携包复测，原生导入仍由用户最后确认。更新使用说明/日志，选择性同步GitHub。母版、游戏规则与Gitee不改。

接受标准：默认操作不要求用户填写任何参考骨名或打开高级表单；完整调查保留其他方向供AI判断；错误身份/骨名/共享骨扩权/跨方向映射仍拒绝；AI参考与候选只经数据校验应用，不执行返回代码；实际复制与需校准、未解决分开报告。
