## 1. 本轮要交付的玩家体验

玩家能在副本外查看金币与生命力库存、兑换并选择携入量；可以零生命力进入。进入后，真实击杀收益进入随身生命力，培养、召影与主动抽牌竞争这一余额。抽牌每次只追加一张，已有手牌保留；不需要的手牌可以变卖。节点失败、回到副本地图、安全撤离、完成副本和整个副本失败，产生不同且可解释的资源结果。

最终验收必须至少覆盖：

`局外库存 → 兑换/携入 → 实际战斗获利 → 培养/召影/抽牌 → 变卖 → 节点过渡 → 合法带出或失败损失 → 再次进入`

**零携入需要能靠基础本体取得首次击杀，不要求由此证明所有关卡都必须零投入通关。**

本轮结束应能在正常界面完成上述操作，而不是只在控制台改字段。也不能只改余额名称、只做免费升级或只增加一个变卖按钮，就宣布模块完成。

### R5-B2：手牌来源、满手与寿命

这组是卡牌系统操作，不是新技能能力设计。

- **旧自动抽牌：**建议停用 UI、命令和 tick 自动消费路径，明确按主动请求抽牌；单次按下只提交一次，不利用按键重复或 pointerup/click 重复扣款。是否额外增加短防连点间隔单独确认，不默认新增长 CD。
- **初始手牌：**建议不再免费赠四张背包牌。临场牌与专属牌按明确来源发放；已有临场疾行可保留为测试来源，但须确认发放周期与售价。
- **非付费来牌遇满手：**原文只锁定“满手禁止付费抽牌”。建议本轮统一容量，满手拒绝该次被动入手并提示，不顶掉旧牌、不自动兑换；这次事件是否保留补领资格须确认，不能由代码默认决定。
- **重试发牌：**建议同副本内同一节点的首次赠牌、同一奖励事件不因重入重复产生可卖资源。不能只去重金币/生命力，却保留重入赠牌再卖的循环。
- **手牌跨界：**建议背包手牌在同副本节点间/重试保留；临场牌按所属节点结束清理；绑定复制体的专属牌仍随该实例销毁清理；其他专属牌依来源规则。整个副本结束清空剩余临时手牌，不自动折价入库。此建议必须确认，原文没有给出所有类别的完整寿命。
- **旧牌能力：**建议继续以现有已批准效果作测试牌池，只增加模板身份、来源、售价、发放周期；不讨论新的治疗/位移/冷却能力规则。旧牌保留不等于未来牌池定稿。

开工前形成一张小型“牌模板—来源—初始/事件发放—容量策略—售价—清理时点”表；不需要先做永久牌库编辑器。变卖不得删除模板或玩家的牌库配置。

### R5-B3：让本轮经济能够走完的最小结算场景

现有节点地图不是完整的副本撤离系统，不能把“返回节点地图”直接当作安全结算。[S6]

建议利用现有节点做一个最小、正常可操作的测试闭环：

- 保留节点 1 → 休息节点 2 → 节点 3 的既有内容；节点 3 获胜作为本测试副本完成条件。
- 节点 1 通关后，在副本地图开放一个明确的“测试撤离节点”；只能在副本地图且满足该条件时确认安全撤离。不是战斗中随时撤离，也不是水晶安全点功能。
- 单纯从战斗结果返回地图不入库；进入上述撤离节点确认或完成测试副本，才结算剩余资源。
- 放弃整个副本按失败处理；提示随身两种资源会损失。确认提交之后不能用“开始新局”绕过损失。
- 不趁本轮重定水晶重试 0/1 语义。建议明确保留当前“剩余重置机会”的过渡解释：失败前大于 0，扣 1 并允许再试；失败前已为 0，整个副本失败。该解释仍须获得本轮过渡确认，不把旧实现写成 v0.2 定案。

这只是本轮建议的验证副本/入口。用户可选择其他同样受约束的完成/撤离条件，但本轮不能只剩一个开发按钮、没有正常成功结算流程。

探索暂不新建真正出口：资源组件接收节点进入、离开、入战/脱战等事件并接受测试；第七轮负责把真实探索条件接入。测试事件不能改变正式安全撤离资格。

### R5-B4：存储寿命与操作状态

- 建议本轮局外库存、默认倍率、解锁和偏好在**当前页面运行会话**内跨副本保留；不新增刷新恢复、存档升级和断线惩罚。界面明确提示本轮不保证刷新保存，不能宣称已经完成持久存档。
- “首次账户初始化”与“开始新副本”必须分开。后者保留局外账本；重新生成关卡不得覆盖库存或重送测试资金。
- 建议副本外仅兑换/准备携入；副本内才允许用随身生命力培养和抽牌。节点 briefing 是已经入副本的准备，不与局外账户页混为同一状态。
- 建议正常抽牌/变卖允许在局内节点准备和战斗时进行；是否也开放副本地图交易一并确认，不能仅因 `phase !== battle` 就误认为副本外。
- 建议手牌拖拽变卖沿用临时 0.1×，清持续移动；暂停/模态/隐藏仍优先，取消后恢复玩家设置的 1×/2×，不恢复固定 1×。失焦、目标卡被其他事件清掉时取消未提交拖拽，不产生交易。

## 6. 工程建议：明确数据寿命与交易责任

以下是实现方案，不新增玩法制度；最终命名允许执行者结合代码调整。

### 6.1 四个余额、三个不同周期

- 局外账户：金币、生命力库存，不被 `newExpedition` 的 fresh state 覆盖。
- 当前副本：携入及途中得到的随身金币、随身生命力，带独立副本身份与结算状态。
- 计价周期：塔防 battle attempt 或探索 node visit，不用“当前是否在战斗”作为所有重置条件。

卡牌至少区分稳定模板身份和手牌实例身份；奖励区分地图预设实例与运行时单位实例。可以沿用当前基础类型，不要求搭建通用经济框架、数据库或事件总线。

### 6.2 必须共享最终校验

建议提供小而明确的查询/命令边界：兑换、携入、领取奖励、生命力支付、抽牌、变卖、最终结算。培养和召影保留各自资格校验，再调用同一支付方法。

每次命令先完成资格/余额/容量/报价版本校验，再整体提交。失败可以记录原因，但不能改变余额、价格次数、手牌成员、技能等级、复制体数量或奖励领取记录。

预览不改变随机种子。抽牌只有成功才推进抽取随机状态及价格计数；售出只按卡实例成交一次；同一次携入和最终结算不能重复提交。

UI 不手动加钱或销毁手牌来模拟命令成功；动画不是资金到账的时点，也不能因隐藏页面未播完动画而丢失收益。

### 6.3 奖励去重为何纳入本轮

原先把预设敌人奖励去重列在后续节点模块；本稿建议**只把真实入账所依赖的这条规则前置接通**，否则第五轮会在一个可以反复刷同批敌人的经济中验收。

沿用当前地图/刷怪调度，为预设实例配置稳定奖励键，如“副本身份 + 节点定义 + 刷怪组定义 + 组内序号”。不要使用 `nextId`、生成顺序混合计数或同种敌人的名字。第六轮引入波内批次时再接其稳定定义，不在第五轮重写波次系统。[S1 §8][S6][S9]

已领取实例被重试杀死，仍有正常死亡与战斗计数，只是不再发同一奖励。不能为了收益去重而停止痛印、普攻蓄能等战斗机制。可变卖的事件卡奖励也要按获准来源周期处理，避免间接重复领钱。

### 6.4 结算必须只有一个结果

节点失败且可留在副本，不做最终清算。整个副本成功或失败时先确定唯一结果，再更新局外/随身账本并标记已结算，随后进行关卡/培养/复制体清理。

禁止先生成新状态再尝试读取旧余额；禁止连续点击成功结算后又执行失败清算；禁止把所有 `endExpedition` 开发调用默认视作安全撤离。调试重置与正常“新副本”分开，不能进入正常奖励路径。

## 7. 执行顺序：完成同一模块，再进入后续模块

### R5-00：范围确认与真实基线

收束 R5-B1—B4，形成参数表、来源寿命表和最小结算条件。复核当前 main、本地未提交差异、最新授权和实际 Skill。第四轮授权不延伸到本轮。

获准实施后运行当前逻辑、构建与浏览器基线；保存退出码、环境和原始日志。将 T-010 角落停滞与任何新增失败分开。先记录历史测试会写哪些证据文件，防止覆盖前轮证据或用户工作。

完成条件：正常与测试入口边界清楚，关键缺口已确认，基线事实可追溯。

### R5-01：账户、携入与副本账本

拆分账户/随身余额与生命周期；先接正常局外页面、兑换和携入。取消入场自动赠款；保留基础角色可部署/作战。新副本保留账户和长期资料，开局配置不冒充副本外付款。

先覆盖非有限/负数/越库存、预览取消、重复携入、零携入和连续两次副本的测试。

完成条件：能正常进入一次零携入和一次非零携入，账本守恒，没有每局免费补款。

### R5-02：收益、培养与召影支付

为当前预设敌人接稳定奖励键和单次领取；击杀、非击杀离场与重复击杀分开。培养和召影改为随身生命力支付，保留技能购买等级、分支名额和复制体预览/提交的一致性。

完成条件：金币很多但生命力不足时三类生命力消费不能代付；实际击杀后可以立即消费；同副本重试不给同实例再次收益。

### R5-03：单张抽牌与计价周期

按确认表改为每次一张、三类来源与容量、动态下一价；接通塔防 attempt/探索 visit 的价格状态。停用获准替换的旧自动抽牌和整组刷新路径。移除旧赠牌循环，保留批准的事件来源。

完成条件：原手牌身份保留；失败不扣费、不涨价、不推进随机状态；探索测试脱战不重置价格。

### R5-04：变卖、手牌寿命与反馈

完成拖拽预览、松手成交、拖回/右键/失焦取消；三类手牌可售，固定售价来自模板。正确处理售出与使用、owner 清理、节点清理的同实例竞争，保留其他牌和永久模板。

同时接通牌数、可用余额、下一次抽价、卖出金额及手牌过多时的可达布局；不等全部逻辑结束才第一次测试拖拽。

完成条件：正常 UI 可以抽一张、保留旧牌、卖一张、重新消费；不能同一张牌既施放又卖钱。

### R5-05：结算、重试与再次出发

接通批准的测试副本完成条件/撤离节点与失败放弃。节点地图不入库；可重试失败保留余额；成功带出保持资源类型；整个副本失败只清随身资产。

再次开始副本必须重新从保留的局外库存选择携入。联动既有培养清空、伤势/耐久保留、节点技能重置与复制体清理，不免费恢复这些系统。

完成条件：正常流程能得到成功与失败两类最终结算，而且无法重复入库或跳过损失。

### R5-06：完整回归与证据

运行全部自动化、浏览器交互与至少两组真实资源流程。检查 1440×900、1000×720、减少动态效果、暂停/观察/默认倍率/Alt、手牌拖拽与其他输入互斥。

完成条件：本轮功能及第一至第四轮关键回归有证据，新增失败有明确处置；不是仅逐个 API 测试通过。

### R5-07：收尾与交接

按本轮有效授权维护任务、状态、受影响规则对账/入口和纯术语；明确采用的参数、旧行为替换及仍未做的第六/七轮内容。提交与推送须另核对授权和实际差异，GitHub/Gitee 分工不变。

所有本轮已批准范围完成后，才进入波次批次、塔防节点等下一模块。可以分提交，不把抽卡或结算留半套便切换主题。
