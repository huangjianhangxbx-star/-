## 0. 一页决策：这次技术路线终于要“换底座”，而不是继续堆提示词

**用户明确的生产目标：**

1. AI 可以先出**一张或少量**适合人工修改的样品。
2. 用户**只手修一张被认可的视觉样品**，不承担切图、画 16/47 种变体、手工拼母版。
3. 工坊把这张定稿图作为**唯一主要画法依据**，生成面向 AI / Agent 的具体绘制任务。
4. 对于基础地形的自动联通，使用**Dual Grid（双网格）**这一明确的技术模型和**16 种四角状态**，不再让 AI 自由想象“怎样联通”。
5. 正式出图后，程序给出**准确的双网格运行预览、16 态图集、切割编号、接缝/重复诊断和 Unity 接入资料**。
6. 工坊本身保持离线，不接 AI API、不依赖 LoRA；已存在的 `off / standard / extreme` 任务级风格约束继续可选。

**对之前工作的客观纠偏：**

| 当前 0.5.0 研究事实 | 为什么还未解决用户痛点 | 本次改变 |
|---|---|---|
| 单张样品→v8正式制作包、手工批准已经实现 | 上游基本正确 | **直接复用**，不另造一套样品数据库 |
| 当前 art-directed 仍围绕条件八邻 **47态/188变体** | 适合部分旧研究，但不应作为所有基础地形的唯一语法 | 地形新增**独立 dual-grid/16** 路径；旧流程继续可用 |
| 真实 AI 返回 1774×887，后续选取 8 个 64×64 窗口 | 文档记录有效像素只有 **2.08244%**，完整石砖结构及黑缝关系被大幅丢掉 | **禁止“少量窗口成功编译 = 画法成功迁移”**；使用连续绘画母图及像素覆盖报告 |
| 47态结构检查通过，实际石砖竖黑线重复，草地有棋盘格与程序化孔洞边界 | 技术可拼接≠审美合格 | 独立报告 **mask正确 / 像素接缝 / 材质重复 / 用户美术** 四种状态 |
| AI 提示词承担许多拓扑说明 | 文生图会自由诠释边角、角度、相位 | **程序决定拓扑；AI决定画法；用户决定是否认可** |

**重大限定：**Dual Grid **不是**“输入一张 PNG 就能智能补画出全部美术”的生成魔法。它保证选片规则可被定义为 16 种**二值四角组合**，并可让边角几何由程序确定。**如何画得像用户手修石砖、如何避免大片重复**仍要依赖连续绘画母图、艺术轮廓设计和明确视觉验收。计划必须诚实拆开这几个问题。

### 0.1 唯一推荐的主路线

```text

                             ↓
         [新] 本机程序：四角 mask → 16 张精确状态 PNG → 4×4 atlas
                             ↓
         [新] 真正双网格 Data/Render 交互涂画 + 数学/像素/观感检查
```

## 3. 核心数学契约：Dual Grid v1，不允许写成模糊自然语言

### 3.1 明确世界模型

- `DataGrid`：存储**每一逻辑方格的地形类型**，首轮 `A=1` / `B=0`；它是地图编辑的唯一数据权威。
- `RenderGrid`：**相对 DataGrid 在 X、Y 各错开半个单元格**的显示网格；每个显示格与四个相邻逻辑格关联，按四角状态选 Sprite。
- 两个网格的**格边长相等**，不把“错半格”误当成缩小到一半大小。
- PPU 独立于像素尺寸：逻辑边长 `c=128px, PPU=100` 时一个网格世界尺寸 **1.28 单位**，半格偏移 `0.64 单位`，不是默认1世界单位。如果要一个世界单位，必须显式选择 `c=100px, PPU=100` 或其它比例。
- 图片坐标 +Y 向下；Unity XY +Y 向上，**只有适配层**转换，核心算法不混用两套轴。首轮正交俯视平面，不把动画/排序当已经验证。

### 3.2 四角 bit 位（**本项目规范候选，固定为第一版权威**）

```text
一个 RenderCell 覆盖的四个 DataCell（屏幕坐标 y 向下）：

          左        右
      ┌─────────┬─────────┐
  上  │ TL: bit0│ TR: bit1│     TL = 1, TR = 2
      ├─────────┼─────────┤
  下  │ BL: bit2│ BR: bit3│     BL = 4, BR = 8
      └─────────┴─────────┘

mask = TL*1 + TR*2 + BL*4 + BR*8      ∈ [0,15]
```

**索引与几何的显式定义**（首轮全16态，无“先省成6张”的隐形旋转）：

| mask | 占用角（A） | 语义 |
|---:|---|---|
| 0 | 无 | 完全 B |
| 1 | TL | 单独左上角 |
| 2 | TR | 单独右上角 |
| 3 | TL,TR | 顶部横边 |
| 4 | BL | 单独左下角 |
| 5 | TL,BL | 左侧竖边 |
| 6 | TR,BL | 对角分离（棋盘格之一） |
| 7 | TL,TR,BL | 缺右下角的内角 |
| 8 | BR | 单独右下角 |
| 9 | TL,BR | 对角分离（棋盘格之二） |
| 10 | TR,BR | 右侧竖边 |
| 11 | TL,TR,BR | 缺左下角的内角 |
| 12 | BL,BR | 底部横边 |
| 13 | TL,BL,BR | 缺右上角的内角 |
| 14 | TR,BL,BR | 缺左上角的内角 |
| 15 | TL,TR,BL,BR | 完全 A |

**对角规则**：首版 `6` / `9` 为**两片角区，不暗中连成一条斜桥**；允许背景 B 从中间隔开。任何想改成贯通斜线的设计应升为明确配置候选，并更新所有预览与联通测试；不接受模型临场选择连法。

### 3.3 显示格索引、单格编辑的局部更新

统一屏幕 y 向下坐标，令数据格为 `D[x,y]`，以某个数据格交点为 `R[x,y]`。建议显式采用：

```js
TL = D[x-1,y-1]
TR = D[x  ,y-1]
BL = D[x-1,y  ]
BR = D[x  ,y  ]
R[x,y].mask = TL | (TR<<1) | (BL<<2) | (BR<<3)
```

上式 D 已经是0/1。渲染单格的世界几何中心位于四个 DataCell 的交点，渲染图块边界穿过这四个 DataCell 的中心（精确世界偏移符号由坐标原点测试确定）；不许只把渲染图画在数据格原位置。

**编辑 D[x,y] 后，仅需更新四个 RenderCell：**`R[x,y]`、`R[x+1,y]`、`R[x,y+1]`、`R[x+1,y+1]`。还要处理画布边界的外侧背景哨兵；首轮地图 `W×H` 个数据格应有 `(W+1)×(H+1)` 个可见顶点显示格。对空地图、左上角、右下角、擦除、连续拖拽分别实测，防止 off-by-one。

### 3.4 两种不同层次的“正确”

1. **拓扑正确：**16个 mask 对应的四角 A/B 状态全部匹配，边、角、孔和棋盘对角不会错连。
2. **美术连续：**相邻 RenderCell 在边缘上的颜色、黑线、明暗、透明覆盖不突变。Dual Grid **并不自动保证这一点**，必须在美术母版与编译器中另外处理。

任意一层失败，都不能宣布“可用地形”。

## 4. 画师生产方法：不是画16个孤立方块，也不是抽整图2%的像素

### 4.1 **首选**“连续母图 + 程序定拓扑”

工坊给 AI 的任务必须有**明确的两个职责不同的工序**：

**A｜绘制连续表面材料（AI 可发挥，但遵守样品画法）**

- 输入：用户的 **exact SHA** 手修石砖 + `L0/L1` / 适用 `L2` + 固定俯视 + 标准/极端档。
- AI 不去画16张 Tile 的最终轮廓，而是在一张**连续画板**中设计石砖的铺砌、黑色砖缝、主要暗块、有限表面变化。
- 重点保留整砖之间的**相位与砖缝大形**，不能从整幅艺术原稿随意只截八个小窗，更不能为方便技术编译直接压平砖缝或用噪声补全。
- 建议首轮连续 A 母图最小为**4×4逻辑格**（当 c=128，512×512px），必要时支持 K=2/4/8 的有限周期实验；**这只是画板的建议规格，不声称 AI 生图必然遵守真实像素尺寸。**
- B 底层可由工坊使用原创合规底图或 AI 另行生成连续 B 母图；石砖的透明外角必须露出 B，而不是露出棋盘格。

**B｜画边缘的方法（主要由程序约束）**

- 由 Dual Grid 的4角 mask **决定 A/B 接触边缘与拓扑**，不是 AI 猜几何。
- 允许 AI 附带一张有限的**石砖边缘绘画示范**（黑色石缝、接触暗块、边缘的粗细与简化方式）；它是绘画风格/笔触输入，而不是需要美术人员手绘的 16 张精确编码 PNG。
- 编译器使用模板参数生成16态的形状遮罩、基础接触暗线；笔触偏移和非连续性来自**稳定的坐标/参数**，而不是每次渲染随机扰动。
- 支持“几何轮廓”和“画师暗线”的**分离**：不以柔亮边替代黑线，也不强制给每块地砖外沿画黑色整圈。

### 4.2 人工修一张图，编译器不能擅自改它

- 原始已批准 PNG 按原字节留存，绑定 sample ID、revision、SHA、格式与手修说明；无截图背景时不自动抠图，有背景也不认成 Alpha。
- AI 输出原稿与编译输入**分别保留**，不能用计算出的可用图覆盖用户手修版。
- AI 如果返回错误尺寸：保存原件，提示准确尺寸差异；**禁止悄悄缩放、重采样、镜像、旋转、裁边、平滑或重新绘制**来伪装原稿达标。
- 有代码/图像能力的 Agent 可做**确定性的、用户可见的编排**：例如按明确画板窗口裁剪并记录 SHA、占比和坐标；不要求人工自己做此事。
- 对于输入源不能形成完整连续石砖结构的情况，要**停在“绘画素材不足”**，不能把取样比极低的技术通路标成美术成功。

### 4.3 **美术连续性**的工程级约定

首轮建议可并行支持两种策略，但只需先做 A 达标，B 作为证据充分后才扩展：

**策略 A（首轮必须可用）：有限周期连续母图。**

- 将 A / B 分别定义为 K×K（例如4×4逻辑格）的可循环采样母图，并保存真实源图像与周期 K。
- 贴图相位由**世界显示格坐标**决定；相邻显示格不得各自随机选择不相关的采样相位。
- 若原稿最左/最右、最上/最下不能周期对接，程序可生成预览并指出边界不连续，**不得无声明进行模糊或边缘平均修复**。如需生成修复版，保留前后原件与显式同意，且单独列为“处理后图”，绝不替换原稿。
- 若仅导出16张固定 Canonical Sprite，应在文档里声明其只能提供**有限重复图案**，不能同时保证任意大地图的非重复连续石纹。

**策略 B（升级候选）：同坐标相位的变体图库。**

- 用 `(worldX mod K, worldY mod K)` 决定从连续母图读取哪一段，再应用 mask；避免为相邻格随机选不同贴片破坏砖缝。
- 可输出 `16 × K²` 个**有坐标语义**的扩展变体，而不是不受控的“188 random variants”。
- 传统仅支持16张 tile 的 Unity 导入器可能无法自动利用 K² 相位；需使用自定义 renderer / 自定义 Tile 规则，或者单独导出 canonical16 兼容降级版，标记视觉重复风险。
- **不要在 M1 就因追求无穷非重复而开做 Shader/动态纹理大系统。**

### 4.4 怎样从用户的石砖图继承绘画语言

生产任务要把“画法继承”拆成可审阅要素，并让 AI 明确保留它们：

- **黑线/黑块：**真正解释砖缝、接触、断裂与遮挡；不是所有小面都有完整粗黑轮廓。
- **亮边：**严格克制，不沿所有砖块硬边画均匀连续提亮。
- **暗部：**大色块优先，停止细碎渐变刻画；极端档允许每种材料以两组主要明暗为主，不是整图 RGB 只能两色。
- **分块：**优先大中小块关系与真实砖块连续分布，不制造密集小破损/过于规则的独立重复砖。
- **画板结构：**AI 绘制的是连续地面，不是四块不同摄影机角度的景观模型。
- **参考角色：**用户批准原图是唯一主要**画法**权威；程序 mask/坐标是唯一**联通**权威；额外参考仅有明确选择时进入 ZIP，不能悄悄改变形制。

**必须给 AI 的否定条件：**不要把样品直接复制16次，或在样品周围随意生出一圈浅色边框；不要在47张旧图的基础上换编号；不要把整张图片按八个小窗切碎后再宣称掌握了整块石砖画法。

## 5. 16态图的生成契约：保证数学结构，保留尽可能多的手绘结构

### 5.1 必须清楚分层

```text
approved-reference.png     用户定稿原图：视觉依据，永不更改
A-continuous.png           AI 绘制的连续石砖母图（精确像素解析另行验证）
B-continuous.png           底层地面母图（首版可用原创夹具）
edge-style.png [optional]  AI 边缘画法参考，不承担 mask 语义

                  ↓  [纯程序 / 可测试]
corner occupancy TL/TR/BL/BR → A-region mask / B-region mask
                             → 交界线/墨线（稳定局部笔触参数）
                             → 全地形颜色/透明语义
                             → 16张主Sprite（mask 0..15）
                             → 4×4 atlas + map.json + preview cases
```

**特别注意：**图层名称是本计划提出的**新接口建议**，不是现行工坊已有文件。Codex 需实现 `dual-grid/` 隔离模块，不把它伪装成 v8 已内置能力。

### 5.2 mask 轮廓的确定性算法（先用简单实现证明正确）

- 以四个 DataCell 的占用值构造显示格的四角约束，保证输出局部四角 A/B 分类**精确一致**。
- 首版可用几何插值、离散像素 SDF/几何边界模型中的一种**有文档、有测试**的实现。不要为追求手绘感先写一个很复杂的随机轮廓系统。
- **相邻 RenderCell 共边**的 A/B 类型边界和所有线条采用同一确定性函数、同一世界坐标相位或同一边缘签名；不能一个边随机凸出去，另一块随机凹进去。
- 黑线可以不连续、粗细可变，但允许中断的位置必须遵循用户画风、不会造成**视觉上的断缝或露底硬缝**。结构缝和高光边区分。
- 对角 `6/9` 不误桥接；0、15 不出现多余环形轮廓；边缘中点/角点严格吻合邻居。
- **是否更换边缘画法，不应改变 A/B 拓扑**。程序依据 mask 产生数学边界；AI 参与艺术边缘风格，但不让AI替代位掩码权威。

### 5.3 atlas 布局与外部适配

**工坊内部第一版统一 atlas：**4列×4行，行主序 `mask = row*4 + col`，独立文件名 `mask-00.png` … `mask-15.png`；同时提供元数据：

```json
{
  "schemaVersion": "xh-dual-grid/1",
  "coordinateSystem": "screen-x-right-y-down",
  "renderGridOffsetInDataCells": [0.5, 0.5],
  "cornerBits": {"TL": 1, "TR": 2, "BL": 4, "BR": 8},
  "atlas": {"columns": 4, "rows": 4, "order": "row-major-mask-0-to-15"},
  "cellPixels": 128,
  "ppu": 100,
  "terrainA": "stone-floor",
  "terrainB": "background-test",
  "diagonalPolicy": "separate-islands",
  "unityIntegrationStatus": "unverified"
}
```

以上仅**示意字段**，真实权威需有完整合法性校验、样品批准 SHA、源 A/B SHA、mask 到 atlasRect、Pivot/Alpha、边缘参数/处理声明和编译器版本。不要复制示意值当成实际读到的项目配置。

**Unity 适配注意：**skner 的自动 Rule Tile 生成对切片顺序与 Sprite 命名有特定约束。Codex 需读其准确仓库版本并编写 `skner-import-map.json`（或转换出的兼容 atlas），**不能假定它读取的 `_0.._15` 正好等于本规范的 mask 值**。需16态逐一通过截图/规则测试才可宣称 skner 适配成功。

### 5.4 透明与下层合成

- mask0 显示完整 B（或明确允许 B 由底层 renderer 负责），mask15 显示完整 A，其余 mask 是 A/B 合成，不允许意外露出棋盘底。
- 如选择“ A PNG 带 Alpha 覆盖 B”的实现，输出应分别声明 `tileColor`/`tileAlpha` 和 B underlay 的显示顺序；透明像素表现下方地面，不等于接缝。
- 像素检查要在**透明正确合成后**进行，不能只比对透明前景中的 RGB 作为最终观感。
- 首轮地面不需要任何顶部凸出的立面或高差墙阴影。不要把旧 `stone-front` 的前立面混入石砖顶面。

## 6. 工坊 UI：新增独立“双网格地形”入口，保留已有样品批准能力

### 6.1 入口位置（建议，不重做所有 UI）

在“样品到正式联通”内、用户已有一个**准确批准版本**后，增加：

> **正式生产方式：**`双网格地形（16态，推荐平面地面）` / `条件八邻（47态，旧方案）`

若用户直接从普通任务选择地形，可提供快捷入口“**双网格地形生产**”，但后台还是调用已有单样品档案与审批接口，不存第二份批准身份。

**首轮界面只需：**地形 A、底层 B、逻辑格 px、PPU（默认100）、画法压制（沿用标准/极端等）、查看16态模板、导出绘画任务、导入连续母图、编译、涂画预览、返工报告。

隐藏 mask 编码、数学解释、atlas 格子行列、版本哈希等专家选项；**并不取消其实际硬约束**。用户无需每次填写冗余 ID 或标题。

### 6.2 “画师母版页”是美术工序，不是编码表

显示至少三种不同图：

1. **绘画原稿说明（AI看的）：**连续铺装地面示意、石砖结构跨区域的意思，画板方向与预期取样覆盖；不同色块不是16态。
2. **程序生成的16态编号模板（检查用）：**只显示 mask/角状态/边缘，不要求 AI 在上面画16张独立图。
3. **实际拼接地图（最终验收）：**用户涂逻辑网格时 RenderGrid 自动更新，每一处可点击追踪对应 mask、源贴片坐标、具体样品及原件 SHA。

不能让同一张看起来漂亮的四格样品，既当“已批准画法”又当“已验证的真正16态成品”。

### 6.3 错图直接返工，不让用户做无意义操作

当 AI 返回以下问题时，提供一键诊断：

- 不符合母图画布/精确像素尺寸：记录原始尺寸，返回**准确目标尺寸与差距**，绝不静默缩放。
- 不是连续石砖、黑色砖缝被分成8个独立小图：可视化标注缺口/断裂源区域。
- 联通正确但大面积纹理重复：截图对比与位置列表，报告是“艺术重复”而不是拓扑错误。
- 边缘线处理过头或高光连续：作为**人工视觉偏差**加入同一准确批准样品的返工包，不篡改形式 mask。

返回 AI 的诊断 ZIP 必须继续带**原批准图及当前源图（两个身份/用途分开）**、具体问题坐标、期望修复操作、原文件 SHA，不要求用户重新维护所有参考图片。

### 6.4 离线涂画预览（不靠 Unity 才能看）

- 画布展示 DataGrid 可编辑格子和真实 RenderGrid 图像的叠加；可以开关网格帮助理解错半格。
- 左键涂 A、右键/橡皮涂 B；按下拖拽连续更新；有明确“重置、填充、单格、画线、矩形、撤回/重做（至少一步）”操作。首版按钮不必铺满。
- 点击任何显示格可看到 `DataGrid TL/TR/BL/BR`、mask 0–15、贴图、精确像素源/相位、逻辑格/显示格位置。
- 至少有 3×3、8×8、16×16 与**任意涂画**场景；输入不可直接写到 RenderGrid 数据上绕过算法。
- 导出的 PNG 必须是**现行真实 RenderGrid**渲染结果；不得让 demo 绘制一套与编译图不同的漂亮假预览。

## 7. 分阶段执行单（M0–M10）

> **推进原则：**每个阶段先建立“小而真实”的证据，按依赖顺序继续；技术细节无需用户逐项表决。但若实际样品不可获得、不同许可影响目标、原型确实不能处理用户想要的砖缝连续性，则**暂停受影响阶段、报告并提出唯一推荐收敛方案**。用户最终视觉批准不可由 synthetic 测试替代。

### M0｜接手、基线与技术路线选型（P0）

**工作：**

- 读取 §1 指定资料，核对版本/适用 AGENTS、真实 Codex Skill、Git HEAD 与未提交文件（尤其另一个游戏任务的并行工作）。
- 复核 skner 与 Jess Hammer **确定版本**的 README、mask/偏移算法、协议、依赖和许可证；测试性运行其**最小示例**（如果构建环境存在且代价合理），记录截图、16状态位顺序及差异。
- 建立新任务记录 `docs/tasks/2DW-DUALGRID-01/`（若现有任务编号或目录已有，核实后不可覆盖）；确认源工坊0.5.0、v8文件/批准接口和原有47态编译器文件 SHA。

**产物：** `intake.md`、`tech-decision.md`（明确为何先做独立 JS/CJS DualGrid，Unity 包仅作为接入候选）、`compat-baseline.json`。  
**退出条件：**核心调用点与兼容边界明确；没有把开源 demo 未验证部分当作项目既成事实。

### M1｜纯程序 16 态 + 空白几何金样（P0）

**工作：**

- 在 `自制工具/asset_workshop_2d/dual-grid/` 下新增**独立**纯算法模块，例如 `corner-mask.cjs`、`data-grid.cjs`、`render-grid.cjs`。
- 精确完成 §3 坐标、mask、16态、边界与局部更新；生成**非美术**黑白/双色样图，仅用于测试数学。
- 实测 `D(1格)→R(4格)`、`D(2×2)→R(3×3)`、空/满/孤岛/直线/十字/环/孔/棋盘6、9/擦除回退/边界涂画。
- 明确 16 状态查表、单元 tests、完全确定性的 mask→map 结果，禁止通过读取原有 47态输出代替新算法。

**产物：** `dual-grid/16-state-table.json`、16个自绘几何 PNG、纯算法单测、示例地图 JSON。  
**退出条件：**16/16状态标注正确，单格编辑只更新对应4个 RenderCell，边界无越界或方向倒置。

### M2｜真实双网格交互铺设器（P0）

**工作：**

- 使用 M1 的同一权威 Data/Render 算法，新增最小 UI 画板；用户直接涂**逻辑地形**，系统瞬间选择显示 mask。
- 支持直观查看16态+atlas与实时场景（不使用提前绘好的静态示意图替代运行结果）。
- 确保新 UI 是现有 Electron 内嵌模块，无网络依赖、不增外部模型。

**产物：**可录屏的双网格画布、场景导出截图、坐标/四角/位索引追踪。  
**退出条件：**开发者绘制一个实心矩形并逐格擦除，四角与边界马上随之改变；表现符合 Jess/skner 同类测试场景的数学位置关系。

### M3｜单样品身份复用与绘画任务 ZIP（P0/P1）

**工作：**

- **复用** v8 的 `approved sample` / revision / SHA / 精确人工审批。新流程需要绑定同一批准原图，不能复制用户输入另建“近似已批准”的引用。
- 新增 `dual-grid-art-task` 阶段数据规范：A/B 素材、连续画板尺寸建议/边缘语言、mask规范、相位说明、真实样品原图、风格档、期待回件、技术与人工分工。
- 工坊输出给 AI 的文字明确：“画连续石砖，不画16个独立图块，不绘制 mask/数值图；若无代码能力，只返回真实艺术原稿。”
- 建议独立 `2dw-zip/9` 或其它**显式新版本**，由 Codex 经兼容测试落实。所有权威镜像、文件哈希和签名/身份绑定要保留旧安全模型，不让说明文本成为第二份矛盾的硬规格。

**产物：** `approved-reference.png`、`drawing-contract.md`、`dual-grid-spec.json`、`guides/continuous-master.png`、`guides/dualgrid-16-map.png`、`prompts/agent-task.md` 与有效 manifest 的任务 ZIP。  
**退出条件：**没有准确批准样品不能产出正式任务；测试图明确标 test-only；ZIP 真正包含被批准原 PNG，不要求用户再次上传。

### M4｜连续材质、边界墨线与16态编译器（P1，**关键高风险阶段**）

**工作：**

- 先使用人工编写的**原创连续石砖测试母图**验证，确保程序能够保留跨格的石缝结构，而不只是颜色采样。
- 实现至少**一种**可靠生成路径：周期/相位一致的 `A-continuous`、`B-continuous` → mask → 边界笔触 → `mask-00..15`、4×4 atlas。
- 内部采用真实像素或真实绘画母版输入，不是同色块程序模板取代石砖纹理；输出每态源像素覆盖率、实际母图覆盖比、可复原坐标与 SHA。
- 兼顾轮廓曲线/转角可变、不过分亮边；边线策略不影响 mask 的 A/B 占用。
- 对抗“只使用整个 art-source 2%”：源像素采样覆盖率列硬诊断和显著警告；默认路径不能把低覆盖率与美术质量混同。推荐完整母版采样或世界相位方案，绝不只凭输出47/16态数量断言成功。
- 对任何工具不支持的艺术边缘输入，明示“数学合格、艺术轮廓仍候选”，而不是伪造 AI 已绘制该艺术层。

**产物：**新 `dual-grid/compile.cjs`、16张图、atlas、B 合成/Alpha、材质源图及编译追溯表。  
**退出条件：**16/16源像素合成一致；黑缝不被自动磨平；至少一个程序自绘连续原稿在 8×8 回拼中边缘吻合；没有为了通过而对用户原件做未声明修图。

### M5｜技术诊断与大面积重复检测（P1）

**工作：**

- 从同一真实编译器生成 `3×3` 四邻、`8×8` 人工地图、`16×16` 大面积、内/外角、1格、2格、斜对角、孔洞、岛形等完整场景。
- 硬错误区分：`mask-mismatch`、`corner-inversion`、`empty-neighbor`、`alpha-gap`、`source-dimension`、`atlas-index`、`phase-discontinuity`。
- 警告区分：`material-color-seam`、`black-line-break`、`high-repeat-rate`、`unapproved-style`、`border-looks-mechanical`（后两者仅人工标记，**不伪称机器自动判美术**）。

**产物：**地图测试图、diagnostics.json、UI 可点追溯、结构/像素/视觉分栏报告。  
**退出条件：**至少一种故意制造的不连续与错位样本被准确报错，合法样本不被误判严重失败；美术手工检查单独待验。

## 10. 风险、决策边界与明确降级路线

| 风险 | 现象 | 必须采取的处理 |
|---|---|---|
| AI 不遵守画板尺寸或连续构图 | 又生成独立漂亮石头而非俯视石砖母图 | 留存原件并明确返工，不因有PNG就启动正式编译 |
| 双网格16态成功，但石砖内部图案重复 | 有数学完整性，无成熟观感 | 保留16态编译结果作技术版本，优先改**连续母图/相位**，不再改 mask 凑图 |
| 16张 Canonical 无法表现无限非重复砖缝 | 地图16×16有明显相同大砖 | 明确说明有限资产限制；再评估坐标变体/K²或世界坐标纹理，不能声称双网格天然消除重复 |
| 错把墙体按平面地砖处理 | 立面厚度/遮挡/排序错误 | 本轮只开放平面A/B，不在此流程中标“墙体生产通过” |
| 用户只有聊天截图，Codex 没拿到原 PNG | 无法核实精确样品、尺寸/Alpha/SHA | 先用原创test-only演示工程功能，**用户真实试产标阻塞**，不能假造批准；告诉用户需要导入准确原图 |
| 实时编译性能或 UI 卡顿 | 16×16拖动明显滞后 | 单格编辑只更新4片Render；缓存已编译Sprite，节流预览与完整导出分开，不省略即时结果 |
| skner版本/Tilemap依赖冲突 | Unity接入/自动切片规则错序 | 独立JS编译和映射仍可交付，Unity实机状态明确unverified；不顺便升级游戏/引擎配置 |
| 修改旧签名逻辑破坏历史项目 | v6/v7/v8无法恢复或旧批准意外变化 | 采用新协议显式分流；无法安全保证时阻止发布而不是弱化签名 |
| 版权/私有资产误发布 | 原游戏研究PNG或个人手稿进入公共repo | 所有真实AI/游戏/用户图片仅 ignored validation，公开仅自制几何夹具与通用代码 |

**唯一需要用户主动判断的最终环节：**这套真实石砖的大地图是否达到“我愿意采用”的水平。Codex 不得自己替用户勾选视觉通过。若本轮全部技术模块已经达标但尚无实际AI原图，允许如实技术交付并保留此项待用户验收，不无限等待或伪造图。

## 13. 结语：如何判断这轮路线真正成功

**最先需要看到的，不是更长的提示词，也不是一个漂亮的16格图片。**

要看到的是：**你在双网格画板里用鼠标随便涂一块石砖区域，边缘和内外角马上自动正确连接；那些表面黑线、砖块大形、暗块归纳依旧来自你批准的画风母图，而不是被公式抹平成几何卡通。**

如果**数学和铺设完全正确，但石砖仍像机械重复**，下一轮就只研究更成熟的连续纹理/变体策略，而不是重做16态的数学。

这才是工坊走“专用技术模板＋人工批准画法＋AI扩展生产”路线应有的分工。
