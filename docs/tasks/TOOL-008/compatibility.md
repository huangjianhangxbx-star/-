# TOOL-008 v2 契约与兼容边界（2026-10-19）

## 项目级资产

新项目使用 `xinghai-workshop-project-2`，场景使用 `xinghai-workshop-scene-2`。旧版 `xinghai-workshop-project-1` / `xinghai-workshop-scene-1` 保持独立验证器和读取路径，禁止在 v1 schema 下静默扩展字段或原地覆盖。v2 项目有 `assets[]`（稳定 `assetId`、显示名、修订号、原生类型、规范相对源路径与预览记录）及 `scenes[]`；v2 场景只保存实例/贴花的 `assetId`、变换和分组，不保存场景私有源表。

体素源固定为 `assets/<assetId>/asset.xhmodule.json`，或用户在首次保存时选定的受控分类目录 `assets/<分类>/<assetId>/asset.xhmodule.json`；其格式仍是现有 `xinghai-workshop-asset-1`，不改体素单位和几何算法。GLB 与 PNG 原料可保存在项目级受控路径；预览与体素源同目录，场景预览在 `scenes/<sceneId>/preview.png`，记录生成时的源修订号和 SHA-256，源变化即视为失效。显示名可更改而无需移动路径。所有路径只允许项目内规范相对路径，实例不能指向任意外部绝对文件。

`core/workshop-v2.ts` 实现严格结构验证与项目/场景引用检查；磁盘读写由独立的 v2 repository 管理。新项目默认使用 v2，旧 v1 项目继续由原验证器和原界面读取，不会因打开而转换。项目级原生资产编辑、同源试摆、缩略图、回收区和单资产 FBX 已接入 Electron。

## 旧项目迁移原则

默认在用户选定的**新目录**创建副本，原 v1 `project.xhproject.json`、场景私有资产、`releases/` 和发布记录均不改。不同场景同名资产不自动合并；冲突 ID 根据源内容重分配并记录映射。先写临时目录、验证源身份与引用、再原子改名为用户目标目录；取消和已有目标不会覆盖。迁移报告随副本保存。定向测试验证了原 v1 项目和 `releases/` 字节不变；未对用户所有历史工程批量迁移。

## 当前明确边界

- 项目根目录可在新建时选择；未保存资产可选择一个项目内分类子目录，已保存资产路径固定。要变更分类可另存为新资产。整项目可另存到用户选择的其他父目录，复制在临时目录验证后才成为新项目，旧项目不改；回收区不随副本复制。
- v2 普通入口只导出单件 FBX；同名目标可取消、改名或显式备份并覆盖。旧成品被移动到并列 `.backup-<id>` 目录，新成品成功放置后反馈备份路径。导出用内部 GLB 中间文件、Blender 5.1.2 和材料旁车，失败不会生成半个正式输出目录。
- v2 公共库只允许带工坊体素源的条目复制为项目资产；无可编辑源的 GLB/PNG 旧式导入按钮在 v2 试摆中隐藏。旧 v1 装配仍保留旧行为。
- 试摆缩略图当前为平面位置概览；资产缩略图才按体素几何绘制。缩略图为缓存，不能代替源文件。大型模型可能显示明确占位。
