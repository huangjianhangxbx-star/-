# 1. EC-02 的核心目标

正式建立：

> **玩家是真正在同时玩两个角色。**

任意时刻：

```text
一个角色 = DirectActor / 当前直接操控
另一个角色 = AIActor / 当前由伙伴AI接管
```

玩家可以：

> 猎人制造机会  
> → 快速切换到伙伴  
> → 伙伴兑现机会  
> → 再快速切回猎人

整个过程：

- 不打开角色菜单；
- 不暂停；
- 不重置攻击；
- 不重置技能；
- 不重置架势；
- 不重新入战；
- 不让切走的角色突然跑回很久以前的锚点。

# 3. 为什么当前系统还不等于 EC-02

当前其实已经存在：

- 点击 / 数字键选择本体；
- 选中对象可用 WASD；
- E 使用当前对象技能；
- `selectedBodyId` 会让对应 AI 让权；
- 未选中本体可以执行当前自治逻辑；
- 探索镜头会从猎人向被选伙伴偏移。

这说明技术底座已经具备。

但还存在几个结构问题：

1. **“UI选中谁”和“玩家直接控制谁”语义没有真正分离。**
2. 默认仍有大量代码使用 `input.selectedId || hunter` 推断主控角色。
3. 探索非战斗跟随始终默认猎人是领队。
4. 当前镜头仍以猎人为根，只对被选伙伴增加有限偏移。
5. 切走角色后，AI 有可能根据旧锚点恢复行为。
6. 查看复制体、角色详情、目标UI时，可能污染“当前直接控制对象”的语义。
7. 没有一个专门的“快速交换控制权”输入。
8. 当前主控角色失能以后，没有完整定义谁自动接管。

EC-02 就是把这些问题一次收敛成正式契约。

---

# 4. 新的核心概念：DirectActor

## 4.1 GameState

建议增加明确字段：

```ts
controlledBodyId?: string | null
```

语义：

> 当前玩家实时输入应该作用到哪个本体。

独立暗牢进入时：

```text
controlledBodyId = hunter
```

## 4.2 为什么不继续只依赖 `selectedBodyId`

当前 `selectedBodyId` 已经承担角色选择、AI让权、部分UI、观察和指令对象。
未来还会出现复制体观察、弱点锁定、伙伴指令、敌人信息等，这些都不应该改变：

> “WASD现在控制谁？”

所以从 EC-02 起：

- `controlledBodyId`：只表示玩家当前直接操控本体；
- `selectedBodyId / input.selectedId`：仍可用于UI观察、角色详情、鼠标选择等。

为了兼容现有交互：

> 点击另一名有效双人本体时，可以同时把它设为 controlled body。

但查看复制体：

> 只改变观察对象，不改变 DirectActor。

---

# 5. 统一控制权查询

新增统一查询，例如：

```text
controlledBody(s)
```

返回：

1. `controlledBodyId` 对应的合法本次探索本体；
2. 如果失效，则合法 fallback；
3. 不存在则 null。

独立暗牢所有实时输入必须通过它：

- WASD；
- 当前技能 E；
- 鼠标快捷移动的默认角色；
- 当前角色控制文字；
- 世界技能按钮；
- 相机主目标；
- 后续 EC-03 闪避；
- 后续 EC-07 三技能。

不要继续散写：

```text
input.selectedId || 'hunter'
```

---

# 6. 哪些对象可以成为 DirectActor

只允许：

- 猎人；
- 本次选择的 Companion；
- team = ally；
- original body；
- 当前仍属于本次 standalone party；
- life = active；
- 非 shadowResident。

不能直接控制：

- 复制体；
- 未选择伙伴；
- 敌人；
- dead；
- downed；
- rescued；
- withdrawn；
- respawning；
- departed。

---

# 7. 破势 / 硬直不阻止“切换控制权”

如果伙伴 `posture = 0`，玩家仍然可以切过去。

只是：

- WASD 仍被破势移动锁拒绝；
- 普通移动仍不能发生；
- 可以执行当前规则允许的原地攻击/技能；
- 再受架势伤害仍会硬直。

同样，切换到正在硬直的角色也是允许的。

控制权和“当前能不能行动”是两件事。

---

# 8. 快捷切换输入

## 8.1 原型快捷键

建议首版：

```text
C = Hunter ↔ Companion 快速切换
```

理由：Tab 已是手牌，E 是技能，Q/H/B/Shift/Space/Alt 均已有用途；C 当前未占用，也不抢未来可能使用的 F 指令轮盘、Q/E/R 三技能方案。

C 只是原型默认键，未来可以重映射。

## 8.2 数字键

独立双人探索：

```text
1 = 猎人
2 = 当前伙伴
```

3 / 4 不再指向未出场角色。

塔防继续沿现有 1–4 逻辑。

## 8.3 鼠标

点击猎人/当前伙伴本体或 portrait：

> 直接接管对应本体。

点击复制体：

> 只查看复制体详情，不改变 `controlledBodyId`。

---

# 9. 切换命令必须进入核心层

不要只在 `main.ts` 直接改字段。

建议新增 Command：

```ts
{ type: 'controlBody'; id: string }
```

核心验证：

- 当前是 standalone exploration；
- phase = battle；
- id 属于本次双人；
- 对象当前可作为 DirectActor。

这样浏览器、自动测试、未来手柄和未来键位映射全部走同一规则。

---

# 10. 切换不是“打断动作”命令

切换控制权本身：

> **不取消合法已经成立的动作。**

## 已经出手的普攻
`attackPending` 已存在时继续完成。

## 已经发动的技能
`SkillRun / skillTime` 已成立时继续运行，不清 CD、不重启、不重算 snapshot。

## 换装
合法换装继续。

## 跨层 / 回镰 / 特殊位移
控制权可以切换，但不可中断生命周期仍按自身规则完成。

---

# 11. WASD 行为：切走就停止

当前角色正在 WASD / direct locomotion 时按 C：

1. 清掉旧角色直接方向输入；
2. 停在当前合法位置；
3. 不继续沿旧 held key 前进；
4. 把该点作为 AI 接手参考位置；
5. 键盘输入随后作用于新 DirectActor。

否则会出现切人后旧角色继续被 W 推着跑的问题。

---

# 12. 鼠标“已下达移动命令”与 WASD 不同

如果玩家已经点击地面，让角色自动走向一个合法目的地，然后切换：

> **该明确移动命令继续执行。**

例如：

```text
让阿尔向右侧移动
→ 切猎人
→ 猎人正面接敌
→ 阿尔完成刚才的明确走位
→ 命令完成后AI重新接手
```

因此：

- WASD 是实时输入，切走立即停止；
- 鼠标目的地是已提交命令，切走后继续完成。

该移动完成以后更新当前位置/锚点，再由 AI 后续接管。

---

# 13. AI 接手：Outgoing Actor

当角色从 DirectActor 变成 AIActor：

### 如果存在明确玩家路径
先完成该命令，AI 不抢。

### 如果刚才是 WASD
立即停下；在探索战斗状态下以当前位置重新建立临时战斗锚点，避免返回很久以前的旧锚点。

### 如果正在技能/攻击生命周期
动作继续，AI 不主动 interrupt。

### 命令结束
恢复当前 T-016 AI：Attack Task、Brace、Return、Support、现有活动半径。

EC-09 才取消探索 Anchor 约束。

---

# 14. AI 让权：Incoming Actor

切换到一个 AIActor 时：

1. 立即停止 AI 自己生成的 Approach / Return / Follow 普通路径；
2. 清除当前纯 AI task ownership；
3. `phase = player`；
4. 不清除已出手攻击、已发动技能、crossing、skillLanding、合法 loadout。

之后玩家输入拥有最高优先级。

---

# 15. 玩家切换时不继承 AI 旧路径

如果阿尔 AI 正在向左追怪，玩家按 C 接管：

> AI 左移路径立即失效。

但已经发出去的箭继续。

玩家接管的是当前角色，而不是“角色 + AI没走完的方向”。

---

# 16. Non-combat：当前操作者成为队伍领队

这是本阶段非常重要的一项。

现在非战斗软阵型默认猎人领队。如果玩家真正控制阿尔探索，猎人仍站在原地是不成立的。

所以 standalone exploration Idle 改为：

```text
formationLeader = DirectActor
follower = 另一名本体
```

### 猎人 DirectActor
伙伴跟猎人。

### 伙伴 DirectActor
猎人跟伙伴。

猎人使用现有软槽位、合法落点、catchup、友方互穿规则成为 follower。

### 切换时
不瞬移重新排阵；旧 DirectActor 从当前位置自然变成 follower，新 DirectActor 从当前位置成为 leader。

---

# 17. H / B 暂时不重做

EC-10 才做正式指令轮盘。

EC-02 中：

- H 仍然是猎人身份相关的全队召回 / 影庭逻辑；
- B 仍沿当前“向猎人集结”的历史语义。

即使 DirectActor 是伙伴，H/B 仍作为现有全局命令使用。

UI/帮助文字应明确：H/B 属于猎人的队伍能力，不代表“跟当前操作者”。

---

# 18. 入战时保持当前 DirectActor

进入战斗时不自动切回猎人。

例如玩家正在直接控制阿尔，敌人发动攻击：

```text
explorationIdle → explorationBattle
DirectActor = 阿尔
AIActor = 猎人
```

猎人以入战时当前位置建立现有战斗锚点，由当前 AI 接管。

这正是本轮需要验证的：

> 伙伴被玩家控制时，猎人也能成为AI队友。

---

# 19. 脱战后也不强制切猎人

如果战斗结束时玩家仍控制阿尔：

```text
explorationBattle → explorationIdle
```

继续由阿尔领队，猎人跟随。

玩家想切回猎人时自行按 C。

---

# 20. DirectActor 失能后的自动接管

如果当前 DirectActor 变成：

- downed；
- dead；
- rescued；
- respawning；
- shadowResident；
- departed；
- withdrawn；

核心自动检查另一名合法 active 本体。

存在：

> 自动把控制权交给另一人。

### 伙伴倒地
伙伴主控 → 自动猎人。

### 猎人失能
猎人主控 → 如果伙伴 active，自动伙伴。

猎人复生后：

> 不自动抢回控制。

### 两人都不可控

```text
controlledBodyId = null
```

实时移动输入不作用于任何人。

---

# 21. 伙伴进入影庭后的控制切换

如果当前 DirectActor 是伙伴并合法进入影庭：

> 自动 DirectActor = 猎人。

伙伴重新出来以后：

> 不自动抢控制。

---

EC-01 已明确：两个“人”指两个本体，复制体仍允许存在。

EC-02 锁定：

```text
C toggle = Hunter ↔ Companion Original
```

数字键 1/2 也只对应两个本体。

点击复制体可以查看详情，但 `controlledBodyId` 不改变。

# 23. 快捷键 E 必须跟随 DirectActor

独立暗牢 E 永远作用于 DirectActor。

即使 UI 当前正在查看复制体详情，E 也不能突然对复制体或查看对象生效。

# 24. Shift 必须跟随角色身份

当前只有猎人有瞬影。

### DirectActor = 猎人
Shift 正常瞬影。

### DirectActor = 伙伴
Shift 不遥控猎人瞬影。

第一版提示：

# 27. 相机升级为“双人主控构图”

当前探索相机始终以猎人为基础中心，被选伙伴只产生最多3U偏移。EC-02 要改成：

```text
Primary = DirectActor
Secondary = 另一名 active 本体
```

如果 Secondary 存在：

```text
focus = PrimaryPosition + clamped(Secondary - Primary) * 0.35
```

并限制最大辅助偏移约 2.5～3U。

含义：

> 镜头主要服务当前操作者，但会向伙伴方向稍微让出空间。

### 两人靠近
两人尽量都处于舒服区域。

### 两人相距太远
不无限拉中点，优先 DirectActor。

### 不做动态 Zoom
投影大小保持 T-017 当前规则，只改变 focus，避免同时改变移动速度和距离判断体感。

# 33. 输入模态期间的切换

- 疾行方向选择；
- 召影选点；
- 物品目标选择；
- 瞬影瞄准；
- 拖牌；
- 经济确认；
- 探索退出确认；
- 构筑面板；
- 背包等模态独占输入。

提示：

不自动替玩家取消一半操作再切人。

# 34. 暂停状态

推荐暂停时允许 C / 1 / 2 更改 DirectActor，因为这只是控制归属，不推进模拟时间。

如果当前前端结构让成本过高，可以第一版保持暂停时不能切，但必须在验证记录写清楚。

推荐仍然支持。

# 35. Core helper：控制权生命周期

建议集中实现：

```text
queryControlBody(...)
switchControlledBody(...)
ensureControlledBody(...)
```

职责：

- query：目标是否合法；
- switch：处理 outgoing / incoming；
- ensure：关键生命周期后保证 DirectActor 有效。

不要在 UI、downed、shadow、respawn、exit 等位置各自手写 fallback。

---

# 36. `playerOwns` 必须认识 DirectActor

当前 `playerOwns(s,u)` 依赖 `selectedBodyId` 等状态。

EC-02 中，对 standalone：

```text
controlledBodyId === u.id
```

是最高层玩家所有权之一。

AI 永远不能与 DirectActor 抢移动权，即使 UI 正在查看复制体。

- skill run；
- crossing；
- skillLanding；

# 57. 人工试玩重点

## 切换频率
是否会自然产生“我想切过去做一下事情”，而不是“切人太麻烦，我还是一直玩猎人”。

## AI接手
切走以后角色会不会突然做蠢事、跑回旧锚点、破坏玩家刚制造的位置。
如果这里明显不好，EC-09 Companion AI 需要提前。

## 非战斗双人
控制伙伴跑路时，猎人跟随是否自然；是否真的像“我在控制队伍里的另一个人”。

## 镜头
频繁切换是否晕、跳、看不见另一人；是否需要后续动态双人镜头。

## 操作空窗
如果用户明显觉得“会切人，但切过去除了走和按E没东西干”，则 EC-03 或 EC-07 应提前。

# 63. 本阶段最终判断

EC-01解决的是：

> “是不是一个可信的双人战斗环境？”

> **“玩家是否真的感觉自己拥有并在使用两个角色？”**

只有 EC-02 成立以后，后续的闪避、三技能、Break组合、包夹、弱点、Companion AI 和指令轮盘，才真正有稳定的控制权基础。
