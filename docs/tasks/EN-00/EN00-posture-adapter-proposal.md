# EN00｜架势适配提案与待定参数

本轮只对账，不修改 `pressure.ts` 或角色黄金合同。原作研究没有证明架势条；这是《星骸》新增机制。下面的用户决定、现代码和实现提案分别列出。

## 最新用户决定

来源：[设计会话](https://chatgpt.com/g/g-p-6aba4bb1f00c8191bada2ae5db02c438-xing-hai-hui-lang-yuan-xing-kai-fa/c/6abcecf9-38ac-83ea-96a9-1c5aa80adb5c)，此次只读取最近三轮。引用用户消息 ID：

- `288ee2c3-155b-4254-8afc-a5497e398ed5`：架势到 0 立即受伤动画、不能操作/行动；普通移动不耗体力。范围决定命中，高低差旧规则取消，障碍仍阻挡投射物。
- `64ddb4e1-ec69-47b4-8f9d-b5191b38bbce`：未受击、未使用主武器普攻/技能、未闪避时，普通移动也能恢复架势；DOT 算受击阻止恢复；副手使用允许恢复但速率减半。右手主武器、左手副手，不根据鼠标按键推断持手归属。
- `c86aea7a-3a5c-4884-9a0f-1717719157c0`：副手盾格挡相对直接受击减少架势消耗，减免取决于盾品质/角色成长；即使架盾时架势到 0 也控制角色。

这确定了**零点当次控制、恢复资格与盾格挡区别**，没有确定持续时间、每种攻击削减、盾减免公式、恢复延迟、敌人抗性和架势 UI。不能把旧代码数字自动提升为批准值。会话中“按推荐”没有返回对应助手正文，未把无法读取的建议记成用户批准。

## 现代码不符合处

| 项目 | 当前实现 | 新契约要求/处理阶段 |
|---|---|---|
| 首次削到 0 | `applyPosture` 首次 `becameBroken=true`，下次命中零架势才 `breakReaction=true` | 首次到 0 即控制；EN04 改动，EN00 不补丁 |
| 恢复 | `tickPosture` 延迟后恢复，未按主武器/副手/闪避/DOT 分开 | 主动作/副手动作分类及受击时戳作为资格输入；不只看速度是否零 |
| Hunter 正面格挡 | 防御分支 HP power=0，但压力仍沿旧命中通路 | 盾成功格挡单独架势成本，不能因 HP=0 就视为没有架势命中 |
| 普通反应 | `reactToEnemyHit`、旧硬直和 pressure 会共同影响行为 | V2 一个 Reaction 权威，普通 Hurt、破势、真正 Cancel 分离，避免重复应用 |
| 死亡后 reset | 旧压力重置可能恢复架势 | 死亡不发恢复事件；出生新代初始化另测，不掩盖死亡前最后一次结果 |

`PRESSURE` 现有恢复/控制常数与 melee/ranged/heavy 架势上限只记 LEGACY；不把角色已认可的操作手感当作这些新增规则的数值批准。

## 提议的两个对照模式

`Reference`：关闭**新增架势层**及其破势控制，保留同一 HP、原事件时序、经批准 SAMPLE 的普通受击/硬直/取消。该名称仅表示参照动作对照，不声称原作 AI/OBS 已还原。

`Xinghai`：相同敌人感知、动作和攻击实体，在主 `HitOutcome` 边界附加架势结算。削到 0 当次发出 `PostureBroken` 并控制；恢复资格按上面用户规则。原 Spine `Break` 仅表示攻击解锁，永远不用作 `PostureBroken`。

模式是 AI 提案，尚未批准为正式 UI。EN04 使用冻结可重放剧本分别启动两次场景比较；不要运行中半招切换模式造成费用/控制含义漂移。角色侧后续新增架势规则与已有黄金合同的交叉影响须报告，不能借怪物迁移静默改变 Hunter/Al 攻击、翻滚、RMB 或 E。

### 结算顺序提案

1. 具体攻击实体与目标真实接触，按本能力去重。
2. 现有主防御接口返回闪避/无敌、盾格挡、普通接触等独立结果。
3. HP 与架势各按权限和效果计算；DOT 使用明确伤害种类，不能只看 HP 是否减小推断。
4. 普通 Hurt、PostureBroken、击退/撞墙分别决策；出现实际 Cancel 才取消该身体尚未消费的事件。
5. 取消/死亡依能力处理派生实体；骷髅弓已提交运输保留，Reset 一律按世代清理。

阶段霸体不能静默忽略已确认的零点控制规则。如果候选敌人需要“零点仍不断招”特殊规则，与当前决定冲突，应先提专项问题。原作普通受击抗性也不自动等于《星骸》破势抗性。
