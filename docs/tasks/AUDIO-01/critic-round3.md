## 实际核对的证据

- 静态：四个正式适配器使用同一 `GameAudio`；正式路由仅一处 `AudioContext` 与一个扬声器 `destination`。独立 Action Lab 仍有自己的播放器，但不在正式会话中。敌人参考事件已走 `enemy` 总线；F10 旧隔离会话设静音，现场监控读取父会话。
- 测试：负责人报告 build 通过，定向 Vitest **10/10**、Playwright **18/18**；我独立重跑音频事件和策略两文件 **5/5**。浏览器测试有单 Context、重复解锁不重排、F10 父会话、资源候选、循环虚拟化、180 请求预算、隐藏模拟及四条自然输入故事。
- 四条自然故事的 `work/AUDIO-01/stories/*.json` 与同名 `*.webm` 留在 ignored 本机目录。挥空/开包记录 `reference.release`、`ui.open`，无 `reference.hit`；僵尸故事有 14 个被接受事件，其中 `reference.enemy.release/hit/hurt` 路由 `enemy`；对话记录 `dialogue-focus` 获取和释放、`explore/dialogue` 音乐状态；余额不足记录一次 `ui.reject`、零 `ui.confirm`。这些证明测试操作与音频请求的因果，不单独证明每个请求都清晰可听。
- 四段主输出 Opus 录音约 **1.08/12.72/3.54/1.56 秒**；FFmpeg 测得最高峰分别约 **−19.2/−13.7/−21.2/−18.9 dBFS**。它们证明该样段有音频输出且未严重削波，不代表设备延迟或整局混音听感。未试听这些录音，也未外放/耳机听测。
- `work/AUDIO-01/stem-pcm.json` 记录三个诊断层共同开始时间 3.04 秒、共同 onset 样本 481，循环对照最大误差低于 `5e-14`；强度切换保持相同节点与 transport。它是测试专用 OfflineAudioContext 对当前诊断 buffer 的验证，**不是原作分轨存在或原作实际 BPM 的证据**。
- 原作候选音频只从本机银行定向解码，走 loopback 白名单；源码注明整段重播为评估策略。原作 WAV、银行、解码工具、录音均在 ignored 本机目录，构建列表未见这些媒体。候选名称、长度不能证明正式场景绑定与作者设计的 loop 点。

## 剩余问题与复核条件

1. **P2 · A06/A07/A09，实际转场链仍未闭合。** 自然僵尸故事采集时音乐状态始终为 `combat`，未覆盖“交战→平静→短时再入战”、高优先覆盖结束、原作候选间的实际淡变及一次自然触发 stinger。用同一正式会话录时间线和主输出，核对来源、候选、排程节点与声部数；不能只读最终音乐 ID。
2. **P2 · A10/A11/A13，空间与生命周期证据不足。** 180 请求是诊断性压力而非拥挤战斗；隐藏验证使用模拟 `visibilitychange`。需定向检查墙与门洞、左右远近、高频真实战斗、暂停/hitstop/倍速、离区及新世界时异步素材返回后的作用域是否正确。至少保存一次对应输出和拒绝/抢占原因。
3. **P2 · A16/A18，设备和离线验证待完成。** 需要从桌面离线入口重启实际服务，测试本机白名单音乐/短音与缺失素材时的降级；若未来分发静态构建，应重新核查原作媒体未被包含。对已录主输出进行人工试听并注明设备、音量、环境、听到的问题与复测时间。
4. **内容边界。** 三首原作候选及整段重播可用于本机验证；原作编曲层、节拍、loop 点和场景绑定均未证实。原创诊断三层能验证程序能力，不等于正式配乐完成。

目前未从这些证据确认持续爆音、旧正式播放器绕过 Master 或公开包泄漏原作；也不能据此宣布所有 A01–A18 通过。按计划第三轮结案，交付当前可恢复版本，并把未验部分保留在工程记录中。用户对最终音乐风格与听感的验收仍独立进行。
