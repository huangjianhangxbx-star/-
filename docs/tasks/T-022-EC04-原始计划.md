## 1. 本阶段目标

EC-04 要建立探索主战斗的统一攻击语言：

```text
Telegraph / 预警
↓
Lock / 锁定
↓
Resolve / 结算
```

核心原则：

> **屏幕上显示的危险区域，必须和核心最终判定使用同一份攻击几何。**

不能出现“视觉是一个红圈，但逻辑仍用另一套距离判断”。

本阶段只做：
- 通用 AttackArea / Telegraph 数据模型；
- Tracking → Locked → Resolve 生命周期；
- 严格几何与角色碰撞体命中；
- 当前独立暗牢敌人基础攻击接入；
- 世界地面危险区域渲染；
- 与 EC-03 主动闪避/走位的统一结算；
- 调试统计与自动验证。

明确不做：
- Break 2.0 / 强制位移 / 撞墙；
- 背击 / 弱点；
- 三技能槽；
- 完整敌人技能组；
- 冲锋/Boss多阶段技能；
- 敌人主动闪避/格挡/反击；
- Companion AI 2.0；
- 指令轮盘；
- 怪物知识；
- 卡牌转型；
- 正式音效/特效美术。

## 2. 三阶段攻击生命周期

### 2.1 Tracking
敌人开始攻击后：
- 创建 AttackIntent；
- 显示较淡的危险轮廓；
- 停止普通追击位移；
- 允许有限调整朝向/目标线。

含义：
> “它正在瞄准，你的移动还会影响最后落点。”

### 2.2 Locked
到 lockAt：
- origin / heading / center / to 冻结；
- 不再追踪玩家；
- C切人、瞬影、闪避都不会改变攻击区域。

视觉：
- 更强填充；
- 实线边界；
- 可加轻微锁定脉冲；
- 不只靠颜色区分。

### 2.3 Resolve
到 resolveAt：
- 只检查角色 Body Circle 是否与 Locked Area 相交；
- 区外完全不调用 resolveHit；
- 区内才进入 resolveHit；
- Active Evade Window 仍能在 resolveHit 最前层让本次攻击完整 Miss。

## 3. 通用攻击几何

新增核心 `AttackArea`，首期支持：

### Circle
```text
center
radius
```

### Sector
```text
origin
heading
range
arc
```

### Capsule / Line
```text
from
to
radius
```

要求：
- 判定考虑 `Unit.bodyRadius`；
- 不能只检测单位中心点；
- 使用统一 epsilon；
- 墙和 LOS 不得允许攻击穿透；
- Renderer 不能自行推导第二套形状。

建议模块：
```text
core/attack-area.ts
```

负责：
- 构造几何；
- unit intersection；
- terrain / LOS；
- tracking update；
- lock snapshot；
- resolve targets。

## 5. 区域是真实伤害区域

从 EC-04 开始：

> Area Attack 的几何就是实际危险区。

因此同一敌人攻击区内，如果猎人和伙伴同时站进去：
> 两人都受击。

一个在区内、一个在区外：
> 只命中区内角色。

不画大扇形却只打最初 target。

不做敌我友伤；敌人攻击只打玩家阵营。

## 6. Tracking / Lock 与目标

Telegraph 创建时仍由当前 enemy AI 选择一个初始目标。

开始：
- target 决定初始瞄准；
- `attackCommit()` 仍在此刻触发探索入战。

Tracking：
- melee / heavy 可以有限转向；
- ranged target line 可以有限更新。

Locked：
- 完全冻结；
- 不因 DirectActor 改变；
- 不因目标瞬影/闪避重新吸回。

Resolve：
- 不再只检查原 target；
- 直接查询 Locked Area 内所有合法 party bodies。

---

## 7. Telegraph 期间敌人停止普通移动

一旦建立 AttackIntent：
- 不继续普通追击；
- 不一边画红区一边身体跟着玩家跑；
- 只允许预警阶段有限朝向修正。

Locked 后连朝向都冻结。

## 8. 与 EC-03 闪避的结算关系

顺序：

```text
Locked Area
↓
Resolve 时 Area 与 Unit 相交？
├─ 否 → Position Avoid，完整躲开
└─ 是 → resolveHit()
          ├─ Active Evade Window → Active Evade，完整Miss
          └─ 否 → 正常受击
```

因此存在两种躲避：

### Position Avoid
真正走出危险区。

### Active Evade
仍在区里，但用极短无敌窗口救命。

设计仍优先鼓励：
> 走出去。

统计分开：
```text
telegraphPositionAvoids
activeEvades
telegraphHits
```

---

## 9. 猎人瞬影

Blink 不需要新增 Active Evade Window。

如果猎人在 Locked 后瞬影出 Area：
> 直接按 Position Avoid 处理。

这能进一步突出猎人的高机动特色。

## 10. Telegraph 与 attackPeriod

Telegraph Windup 属于攻击周期的一部分。

正确：
```text
攻击开始
→ attackTimer设置完整周期
→ Telegraph
→ Resolve
→ 剩余Recovery
→ 下一次攻击
```

错误：
```text
先等attackTimer
→ 再额外等0.9秒Telegraph
```

若：
```text
attackPeriod < telegraphTotal
```

则模板至少保证：
```text
effectiveAttackPeriod >= telegraphTotal + smallRecovery
```

避免同一敌人攻击意图重叠。

## 11. AttackIntent 建议结构

建议新增或演进为：

```ts
type AttackShape =
  | CircleArea
  | SectorArea
  | CapsuleArea

type AttackIntent = {
  sourceId: string
  targetId?: string
  startedAt: number
  lockAt: number
  resolveAt: number
  phase: 'tracking' | 'locked'
  area: AttackShape
  damage: number
  postureDamage: number
}
```

核心要求：
> AttackIntent 自己就包含最终判定几何。

可选择：
- 扩展旧 `attackPending`；
- 或 standalone enemy 单独使用 `attackIntent`。

更推荐后者，先不强迫塔防同步升级。

---

## 12. 取消条件

Telegraph / Locked 期间，如果 source：
- 死亡；
- stun；
- 进入返程；
- 丢失攻击生命周期；
- 被未来强控；

则：
> 当前 intent 取消，Telegraph 立即消失，不结算。

同一敌人同时只允许一个 active intent。

---

## 13. Fog / Visibility

Telegraph 不允许无条件泄露未知敌人。

当前基础攻击范围下：
- melee约1U；
- ranged 4U；
- 玩家共享视野5U；

正常发动攻击时敌人通常已经可见。

首版保证：
> 可见敌人的 Telegraph 正确。

更复杂的“隐藏远程技能是否显示危险区”留 EC-08。

---

## 14. 世界渲染

建议新增：
```text
telegraphGroup
```

或等价世界层。

要求：
- 不影响 pick；
- 地面贴合；
- 不 Z-fighting；
- Tracking / Locked 明确可读；
- 不每帧无界创建销毁 geometry；
- reduced-motion 下仍能区分阶段；
- 不改变相机。

普通 HUD 不显示倒计时数字。

Debug 可显示：
```text
source
shape
phase
time to lock
time to resolve
targets currently inside
```

# 17. 用户试玩重点

## A. 攻击是否看得懂
- Tracking 和 Locked 能不能一眼区分？
- Locked 后是否真的不再吸玩家？
- 是否能形成“它已经锁定，我现在走出去就行”的信任？

## B. 几何可信度
重点排查：
> “我明明出去了为什么还中？”
> “我明明还在里面为什么没中？”

如果频繁发生，优先修几何/bodyRadius/视觉贴合，不继续加技能。

## C. 反应时间
分别判断：
- melee 0.55；
- ranged 0.75；
- heavy 0.90。

不统一调。

## D. 闪避价值
观察玩家更常：
- 真正走出区域；
- 还是依赖active evade window硬滚。

如果后者过强，优先收紧无敌窗。

## E. 双人站位
Heavy能命中区域内两人后，玩家是否开始自然避免双人重叠。

# 18. EC-04 通过标准

不是“敌人已经丰富”，而是：

1. 攻击开始时玩家看得懂；
2. 锁定时机明确；
3. Lock后不作弊追踪；
4. 画出来的区域就是实际命中区域；
5. 走出区域可以可靠躲避；
6. Active Evade仍是窄时机救命；
7. 双人区域判定成立；
8. 玩家开始因攻击形状主动走位。

达到这些以后，EC-08新敌人能力才有可靠语言可用。
