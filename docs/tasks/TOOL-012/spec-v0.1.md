## 0. 一页执行摘要

### 0.1 要解决的问题

工坊目前难以看清深色模型、岩壁凹槽、层阶和材质绘制结果。目标不是增加电影感，而是：**同一件模型，可以一键切换到适合看形体、看原色、看受光或检查细小凹凸的观察方式。**

本轮交付四个实际可用的预设：

| 预设 | 画面目标 | 主要用途 |
|---|---|---|
| 清晰灰模 | 中性灰覆盖色，均衡柔光，轻量凹槽增强，密集体素格线默认关 | 深色模型建模、岩柱与层阶观察 |
| 原色检查 | 基础色与绘画贴图都不受灯光、AO、曝光调节或色调映射影响 | 校色、贴图笔触与接缝检查 |
| 材质柔光 | 保留颜色及贴图，基础面和绘画面统一受中性灯光影响 | 日常带色模型预览 |
| 结构侧光 | 灰模为主，侧向主光与低强度补光，可旋转灯光方向 | 检查凹槽、前后错台、削切深度 |

**四种预设、绘画兼容、真实视口接入和便携 EXE 属于同一轮交付。** 实施可分 M0～M6，但不要只完成一个灰模演示或四个按钮，就停止并宣称本任务完成。默认只在最终技术交付后等待用户视觉验收；中途只有真实阻塞或越权设计变更才暂停受影响部分。

### 0.2 最关键的五个合同

1. **只改变显示，不改变资产。** 不改体素、色板、paintSource、对象归属、Root、UV 或导出材质，不标脏、不进入作者撤销历史。
2. **绘画面与基础面一致。** 灰模下绘画不能漏出来；受光模式下绘画面不能仍像自发光贴纸；原色模式下不能二次乘色。
3. **所有新生成内容继承当前显示。** 绘制、重建网格、切画布、撤销、岩体预览、加载资产后，不能回到旧灯光或旧材质。
4. **真实深度提示。** 凹槽增强必须基于深度/遮蔽关系，不能把“加黑格线”冒充 AO，也不能只用 MatCap 冒充自身遮挡。
5. **观察操作不扰动创作。** 改预设、旋转灯光、切背景不重置镜头、不清选区、不重新随机岩体、不取消已存在的塑形预览。

### 0.3 工作量边界

这是一个受限的视口显示模块任务，默认采用**B 级模块验证**。不重做整个 Three.js 渲染器，不升级引擎或工具链，不扩展为通用灯光编辑软件，不重新执行整个游戏的历史测试。

## 1. 用户要求、推荐默认与未包含内容

### 1.1 用户明确要求

- 当前渲染让模型和修改效果难以观察，需要改善可读性。
- 希望像 Blender 一样有几种渲染、光照预设，至少可以看清模型。
- 本轮要求制定实施计划。

### 1.2 本计划的推荐方案，待随计划执行授权采用

四种预设名称、默认背景、默认灯光方向、首次进入视口采用何种预设、凹槽增强强度和菜单布局，均为本计划建议，不冒充用户已逐项确认。

建议首次使用：模块编辑左侧与岩体查看器默认“清晰灰模”；模块右侧与试摆默认“材质柔光”。此后按视口记忆用户选择。程序升级不得在每次启动强行覆盖用户的新设置。

建议新工具入口为每个视口上方的**“显示”**紧凑菜单；不建立庞大的常驻灯光侧栏。工坊整体深色 UI 保持，仅视口背景可独立选择。

### 1.3 不包含

- Blender Cycles/Eevee 复刻、路径追踪、光线追踪 GI、真实物理材质一致性认证。
- HDRI 在线图库、外部环境下载、用户自定义布灯器、MatCap 资源管理器。
- Bloom、景深、色差、运动模糊、电影 LUT、氛围雾、自动曝光。
- AO / 法线 / 高度贴图烘焙；不会给导出资产新增 AO 贴图。
- 修改 TOOL-011 的岩体算法、随机种子、保护掩码、选面范围。
- 重写 TOOL-010 的绘画源格式、笔触语义或全部 B 阶段任务。
- 改游戏本体、2D 工坊、团结引擎工程或人工美术原稿。
- 在本轮新增透视/正交相机切换；保留各入口现有投影方式。

## 3. 四种预设的明确行为

以下均为**建议默认**；具体光强和增强数值通过同一批真实样例校准，记录为 SAMPLE，不写回永久游戏美术规范。

### 3.1 清晰灰模 `studio-gray`

- 只对模型表面使用统一中性灰显示覆盖材质，例如以 sRGB `#A8A8A8` 为调试起点；忽略原有颜色与颜色贴图的 RGB。
- 对原生不透明绘画覆盖面，隐藏其显示，让基础几何统一灰模；不删除、不清空其像素或 CanvasTexture。
- 关闭顶点颜色乘色，保持真实法线、硬边和模型几何；不能通过平滑法线改变体素转折。
- 中性主光、补光与低强度环境光，既有明暗方向又不让背向面整片死黑；不沿用明显黄蓝偏色。
- 默认灯光随视角，默认凹槽增强“低”，体素格线关，结构边线默认关但可开启。
- 背景默认中深中性灰，与模型有对比；不把全工坊 UI 改成浅色主题。
- 灰模仅是作者观察外观，不宣称它等同 FBX 的实际材质。

### 3.2 原色检查 `albedo`

- 基础色、侧面固定色及绘画层走一致的无光照颜色路径。
- 强制关闭光照影响、阴影、AO、色调映射、自动/手动曝光偏移、雾和任何颜色后处理；保持必要的 sRGB 输出转换。
- 建议使用 `MeshBasicMaterial` 或等价无光照实现；基础顶点色与绘画贴图不能重复相乘。[E1][E2]
- 无光照变体只保留基色因子、顶点色、颜色贴图与必要 Alpha；不要继承会继续改色的 envMap、lightMap 或 aoMap。移除的是显示变体上的贡献，不是资产源。
- 不为了“看清深色物体”偷偷抬高黑位。看形体切灰模，看真实 RGB 留原色。
- 默认关闭会遮盖颜色的格线/边线；用户可手动临时开启辅助线，校色测试时必须关闭。
- 模型本来存在的透明/AlphaTest 语义不改；严格像素校准使用不透明样例，不能承诺透明合成后仍等于源 RGB。
- 该模式下曝光、灯光方向、凹槽强度控件禁用并有简短原因，不保留看似有效的空控件。
- “原色”表示显示链未人为改色，不是对用户显示器色准的硬件认证。

### 3.3 材质柔光 `studio-color`

- 显示原基础色和实际绘画贴图，二者接受同一中性工作室光照。
- 新绘画覆盖面的显示材质使用受光路径，法线、显示用粗糙度、灯光参数与下面的基础面一致；不能仍用无光照覆盖层。
- 原生体素以一致的哑光观察材质为本轮目标；不承诺复刻所有导出 PBR 参数、团结 Shader 或任意自定义 GLB 材质。
- 已支持的外部静态材质保留贴图、透明裁切、面朝向等必要信息；不支持的特殊材质明确回退，不强制改其源配置。
- 默认随视角柔光、凹槽增强“低”、体素格线关；亮度调节只影响视口。
- 同色同法线的绘画面与未画面不能有明显接缝或亮度跳变。

### 3.4 结构侧光 `raking-gray`

- 默认统一灰模以排除深色和纹理干扰；少量中性补光，主要依靠斜侧主光和局部凹槽增强读形。
- 默认固定在模型显示空间的光照方向；提供“跟随视角”切换和 0～360° 灯光旋转。改变角度不动镜头、不动模型。
- 灯光俯仰给一个合适默认值，必要时收进高级项，不在首屏增加三盏灯的位置面板。
- 默认凹槽增强“中”，密集体素格线关；允许只保留结构边线辅助。
- 可选的单主光实时阴影是后续增强，不作为首轮必须实现的第二套遮蔽系统；本轮首先把一个稳定的屏幕空间凹槽方案做好。

### 3.5 默认值的边界

灰模与受光模式建议首版采用一致、简单的显示管线，先用 `NoToneMapping` 配合受控光强校准中灰/白色样例，避免高光剪白。若本地实测确需中性色调映射，只选一个已安装版本支持的方案供受光模式使用，并记录原因；原色路径始终绕过。不要给用户再增加一整套色彩管理选项。

中性灯、背景和效果数值均以真实图像检查为准，不能仅因数值“看起来专业”而固定。验收关注是否看清形体、是否偏色或压黑，不以曝光滑条存在作为通过。

## 4. UI 与操作约定

### 4.1 紧凑入口

视口上方显示当前预设，例如 `显示：清晰灰模 ▾`。打开非模态菜单后包含：四种预设、灯光旋转、随视角开关、视口亮度、凹槽增强（关/低/中）、背景（深/中/浅），以及折叠的辅助显示。

辅助显示独立提供结构边线、体素格线、地面网格和“恢复本视口默认”。沿用已有 X-Ray、剖切、隐藏/锁定控制，不再制造同功能的第二套按钮。旧“无光照校色”入口迁入或映射到新状态；旧“体素清晰”映射到“体素格线”，不能产生两个互相矛盾的开关。

首屏只留预设按钮；其余收在菜单内。菜单不遮暗整片模型，右键旋转、中键平移、滚轮缩放继续可用；操作菜单时不得误画体素或改选区。

### 4.2 双视口与同步

每个视口有独立状态，允许左灰模/右原色。提供显式“同步模块双视口”开关，默认关闭；开启时以用户刚操作的视口为主复制显示参数并联动后续变化。

同步只包含显示与灯光参数，不包含相机、缩放、工作平面、选区、模型状态或 X-Ray。场景试摆默认独立，不因编辑视口换预设突然改掉用户自己的场景观察设置。

### 4.3 绘画时的灰模处理

灰模会遮盖笔触，因此建议进入“材质绘制”时：若当前是灰模/侧光灰模，临时切到原色检查并记住之前的显示；退出绘画且用户未主动改预设时恢复。用户主动选择材质柔光后，尊重其选择，不在每笔之后强制切回。

若用户在绘画模式主动选择灰模，清楚提示“灰模不显示颜色笔触”，不得让用户误以为笔刷失效。可以暂停开始新笔画，但不能丢失已提交笔触。模式之间切换不得改变源颜色、吸管取样依据或绘画历史。

### 4.4 正在进行的操作

- 空闲切预设：立即显示，无历史、无标脏、无镜头复位。
- 岩体冻结预览期间：允许切预设、改光向、原形对照；预览体素与种子保持不变。
- 按住鼠标尚未结束的建模/绘画笔画、轴拖动期间：禁用显示变更或排队到手势结束；不要代用户提交半笔，也不要用切预设偷偷完成模型修改。
- 实际窗口失焦仍遵循原有取消规则；点击工坊内的显示菜单不应被当成窗口失焦。
- 菜单 Esc 先关菜单，不将同一个事件继续传给底层清选/取消草稿；菜单关闭后的 Esc 仍遵循现有工具优先级。

### 4.5 偏好与缩略图

本机偏好建议采用版本化键 `xinghai.viewport-display.v1`，按 edit / preview / assembly / rock-lab 分开；只存少量普通显示参数，校验越界数值，损坏时回默认，不写进 AssetDocument 或 SceneDocument。

资产图卡的保存预览继续使用固定、有色的显示配方，不读取用户当前灰模或侧光状态。屏幕截图与模型纹理导出是不同出口：本任务不新增截图工具，也不得把视口截图替代 PNG 材质源。

| `desktop/viewport-display-controller.ts` | 每个视口的显示状态、材质适配、灯组与渲染管线协调 |
| `desktop/viewport-materials.ts` | gray/unlit/lit 变体、绘画面与基础面一致性、缓存及资源所有权 |
| `desktop/viewport-lighting.ts` | 中性灯组、固定/随视角、旋转、目标点与坐标换算 |
| `desktop/viewport-cavity.ts` | 可关闭的屏幕空间遮蔽、相机/尺寸更新、资源释放及降级 |
| `desktop/viewport-display-ui.ts` | 共享紧凑菜单，不拥有模型历史 |

没有必要为了这些模块建立通用插件框架、事件总线或第二套模型状态系统。可以合并小文件，但不要把所有逻辑继续塞进巨大的 `renderer.ts`。

### 5.2 表现控制器需要覆盖的对象类型

明确区分：作者模型基础几何、绘画覆盖面、临时几何结果、半透明 Ghost、模型结构边线、选择/操作辅助、参考图、缺失资产占位。不要简单遍历所有 Mesh 后统一变灰；操作轴、PNG 参考图、笔头、Root 提示不应变成灰块。

新对象创建时登记表现角色；销毁时解除登记并释放仅由该视口拥有的资源。几何重建、Undo/Redo、异步资产加载、画布透明度更新后，重新应用有效显示状态。共享状态的有效结果应是：

`当前预设 × 模型显隐 × 画布透明度/X-Ray × 剖切 × 对象角色`

不能让“切换灰模”顺便把隐藏层显示出来，也不能让下一次 CanvasView 更新把显示材质覆盖回旧状态。

### 5.3 覆盖材质与缓存

优先创建仅供显示的材质变体，保留源材质引用，不就地改共享材质的颜色、map、roughness 或导出配置。允许只读共享纹理引用，但显式记录资源所有权：销毁灰模变体不应 dispose 仍被原模型/绘画层使用的纹理。

缓存以原材质身份、显示模式和实际影响 Shader 的标志为键；灯光旋转/亮度滑条只更新变换或 uniform，不每帧创建材质或重新生成 GLB。几何、模型身份和用于拾取的层级尽可能复用。

`attachVoxelClarity` 已使用 onBeforeCompile 和 customProgramCacheKey。新增功能不得无声覆盖旧 hook；必要时建立局部组合函数，显式形成稳定 cache key。体素格线只作用允许显示的几何，不把画笔 UV 岛边缘当作格线。

### 5.4 原色与受光的颜色合同

- 颜色贴图继续保持 `SRGBColorSpace`，模型颜色按既有线性工作空间处理；不要对已转换的顶点色再次手动 gamma 转换。[E2]
- 绘画层图像已经含基础色与覆盖像素时，显示材质的颜色乘数应为白，不再乘一次底色。
- 灰模关闭颜色贴图和顶点色 RGB 贡献；支持的 AlphaTest/透明裁切与模型形状含义需要保留，不能为了变灰把门窗镂空填上。
- 原色检查禁用 tone mapping、曝光偏移和 AO。原生不透明校色样例需验证已画/未画同色面一致，而不是仅检查 material 类型。
- 使用 composer 时，最终输出只做一次正确的显示转换；OutputPass 负责色调映射与色彩空间转换，不能再叠 GammaCorrection 造成二次处理。[E3]
- 后处理覆盖层必须与背景/模型使用一致的最终输出约定；AO 开关切换不应造成整屏亮度忽然变成另一套 gamma。
- 吸管从实际色板/绘画源取色，不能采集灰模或被侧光染过的帧缓冲颜色。

### 5.5 灯组与坐标

灯组仅存在于显示场景，不作为可选择对象，不进入模型导出、包围盒统计或碰撞。

固定模式使用稳定的显示世界方向，跟随模式使用相机朝向/上方向构建局部正交基；围绕观察目标设置主光与补光。不能把灯挂到相机下却把 target 留在无关位置，导致转视角后方向失效。

源坐标 Z-up 与 Three.js 的 Y-up 转换沿用工程现有函数。先明确每个视口的米到渲染单位比例，避免活动画布变化后灯光/凹槽半径放大四倍。不改变现有相机姿态、投影矩阵语义或 OrbitControls.target。

光向旋转与相机旋转分开：固定镜头改变光向只能改变明暗，不得改变模型包围盒、随机结果、相机或模型坐标。随视角模式在平移/缩放时也应稳定，不产生不断追赶灯位的抖动。

## 6. 凹槽增强：本轮的受限技术路线

### 6.1 首选实现

优先在现有 Three.js WebGL 管线内接入**一种轻量屏幕空间 AO**，从本地已安装的 SSAOPass 或同等现有 addon 开始。不要同时实现 SSAO、SAO、GTAO 三套，也不为本任务引入整套新后处理依赖。[E4]

M1 先用同朝向的前后错台、U 形槽、单体素台阶验证：必须能比仅法线着色更清楚地区分凹角与遮挡。MatCap 可作为以后补充的低成本外观，不作为本轮唯一深度方案；其本身不接收灯光，也不接收或产生自身遮挡阴影。[E5]

### 6.2 必测相机与尺度

- `MapView` 正交相机与 `AssemblyView` 透视相机分别验证；不能只看网页示例支持 Camera 就宣称两者均正常。
- 六向正交、近距离细画布、远距离总览、缩放、双视口分割、窗口缩放都要更新深度重建依赖与尺寸。
- 三精度按适配器提供的物理比例换算，不直接写死一个适合 0.25m 的半径。
- 固定随机核/噪声以免静止画面闪烁；滤波不得把硬朗的体素阶梯模糊成圆滑形。
- 增强主要作用内角与邻近遮挡，不能在孤立外轮廓形成粗黑光晕，也不能把整个凹槽涂成纯黑。

### 6.3 排除辅助物与绘画重复面

AO 的深度/法线输入仅纳入需要参与遮蔽的作者几何或当前临时结果。排除操作轴、选择框、网格线、Root、参考图、笔头、缺失资产警示和 Ghost。

原生绘画层是贴在基础面上的轻微偏移面：颜色输出中可以有覆盖层，**遮蔽输入不能把基础面和绘画面当两层真实几何互相遮挡**。建议使用基础模型的深度/法线代表该表面，颜色阶段再正常显示绘画层。

辅助显示可使用独立渲染层/阶段，但保留原有深度遮挡语义：结构边线不能突然穿墙可见；原本允许始终显示的操作轴可保留原行为。不得无条件 clearDepth 后把所有线画到最前面。剖切面与隐藏状态也要传给深度阶段，不能出现“已剖掉的部分仍遮黑下方模型”。

### 6.4 性能与降级

凹槽增强独立开关；灰模/柔光默认低，侧光默认中，原色强制关。可使用较低分辨率效果缓冲与适度滤波，具体质量在 M1 用当前环境实测确定。

隐藏视口不渲染后处理；窗口零尺寸不创建异常 render target；resize、关闭窗口、切工作区时正确更新或释放资源。尽量复用 render target，避免拖滑条就创建一个新 composer。

若当前 GPU 或本地依赖下不能稳定启用增强，提示“凹槽增强未启用”，仍提供四个基本观察预设。不许 UI 显示“开”但实际无效果。正常目标环境无法完成稳定凹槽增强时，交接标为部分完成，不把其偷偷替换为加黑格线后报全绿。

本轮不要求额外 AO 贴图、烘焙流程或网络资源；不把视口增强传递到导出模型。

开工重新核对 TOOL-010 / TOOL-011 最新提交与本地未提交修改。不要使用旧计划的 schema 或“每画布一个物体”等历史假设。本任务只改它们的显示接线和必要回归，不顺手完成其余未验收阶段。

有并行执行者时先划清 `renderer.ts` / `view.ts` / `surface-paint-layer.ts` 等共享文件的所有权。接在可核验的阶段提交之后实施；不得强制重置或把另一任务的 dirty 一起提交。

### 9.3 颜色与增强的具体证据

- 原色校准使用已知不透明色块，例如 `#404040/#808080/#C0C0C0` 和两种非灰颜色；采样平面中央，不采抗锯齿边、选中覆盖或透明合成处。
- 在同一受控 sRGB 输出环境，建议 RGB 通道误差控制在 2/255 以内作为初始自动判据；超出需调查实际管线和读回方式，不能随意放宽。该数值不代表显示器校准结果。
- 同色基础面与彩绘面在相同法线和照明条件下应没有可见接缝；若计算上相同但截图不同，检查偏移、AO 双层和贴图采样。
- 凹槽关/开对比要求 U 槽内角出现局部差异，而远离遮挡的平面不整体变暗；可结合少量像素区域统计与人工截图检查，不建立跨所有 GPU 的苛刻逐像素快照。
- AO 关/开不能改变拾取、画笔落点或裁剪后的可见轮廓；不能用假的阴影纹理遮盖真实错误几何。

### 9.4 性能验证

用小型校色样例和一个现有中等岩体/试摆样例，记录同机、同分辨率、同镜头下：增强关/低/中、相机旋转、绘画更新、预览替换时的帧间隔统计与资源计数。

记录实际硬件/窗口像素/DPR、样例大小、是否软件渲染；CPU render() 提交耗时不能直接当 GPU 帧耗时或 FPS。检测约20轮切换后 renderer.info 等资源计数是否持续增长，允许首轮缓存建立后稳定。

不预先承诺任意大模型60FPS。若低档增强仍显著拖慢当前常用模型，先降低效果缓冲或采样成本，明确降级；禁止自动改变模型精度、删面或抹掉贴图来换帧率。

## 11. 风险与禁止的“假完成”

| 风险/错误做法 | 必须采用的处理 |
|---|---|
| 只把半球光/方向光强度提高 | 增加用途明确的材质显示与灯光方案，校准过曝/暗面 |
| 四个按钮实际只改背景色 | 每个预设验证材质路径、灯组和效果差异 |
| 灰模后直接改 palette，或把灰色 PNG 保存成材质 | 仅显示覆盖；作者源与导出不变量验真 |
| 基础面受光，绘画面仍 Basic | 同一受光模式统一路径；实际同色面接缝测试 |
| AO 把绘画覆盖层当双层几何 | 颜色与深度角色分离，去掉重复遮蔽 |
| 随便给整场景 overrideMaterial | 按表现角色适配，保留操作轴/参考图/透明裁切 |
| 开增强后选区线条穿墙、Root 变灰 | 保持辅助层颜色与原深度语义 |
| 新建/Undo/随机化后材质回默认 | 在对象生命周期和几何重建接点应用当前显示 |
| 切显示被当作“其他编辑”取消岩体预览 | 显示事件不进入作者编辑事务，不清理冻结草稿 |
| 双视口共享同一可变材质造成串色 | 每视口覆盖状态隔离，共享源只读 |
| 灰模污染持久缩略图 | 独立固定有色缩略图配方 |
| 开发窗口成功、EXE遗漏 addon/本地资源 | 实际便携包启动测试并核对 build-info |
| 公开网页版本与仓库依赖不同 | 以锁定版本实测，禁止盲升依赖 |
