# 星骸 Spine 动画工坊

桌面工坊默认打开 **Spine → Spine**：读取两个角色的 Spine 4.3 完整导出，记录异名骨骼和控制器的对应关系，把选中动作的兼容时间线追加到目标角色的完整 JSON 副本。原有 **GLB 模式**可从右上角进入；其操作记录仍见 [SPW-01 交接](../../docs/tasks/SPW-01/handoff.md)。Windows 便携包制作见 [packaging.md](packaging.md)。

## 准备素材

1. 分别从 Spine 4.3 导出来源和目标的完整 `.json`、同名 `.atlas`、atlas 引用的所有贴图页。每个角色的三类文件放在各自目录内。旧版 `.spine` 应先由官方编辑器打开工作副本并导出 4.3；不能只改 JSON 的版本号。
2. 保留目标角色的**原 `.spine` 工程**和全部贴图。工坊产生的是完整 JSON 副本，不替代可编辑的原工程。
3. 启动便携包中的 `星骸 Spine 动画工坊.exe`；源码启动依次运行 `pnpm install --frozen-lockfile`、`pnpm build`、`pnpm start`。

## Spine → Spine 工作流

1. 载入源和目标的 Spine 导出。窗口会核对版本、atlas 和贴图页；左右预览各使用自己的角色素材。
2. 选择源动作、源/目标皮肤，并填写实际对应方向。方向字段用于约束配置的适用范围，不会自动变换视角。
3. 查看同名候选，逐项设定骨骼、约束、槽、附件或事件映射。检查侧别、父链和权威驱动。依赖列表只列该动作实际打键的通道；无法移植的通道须明确标记为跳过并审阅原因。
4. 需要时在当前动作内加入局部旋转或平移修正。完整片段保留原关键时间和曲线；当前尚不能保证精确截取的片段会被阻止生成。
5. 选择输出目录，生成候选，逐时点对照两侧动作及逐通道报告。**显式跳过的通道不构成已迁移内容；“需目标校准”的键虽写入候选，仍须在目标骨架上校准。**状态会显示“部分迁移候选”。预览成功后保存，得到独立的 `SPW-02_.../` 文件夹，其中有目标完整 JSON、atlas、贴图、配置和迁移报告。
6. 保存映射配置。关闭并重开工坊后，重新载入相同骨架的两份导出与配置，选择第二个动作。角色对象映射会复用；新增动作依赖、通道策略和局部修正分别核对。换来源、目标或参数后旧候选立即失效，必须重新生成。

若要把第二条动作追加到第一条的**同一份完整 JSON 副本**，将第一轮保存目录中的目标 JSON 连同 atlas/贴图载入为下一轮目标，重新生成第二条后保存到新目录；核对配置目标骨架身份和最终动画列表。这个步骤仍只生成 JSON 输出，后续原生 `.spine` 导回按下节操作。

本轮真实样本 `rhiny → rozeul` 使用同一份角色映射验证 `city/interact` 与 `common/talk1`。前者 12 条、后者 13 条通道需目标校准；174/175 条分别明确跳过。两条均为**部分迁移候选**，不能直接当作完整成品动作。试选的 `run` 已淘汰，不属于正式验收。配置、报告和样本位置及逐项结论见 [SPW-02 验证记录](../../docs/tasks/SPW-02/validation.md)。

## 导回可编辑工程

1. 在 Spine 4.3 的 **Import Data** 中打开输出目录的完整 JSON，检查 atlas/贴图及新动画，再把这个临时工程保存为 `.spine`。
2. 打开目标**原 `.spine` 工程的工作副本**，用 **Import Project → Animation** 从临时工程导入新动画。逐项核对缺失对象警告及关键帧；不要把“完整 JSON 导入的新工程”当成原工程的无损副本。
3. 保存、关闭并重开目标工作副本；修改一个可见关键帧后再次保存/重开，以确认后续可编辑。操作路径见 [Spine 官方导入说明](https://en.esotericsoftware.com/spine-import)。

## 当前能力边界

Spine → Spine 模式只接收 Spine 4.3 完整导出；不自动重绑、移植不同拓扑的网格 deform、重建其他方向或修复不兼容的 IK/附件。配置会阻止未处理的打键通道；选择“显式跳过”后仍须人工判断动作是否足够完整。`GLB 模式`保留 SPW-01 的三维来源流程，其地面原地化和俯角参数不作用于 Spine 来源。
