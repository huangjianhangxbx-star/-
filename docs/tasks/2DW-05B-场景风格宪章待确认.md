日期：2026-10-10。状态：**M0 已整理，待内容审阅；未接入工坊默认配置。**

本稿把已表达的意图、实际看图结果与新增建议分开。下面拟注册的规则均为 `candidate`；“有用户来源”表示可追溯，不表示用户已经批准这次规范化表述。05A 已有项目契约仍按原规则工作。

## 先看这四项

建议批准以下方向，再进入计划 M1–M8：

1. **场景共用总纲：**成熟的二次元手绘环境美术，以清楚结构和克制块面为主；可借鉴赛璐璐明暗组织，但不强制所有物件纯两色。不扩展到角色、UI、特效。
2. **质感边界：**允许很弱、整体化的材质变化；避免密集精修，也避免塑料感、儿童绘本式的机械几何平涂。概括不等于清空一切材质可信度。
3. **层次与主次：**保留 05A 默认暗部最多 3 阶、亮部最多 3 阶；“约 6:3:1”仅为形状主次的视觉启发，不变成像素比例或数量公式。软件核对填写的预算，图片是否符合由看图审阅判断。
4. **首版材质：**先做石材与木材两个接入样例。石材沿已观察方向提炼；木材细则仍为实验候选，不声称已获成图认可。土壤、金属、植被先登记身份与待补状态。

可以全部接受、按规则 ID 部分接受、修改或仅留作实验记录。接受第 4 项表示允许木材候选验证，不自动批准每条木材画法。

## 独立失败信号

以下均为候选人工/外部 AI 看图检查点，不表示工坊已经能检测或已验收通过。版本 `0.1`，类型 `failure-signal`，范围 `environment`，状态 `candidate`。

| 规则 ID | 需要判错的信号 | 应检查什么 |
| --- | --- | --- |
| ENV-FAIL-01 | 过密精修 | 微纹理、小高光、精细暗部遮盖了大形与结构。 |
| ENV-FAIL-02 | 廉价塑料平涂 | 细节虽减少，却变成空洞、均匀、机械的卡通多边形。 |
| ENV-FAIL-03 | 高亮过白、过粗、过碎 | 普通转折被整圈亮线或密小锯齿抢走注意力。 |
| ENV-FAIL-04 | 暗部过细或机械几何 | 深色处仍细描；或相同斜面切分出现在不相关物体上。 |
| ENV-FAIL-05 | 破败过碎、识别点过强 | 碎口/裂缝平均分布，重复素材出现显眼重复标记；后者只在明确重复/联通任务触发。 |
| ENV-FAIL-06 | 石材画法污染其他材质 | 木材、土壤、金属、植物都使用同类石缝、裂纹与灰绿色。 |

来源：U1–U4、P1 与 V1/V4/V5 的综合提炼。审阅时说明触发对象与图像位置，不仅给出“AI 感”标签。

## 接入方案与审批边界

推荐采用附件中的增量四层方案：`projectStyleContract` 保持项目总入口，场景层保存唯一规则 ID 与来源；`spec/asset-spec.json` 保持单一权威，其他风格文件只作派生镜像。新版本候选为场景风格 `/1`、规格 `1.2.0`、ZIP `/4`，仍需 M1 根据实际校验器确认。旧 ZIP `/1`–`/3` 与非场景任务不改解释。

两种替代做法不建议采用：继续拼接整段 Prompt，虽改动小却难追溯与去重；重建独立同级宪章，虽分离清楚却制造两套权威和迁移成本。增量方案能复用 05A 的契约、偏移、表单及导出校验。

本轮只完成 M0。按附件 §4.1：“交付这份草稿后，必须停在用户审批点”。待本稿内容获批后，再整理批准/保留候选清单并进入 M1–M8：模型与迁移、规则解析、桌面接入、ZIP、三类样例、模块验证、选择性 GitHub 发布。不会把测试通过当成美术批准。

审阅回复示例：“批准上述四项及候选稿，木材保持实验候选，继续 M1–M8”；也可指出要改的规则 ID。
