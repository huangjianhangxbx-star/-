## 1. 本阶段目标

让“双人包夹、绕后、吸引朝向”第一次具有真实战术意义。

本轮建立：

- Front / Side / Back 严格方向判定；
- 可配置的 DirectionalProfile；
- HP / Posture 的方向倍率；
- Weakpoint 基础语义与事件；
- 当前 Heavy 作为方向机制样板；
- 最小弱点反馈与 Debug 朝向可视化；
- 与 EC-05 Break / WallPin 的真实联动。

核心原则：

> **不做所有敌人统一的“背击×1.5”。**

方向分类是公共规则，但“正面、侧面、背面意味着什么”由目标自己的 Profile 决定。

## 3. 方向权威：目标朝向

方向判定以目标自身的 `heading` 为权威。

如果 `heading` 暂时不存在，则由当前 `facing` 转换：

- east = 0
- south = π/2
- west = π
- north = -π/2

不能使用：

- 镜头方向；
- 屏幕上下；
- 地图固定方向；
- 攻击者自己的朝向。

---

## 4. Front / Side / Back 划分

首版：

### Front
目标正前方 ±60°，总计120°。

### Back
目标正后方 180° ±60°，总计120°。

### Side
剩余区域，左右各约60°。

这样不要求玩家必须精准卡180°，同时仍保留真正的侧面区域。

---

## 5. 核心方向函数

建议新增：

```text
core/directionality.ts
```

提供：

```ts
type HitDirection = 'front' | 'side' | 'back'

hitDirection(target, hitOrigin): HitDirection
```

使用：

```text
target.pos → hitOrigin
```

相对：

```text
target.heading
```

计算。

方向边界必须有固定 epsilon，避免同一站位在Front/Side之间抖动。

若攻击来源与目标几乎重合：
> 返回 neutral/side，不触发Weakpoint。

---

## 6. Hit Origin

方向判定不能永远简单读取 `attacker.pos`，因为以后会有延迟效果、地面效果和派生攻击。

建议给 `HitOptions` 增加：

```ts
hitOrigin?: Pos
```

规则：

### 直接 basic
默认 `attacker.pos`。

### 明确的直接技能 / 投射物
可以显式提供真实来源点。

### derived / delayed / field
如果没有显式 `hitOrigin`：
> 默认 Neutral，不参与方向弱点。

这样不会出现：
> 地面残留效果因为施法者此刻站在怪物背后，就被错误算成背击。

---

## 7. Directional Profile

建议：

```ts
type DirectionalZoneRule = {
  healthScale?: number
  postureScale?: number
  weakpointId?: string
}

type DirectionalProfile = {
  front: DirectionalZoneRule
  side: DirectionalZoneRule
  back: DirectionalZoneRule
}
```

Unit / enemy definition 持有：

```text
directionalProfileId
```

不要把规则硬编码成：

```text
if role === heavy
```

未来 EC-15 可以让同一种基础敌人使用不同方向结构。

---

## 8. 默认 Profile 完全中性

默认：

```text
Front: HP×1 / Posture×1
Side:  HP×1 / Posture×1
Back:  HP×1 / Posture×1
```

因此：

> 不是所有敌人都有背后奖励。

这是本阶段的重要验收项。

---

## 9. 第一个方向机制样板：当前 Heavy

EC-06 不新增敌人类型。

把独立暗牢现有 Heavy 暂时当作：

> 正面装甲 / 后方核心

的机制样板。

这只是战斗验证设定，不宣称最终美术和世界观已经锁死。

---

## 10. Heavy 首轮 Directional Profile

### Front

```text
HP Damage × 0.65
Posture Damage × 0.70
```

代表正面装甲。

### Side

```text
HP Damage × 1.00
Posture Damage × 1.00
```

### Back

```text
HP Damage × 1.25
Posture Damage × 1.35
Weakpoint = rear-core
```

代表后方弱点。

这些都是原型测试参数，不是最终平衡。

---

## 11. 为什么同时影响HP和架势

如果背后只有伤害加成，最终容易退化成普通DPS乘区。

本项目已有 Posture / Break，因此后方弱点还应：

> 更容易制造 Broken。

理想双人过程：

```text
猎人正面牵制
↓
阿尔绕后
↓
Back命中更快削架势
↓
Heavy Broken
↓
高Impact攻击触发Break
↓
WallPin
```

方向系统应该与 EC-05 连起来，而不是平行存在。

---

## 12. 倍率应用顺序

### Posture

```text
base postureDamage
× directional postureScale
→ applyPosture
```

### HP

继续先算既有防御：

```text
damageAfterDefense
```

再应用：

```text
× directional healthScale
```

然后进入 HP / gray / reclaim 相关流程。

这样方向装甲和固定防御职责清晰。

---

## 13. 本轮方向不修改 Impact

EC-06 不让 Back 额外增加击退距离。

Impact仍由：

- EC-05 ImpactSpec；
- ImpactWeight

决定。

避免一次加入太多耦合。

## 14. Weakpoint 基础事件

真实命中一个带：

```text
weakpointId
```

的方向区域时，生成：

```text
WeakpointHit
```

至少包含：

```text
targetId
sourceId
weakpointId
direction
```

未来可以供：
- AI；
- 技能行为标签；
- 怪物知识；
- 音效；
- 特效；
- 锁定系统

消费。

---

## 15. Weakpoint 从第一次遇到就真实存在

EC-06 明确：

> Heavy 的 rear-core 从第一次见到怪时就是真实弱点。

玩家即使还没有怪物知识：
> 自己绕后打中，也获得真实收益。

未来 EC-12 改变的是：
- UI告诉多少；
- 是否显示弱点；
- 是否允许辅助锁定；

而不是让弱点到高知识等级才凭空出现。

## 16. 普通UI不做常驻弱点标记

本轮不显示永久红点。


## 18. 被打不能先自动转向

方向判定顺序必须是：

```text
记录 hitOrigin
↓
读取受击前 target.heading
↓
判定 Front/Side/Back
↓
伤害 / 架势结算
↓
之后 AI 才可能在后续模拟步决定转向
```

不能：

> 阿尔从背后射中Heavy → Heavy先瞬间转向阿尔 → 系统判成Front。

本轮不新增“受击自动转身”。

## 19. EC-04 Facing 继续复用

- Tracking阶段有限转向；

- 猎人在Back普攻，也能Weakpoint；
- 阿尔在Back普攻，也能Weakpoint；
- AI角色自然站到Back时，也应得到真实收益。

未来不同角色只是“利用弱点的方式不同”。

## 27. 与 EC-05 的连接

典型流程：

```text

↓
阿尔在Back攻击
↓
更快削Posture
↓
Broken
↓
阿尔强化箭再次命中
↓
Break Reaction
↓
ForcedMotion
↓

```

职责分离：

- Direction：制造更优Break条件；
- Break：产生控制窗口；
- Impact：决定移动；
- WallPin：兑现空间控制。

# 32. 用户试玩重点

## A. 绕后是否真的值得

是否自然产生：

> “让猎人正面顶住，我切阿尔去后面。”

如果没有：
- Front惩罚可能不够；
- Back收益可能不够；
- 朝向不稳定；
- 绕后成本过高。

先判断原因，不直接堆倍率。

## B. Heavy会不会太烦

正面：
```text
HP×.65
Posture×.70
```

需要判断它是：
- “提醒我绕后”
还是
- “强迫我浪费时间绕后”。

如果后者，优先减轻正面惩罚。

## C. 朝向是否可读

没有Debug时，玩家能否从角色动作和身体朝向理解Front/Back。

如果不够清楚：
> 记录为未来美术可读性问题。

Debug扇区不能成为正式游戏的永久拐杖。

## D. 双人包夹是否稳定

Heavy锁猎人时，阿尔是否能稳定绕后。

若敌人频繁转头：
> 后续 EC-08 需要考虑Facing Commitment / Target Commitment。

## E. 是否与Break真正连起来

最理想：
> Back不仅多伤害，而且明显更快制造Broken和WallPin机会。
