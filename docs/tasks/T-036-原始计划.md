## 0. 本轮目标：回到原 EC-10，不恢复旧 Command Mode

本轮只增加：**不切换实控角色，也能给离手的另一名本体下达简单战术意图。**

```text
实控猎人，阿尔由 AI 作战
```

## 3. 玩家操作契约

### 3.1 打开、选择、提交

首版建议：**按住 G 打开，鼠标选择四个方向，松开 G 提交一次。**

| 方位 | 指令 |
|---|---|
| 上 | 集合 |
| 右 | 集火我的目标 |
| 下 | 保守 |
| 左 | 自由行动 |

中心是取消区，不默认选中任何指令。按住后完全没有选择就松开，不下令。RMB 或 Escape 取消；取消后即使 G 仍按住，也要等待一次真实抬起、再按下才能重开，避免键盘 repeat 重启。

轮盘在打开时的鼠标位置附近出现，按视口边缘钳制；**不能移动系统鼠标**。使用最终可见轮盘中心计算扇区。边缘钳制不能导致刚打开便自动选中：必须有实际指向扇区的鼠标位移。首测外半径约 130 CSS px、中心取消半径约 30 px，可统一配置，不作为长期美术尺寸。

鼠标是四扇区选择器，不再追着世界单位改变目标。轮盘中心显示「给谁下令」，集火项同时显示已经解析出的敌人名称。

### 3.2 打开期间的角色与 AI

- `controlledBodyId` 不变，主技能条、机动资源和镜头 Primary 不变。
- WASD 已持有和新按下都继续控制同一个 DirectActor，**不会自动切人，也不会为轮盘清掉有效移动键**。
- 离手 AI 继续按旧策略行动，直到有效提交新指令；打开、移动鼠标、取消均不改变它的策略、订单或资源。
- 已经提交的攻击／技能正常执行。轮盘不授权新的实控自动普攻，也不新增原主控自动防御托管。
- LMB 在轮盘打开期间被消费，不普攻、不点头像、不触发场景事件，也不作为第二套确认方式。关闭后，曾在轮盘里按下的鼠标抬起不能穿透成普攻。

### 3.3 快捷动作与更高优先级界面

这是键盘通道与鼠标通道的分别路由，不能把轮盘粗暴加入 `controlModal()` 从而把 WASD 全封掉。

| 输入／事件 | 轮盘行为 | 原功能 |
|---|---|---|
| WASD | 维持打开 | 当前角色移动 |
| E/R/T 或 Shift | 先取消轮盘 | 同一次输入按现有规则操作当前实控角色；鼠标方向取真实场景坐标，不把扇区当世界目标 |
| C/1/2 | 先取消轮盘 | 同一次输入显式切人；有效 WASD 交接按 T-035 保持 |
| F | 取消轮盘 | 同一次输入开始当前角色 PathAim |
| H/B/Q、Tab、背包／构筑等明确功能入口 | 取消轮盘 | 延续原入口的合法性、对象和资源规则 |
| Space／暂停按钮 | 取消轮盘 | 再处理暂停，恢复后不补交指令 |
| RMB／Escape | 只取消轮盘 | 不再追加通用取消动作去清 MoveOrder 或其它角色状态 |
| blur、页面隐藏、pointer cancel、窗口尺寸改变 | 取消轮盘 | 清未提交输入；恢复页面不补交 |
| Direct 失效或自动换人、接收者离场、场景／副本结束 | 取消轮盘 | 不重选接收者，不自动提交 |

已有 PathAim/SkillAim/召影/卡牌/经济确认、文本输入、拖拽、暂停或页面隐藏时，G 不抢占它们；拒绝打开并保留旧状态。普通离手角色正在合法动作、硬直或有 MoveOrder 不等于不能打开轮盘；能否接受具体指令由核心查询决定。

### 3.4 时间倍率

轮盘可见且有效期间加入独立 `wheelScale=0.1` 来源；关闭、取消、失焦立即移除此来源。

```text
有效倍率 = 已有基础／模态倍率与 wheelScale 中较慢者
暂停／页面隐藏仍按已有规则得到 0
```

不要写回基础倍率，不在关闭时粗暴设置 1×。用户此前选 2×，轮盘关闭后仍回 2×；其它模态仍在时继续其倍率。轮盘动画、鼠标与 UI 使用真实时间，战斗、AI 与指令时限使用模拟时间。

**不用 `s.tacticalFocus` 复活切人慢动作。** T-035 的 ensure 会清它；本轮应新增可组合的轮盘慢速来源，而不是与 ensure 对写。

## 4. 接收者：下给实际角色，不下给一个会变化的“伙伴槽”

打开时解析并快照：

```text
issuerId = 当前 DirectActor
recipientId = 另一名合法、在场、离手的本体
```

猎人实控时通常接收者为伙伴；伙伴实控时接收者就是猎人。不能写死 `id !== 'hunter'`。复制体、敌人、后备角色不是接收者；没有合法离手本体时拒绝打开。

打开后不因 HUD 查看对象或场景鼠标改变接收者。提交前再次校验：副本、实控身份、控制变更序号、接收者本体资格及有效性。两次切人后又切回，也不能让旧轮盘会话重新合法。

轮盘 sessionId、请求去重和控制 revision 应为轻量状态；有现成标识就复用，没有则增加最小序号。它们不是第二个控制身份，也不需要网络协议或长队列。

## 5. 四项指令的真实行为

### 5.1 集合：先靠近当前主控，不瞬移、不收纳

含义：**暂时停止主动接敌，沿合法路径靠近发令的实控角色，抵达后恢复自由行动。**

- 不是去玩家开轮盘那一刻的位置；在此次指令仍有效、主控未切换时，跟随该主控的 live position 重算附近安全落点。
- 建议在主控周围约 1.2–2.0U 选择可站、可达点；完成要检查真实可达的邻近关系，不能隔墙但直线距离近就宣布抵达。
- 已在合法附近，成功反馈「已在附近」并直接完成，不反复走一步再返回。
- 集合期间优先赶路，暂不新开自主普攻或新的进攻性身体动作；已经提交的攻击、技能、机动和跨层正常结束。后台模式、充能与已生成世界效果不删除。
- 高威胁技能规避仍可临时打断集合；消耗真实资源。不能为了「听话」穿红区，也不能为普通平 A 恢复无条件闪避。
- 不额外增速、不发无成本 blink、不直接改 `Unit.pos`。
- 接近主控可复用现有 regroup 的导航策略／非战斗跟随安全能力，但不能直接调用旧 H/B 的 `requestParty('regroup')`：旧路径包含瞬移归位与以猎人为中心的语义。[R6]
- 在非战斗也可下令，靠近后回原跟随；不主动开怪。
- 临时挡路定期重试；持续无法接近则有上限地结束并提示，不永远挂住。

### 5.2 自由行动：恢复战前倾向和正常 AI

清除当前轮盘特殊战术，按该角色已有 AITendency、职业、战斗／非战斗环境自主行动。

不把用户的 `aiTendency` 改回 default，不恢复旧锚点，不清真实资源。自由行动不暗中删除玩家 F 指定的精确 MoveOrder；有订单时先完成它，再自由行动，UI明确提示。

### 5.3 集火我的目标：优先处理一名明确敌人

不是远程按下某个技能；不强迫 AI 使用尚未授权的 Manual 技能。

目标在**打开轮盘前**解析并冻结：

1. 优先鼠标当时明确指向的合法敌人；
2. 没指到敌人时，可回退到当前实控角色最近一次已实际提交的手动普攻目标，建议时效不超过 2 模拟秒；不能把待执行缓存当作已提交攻击；
3. 两者都没有就禁用集火项，并显示「无有效目标」。不偷偷挑最近敌人。

合法候选必须是活着的敌人、当前可见并属于已激活交战范围，且没有进入 return；不以集火开启尚未接战的房间。只为本轮建立可解释的候选来源，不扩成完整锁定系统。

扇区显示「集火：敌人名」，目标有一个轻量标记。鼠标移向右侧扇区、镜头移动、目标死亡，都不能把候选悄悄换成另一只。

接受后：

- 战术目标与**实际普攻选敌**都优先指定对象。不能只改 `companionCombat.targetId`，结果引擎排序仍一直攻击另一只。
- 沿已有合法攻击位置查询和职业射程接近／输出；生存规避、原子动作与防穿未交战区仍优先。
- 指定目标短暂不可见，只用已知位置／现有合法记忆；不读取消失后的真实坐标完美追踪。超出短记忆窗口、死亡、return、脱战或失去安全贡献路径过久后结束，并回自由行动。
- 不自动把目标换成下一只；需要再次下令。
- 范围普攻／既有 Auto 技能原本能波及其它敌人则保持，但不重写各技能内部索敌或技能内容。

### 5.4 保守：降低冒险站位，仍然正常作战

不是原地待机，也不是收到指令就无限逃跑。

- 提高危险位置代价、减少长距离绕后与追击，更重视与当前主控的距离；安全、可攻击的位置仍可普攻。
- 使用已有 AITendency 作为基础，再施加临时战术权重；不能覆盖战前保存值或 Profile。
- 不修改 HP、防御、速度、命中、闪避资源；不提供额外无敌或完美预判。
- 当前 Ability 防御继续遵守反应延迟、可见信息与资源约束；不新增「优先治疗」手动技能 AI。
- 首测可以提高位置 risk 下限、降低 flank 上限、提高 separation 下限；数值集中到参数对象，保留原 commitment／改善阈值防止高频横跳。

## 6. 指令持续方式与切人规则

首版对玩家展示为**四项互斥**：新指令成功接收后取代该角色上一项轮盘指令。不做隐藏组合、战术队列或自动恢复旧「集火」。

| 指令 | 结束方式 |
|---|---|
| 集合 | 到达主控附近、超时／无法安全执行、接收者被直接接管、有效新指令或副本／角色失效 |
| 集火 | 目标死亡／return／失去有效交战或记忆／长期不可达、接收者被直接接管、有效新指令或失效 |
| 保守 | 同一 Run 内保持；被直接操作期间不控制玩家，切回离手后仍按保守；自由行动或其它指令替换 |
| 自由行动 | 默认策略；没有额外战术约束 |

集合／集火结束后回自由，不恢复此前隐藏的保守状态。新 Run 重置自由。

**战术状态绑定 recipientId，而不是自动追随“现在谁是离手者”。** 例如给阿尔保守，切阿尔实控后，猎人不会凭空继承保守。

接收者倒地、收纳、离队、死亡时清特殊指令并反馈；复归不自动续旧集火／集合。若保守也被清理，统一回自由，避免复归状态不明确。副本退出／重开清全体战术状态。

只有新的控制身份不变的情况下，打开／关闭轮盘才完全不动策略。真正切人仍按 T-035：旧角色完整离手 AI、新角色撤销普通 AI 路线、资源和原子动作保留。

## 7. 与 MoveOrder、H/B 和动作生命周期的关系

### 7.1 不是所有「下命令」都等于取消所有订单

| 新输入 | 接收者已有 MoveOrder | 当前实控者的 MoveOrder |
|---|---|---|
| 打开／hover／取消轮盘 | 保留 | 保留 |
| 自由行动／保守接受 | 保留；策略在订单约束下生效，不能重写目的地 | 保留 |
| 集合／集火接受 | 这是明确的新目标意图，**接受成功后取消接收者旧订单** | 保留 |
| 集合／集火验证失败 | 保留原订单与原战术，绝不先取消后报错 | 保留 |
| 玩家以后切到该角色，F 确认新目的地 | 清集合／集火等旧临时目标，精确订单接管；保守不覆盖订单 | 按原订单契约 |

轮盘 hover「集合／集火」时，若会取代接收者订单，显示「将替换阿尔当前移动目标」；不额外增加二次确认弹窗。

### 7.2 既有高层任务

接收者已在收纳、救援、撤离或明确 partyTask 中时，集合／集火先拒绝并说明，避免把这些动作截断。自由／保守只能改变后续战术偏好，不能改该任务本体。

H/B 保持旧功能，不把轮盘四项硬塞进 `party:{kind:'recall'|'regroup'}`。如果 H/B 真正被某角色接受，清该角色冲突的集合／集火；拒绝的对象不清。不要顺便全面重做影庭或 H/B。

### 7.3 身体动作

普通 AI 路线可以让位给新轮盘目标，已提交的 Basic／Skill／Evade／ForcedMotion／Crossing 不因轮盘直接清除。

指令可被接收并标记「待当前动作结束」，而不是强行排入一个技能队列。身体恢复后按最新有效战术决策；原子动作等待与真实阻塞应区别记录。

危险规避在物理允许时优先；集火不等于硬吃大技能，集合不等于花免费闪避赶路。

## 8. 最小架构：一个战术层、一个轮盘工具

建议新文件（尚不存在，实施时可按实际结构等价调整）：

```text

game/src/tactical-wheel.ts           G会话、扇区选择、UI和鼠标事件消费
```

不新建完整 AI、寻路、技能执行器或第二份 DirectActor。

推荐最小核心状态：

```ts
type TacticalKind = 'free' | 'rally' | 'focus' | 'cautious';
type PartyTactic = {
  recipientId: string;
  issuerId: string;
  kind: TacticalKind;
  targetId?: string;
  issuedAt: number;
  execution: 'pending-body' | 'active' | 'blocked';
  reason?: string;
  lastKnownTarget?: { point: Pos; seenAt: number };
};
```

按角色保存，free 可用缺省表示。引用已有 Unit / Pos，不保存另一份血量、CD或角色实体快照。计时与状态只存必要数据；ready、目标有效性等能查询就不复制成多个布尔真相。

UI `WheelSession` 与游戏里已接受的 `PartyTactic` 分开。Session 保存打开时的发行者、接收者、控制 revision、候选目标、屏幕中心、所选项及唯一请求身份；**不写入旧 `explorationControl.aim.source='command'`**。

建议核心接口：

```text
queryPartyTactic(...)       无副作用预检
issuePartyTactic(...)       校验、接受、必要订单覆盖与一次状态提交
clear/finishPartyTactic(...) 带原因收尾
partyTacticFor(...)         当前有效策略
```

引擎命令只需一种可判别请求，类似：

```ts
{ type:'partyTactic', issuerId, recipientId, kind, targetId?, requestId, expectedControlRevision }
```

重复请求不得重复取消订单／重启行为。校验失败不改变角色、当前战术或订单；UI反馈与日志可以记录拒绝原因。不要在每个 tick 反复提交同一指令。

## 9. AI 接入位置与三个容易漏的点

### 9.1 不复制 `advanceCompanionCombat`

在既有 AI 流程中增加战术查询：

```text
失效／实控者 → 不运行离手战术
原子动作／高层合法任务 → 等待
已有精确 MoveOrder → 仍按订单规则
技能危险 → 现有防御
集合分支 → 靠近主控
集火分支 → 指定目标与安全贡献位置
自由／保守 → 正常选敌与位置评分（保守只改变有效权重）
```

普通攻击起手在引擎另一个位置，必须与本次战术选择对齐。集合要能阻止新自主攻击拦住赶路；集火要能实际影响命中对象。不能只改 Debug 标签就认为实现了命令。

### 9.2 路径所有权

集合的路线由战术 AI 持有，不伪装成玩家 `direct` 输入，不误用 `claimControl('direct')`。沿用既有路径所有权或增加最小标识，收尾只清自己拥有的普通路线，不能清技能落位／强制位移／玩家新路径。

非战斗集合与 `followParty()` 必须只有一个写路者；集合有效时 Follow 让路，到达后重新允许 Follow。集合可离开旧战斗域接近主控，但继续检查 inactive encounter 风险；没有安全路线就反馈，不直接 teleport。

### 9.3 临时策略不改永久倾向

用统一的 effective weights 查询同时服务本轮位置评分，必要时传给现有防御查询；不要临时赋值 `u.aiTendency` 再恢复，也不要修改 Profile。

当前 Ability 防御已经可用。本轮不发明概率闪避、治疗逻辑或技能协同评分。Manual 技能权限继续关闭，AUTO/BG 在未与集合的身体动作让权冲突时保持原规则。

## 14. 必须保留的真实浏览器场景

### S1 边走边下令，主控不变

真实按住 W 操作猎人，不松 W 按住 G，选保守或集合，松开 G。检查全程 `controlledBodyId` 为猎人，伙伴被正确接收，W 不被吞，关闭后恢复原倍率。不得用只在静止状态的测试替代。

### S2 反向下令

先通过真实 C 切阿尔，再开轮盘。接收者必须是猎人。给猎人集合，猎人沿路靠近阿尔，阿尔的主技能栏与镜头主目标不变化。

### S3 集合不是旧瞬移

在同一可达房间拉开距离，命令集合。记录连续位置样本、真实导航与到达；位移符合运行时速度，不能一次跳到目标或凭空消耗/增加 blink 资源。路上有技能危险时允许规避，之后继续集合。

### S4 两个敌人的真实集火

固定两个已激活可见敌人，鼠标指向非最近的一只，按 G 后移向集火扇区再松开。检查指定目标锁定不随扇区鼠标改变，AI真地接近/攻击该敌人。该目标死亡后不默默换下一只。

### S5 保守与自由的成对对比

同一固定敌群和位置、同样资源，分别选择保守和自由。记录目标、路径、风险评分和命中；保守更少选择高风险长绕路，仍有安全输出。随后自由应恢复原战前倾向，而不是写成 default。

### S6 MoveOrder覆盖与拒绝

伙伴已有 F 订单，切回猎人。打开／取消、选择保守后订单 id 不变；合法集合后伙伴旧订单被明确取代；对无效目标集火失败，旧订单完整保留。猎人自己的订单不被伙伴指令修改。

### S7 紧急中断

G 打开时按 Shift，先关轮盘，再对原主控尝试真实机动；随后 G up 不补发指令。另测 C 同键切人、F 同键选路，及 LMB 不穿透普攻。

### S8 清理与正常遭遇

失焦／暂停／对象失效后无迟到指令与慢速残留。再跑一段正常遭遇，交替集合→自由→集火→保守并正常切人，不靠手工赋值「已到达/已命中/已躲避」制造结果。

测试夹具可以固定地图、资源、目标和危险时序；实际输入、寻路、命中、资源消耗和结果必须走正常运行。框架测试不冒充真实玩家操作证据。
