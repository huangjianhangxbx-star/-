## 1 本轮要交付什么

交付一座可以跟随鼠标笔迹连续生长、在合理曲率范围内自由转弯、保存后仍可编辑的桥；在同一份线路上，让少量 Tiny Glade 原作源件确实参与 Unity 中的生成，再用已有原创 A/B 套件做供给对照。

这轮结束时，用户应能回答三个问题：

1. 我画出的方向和弯曲，是否就是桥实际生成的方向和弯曲？
2. 原作素材到底怎样进入工具、被哪些部位使用、受到什么变换或限制？
3. 我下一批母件应该提供哪些接口、哪些可变形区域、哪些连接件，才能支持这样的绘制？

**本计划替代 v0.1 中把正交折线、转角平台和“不同中间路线产生不同结果”作为绘制收口条件的部分。**已完成的作者对象、候选事务、撤销、来源映射、保存重开和两套原创素材供给继续复用。旧版计划保留为历史记录；用户对“随鼠标拖拽延伸和转弯”的最新说明是本轮功能依据。

上一版由 AI 提出的“折线加转角平台”范围过窄，允许了不符合用户意图的实现。下一轮需要修改线路、曲线构造和原素材接入，不能以“再补两项桌面测试”代替这些开发。

### 2.2 为什么换素材或只改旋转角度都不够

`RouteSketch.Build` 会把斜向位移拆成先 X 后 Z 或先 Z 后 X；`RouteSolver` 还拒绝同时包含 X/Z 位移的路段，并使用曼哈顿长度、四个方向和全局方格边界。`ReplicaGeometry` 的桥体核心按轴对齐盒输出。限制同时存在于输入、求解和几何层。[S4][S5][S6]

附件中的执行者报告：标高为 0 时，输入 `(0,0)、(5,5)、(10,10)、(15,15)、(20,20)`，得到 `(0,0) → (20,0) → (20,20)`。这是附件所载的运行结果；本次源码核查与其一致，没有重新运行该测试。默认抬高路线还会加入两端台阶节点，但不会因此获得自由走向。[S3][S4]

因此，删除一处正交转换、把朝向改成任意角度，仍不足以让内外侧铺面、栏杆和桥体正确转弯。现有实例消费矩阵可以保留，依赖方格和轴对齐盒的构造必须一起调整。

另外，`ResearchOnly` 目前只用于字段声明和界面文字，不能证明已加载原作素材，也不能当作已存在的导出隔离机制。登记器当前认证的是原创 `bridge-orthogonal-v1` 固定接口族，不能直接视作 Tiny Glade 的母件规则。[S7][S8]

## 3 范围与执行环境

### 3.1 本轮功能范围

支持单座桥的任意水平朝向、平缓 C/U/S 形线路、持续拖拽预览、端点续画、局部线路修改、既有标高调整，以及保存重开后的继续编辑。桥面、两侧收边、栏杆、端头和必要桥体支撑必须随线路更新。

## 4 开发顺序和阶段结果

采用两条可以并行的开发线：A 负责随笔迹生成，B 负责原素材真实接入；二者在同一份路线数据上汇合。

| 阶段 | 具体工作 | 这一阶段必须拿到的结果 |
| --- | --- | --- |
| P0 确认工作基线 | 核对本机差异、保护未保存样例、定位现有原作候选和 A/B 套件，复现斜线失真，固定代表性曲线输入 | 一份准确基线、可重复的失真输入和本轮 U/S 验收笔迹；不重复整轮历史测试 |
| P1A 保留笔迹 | 改采样、线路表示、简化平滑及自由方向编辑；先用现有原创套件验证 | 斜线仍为斜线，缓弯跟随笔迹，拖动时桥体持续更新 |
| P1B 接入原作源件 | 与 P1A 并行，读取少量实际源文件，转换必要网格属性并进入生成调用链 | 原文件到 Unity 网格、到桥上部位的可追溯实际消费；先可在短直段验证 |
| P2 完成曲线构造 | 处理桥面、内外侧边界、栏杆柱距、端头、桥体与碰撞，补齐续画和局部编辑 | 一条平缓 U/S 线路可用，曲线接缝和支撑有明确处理 |
| P3 在同一路线上对照 | 将 P1B 的原作源件接入 P2 线路；再使用现有原创 A/B 套件 | 同一作者线路的原作研究版和原创供给版，角色和来源差异清楚 |
| P4 验收并写供给规范 | 聚焦真实鼠标操作、保存重开、失败恢复和来源反查，沉淀曲线母件使用规则 | 可操作样例、必要证据、母件规范草案和准确交接状态 |

P1B 不以原作模组界面补测全部结束为前置条件。已经能够读取的源件可先接入 Unity；“原作里怎样使用它”和“我方已经真实消费它”分别记录。若某件源数据无法解析，只阻塞相关素材项，不停止独立的线路修正，也不拿原创替身冒充接入成功。

本轮包含求解和资产适配开发，不能给出“再花 5～10 分钟即可做完”的承诺。P0 后依据本机代码差异与源格式复杂度更新开发估计；下文 10～25 分钟是最终模块验证的初始预算，不是全部开发工期。

## 5 A 线实现随笔迹绘制

### 5.1 输入和作者线路

鼠标轨迹先在明确的绘制平面上转换为世界坐标。自由绘制默认不做 0.5 米 X/Z 取整，不将朝向限制为 0、45、90 度等离散值。若保留吸附或正交模式，应由用户主动选用并在界面上明确显示。

在可接受误差内做去噪、简化和必要的平滑，然后按弧长及曲率采样。距离采用实际空间长度；曲线切线和局部横向方向由实际路线产生。平滑不能抹掉明显绕行，简化不能只保留端点或把整条笔迹分类为几个预设形状。

保存的数据应足以重建和继续编辑这条路线，包括控制点、稳定身份、处理参数和版本。原始采样可作为输入证据或调试数据，但不能建立两份相互竞争的权威线路。生成节点、网格和实例均是作者线路的派生结果。

现有 `editable-orthogonal-bridge-route` 文档按旧版本解释。新增格式或版本时提供明确迁移和保存策略，旧样例不因新求解器接入就静默改变外形。已有开口与节点的关联要有迁移规则，不能因为重排节点 ID 随机转移。[S11]

### 5.2 真实连续预览

从按下鼠标到松开属于一次绘制事务。输入持续到来时，候选中的桥面、边缘和栏杆应跟随增长；不能只画辅助线，松手后才一次性出现结构。

允许合并高频事件、简化候选碰撞、复用生成片段。先正确消费最新输入，再根据实测耗时决定局部重建范围，不预先建设大型增量框架。松手时必须消费最后有效采样，最终结果和最后有效预览一致。

继续沿用采用、取消、Esc、一次 Undo 和导航切换的事务语义。非法候选不能清空已采用的桥。预览中断、异常或输入所有权变化时要能回到稳定状态。[S12]

### 5.3 编辑操作

本轮至少支持以下操作：

1. 从一个端点接着自由拖画，接缝处保持已有线路和有效连接。
2. 拖动一个中间控制点或局部线路，使桥在任意水平朝向更新，不退回正交。
3. 调整受支持的标高，桥面、台阶或坡面与支撑按明确规则联动；标高规则可以离散，不能借此重新量化水平走向。
4. 保存重开后重复上述操作，并能撤销一次完整编辑。

本轮不增加大批参数滑块。调参只负责宽度、标高和构造选择等明确属性；路线必须通过空间绘制和编辑表达。

## 6 曲线桥体和母件怎样协作

### 6.1 从中心线生成两侧真实边界

中心线、左右偏移边界、桥面和桥体需要使用一致的空间基准。弯道内侧和外侧长度不同，各侧构件的分配、柱距和接缝要分别计算，不能套用同一排数量后强行挤到两边。

桥面在可行曲率内应形成连续可见表面；侧缘和栏杆不能在内侧严重堆叠、在外侧透空。栏杆与立柱、桥面与端头、续接处和断开处必须有明确连接规则。碰撞应与可见可走表面一致，不能用不可见大平面掩盖视觉缺口。

桥体核心采用能够表达实际方向和弯曲的截面、扫掠或其他等效构造，替代把旋转结果重新包成全局轴对齐盒的做法。直段拱洞保护在新的坐标系下做相关回归；不把整座桥退化成一条悬空平带。

### 6.2 按职责决定变换方式

以下是本轮要用样例验证的供给分类，不预先认定为 Tiny Glade 内部实现：

| 母件职责 | 建议验证的使用方式 | 必须明确的约束 |
| --- | --- | --- |
| 立柱、柱头、端饰等造型件 | 保持刚性，沿实际切线或局部框架定位 | 枢轴、朝向、接口位置、间距和端头规则 |
| 连续收边、栏杆中段等 | 有条件重复、裁切或只对指定中段弯曲 | 允许变化的区域、长度范围、连接边和受保护造型 |
| 桥面或踏步单元 | 按真实路线排布；必要时由可变形模板区域或连接面补齐 | 内外侧接缝、纹理变化、厚度和碰撞 |
| 转接、收口和余量部位 | 采用经过样例验证的端盖、接头或局部生成面 | 哪些由母件供给，哪些由生成器承担 |
| 桥体填充与支撑 | 依据线路和开口生成，使用明确的几何配方 | 与外露源件的边界、洞口和地面连接 |

只实现能解决样例问题的一组策略，不要求同时实现所有裁切、弯曲和布尔方案。禁止为省事无差别拉伸整套 FBX；若原契约禁止变形而新能力需要变形，应升级契约或增加明确派生件，不暗改规则。

### 6.3 曲率和不可行输入

“自由绘制”在本轮指任意水平朝向及合理曲率范围内的连续路线，不意味着无限小半径或任意自交。最小半径由桥宽、内侧剩余空间和接缝策略共同决定，并记录为可理解的使用范围。

初始样例建议用半径约为净桥宽 3 倍的平缓 U/S 弯来暴露内外侧问题，再测出实际可支持范围。这是我方样例建议，不是原作参数，也不是未经验证就固定的母件标准。不能通过把最小半径调得极大来回避演示场地中正常的转弯。

急转、自交或几乎贴合的双段若不支持，显示局部问题并保留最后有效候选；如果做自动圆角，应让用户看见圆角后的线路。自动插入正交平台只能是用户主动选择的构造方式。

## 7 B 线接入 Tiny Glade 原作源件

### 7.1 从真实源数据到桥上部位

在已登记的本机研究目录中选择少量候选，逐件保留：源路径、文件指纹、格式、实际几何内容、坐标及单位转换、用途判断及其证据。只有文件名或缩略图不够。

解析或转换后形成 Unity 实际使用的网格，检查索引、法线、UV、颜色以及与表现相关的其他顶点属性；对没有恢复的属性语义做具体说明。现有固定 FBX 加 PNG 登记约束可以继续服务原创 A/B，原作格式通过明确适配层进入共享角色消费接口，不要求其原始结构伪装成同一套文件格式。

每件接入后，证据必须连起来：

1. 原始文件与指纹。
2. 转换前后可对应的网格、属性和可辨识特征。
3. Unity 中真实的源 Mesh 引用或可验证转换产物。
4. 生成路线中的职责、实例或合并网格片段映射。
5. 一个受控的源件变化确实影响对应生成部位；改动使用研究副本，恢复后结果可复现。

研究源件需要在实际桥上承担可见的构造职责。把原件摆在桥旁边、仅展示独立预览、只改来源标签或贴上原作纹理，都不算完成这一项。

### 7.2 表现范围和原作机制证据分别记录

如果原着色器尚未移植，可交付“原作几何加兼容材质”，清楚说明保留和缺失的表现。兼容材质不应掩盖网格错误或丢失属性；原作几何本身必须真实。

原作游戏中的受控替换继续用来判断其消费规则，例如某个几何变化是否作用于预期部位、是否随结构变化而调整。此前模组启用并恢复只能证明启停操作，不证明上述几何现象。

因此，至少分开记录三项状态：

| 状态 | 能说明什么 |
| --- | --- |
| 原作源件已转换并被 Unity 消费 | 我方确实在使用该源件 |
| 原作游戏内受控变化已观察 | 对该源件在原作中的作用获得实验支持 |
| 我方构造方法已通过曲线样例 | 我方实现能用这些输入完成目标绘制 |

三项不能互相替代。未观察到原作消费行为时，不把我方成功运行的算法称为“已恢复原作内部算法”。

本轮至少选取一项与这些源件有关的关键使用行为做原作与我方对照，例如长度变化时怎样重复或分配余量、接缝怎样连接、端头怎样收口，或哪部分几何随构造变化。优先利用已有候选和受控变化做一次定点观察，不重做整轮模组操作。只验证这项具体行为；即使对照成立，也不外推为恢复全部原作算法。若原作一侧仍没有可判读结果，可记录自由绘制和源件接入的阶段完成，但“素材使用机制复刻”保持待证。

### 7.3 同一线路接入与失败行为

原作研究版与原创版共享一份作者线路和编辑事务，通过明确的素材适配及使用规则接入。素材不同可以造成接缝数量、局部构造和外观差异，但不能偷偷重写路线来规避某套素材的能力缺口。

源件缺失、解析失败或职责不支持时，界面和报告显示具体缺口。不得静默回退到原创 A 套件，再把整桥标成“原作素材版”。允许研究版只覆盖部分职责，其余部位要逐项注明由哪套原创素材或生成配方承担。

原作源件及相关研究产物遵循既有本机研究范围。提交前按实际依赖核对文件清单；不要依赖目前只有界面文字的 `ResearchOnly` 标记来判断文件是否会随发布进入仓库。

## 9 验收项目与通过条件

### 9.1 共用标准

路线测试临时叠加三条参照：输入轨迹、持久化作者中心线、实际生成桥面的中心线。先检查是否存在明显折向或删掉绕行，再测误差。可行、干净样例的中心线最大偏差建议控制在净桥宽 W 的 5% 以内；即 W 为 2 米时约 0.1 米。这是本轮建议值，不是 Tiny Glade 参数。

开发前固定验收桥宽、代表性 U/S 输入轨迹和误差口径，保留输入数据。已选的正常转弯样例无法通过时，记录为能力缺口；不得仅通过事后扩大最小半径、放宽误差或将其重分类为非法输入来宣布完成。确需调整时，保留原失败记录并说明对用户绘制能力的影响，不另设例行审批环节。

误差应检查双向距离及沿程对应，防止自交、绕行或回头被“最近点距离很小”掩盖。验证用明确输入样例排除鼠标噪声；真实鼠标操作另验证自然手感。若需调整容差，应附失真示例和原因，不能为了得到通过结果悄悄放宽。

| 编号 | 操作或样例 | 通过条件 |
| --- | --- | --- |
| T1 斜线回归 | 输入附件中的五点斜线；再覆盖少量非 45 度朝向 | 仍沿原方向生成；不会变成 L/Z，桥体和边缘也沿同一方向 |
| T2 缓弯忠实度 | 平缓 C/U/S；包含同端点但不同中间走向的样例 | 三条参照在约定范围内一致；明显绕行和反向转弯保留 |
| T3 拖拽中生成 | 一笔经历起步、首次转向、反向转向和松手 | 每阶段桥面、边缘及栏杆可见更新；松手不突然换成另一条路线 |
| T4 曲线接缝 | 从上方和斜侧观察 U/S 内外侧及端头 | 没有未处理的外侧透空、内侧严重堆叠、悬空栏杆或错误收口 |
| T5 桥梁构造 | 带直段拱洞的线路及可走桥面 | 桥体、支撑、开口和碰撞合理，未用实体填满原有洞口 |
| T6 继续编辑 | 端点续画、中段移动、受支持标高修改、Undo | 更新同一作者对象；局部修改不退回轴向；一次撤销恢复 |
| T7 原作真实参与 | 在同一条已验 U/S 路线上使用研究源件 | 可见职责有真实源件映射，受控变化会改变对应生成部位 |
| T8 原创供给对照 | 同一条路线切换 A/B，并核对受保护造型 | 不改路线求解器即可接入；曲线使用规则被遵守，差异来自实际源几何 |
| T9 保存生命周期 | 新样例保存、重开、再编辑；加载一个旧格式样例 | 新曲线与源身份保留；旧路线按明确版本处理，不静默变形 |
| T10 失败恢复 | 急转或自交、研究源缺失、取消候选 | 说明局部原因，保留有效桥；不静默正交化或用原创替身伪装成功 |
| T11 使用行为对照 | 对一个已接入的构造母件做原作定点观察，并在我方对应样例复现 | 至少一个关键消费行为有可判读的前后证据和我方对照；模组启停或原件导入本身不能代替 |

T1 和 T2 可以用少量确定输入做针对性自动验证；不需要围绕每个临时艺术参数建立永久测试。T3 必须包含真实鼠标证据，合成事件报告不能代替。T4、T5、T7 应有实际几何和来源证据，不能只凭配置文件通过。

### 9.2 性能和验证成本

使用 B 级模块验证：相关线路与几何测试、工程编译、少量真实输入、来源核验和保存生命周期。最终验证初始预算按项目细则参考 10～25 分钟，开发期间按变更跑最小相关集。[S9]

记录样例长度、桥宽、硬件、可见实例或网格规模，以及输入到可见候选更新的实际延迟。后台一次构建耗时不等于用户看到的响应时间，更不等于帧率。先验证正常绘制不会持续追不上鼠标、松手不丢末点；测到具体瓶颈后再扩大优化范围。

不重复原作完整菜单流程、无关地形、所有历史系统或全部 A/B 静态证据。若耗时超过预算，区分功能缺陷、环境问题与非必要检查，保留真实失败并定向处理，不能以预算为由宣布未完成项目通过。

### 9.3 桌面操作安排

先在后台完成能完成的代码、导入、编译和确定输入验证，再在有效桌面授权范围内集中验证实际入口。此前限时的桌面许可不自动变成无限期占用。

一次聚焦操作可依次展示：斜线和 S 形绘制、端点续画、中段或标高修改、素材对照、保存重开。需要原作几何补证时，只做已准备好的受控变化，避免再次把大部分桌面时间花在模组启停。

发现用户并发输入、前台转到其他工程或操作归属不明时停止发送桌面输入，保留当前状态。可继续独立后台工作；不通过另一种自动化绕过输入冲突，也不结束用户进程。报告准确列出已完成、未完成和未保存内容。

## 10 本轮母件供给规范应该留下什么

在上述样例实际跑通之后，更新现有供给说明，形成曲线使用规范草案。它描述我方工具已经验证的消费方式，并注明哪些结论得到原作实验支持。

| 供给字段 | 建模人员需要知道的内容 |
| --- | --- |
| 职责和适用结构 | 该件负责桥面、侧缘、栏杆、柱子还是端头；适用直段、缓弯或两者 |
| 坐标和接口 | 单位、前向、上向、枢轴、拼接边和连接点 |
| 可变区域 | 哪段允许伸缩、弯曲、裁切；哪些造型必须保持刚性 |
| 几何使用范围 | 允许长度、宽度、曲率范围；超限时如何提示或换连接方式 |
| 内外侧与余量 | 柱距、重复间距、内外弧不同长度的分配、末端余量处理 |
| 表现属性 | UV、法线、颜色与其他必要属性；变形时如何保持连续 |
| 连接与碰撞 | 接缝、端盖、桥体接口以及碰撞由资产还是生成器负责 |
| 来源和验收 | 源件及指纹、已通过的直线/U/S 样例、已知不支持范围 |

供给结论需要落到三个明确清单：**必须建模的母件、由生成器产生的结构、当前需要专用连接件的情况。**不要把“所有模型统一固定尺寸、统一禁止变形”当作建筑资产的通用结论；也不要因为一种桥跑通就宣布整栋目标建筑的供给标准已定。

下一批资产数量应由真实缺口决定。优先复用 A/B 并增加必要的小型连接件或可变形区域定义；当曲线样例证明某类母件确实缺失时，再安排补做。
