## 3. T-033 遗留检查：只做完整性，不做手感设计

### 3.1 已读代码提供的排查线索

目前 Basic 前摇结束后，`engine.ts` 只有在目标仍合法可命中时才调用 `releaseAttack()`；无目标或目标失效时，Basic 分支只清理续段输入。

`audio.ts` 的攻击声音主要来自新增 `state.effects`。没有进入现有反馈路径的空挥，可能没有对应音频触发。

`view/scene.ts` 中存在：

```text
先前有 pending
→ 现在 pending 不存在
→ attackFlash <= 0
→ 视作 cancelledWindup，清 attackRemaining
```

因此，“空挥已经完成前摇/出手，却被渲染层当成取消”是一个具体的待验证原因。

以上是静态代码线索，不代替实际浏览器复现。

### 3.2 检查场景

执行者先用当前分支实际版本复现：

1. 猎人空场，单次左键后完全不操作。
2. 猎人对高生命敌人单次左键。
3. 起手后目标离开范围，形成落空。
4. 前摇中成功 WASD 或闪避，形成合法取消。
5. 同样操作分别在正常速度、Tactical Focus 期间观察。
6. 使用真实输入解锁音频，并确认不是静音、浏览器音频状态或素材加载失败。

记录“开始、出手/取消、命中与否、动画选择、音频请求”的相对时刻，不只截图最终站姿。

### 3.3 允许的有限修正

证据确认存在接线缺陷时，可做：

- 区分正常出手/挥空与真正取消，不能用“没有命中”代替“攻击没发生”。
- 每次合法出手有可识别的表现通知；实际命中另外通知。
- 空挥可复用现有临时出手/挥击声音；只发一次，不产生假命中音、假伤害或假目标。
- 动画层不因正常空挥而无故切回 idle；仍允许玩家合法移动、技能、闪避、硬直和新动作接管。
- 不以“必须播完整段素材”为理由锁住玩家输入或修改伤害时刻。
- 如果提取轻量表现事件，必须独立于命中统计和技能计数。

尤其不能为了给空挥发声，直接伪造一个命中 Effect，或让空挥误增原有“命中次数/实际普攻计数/吸血”等游戏逻辑。涉及 Reap 计数等既有规则，按当前合同单独核对，不借表现修补改设计。

### 3.4 停止条件

完成标准只是：

> 能明确区分正常出手、挥空、真实命中和合法取消；表现不会无理由截断、重复播放或误结算。

不继续做：
- 全职业动作重制；
- 攻速、前后摇、连段收益平衡；
- 新根运动；
- Hit-stop / 镜头震动；
- 音效素材大采购；
- 大规模 VFX 风格调整。

若发现问题实际贯穿完整动作系统、不能在小范围隔离修正，记录复现与影响，单独说明；不要把本轮扩成 XC-08 重写。只有会污染输入/施法/命中正确性的故障才阻塞本轮技能交互。

## 4. 本轮主目标：技能输入与动作执行解耦

目标链路：

```text
Command UI 或 Direct Hotkey
  ↓
明确 actor / skill / source / target
  ↓
纯查询：当前能否准备、预览是否有效
  ↓
AimSession（需要时）
  ↓
玩家确认 / 即时请求
  ↓
提交前重新校验
  ↓
现有技能执行层
```

不要求先决定：
- 阿尔 A2 应该多快；
- 猎人怎样蓄力；
- 近战有没有停顿；
- 最终动作系统是否采用某研究中的具体组织形式。

本轮只要求技能执行层接受一个明确、可验证的请求。以后更换动作实现，不应重写角色选择、鼠标确认、目标绑定和资源校验。

不要预造一个可组合所有攻击、升级、动画、AI的大型总框架。接口只覆盖当前实际需要。

## 5. Target Type 与 Input Style 分离

### 5.1 目标数据

建议让输入层最终解析出明确数据，例如：

```ts
type SkillTarget =
  | { kind: 'self' }
  | { kind: 'direction'; direction: Pos }
  | { kind: 'point'; point: Pos }
  | { kind: 'unit'; targetId: string };
```

以上是建议结构，不要求照搬字段。

“Area”描述技能影响几何，不一定是另一种目标身份。
“SmartUnit”描述对象预选策略，不表示可无视合法性自动施放。

### 5.2 输入方式

支持最小描述：

- 即时：按键后按技能自己的真实目标语义提交；
- AimConfirm：进入会话后左键确认；
- SelfToggle：对自身模式进行开关/退出操作。

未来 HoldRelease 只留可扩展位置，本轮不做蓄力系统。

不要因为名为 `InstantAtCursor` 就给所有技能强塞鼠标落点。自身治疗和模式开关没有落点，不应假装它们受鼠标影响。

### 5.3 原有触发方式不被重定义

`manual / toggle / full / route`、技能充能与持续规则继续由技能定义决定。

输入方式不能把：
- Rain 自动充满发动；
- Reap 计数与合法路径触发；
- Dance 自动进入、手动退出；

悄悄改成三个随时可点的大招。

## 7. Command：UI进入，不偷换 DirectActor

示例：

```text
DirectActor = 猎人
CommandFocus = 伊内丝
  ↓
点击“折痛回响”
  ↓
建立 skill Aim
  ↓
伊内丝进入 Reservation
  ↓
显示范围、准备状态和“左键确认 / 右键取消”
  ↓
确认成功，伊内丝释放
  ↓
DirectActor 始终是猎人
CommandFocus 仍可保留伊内丝
```

Command UI 不能借调用 `promoteCommandFocus` 来绕过技能执行权限。

### 7.1 进入会话

绑定：
- actorId；
- source=command；
- slot；
- skillId；
- 会话唯一身份；
- 当前目标候选；
- 如有必要，槽位/构筑版本标记。

不要仅保存 slot，在确认时静默变成槽里后来换入的另一个技能。

### 7.2 进入不等于释放

打开会话：
- 不扣 CD/痛印/次数；
- 不生成伤害、治疗或领域；
- 不取消旧 MoveOrder；
- 按已有规则暂停该角色订单；
- 清理该角色不再可信的普攻预输入；
- 已提交动作按既有生命周期完成。

### 7.3 角色尚未稳定

可以显示“动作结束后可确认”和预览。

不要自动排队释放；不要打开会话就强行取消不可取消的技能或跨层。

确认合法性按具体技能与现有动作规则判断，不能仅用一个粗略布尔值把原本允许共存的后台模式全部禁掉。

## 8. Direct：快捷键进入，同一执行层

E/R/T 继续作用于当前有效动作对象。

存在另一角色 CommandFocus 时：

```text
按技能快捷键
→ 取消原 Aim
→ 同次输入 Promote 焦点角色
→ 按该技能 Direct 输入方式处理
```

Direct takeover 与技能是否最终可施放仍分开：
- 技能因 CD 等被拒绝，不把玩家弹回原角色；
- 没有成功提交技能，不误取消 MoveOrder。

对 AimConfirm：
- 快捷键只打开会话；
- 下一次左键才确认；
- 左键不是普攻；
- 右键只取消会话，不退还不存在的已消费资源。

对自身即时/模式技能：
- 快捷键直接提交；
- 不为了统一 UI 强行要求所有技能二次点击。

本轮 Direct 技能栏只提供状态、快捷键与说明；不新增“点击 Direct 栏绕过快捷键规则”的第三套入口。旧按钮处理必须明确迁移，不能保留隐形即时释放通道。

## 9. Confirm 是一次校验完整的提交，不是 UI 自己放技能

建议集中提供：

```text
querySkillIntent
beginSkillAim
querySkillAimPreview
confirmSkillAim
cancelSkillAim
submitSkillIntent
```

这是职责建议，不要求恰好六个文件或函数。

确认时至少重新检查：
1. actor 是否仍为合法在场本体；
2. source 是否仍匹配当前 DirectActor / CommandFocus；
3. session 是否仍有效且未消费；
4. slot 中是否仍为会话绑定的 skillId；
5. 技能当前能否被手动请求；
6. CD、计数、模式、前台动作、生命与控制状态是否允许；
7. 目标、方向、范围、LOS、视野等该技能实际需要的条件；
8. 当前是否暂停或被更高模态占用。

### 9.1 成功

恰好一次：
- 提交技能；
- 按原技能时点消费资源/开始运行；
- 取消该施法者旧 MoveOrder；
- 清其未消费普攻请求；
- 结束当前 Aim；
- 保留 CommandFocus（如果是 Command 来源）；
- 不触碰另一角色订单或防御路径。

“确认时提交技能”不等于所有技能此刻直接扣血。已有前摇、脉冲和领域仍在其原本的后续时点结算。

### 9.2 失败

可恢复失败，例如 CD 未好、动作未结束、目标当前不合法：
- 不消费资源；
- 不生成半截技能；
- 不取消旧订单；
- 会话保留并显示原因。

身份/槽位/技能已经失效：
- 安全取消会话并提示；
- 不偷偷改投另一个技能或对象。

### 9.3 防止重复提交

同一物理点击不能在 pointerdown / pointerup / click 中重复施放。

一条会话最多成功确认一次。

不要从 `confirmSkillAim` 嵌套调用两层都会做“玩家成功动作后处理”的 `command()`，造成双统计、双取消或错误路径清理。应提取共享校验/执行与一次性提交后处理。

## 10. SkillAim 的目标与镜头

### 10.1 自身范围

预览以实际施法者为中心，保留原技能真实范围。

不能把鼠标移到哪里，自身技能的圈就搬到哪里。

### 10.2 方向与点位

需要鼠标世界位置的技能：
- 从真实 pointer event 更新世界候选；
- Confirm 使用用户实际预览过的候选；
- 相机自行移动、原 Direct 防御移动，不得把静止鼠标重新投影成另一个无提示目标；
- 提交时重新检查可达/范围，不盲信旧缓存。

方向型按实际技能语义保存方向，点位型保存世界点；不要把两者混成一个可随镜头改变的 screen point。

### 10.3 对象型

- 仅从当前合法、可知对象预选；
- 唯一合法对象可以预锁，仍须确认；
- 多对象按鼠标候选与稳定规则预选；
- 不因目标死亡就静默改选另一个对象完成原请求；
- 角色移动后是否追踪对象由技能契约决定；
- 不能从未知区域获取全图目标。

这些通用能力没有正式技能承接时，测试证据必须标为框架夹具。

## 11. Aim、输入、Reservation 与防御托管

### 11.1 左键权威

```text
Modal
→ 当前 Aim 的确认
→ 明确场景交互/角色操作
→ 无 Aim 时的手动 Basic
```

SkillAim 左键不同时：
- 普攻；
- 选路确认；
- 点篝火；
- 换焦点；
- 点敌人触发另一命令。

### 11.2 取消和替换

- RMB：只取消当前 Aim。
- Escape：先取消 Aim，之后才按既有规则清焦点/关闭其他层。
- 点另一个明确的 Command 技能按钮：取消旧会话并准备新技能，不是同时发两个技能。
- F：按已有输入意图切到 PathAim，不能残留 SkillAim。
- WASD / Shift：保留同输入直接接管/行动通道。
- E/R/T：在 Command Aim 中按既有约定先转 Direct 再处理相应技能；不要把它误当成 Command UI 确认。
- 构筑、背包、卡牌等明确功能开始前取消当前 Aim；只读调试工具不应抢权。

### 11.3 逐角色权限

```text
猎人 Direct
阿尔 CommandFocus + SkillAim
```

阿尔：
- Reservation 限制新的 AI 战术走位、普攻、主动闪避和前台 Auto；
- 已提交动作与后台时钟沿现有规则处理。

猎人：
- 继续 T-033 有限防御托管；
- 不自动普攻；
- 不因阿尔有 Aim 被一起冻结；
- 不为她的会话刷新 Tactical Focus；
- 防御使用真实资源。

取消 Aim 但保留 CommandFocus：
- 阿尔恢复自己的合法 AI/订单；
- 猎人的有限防御授权仍按 CommandFocus 是否有效判断。

真正 Promote 阿尔：
- 权限重新按当前身份计算；
- 猎人转普通离手 AI；
- 阿尔成为纯手动普攻角色；
- 旧玩家预输入不得跨控制会话迟到执行。
