推荐先做阶梯石拱桥。它同时覆盖路径编辑、真实构件配方、支撑派生、受保护开口和整体修改，适合检验 B 线是否确实具备专用规则。水洼可随后验证区域轮廓、水面、岸边过渡和配套物，第一轮不并行加入。

当前没有可用的桥生成器／通用 B 建筑编辑器。SB-02 已有可复用的真实 FBX 参数房间验证：28 个规格、默认使用23个，3735个逻辑摆放合并44个显示块，具备source／host／role映射、源版本采用与回退、Manual保护和烘焙。其固定房间、直角与固定宽踏步不能直接冒称自由桥梁功能。LE-04提供A地貌、后台候选／提交、缓存和历史经验；LE-03整体体素世界组合器不作为B的上传链。

## 推荐设计：一座有结构关系的桥

用户操作一条线路及其控制节点，调整宽度、节点标高和桥下净空。一次拖画得到一个桥作者；控制节点移动后，规则重新安排整座结构。输入可以支持拖画后简化节点，后续继续拖节点精修。

作者保存“线路节点＋宿主锚点＋宽度＋标高＋下穿净空＋配方／源版本＋明确的人工覆盖”。显示构件是派生结果，保留稳定的桥／路段／角色／来源编号。与A地貌分别拥有root、Mesh和作者；A只提供只读地面和支承采样。

```mermaid
flowchart LR
  A[线路与标高] --> B[踏步 / 平台路段]
  B --> C[离地净空与支承区间]
  C --> D[桥台 / 桥墩 / 拱洞布局]
  D --> E[原创构件与限定剖面生成]
  E --> F[栏杆收边 / 显示网格 / 碰撞]
```

采用“真实构件＋配方明确授权的生成区域”。踏步鼻口、桥台、栏杆节点、拱脚／拱顶保留源设计；桥面底床、墙芯和拱洞周围填充可以按该风格的指定剖面生成。每个生成区域也有职责、材料和边界，不采用缺件后任意填灰块的兜底。模型直接按其构件契约使用，不转成A的通用形色参考场。

两种其它路线暂不选：整桥预制体缩放／连续盖章难以协调踏步、支撑与洞口；全靠通用体素体积生成难以体现B的真实构件设计和用途约束。局部邻接规则可作为实现手段，但不替代桥的结构配方。

## 需要建立的规则

1. **先决定可行走线路。** 水平段生成桥面／平台，有高差的段安排踏步；转角预留落脚平台。踏步数量、步高和有效进深由风格配方共同约束。过陡／过短时说明约束并保留原结果，首轮不扩展梯子和魔法悬浮。
2. **根据离地与跨空决定支撑。** 不只使用“长度过阈值就变桥”。读取实际净空、无地面支撑的区间、合法桥台和桥墩位置，再选实心承托、单拱或重复桥跨。长度余量在整组跨间协调分配，保持端头和主次节奏。
3. **桥下洞是受保护空域。** 开口剖面位于桥长—高度平面，沿桥宽贯穿；支撑和墙芯先避开它，拱圈围绕它安排。视觉和碰撞均留空。桥太低容不下指定净高时报告冲突，不悄悄填洞；若A地形本身堵住通道，由用户调整地形或抬桥，不自动挖改A。
4. **构件遵守固定接口。** 登记单位、逻辑占位／美术外扩、枢轴、端口剖面、允许旋转、保护造型、允许重复区和源版本。初版不用整件非均匀缩放；改宽和改长使用中段、收口或经过认证的规格。
5. **改变局部时保持设计稳定。** 按稳定路段身份分配构件与变化，保存重开不重新洗牌。只重建受影响桥段；独立摆件与A网格保持原样。支撑人工覆盖需保留并参加合法性检查。

SB-02旧踏步逻辑为1.5×0.25×0.5m、细节单位0.125m、禁止缩放，不能直接拉宽充作新桥踏步。首套建议沿用统一细节单位与结构步长的明确契约；新规格另存原创源，不改旧母版。

## 第一套原创素材角色

先做约8—10类角色：踏步／鼻口与重复中段、桥面铺面、楼梯—平台过渡、侧缘收口、栏杆直段与端节点、桥台／支撑脚、桥墩中段、左右拱脚、阶梯拱圈和拱顶节点。角色不等于每角色只能一个模型；需要的长短规格计入同一套来源清单。

首次展示必须同时给出“实际素材板＋桥上同编号位置＋来源高亮”。可从桥上的一段反查其源、职责和所属路段；采用一版新栏杆能直接看到只改变对应设计。先让结构和素材使用可检查，再扩素材数量。

## 建议的首轮可操作切片

先在同一个生成器内完成：地面短阶梯→抬高后的承托阶梯→跨空单拱桥。连续画线路、拖长、改宽、改端高后，踏步／桥面／支撑／洞口／栏杆一同适应。随后验证一个带落脚平台的L转角；平滑弯桥要另验内外侧长度、踏步放射和拱圈转向，首轮不承诺任意曲率。

最低验收包括：

- 输入疏密不同的相同路线得到同一结构；不是每帧多放一座桥。
- 宽、高、长变化分别触发正确角色变化，SourceMap可以解释每个可见部分。
- 桥洞具有实际几何／碰撞净空；修改、撤销、保存重开后仍贯通。
- 无合法桥墩位置、缺源、开口过低、转弯过急等失败保留上一结果。
- 候选可取消，一次修改一条Undo，松手后导航保留，迟到结果不覆盖新状态。
- 对照A与独立Manual物件指纹不变；可烘焙为独立可显示／有碰撞的场景。
- 在固定长度／跨数／构件数下记录输入、解算、上传和撤销成本，指标是待测目标，不引用A的成绩当B已达标。

## 实机补测与接续状态

本轮无需启动游戏。旧证据已足够选择结构与首次切片。若要确定更接近原作的模式切换，只补同一小桥的低／中／高三态，再延长一次跨空、增加／撤去一次下穿路径；固定节点、宽度和视角，配合作者差分。此补测不扩回窗户、屋顶、室内和全套性能研究，完成后关闭游戏。

## 执行结果（2026-11-03）

已接入原 LE-01 研究工程的 Assets/SB03，入口为“星骸 → 专用搭建 → 打开石拱桥样例”。另有连续拖画、尺寸联动、场景长度/标高手柄、来源高亮、一次Undo/Redo、Esc候选取消、原生CtrlS/JSON作者及无脚本预制体烘焙。

九件原创工坊源直接消费FBX网格、UV和色板，原生重开与引擎轴向、鼻口、顶点来源检验通过。默认14m×2.5m、两端各8阶，4m跨度/1.25m中心净高洞口；352构件合并10显示块/10556三角面，墙芯为21个合并剖面段。栏杆接口已避开与柱身共面重叠。

规则12项、真实编辑会话6项、合成SceneView操作8项、普通保存、多桥身份隔离、独立进程重开与烘焙碰撞验证均通过。重开先核对原生Mesh数组，再验证继续编辑。固定5次预热/20次采样，14m候选重建P95约6.97ms，24m约9.35ms；这是后台实际网格/碰撞构建成本，不是屏幕FPS。

首轮限定直线单孔与水平支承基准。复杂地形支承采样、曲桥、多跨和L平台未实现；B不自动挖改A，也不做两线网格布尔融合。原有794个研究工程资产文件逐件SHA保持，正式项目未触碰。
