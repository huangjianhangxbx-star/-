## 0. 为什么必须修订 v0.1

用户指出：目前并**没有正式设计左手武器**。上一版虽然要把右/左做成真实独立装备，但对左手实际上要放什么、玩法如何成立写得不够具体，存在 Codex 只做“装备框＋耐久表”的风险。

本轮新增的**用户明确要求**是：

1. 请 Codex **自己创造一个可以装备的左手装备，作用是投掷一颗炸弹**；图标无需正式美术，可以用最简几何/占位表现。
2. 用户正在权衡：小蓝（本轮映射为 Hunter/猎人）原有 RMB 举盾，究竟取消，还是只有装备盾牌后才允许使用。

**本计划的推荐实施选择（AI 临时建议，须标 SAMPLE 而非冒充最终用户决定）：**

- **不要删除或重制已认可的举盾**。将它变成装备“护盾型副手”时才可触发的 `RMB` 动作。
- 加入新“投掷炸弹型副手”。装备炸弹时 `RMB` 抛一颗炸弹，**不再能够举盾**。
- 小蓝现有 `E` 动作本身叫“盾冲/盾准备→冲锋”，建议暂时也设为**需要装备盾牌**才能使用；换炸弹后 `E` 显示“需要盾牌副手”，不以另一套伪动画代替。这个 E 依赖是待用户试玩的 AI 建议，不是已确认的永久系统设计。
- 阿尔已有 `RMB` 射击暂视为“射击型副手”的既有动作，不改枪/动画/弹药。阿尔若改装炸弹，也改为 RMB 丢炸弹；其 `E` 火箭弹射仍照原规则可用（不依赖盾牌）。
- `LMB` 永远是右手当前主武器的真实原生普攻；换**左手**不更改职业、右主技能库或已认可 LMB 动作时序。

本轮的目标是**用一个真的、可替换且有战斗差异的炸弹，验证双手装备系统**；不是做大量空装备框，也不是扩展整个装备图鉴。

## 1. 来源与应保护的工程事实

- `EN-BAL-01`：高压 V2 僵尸/骷髅弓的 HP/架势、真实方向盾与闪避都不应被重新平衡。

## 2. 本轮可玩的副手装备方案

### 2.1 初始装备与可切换候选

| 角色 | 右手 / LMB | 初始左手 / RMB | 可更换成 | 额外说明 |
|---|---|---|---|---|
| Hunter（小蓝/主角） | 现有已认可主武器及普攻 | **实验护盾**：按住 RMB 举盾 | **试验炸弹**：RMB 投弹 | 盾与炸弹二选一，不同时生效 |
| Al（阿尔） | 现有已认可主武器及普攻 | **实验射击器**：RMB 原射击 | **试验炸弹**：RMB 投弹 | 射击与炸弹二选一；E 原火箭保留 |

“实验护盾/实验射击器”是**给已有行为明确装备身份的临时名称**，不是用户指定的正式装备造型、枪械定位或道具图鉴。可在每位角色的原位装备面板中，免费在其**已拥有的样板副手**之间进行真实合法切换；这不是背包掉落或货币购买系统。

- 每个角色拥有自己的装备实例 ID；即使都装备炸弹，两个实例也不能合并、跨人物自动转移或共享耐久/CD。
- 右主装备实例有自身耐久/职业/适配；左副装备实例有独立耐久/行为；右主决定职业，左副不改职业。
- 本轮主武器只做必要的现有右手实例化和正确接线；不要为了交付 EQ-01 新造一批主武器或不同职业动作。
- 对没有适配能力的角色/手别，核心必须返回明确的不可装备理由，前端不能偷偷替换为其他动作。

### 2.2 炸弹副手：本轮 SAMPLE 玩法合同

用户明确的只有“**装备它，使用时扔一颗炸弹**”。以下用于快速试玩的细节是 **Codex 实施建议值，全部 SAMPLE、集中配置、易改**：

| 参数 | 推荐原型值 | 说明 |
|---|---|---|
| 输入 | `RMB` 单次按下 | 一按只投一颗；长按不重复；松开再按才有新请求 |
| 可投距离 | 4.5 游戏单位 | 按当前鼠标战场瞄准点/方向，非法点有提示 |
| 飞行/落地延迟 | 约 0.45 模拟秒 | 一颗实际在途实体；可以用几何小圆球和短弧轨迹表示 |
| 爆炸范围 | 半径约 1.25 游戏单位 | 敌人全员按**同一次爆炸事件**各合法命中最多一次 |
| 爆炸基础伤害 | 45 HP | 仅作用于敌人，本轮不做友伤；真实防御仍走主命中权威 |
| 爆炸架势冲击 | 25 | 同样走现有命中/架势系统，无独立扣除通道 |
| 体力消费 | 20 | 接受时一次付款；拒绝不扣，之后取消不退款 |
| 冷却 | 5 模拟秒 | 以真实装备/Unit 资源时钟推进；切人/离区冻结，不免费重置 |
| 弹药/制作消耗 | **暂不启用** | 这是可重复使用的**副手装备样板**，不是背包的一次性炸弹堆叠；后续 INV 再决定耗材 |
| 视觉素材 | 黑底细边的小炸弹图标、简单投射圆球和爆炸圆环 | 不要求完整动画、Spine 附件、商用品图标或新美术生产线 |

投射合法性：沿用当前 `spatial`/`attack-area` 能力检查有效目标与障碍；不能透墙命中或在不可到达点凭空爆炸。可实现为抛物线**仅用于显示**，权威落点使用可解释、确定性的碰撞/边界；必须给出合法拒绝原因。射程不够或有障碍时不要凭空修正到隐形目标点；对可达边界截断策略可作为 SAMPLE，但要在交接写明并用测试固定其实际效果。

结算生命周期：

1. `RMB down` → 按当前实控人物及**当前左手装备实例**查询动作资格（存活、控制、动作窗、瞄准、体力、CD、耐久）。
2. 满足全部资格后**只接纳一次**：创建独立 `actionId` / `accepted instanceId` 快照；按权威体力扣 20，登记装备 CD。失败请求无体力/耐久/CD 损失。
3. 真正 Release 时生成**一颗**炸弹实体，扣该装备**一次**耐久（SAMPLE 选择 Release 而非重复每命中目标扣）；若 Accept 后在 Release 前被取消，不恢复已付体力/CD，但不扣未实际 Release 的耐久。不得跨同一请求生成多颗。
4. 到达有效落点后触发**一次**主结算 `resolveHit`，记录 source actor / offhand instance / attackEvent identity；一个目标最多记一次。同组多个敌人可各受一次真实伤害与架势，不重复奖励。
5. 已投弹被所属角色死亡、全灭或区域卸载清理（按 LT-01 本体派生物死亡清理策略），不能跨世界访问残留；若玩家仅 Z 切人，已合法 Release 的在途炸弹可完成自身生命周期，但不会继承新主控的人物/资源。

### 2.3 盾牌与 E 的动作约束（推荐、不是用户永久决定）

**穿着实验护盾时：**

- Hunter `RMB` 按原本方式举盾：0.08 秒生效窗口、方向角、成功防御不掉 HP / 减半架势、霜寒与 `CB-02` 开盾8＋持盾6/秒，均与旧版一致。
- Hunter `E` 仍是原盾冲：原受理、准备/释放、Hit、CD、体力28、动画不变。护盾型副手是该动作的**资格条件**，不是将技能移动到 RMB。

**穿着炸弹时：**

- Hunter RMB **只能投弹**；不得继续通过热键、AI、旧 `hunterInput('guard')` 或旧防御状态绕过装备条件举盾。被动防御仍按正常护甲/格挡系统已有规则，不把“无盾”解释为无敌。
- Hunter `E` 原盾冲推荐显示**“需要装备护盾型副手”**并拒绝，不得暗扣 28 体力或发生盾冲动作。该 E 装备依赖是待试玩的 SAMPLE 建议；如果用户将来决定 E 不靠盾，可以只调整能力要求，而不用推翻双手架构。
- 切装备前若正在举盾或 E 动作中：优先**拒绝切换直到动作合法结束**，不能瞬间让当前防御/Charge 在炸弹状态下以旧盾合法持续。如果 Codex 因已有配置门需要采用安全取消，必须明确保证已接受支付不退款、无下一帧幽灵举盾。

**阿尔：**

- 射击器装备时 `RMB` 的 4 发、真实 Hit 扣弹、装填、0.5333 动作与 CB02 stamina15 不变。
- 炸弹装备时 `RMB` 单投炸弹而**不会**再触发阿尔射击、自动开火或扣射击弹药；`E` 火箭弹射和 LMB 原生能力保留。
- 切回射击器不免费补充弹药/重置 CD。阿尔本体的弹药与 reload 时钟按原允许的模拟钟继续或冻结，不让“换副手”成为免费补给。

### 2.4 装备耐久：只证明双手与实例确实独立

- 真实 `current/maxDurability`、唯一实例 ID、所有者、类型、正在装备与保管/候选状态；不会因为 Z、HUD刷新、死亡复活、NR离区继续而复原。
- 主武器损耗继续接原合法事件。左手样板建议：护盾**成功格挡**一次扣 1，射击器**真实子弹 Release** 一次扣 1，炸弹**真正投出** 一次扣 1；全为 SAMPLE，按 actionId/实例只扣一次。
- 0耐久时对应左手动作拒绝，并显示“损坏”；不能借瞬时卸/装备恢复。维修/资源费用/图纸改进仍留给 INV/EQ 后续，**本轮不凭空加入免费修理**；为了快速试玩可给每角色若干高耐久样板，不影响观察动作功能。
- `weightProfile` 当前会把整个 `weapons[]` 求和。实现双手装备不得把**未装备候选**计入负重而意外改 Hunter/Al 黄金移速、普通攻击恢复门和 Shift。需要时以迁移桥保证当前默认构筑行为等价，并以 before/after 核对；不能顺手重平衡。

## 3. UI / 输入实现

- HUD 保留六区、头像、左右手上下排布。将已有 `[data-hand='right'|'left']` 只读预留位连接真实装备实例与耐久，`RMB` 区根据当前副手显示 **盾/枪/炸弹** 的简化图标或汉字；不制作复杂艺术资产。
- 点击装备槽打开独立装备面板：**右主/左副两列**、当前实例、耐久、对应输入和可更换候选；可真实选择样板炸弹，并显示每件的使用规则。非对应角色不能直接互转装备。
- 默认装备不得变：Hunter盾、阿尔射击器；用户可主动换成炸弹试玩。武器切换必须经核心查询，交战或动作忙碌不能通过 UI 绕权限；必要时允许在配置/脱战时切换。
- 炸弹临时图标优先由现成 CSS/SVG 几何绘制即可；需要新的可复用 PNG 时核实再用 `xinghai-ui-geometry`。输入模式、费用、可用/冷却和 E 需盾提示均由**真实状态**读取；不造假展示。
- 一个 RMB 物理输入只能路由到当前已装备的副手动作；失焦、死亡自动切人、暂停、G/F、装备面板打开时清除旧持键/旧 pointer capture，不得把旧猎人盾输入当新阿尔射击或炸弹投掷。
- 装备面板打开时 UI 捕获操作，不透传 LMB 基础攻击/RMB 举盾/射击/F选路；Esc 合法关闭。未实现 Tab 背包/Y瓶/QER配置/V升级/C双形态均保持原预留/已有行为。
- 后续可以将左副装备同一查询接口用于不同职业技能或 AI，但本轮**不实现 AI 自动投弹**，避免未确定的物品使用策略；离手伙伴仍可以使用已有符合实际副手的原生攻击策略，若不支持炸弹则清楚保持“AI 暂不会主动使用炸弹”。

## 4. Codex 实施顺序

### G0｜接手与最小合同审计

1. 核对最新 `HEAD`/远端/dirty 和并行任务；核对开发细则 v2.2 §5/§6/§7.1.1 及适用 AGENTS、LT-01/CB-02/UI-01C/EN-BAL 交接。
2. 针对相应源只读梳理 Hunter/Al 当前 RMB、Hunter E、伤害主结算、体力支付、既有在途实体和生命周期取消；**不要全量扫旧塔防、全部资源或所有 Skill**。
3. 记录这里的三层事实：用户明确要**炸弹副手**；“装盾才举盾 / E需盾”是本计划建议用于测试的**SAMPLE**；尚未决定的永久成本、背包耗材、友伤、正式爆炸视效不做暗中终局设计。

### G1｜双手权威与样板装备（先 RED）

1. 写最小失败例：默认 Hunter右主＋左盾、Al右主＋左射击器；每人可换炸弹；右主与左副实例 ID/耐久分别拥有，不串角色。
2. 设计唯一真正的 `equipped.right`、`equipped.left` 数据接口与行为 `OffhandActionType='guard'|'shot'|'bomb'`（字段名/模块由 Codex 基于真实架构决定），避免 UI 造状态、`weaponIndex` 与双手互相覆盖。
3. 旧职业来源仍为右主，左副切换不改身份、职业、LMB连段/当前QER基础资格；旧影武器不能假装左副。

### G2｜副手动作权威与投弹 Runtime

1. 建立统一 `queryOffhandAction → acceptOffhandAction`；RMB 根据当前**装备实例**派发盾、射击或炸弹，而不是一直根据 `hunter`/`ranger` 的身份硬路由。
2. Hunter 原盾/E 的装备资格门、Al 原射击器门 **必须在核心**；保证原有时间窗与支付事件未改。炸弹一颗实体、合法落点、单一爆炸源与不重复伤害。
3. 新 `bomb` 消耗、CD、耐久符合一次真实动作付款原则；适配 LT 的死亡/输入Epoch、NR 的离区暂停和全灭清理，避免新炸弹复活旧状态。
4. 通过定向用例后才接 UI 和真实浏览器，不为迫使测试全绿修改黄金动画片段。
