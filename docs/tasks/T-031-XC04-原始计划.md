## 1. 本阶段目标

第一次把现有的：

```text
CommandFocus + AimSession + Command Reservation
```

接到玩家真正可操作的“选路”功能。

完成后：

```text
Command Al
→ F / 选路按钮
→ Al进入PathAim并让出AI战术控制
→ 鼠标预览路径
→ LMB确认
→ Al执行一次move
→ Aim结束，但CommandFocus保留
```

Direct Mode：

```text
Direct Hunter
→ F
→ PathAim
→ LMB确认
→ Hunter执行一次move
→ 回Direct
```

本轮只完成“显式瞄准 + 一次move命令”，**不做XC-05持续MoveOrder**。

---

## 2. 正式废除旧输入

Standalone Exploration 从本轮起：

> **无PathAim时，点击空地不再移动角色。**

同时：

> **无PathAim时，不再因为鼠标hover自动显示路径。**

也就是说选路必须显式激活。

Tower Legacy不跟随这套新规则。

---

## 3. PathAim入口

首版推荐：

```text
F = Path / Move Command
```

理由：
- WASD附近；
- E/R/T已是技能；
- Q已有收纳；
- Shift为机动；
- C为CommandFocus；
- H/B为旧队伍命令。

### Command Mode
入口：
- “选路 [F]”按钮；
- F快捷键。

### Direct Mode
入口：
- 仅F快捷键；
- 不常驻显示Path按钮。

---

## 4. Aim Core泛化

XC-03已有：

```ts
ExplorationAimSession {
  kind: 'path'|'skill'|'mobility'
  actorId
  startedAt
}
```

当前Begin Aim偏向CommandFocus。

本轮建议泛化为统一入口：

```ts
beginExplorationAim(s, actorId, kind, source)
cancelExplorationAim(s)
```

其中：

```ts
source: 'command' | 'direct'
```

Command source：
- actor必须是CommandFocus；
- 触发Command Reservation。

Direct source：
- actor必须是DirectActor；
- 不触发Command Reservation。

不要写两套PathAim系统。

---

## 5. Path Preview

建议GameState继续只保存Aim的权威状态，不把鼠标每帧的动态path写回状态。

实时派生：

```ts
queryPathAimPreview(s, actor, hover)
```

返回：

```ts
{
  valid
  path
  destination
  reason
}
```

合法性至少检查：
- position known / 可探索；
- `canStop`；
- body radius；
- 当前layer；
- `navigate`可达；
- 障碍和身体碰撞。

### Command actor
额外复用：

```text
pathSafeFromInactiveEncounters
```

防止伙伴命令自己穿过未激活Encounter的感知区。

### Direct actor
不使用这一AI限制。

玩家自己可以主动走进下一Encounter。

---

## 6. Preview必须属于Aim Actor

例如：

```text
Direct Hunter
Command Al
PathAim
```

路线必须：

> 从Al当前位置算。

不能错误地从Hunter开始。

同时使用：
- Al body radius；
- Al所在层；
- Al当前可达性。

---

## 7. 路线显示

复用现有：

```text
UIOverlay.path
WorldFeedback route
```

PathAim active：

```text
overlay.path = [actor.pos, ...preview.path]
```

Aim=None：

```text
overlay.path = []
```

这次正式删除T-029留下的Direct Mode旧常驻Preview。

---

## 8. LMB Confirm

PathAim active时，场景LMB只表示：

> Confirm Path。

不能同时：
- Basic；
- 选角色；
- 选敌人；
- 触发篝火/事件；
- 触发出口。

Aim拥有场景鼠标最高优先级。

---

## 9. Confirm成功

继续复用现有：

```text
command({type:'move', id:actor.id, to:destination})
```

### Command Path
成功：
- move发给CommandFocus；
- Aim结束；
- CommandFocus保留；
- DirectActor不变。

### Direct Path
成功：
- move发给DirectActor；
- Aim结束；
- DirectActor不变；
- 返回Direct输入。

---

## 10. Confirm失败

例如：
- 地形阻挡；
- 路径不存在；
- 目标格被占；
- actor状态变成不可行动。

结果：

> **Aim保持。**

不发送move。

显示短reason，允许玩家继续换位置。

---

## 11. Reservation Ready

XC-03已有：

```text
commandReservationReady()
```

Command PathAim中，即使角色还在：
- 已Commit Basic；
- Evade；
- Crossing；
- Foreground；
- ForcedMotion；

仍允许：
> 先看路径Preview。

但：

> Ready=false时不能Confirm。

提示“角色当前动作尚未结束”。

本轮不做“等动作结束自动执行”。

那属于后续命令队列/MoveOrder范畴。

---

## 12. RMB / Escape

### RMB
PathAim active：

```text
cancel Aim
```

Command：
- CommandFocus保留；
- AI从当前位置恢复决策。

Direct：
- DirectActor保留；
- 回Direct。

### Escape
Command + PathAim：

```text
第一次Escape → Cancel Aim
第二次Escape → Clear CommandFocus
```

继续XC-03/T-029的层级语义。

---

## 13. F Toggle

建议：

```text
Aim=None + F
→ Begin PathAim

PathAim + F
→ Cancel PathAim
```

简单明确。

---

## 14. 点击其它功能按钮

已确认交互：

> 不需要“先退出PathAim，再点第二次”。

PathAim中点击一个明确功能按钮：

```text
cancel PathAim
→ 同一次click继续执行该功能
```

至少处理：
- Path按钮自身；
- Build；
- Backpack；
- Party Command；
- 现有Blink入口；
- 明确的模式/功能按钮。

未来 Skill / Mobility UI继续复用同样机制。

---

## 15. 鼠标输入独占

PathAim中：
- 点击角色模型不切CommandFocus；
- 点击Clone不进入查看；
- 点击敌人不做其它行为；
- 点击篝火/事件不Interact；
- 点击出口不Exit。

场景LMB只有：

> Path Confirm。

---

## 16. WASD Escape Hatch

### Direct PathAim

```text
F
→ W
```

同一次W：
- Aim取消；
- 角色立即Direct移动。

### Command PathAim

```text
Command Al
→ F
→ W
```

同一次W：
- Aim取消；
- Al Promote成Direct；
- Al立即移动；
- Hunter进入Off-Control AI。

不能要求第二次W。

---

## 17. Skill / Mobility Escape Hatch

PathAim中按：

```text
E / R / T / Shift
```

同样：
- Cancel Aim；
- Command source则Promote；
- 同一次输入继续执行技能/机动；
- Direct source直接执行。

---

## 18. CommandFocus切换

Command Al + PathAim：

```text
C / 1 / 2
```

应：
- 取消旧Aim；
- Al恢复AI；
- 切换/清除CommandFocus；
- 新Focus不自动进入PathAim。

必须再按F。

---

## 19. Tactical Focus

进入CommandFocus时已经启动1.5s Tactical Focus。

进入PathAim：

> **不能重新启动Tactical Focus。**

否则可以反复F无限刷新慢动作。

即使慢动作已经自然结束：
- CommandFocus仍在；
- 仍可按F PathAim；
- 此时就是1×时间下瞄准。

本轮不增加Aim专属减速。

---

## 20. Command UI

本轮第一次增加真正的Command功能UI：

```text
选路 [F]
```

仅CommandFocus存在时显示。

Direct Mode：
> 不显示Path按钮。

PathAim active：
> 按钮显示“选路中…”或等价状态。

不提前做正式Command技能/闪避UI。

---

## 21. 暂不做持续MoveOrder

这是重要范围边界。

XC-04只验证：

```text
PathAim
→ Confirm
→ 现有move命令
```

如果途中自动攻击导致当前旧路径被中断：

> 本轮不声称角色还能继续原目标。

下一阶段XC-05才正式实现：

```text
MoveOrder.destination
+
Suspend / Resume
```

---

## 22. 性能

当前旧代码已经会随hover算path。

本轮建议简单优化：

```text
鼠标仍在同一tile
→ 不重复navigate

hover tile变化
→ 重算

actor起点/map状态变化
→ 缓存失效
```

不做复杂Path缓存或性能专项。

# 27. 用户试玩重点

1. **路径终于不是常驻鼠标状态。**
2. Command Al → F → 点位置，感觉像“给Al一条移动指令”，而不是切身体。
3. 进入PathAim时AI自然收住；取消后自然恢复。
4. LMB在PathAim里绝不乱触发其它东西。
5. Direct F选路是一次性工具，不变成RTS常驻控制。
6. W/E/Shift能随时从PathAim直接接管。
