# 星骸回廊：T-025 / EC-07 三技能槽与独立技能运行时实施计划 v0.1

> 日期：2026-10-06  
> 当前核对基准：GitHub `main@d188a33d031846e4feb5073309cb788cfb388787`。  
> 前置：EC-01～EC-06 已实现；用户试玩最新版暂未发现需要先回修的问题。  
> 状态：计划草稿，尚未实施、未写入仓库。

## 1. 本阶段目标

EC-07 要把独立探索从“单一当前技能”升级为：

> **每个角色最多3个主动技能槽；每个已装备技能拥有自己的独立充能、计数、持续、Toggle和运行时状态。**

这一步只改探索主玩法。塔防和旧庭院继续维持单技能兼容。

本阶段不新增第三个技能，也不开放跨职业技能。当前职业技能不足3个时允许空槽。

---

## 2. 当前技能内容与默认槽

当前正式技能：

- Hunter：`hunt`
- Healer：`prayer / ward`
- Cantor：`bell`
- Guard：`poison`
- Ranger：`snipe / rain`
- Shieldguard：`pain / sanctuary`
- Scythe：`dance / reap`

建议默认：

```text
Hunter       Hunt / Empty / Empty
Healer       Prayer / Ward / Empty
Cantor       Bell / Empty / Empty
Guard        Poison / Empty / Empty
Ranger       Snipe / Rain / Empty
Shieldguard  Pain / Sanctuary / Empty
Scythe       Dance / Reap / Empty
```

旧玩家默认技能必须保留在 Slot1，不覆盖已有配置。

---

## 3. Skill Loadout 结构

把局外默认从单Skill升级成：

```ts
type SkillLoadout = [
  SkillId | null,
  SkillId | null,
  SkillId | null
]

profile.loadouts[unitId][profession] = SkillLoadout
```

Unit增加当前Run实际装备：

```ts
skillSlots?: SkillLoadout
```

规则：

- Slot1不可空；
- Slot2/3可空；
- 同一Skill不可重复；
- 仍只能装备当前Profession技能；
- Weapon切Profession时载入该Profession自己的三槽。

EC-07不实现“猎人装备盾卫技能”等跨职业构筑。

---

## 4. 旧 defaults 迁移

如果只有：

```text
defaults[unit][profession] = skillId
```

则迁移为：

```text
Slot1 = skillId
```

如果该Profession还有第二个现有技能，可首次初始化到Slot2。

Slot3保持Empty。

Tower/legacy继续把Slot1当兼容主技能。

---

## 5. SkillState 独立化

当前已有：

```text
u.skillStates[skillId]
```

这是很好的底座。

新增/统一接口：

```text
skillState(u, skillId)
skillInSlot(u, slot)
skillStateInSlot(u, slot)
resolvedSkill(u, skillId)
equippedSkills(u)
```

Standalone不能再让：

```text
currentSkill()
```

成为整个角色唯一运行时权威。

`currentSkill()`可以继续保留给Tower/legacy和Slot1兼容。

---

## 6. Legacy mirrors

当前：

```text
skillCd
skillMax
skillTime
skillPulse
sniperMode
autoSkill
```

映射到单一currentSkill。

EC-07后：

- Standalone核心直接读各SkillState；
- Tower/旧庭院继续把legacy mirror投影到Slot1。

不要一次删除所有旧接口，但新探索逻辑不得依赖这些字段代表全部技能。

---

## 7. 快捷键

Standalone原型建议：

```text
Skill Slot 1 = E
Skill Slot 2 = R
Skill Slot 3 = T
```

保留：

- Q：影庭
- Shift：当前DirectActor机动
- C：切换角色
- Tab：手牌
- F：预留未来指令轮盘

按键以后可重映射。

---

## 8. Skill Command

从：

```text
{ type:'skill', id }
```

升级为：

```ts
{
  type:'skill'
  id:string
  slot:0|1|2
}
```

Standalone按slot解析具体SkillId。

空槽拒绝。

Tower旧调用默认slot=0。

---

## 9. 三槽HUD

把当前单个world-skill改成紧凑三槽：

```text
[E] Slot1
[R] Slot2
[T] Slot3
```

每个槽独立显示：

- icon
- 名称
- CD/charge
- counter
- enabled
- active
- Empty

HUD跟随DirectActor。

查看Clone或别的详情不改变当前DirectActor技能栏。

---

## 10. 空槽

Empty必须可见但弱化：

```text
—
空
```

让玩家理解：
> 系统已经是三槽，但当前职业内容还没补满。

---

## 11. 并行充能

只有当前Profession的已装备Skill会推进：

- CD
- counter
- auto charge
- mode state

未装备技能：
> SkillState保留但冻结。

重新装备：
> 从被冻结状态继续。

本Run第一次装备的新Skill：
> 按冷启动创建。

---

## 12. 新副本冷启动

新独立探索：

> 三个已装备技能都按各自规则冷启动。

不能只有Slot1空充，Slot2/3直接Ready。

---

## 13. 三种并行的区别

### Charge并行
必须成立。

### Background Mode并行
允许成立。

### Foreground Action
一次只能一个技能占据角色身体。

例如不能同时：

```text
Prayer cast
+
Ward cast
+
Reap slide
```

---

## 14. Skill Execution 分类

建议给SkillDefinition增加或推导：

```text
foreground
background
```

当前可按真实行为映射：

### Background
- poison
- snipe
- dance（模式）
- rain的充能阶段

### Foreground
- hunt
- prayer
- ward
- bell
- pain释放
- sanctuary
- reap
- rain实际运行阶段按现有动作占用决定

---

## 15. Auto Ready 不抢动作

如果：

```text
Prayer正在施法
Rain此时充满
```

Rain进入Ready等待，不打断Prayer。

Foreground空闲后再请求执行。

同tick多个Foreground Auto Ready：

```text
Slot1 → Slot2 → Slot3
```

确定性处理，一次只启动一个。

---

## 16. 所有 SkillKind 都要兼容

自动测试必须覆盖：

- timed
- toggle
- count
- auto
- chargedMode
- return

不能只验证普通CD技能。

## 17. Ranger 样板

```text
Snipe / Rain / Empty
```

要求：

- Snipe开启后Rain仍独立充能；
- Rain自动运行不把Snipe状态切走；
- 两个SkillState互不重置；
- Snipe仍兼容EC05 WallPin和EC06背部弱点。

这是最重要的“多技能同时存在”验收之一。

---

## 18. Shieldguard 样板

```text
Pain / Sanctuary / Empty
```

要求：

- Pain受击counter累计；
- Sanctuary同时CD/charge；
- 释放Pain不重置Sanctuary；
- 释放Sanctuary不清Pain counter。

---

## 19. Scythe 样板

```text
Dance / Reap / Empty
```

要求：

- Dance mode可保持；
- Reap正常累计basic count；
- Reap发动时取得Foreground特殊移动；
- Reap期间不重复触发Dance普通横扫；
- Reap结束后Dance仍保持mode。

这是最容易暴露多运行时冲突的组合。

---

## 20. Healer 样板

```text
Prayer / Ward / Empty
```

两者：

- CD独立；
- 一个施法不重置另一个；
- Foreground不能同时执行。

---

## 21. Basic Attack Modifier迁移

当前不少逻辑类似：

```text
currentSkill == snipe / dance / poison
```

EC-07后必须改成：

> 查询当前已装备并enabled的具体SkillState。

重点迁移：

- Snipe
- Dance
- Poison
- Reap basic counter
- Pain hit counter
- Rain

建议建立：

```text
activeBasicAttackModifiers(u)
```

或等价明确接口。

---

## 22. Build UI 三槽

构筑面板改成：

```text
技能槽1
技能槽2
技能槽3
```

选择某槽后，列出当前Profession可装备技能。

规则：

- Slot1不能置空；
- Slot2/3可置空；
- 禁止重复；
- 每个技能显示自己的stage/branches。

## 23. Upgrade 必须指定 SkillId

当前培养依赖“当前技能”。

改成：

```ts
{
 type:'upgradeSkill'
 id
 skillId
 kind
 branch
 expectedLevel
}
```

升级A技能不能污染B技能：

- stage
- branch
- CD fraction

都独立。

本轮允许临时换槽，但有安全规则。

---

## 26. Hot Swap 安全规则

不能替换：

> 当前正在Foreground执行的那个Skill。

其他未运行槽可以调整。

同Skill不能重复。

必须符合Profession。

---

## 27. Toggle / Mode 卸下

卸下：

- Snipe
- Poison
- Dance

时：

> 安全关闭 enabled。

但其SkillState冻结保留。

重新装备后：
> 不自动恢复ON，玩家或原有自动规则重新开启。

---

## 28. 已生成世界效果

已经合法生成的持续场/延迟效果：

> 按自身寿命继续。

卸下技能不能凭空删除已成立效果。

---

## 29. 换入技能状态

### 本Run曾装备过
恢复冻结状态。

### 本Run从未装备
按冷启动初始化。

防止热换技能无限刷新。

## 30. Profile Default vs Run Loadout

建议：

### Profile
保存局外默认：

```text
profile.loadouts
```

### Unit
保存当前Run：

```text
skillSlots
```

Account/Briefing调整：
> 更新Profile默认。

Battle临时调整：
> 只改本Run，不回写Profile。

新Run：
> 从Profile重新复制。

## 31. Campfire

篝火不再简单：

```text
skillCd = 0
```

而是逐技能恢复。

建议：

### timed
ready。

### auto/charged
ready / 满充。

### count
不凭空补counter。

### return
不补普攻计数。

### toggle
不自动乱开/乱关。

需要专门：

```text
restoreSkillAtCampfire()
```

或等价接口。

## 38. Runtime Clock

建议：

```text
advanceEquippedSkills(s,u,dt)
```

但Execution Ownership独立处理。

不能只把旧单技能clock简单循环三遍就认为完成。

---

## 39. 计数触发

例如：

### Pain
敌方直接命中时，如果Pain当前装备：
> 加Pain自己的counter。

### Reap
真实basic出手时，如果Reap当前装备：
> 加Reap自己的counter。

不能再写：

```text
if currentSkill(u).id === 'pain'
```

---

## 40. 多Modifier冲突

当前实际组合逐个定义，不发明无限通用叠加系统。

### Ranger
Snipe + Rain：
- Snipe改basic；
- Rain独立auto。

### Shieldguard
Pain + Sanctuary：
- 无basic冲突。

### Healer
Prayer + Ward：
- 无basic冲突。

### Scythe
Dance + Reap：
- Dance控制basic；
- Reap累计basic；
- Reap执行时接管Foreground；
- Reap结束Dance保持。

未来两个独立技能同时修改basic时，再在角色设计阶段定义。

---

## 41. 卡牌不删除

EC-07完整保留卡牌。

这一轮只是观察：

> 三技能出现以后玩家是不是明显更少依赖手牌。

这会成为EC-13卡牌转型的证据。

# 44. 用户试玩重点

### A. 操作密度
多技能并行后，战斗是否终于不再像“等E”。

### B. UI负担
三个技能是否清楚而不挡画面。

### C. 并行充能
重点玩：
- 阿尔 Snipe + Rain
- 伊内丝 Pain + Sanctuary

判断不同充能方式并行是否更有节奏。

### D. 第三技能内容缺口
第三槽空着以后，是否强烈感觉角色确实需要第三个正式技能。

如果是：
> EC-14角色内容优先级上升。

### E. 战斗中换槽
观察：
- 0.1×换槽是否舒服；
- 是否容易滥用；
- 是否以后应限制到脱战；
- 是否需要换技读条。

### F. 卡牌存在感
观察三技能后玩家是否明显更少打开手牌，为EC-13提供证据。
