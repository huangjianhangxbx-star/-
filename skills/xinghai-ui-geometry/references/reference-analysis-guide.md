# 参考图分析指南

## 操作分类

- **形状参考**：只读取组件的轮廓、内缩和形状家族。人物、文字、图片不应进入资产。
- **风格参考**：只读取色调、对比度、线条粗细、留白和材质取舍，不改变组件结构。
- **两者皆是**：可同时读，但须保留本项目固定几何与纯色约束。

## 证据与决定分层

1. `source`：原始图名、SHA256、裁剪区。
2. `observations`：像素可量信息，包含中性色、中间色、高饱和色以及局部连通区域。不是全图语义理解。
3. `interpretation`：候选几何和建议颜色，带依据（explicit/heuristic/type-based）。
4. `review_required`：必须复核的歧义。摄影/贴图/背景的颜色可能污染建议。
5. `approval_status`：用户未选择具体方案前必须保持 draft。

## 典型陷阱

- 一张人像图里出现大片粉红色，不代表圆形头像框应该是粉红色。
- 一张血条截图里存在绿色阴影，不代表血条主填充一定是绿色；脚本优先识别像素面积最大的强烈单色通道。
- 一张完整 HUD 截图里有多个黑色框，不应强行判断成一个大矩形。
- 未提供 Alpha 的白底截图，不能证明 UI 本身已透明。
- 类似圆形、菱形的视觉轮廓可能被透视/截断扰乱，应显式指定目标几何。

## 固定项目指令

- 用户已确定：黑色底 + 异色纯色细边，形状只能在简单几何范围内变化。
- 头像尽量圆，血条始终矩形。
- 禁止明确方向光源、金属写实反光、复杂纹理裂纹。
- 未确认的提案与实际已经实现的文件要分开。
