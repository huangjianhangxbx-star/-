## 0. 总目标：先有一款可连贯游玩的游戏原型

当前不以完善种田、伙伴 AI、技能树、农业经济或道具图鉴为目标。每个新模块只建立：

1. **一个玩家能真实触发的操作入口**；
2. **一个会影响真实世界状态的示范效果**；
3. **必要的唯一权威、生命周期及最小扩展接口**；
4. **一次可复现的短流程验证**。

已有可证明闭环的模块默认**冻结纵深开发**。除非影响连续游玩、已有批准要求或出现真实 Bug，不因为“还可以再智能一点”而增加阶段任务。

### 决定与现状须分开

- **用户本次明确方向：** 种田与阿尔 AI 都只需象征性功能和可扩展接口；不反对上一轮 AL-ITEM-01B，但要求防止路线被局部功能牵走。
- **GitHub 已技术交付：** FARM-01 两块田基本闭环；AL-ITEM-01A 阿尔后备五格、优先意图和实验缓回药自动使用。两者仍有用户试玩 Gate，不能视作永久玩法定稿。
- **AI 本次建议：** 将 AL-ITEM-01B 缩为一次性战术投弹样板；完成后转回其他尚未闭环的玩法。下面的条件与排期还不是用户批准决定。
- **继续冻结：** 武器升级机制深化、SK-03/04、睡眠清级、成长被动拓展。

## 1. 先做：AL-ITEM-01B-LITE（阿尔实验投弹样板）

### 1.1 任务目的

在 01A 的缓回药以外，证明**第二种不同用途的道具也能被阿尔真实持有、等待合适情境、自主使用**，且自由栏偏好不覆盖安全性和紧急治疗。

这是该系统在本阶段的**收口任务**，不是建设完整战术 AI、通用物品执行器或复杂权重评分体系。

### 1.2 最小功能范围

**A. 一个新物品**

- 新增 `sample-al-bomb`（实验消耗型炸弹），新测试世界给团队背包 **2 个 SAMPLE**，阿尔起始为 0。
- 沿用 Tab 背包、阿尔五格后备、每次交付/撤回 1 件、原自由栏设优先的现有操作与数量权威。无新背包页、配方、图鉴或购买流程。
- **严格区分**该库存消耗品与 EQ-01 的左手副装备炸弹：后者有独立装备、耐久和玩家 RMB 操作，不得把装备实例当作免费库存或重复扣费。

**B. 两种道具的简单行为选择**

- 继续在已有阿尔 AI 决策入口调用，不新增一套定时器、行为树或通用评分系统。
- **先合法、后偏好**：阿尔非实控、存活、当前动作安全、真实持有、目标同层、可见且路径合法才可使用。
- **治疗优先保命**：合法的低血量缓回需求优先于普通投弹机会；即使自由栏设为炸弹，也不会因此拒绝紧急治疗。
- **投弹简单策略**：优先栏指定炸弹时，附近存在至少一名可合法命中的敌人且安全，即可寻找投弹时机；仅存后备且未设优先时，可采用“能覆盖至少两名敌人”这一简单保守规则。均为可替换 SAMPLE，不做敌群预测、风险收益精算或长期记忆。
- 条件不满足就等待，而不是为投弹瞬移、穿墙、取消已接受动作、改变黄金普攻节奏或主动引入新敌群。

**C. 一次真实的投弹结果**

- 尽量复用 `game/src/core/offhand.ts` 所在的已有炸弹路径、投射表现、面积命中和统一伤害权威；允许为了库存型投弹提取最小共享函数，禁止直接绕过原副手的实控资格检查。
- 使用成功必须看见真实在途投射物／落点爆炸，并经现有结算让合法敌人真实受伤；不允许纯日志、瞬间文字扣血或复制一条新的伤害总线冒充实现。
- **以成功释放／生成实体作为唯一耗材扣减点**：扣阿尔后备 1 件；此前取消不扣，释放后不退款；同一投弹不会重复命中或重复扣物。不要强制加入新 Spine 动作、美术素材或新的正式体力／冷却平衡。
- 投弹状态用现有自由栏/背包短提示与已有效果显示即可，不能新增一组永久 HUD 部件。

### 1.3 明确不做

不做多道具通用 AI 框架、复杂评分、精准队友避让、友伤、投弹移动寻位、AI 自动拾取、后备自动整理、礼物好感、拖拽到人物模型、正式道具库、配方、长期存档、全地图伙伴行为重写。FARM-02 和成长系统不随本轮启动。

### 1.4 低成本实施步骤

1. **开工核对（只读）：** 最新 `main` 与本地工作树；读 `AL-ITEM-01A` 合同/交接/验证、EQ-01 炸弹合同、相关现行规则；核对源码真实入口。按 `开发细则` §5/§6 选择并读取本机可用的 Skill，不把本对话不可用的 Skill 冒充已执行。
2. **最小 RED：** 团队/阿尔两份数量守恒；偏好炸弹时遇到真实治疗资格仍会先救人；无合法敌人/主控/动作锁/隔墙/失效访问不会投弹；成功释放唯一扣 1 与命中去重。
3. **最小 GREEN：** 新物品注册、两种候选顺序、复用已有投弹与命中流程；不改原农田、Y 瓶、副装备或黄金基本动作的权威。
4. **原位 UI：** 用现有后备栏与自由栏完成交付、设置优先、消耗数量和简短等待反馈，不重新设计 HUD。
5. **B 级定向验证：** 受影响核心测试、适用的类型检查与构建；少量真实键鼠情境验证“交付→等待→投出→减少库存”“低血量优先治疗”“非法条件不消费”，补测 EQ-01 玩家 RMB 炸弹和既有 FARM/Y 代表路径。使用真实敌人和操作，不注入状态冒充自然故事；夹具边界单独标注。
6. **停在用户试玩 Gate：** 简短交接真正实现、未实现、SAMPLE 参数、验证证据与已知风险。若获准实施且满足既有 GitHub 开发发布授权，仅选择性提交 GitHub `main`；不推 Gitee。

### 1.5 止损线（重要）

如果复用 EQ-01 炸弹需要大范围重写共享战斗状态机、投射物系统、统一伤害结算或伙伴 AI，则**先停下并报告最小替代方案**，不能为了完成一个样板默默演变为架构重构。真实阻断 Bug 可以单独提出修复，不应借机扩大玩法。

**01B-LITE 完成定义：** 玩家将炸弹交给阿尔；她在合适时机完成至少一次真实、唯一消费的投弹；低血量时仍能使用缓回药；原战斗/装备/库存没有明显回归。到此即冻结阿尔道具 AI 的深度开发。

## 2. 01B 之后：立即恢复横向主线

下表是**AI 建议的候选顺序**，均须在各任务开始前核对既有任务和设计依据，并单独批准；不因本计划自动批量授权。

| 候选顺序 | 任务线 | 本阶段的“浅层闭环” | 不做什么 |
|---|---|---|---|
| P1 | **QST-01B：任务推进样板** | 一件能接取/推进/完成的探索任务，能读到进度与结果；复用 QST-01A 已有基础 | 大量 NPC、长对白、分支剧情、任务编辑器 |
| P2 | **SUR-01：生存/环境样板** | 从已确认设计中挑一个环境或生存因素，只验证“状态变化→可见影响→一种应对” | 饥饿/天气/昼夜/温度全套体系同时上线 |
| P3 | **BLD-01：建造/放置样板** | 一种可放置对象，含合法性检查、可见结果与当前世界状态 | 自由建筑、蓝图系统、装修、完整生产链 |
| P4 | **VAL-A / VAL-W：短流程整体验证** | 从进入当前世界、战斗/技能/道具/任务/至少一个非战斗互动直到合法退出和继续，确认多个样板能串起来 | 新增大量内容来掩盖系统衔接问题、发布级全量验证 |

表中的 QST/SUR/BLD 具体规则仍以已有有效设计为准。若某项已有足够的真实闭环，则**直接跳过深化**，选择下一个未被覆盖的机制；如果主线清单的顺序与新版批准决定有冲突，先以最新批准为准重新排队。

## 3. 以后每轮必须先回答的四个问题

1. 这是在**补一个没有的玩法入口**，还是在**深化已经能演示的功能**？前者优先。
2. 完成后玩家能否用**一句话描述新的实际体验**？不能就缩小任务。
3. 是否真的需要新增框架、复杂参数、很多 UI 或长流程测试？不必要就删除。
4. 是否已经达到**功能演示 + 最小接口 + 关键不变量**？达到即停，不凭工程师兴趣扩张。

验证遵循细则 v2.2 的 A/B/C 适用分级：原型阶段小改默认 A；库存、AI 与命中共享权威按 B；重大不可隔离迁移才考虑 C。自动测试通过不代表用户试玩认可。
