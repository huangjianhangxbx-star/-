## 0. 目标与明确规则

用户已明确的 **USER_CONFIRM** 设计：

1. **Y** 触发回血瓶；主角猎人与阿尔**同时回复相同的绝对生命值**（不是每人相同的百分比）。
2. 回血瓶是游戏**唯一的瞬间回血道具**；其他未来回血物品/技能若有治疗应随时间恢复。现有篝火和夺回灰血是不同机制，不擅自修改。
3. 当前探索初始一瓶；每次**成功坐篝火/使用篝火**刷新。
4. PPT **左上主角专属 Y 槽**是显示位置；这不是阿尔的自由道具。阿尔自由道具以后独立实施。

**AI 建议的可替换 SAMPLE（本轮为可玩样板，可试玩后调整）：**

- 每次 **猎人与阿尔各回复固定 100 HP**（以当前最大血量封顶）。
- 由当前存活且可控制的猎人**或阿尔**按 Y 使用同一瓶；瓶仍显示在猎人专属 HUD 槽，绝不为每人复制一个。
- 只治疗 `life=active` 的正式本体；死亡或 `respawning` 不回复、不提前复活；两人同时死亡时无法使用。存活一人时合法使用只治疗该活体，但消耗同一瓶。
- 两名存活本体都满血时，Y 拒绝且**不消耗**；只有一人有缺血也允许使用。拒绝需短提示。
- 即时治疗，不加入长读条、技能冷却、攻击取消或体力费用；不误把回血瓶做成右手 QER 技能或左手 RMB 装备。
- 篝火刷新为**补至 1 瓶，不是额外加 1 瓶、无限叠加**。只在现有篝火交易成功时发生；重复/非法篝火不刷新。
- 单死/双死、全灭返场、合法离区继续不赠送免费瓶、不重置使用历史；新世界有新的初始 1 瓶；刷新页面仍无存档。

上面样板选择只是为了不被小参数阻塞；Codex 不得记为用户永久认可。

## 1. 现有接口与不能踩的坑

实施前核对下列**已发现的实际位置**及其在最新代码中的变动：

| 位置 | 当前有关行为 | 本轮接线要求 |
| --- | --- | --- |
| `game/src/exploration-hud.ts` | 左上用 `data-reserve-kind="bottle"` 保留 Y 槽 | 直接在**原位置**替换成真实瓶数与使用资格，不重排 HUD 或改头像 |
| `game/src/geometry-hud.css` | `[data-reserve-kind=bottle]` 的尺寸、位置已固定 | 复用现有黑底细边几何；需要新增素材时再按需用已安装 Skill，非必要不做大规模资产生产 |
| `game/src/exploration-app.ts` | 统一键盘处理、`controlModal()`、`G/F` 输入所有权、失焦/暂停处理 | 单次 Y down 只调用一个核心命令；严格阻止浏览器 repeat、模态穿透和持键切人串发 |
| `game/src/core/pressure.ts` | `healHealth(u, amount)` 可按最大 HP 封顶并维护灰血约束 | **复用正式 HP 权威**，不直接只改 DOM、不伪造第二 HP |
| `game/src/core/campfire.ts` | `useCampfire` 已实现合法资格、敌人追击判定、记忆一次性写入、活体恢复 HP/架势/体力 | 仅在合法成功分支补瓶；非法/重复不触发；不改变原有篝火能力 |
| `game/src/core/world-session.ts` | `beginWorld` / `leaveWorldArea` / `continueWorld` 管理同一世界 | 回血瓶余额建议成为**WorldSession 唯一权威**，不会因访问/复活重建 |
| `game/src/core/party-lifecycle.ts` | 角色死亡立即消失、单死复活、全灭同世界出生点返场 | 瓶不能复活死者，返场不免费重置瓶 |
| `game/src/core/engine.ts` / `types.ts` | Core `command(...)` 和 `GameState` 类型 | 核心命令接受/拒绝必须原子；UI 只读授权状态 |
| `game/src/core/economy.ts` / legacy item | 旧 `inventory.heal=3` 等为历史/开发兼容 | **不得复用旧三瓶 inventory 作为正式余额**，不得打开旧卡/旧使用道具通路 |
| `game/src/core/weapon-activation.ts` | SK-02 当前 Level0～3 共享世界实验状态 | **冻结：绝不为回血瓶改 V 模态、被动、升级费用、活跃等级与预选方案** |

推荐最小新接口（文件名按最新工程合理化，避免重复架构）：

- `queryHealingBottle(s)`：纯只读资格，判断普通正式探索、当前控制、活体和血量状态；错误返回原因。
- `useHealingBottle(s)`：在核准时**唯一扣瓶**并分别调用 `healHealth`，处理同世界的唯一余额，发出足够短的提示/效果事件。
- `refillHealingBottle(s)`：仅由成功篝火路径调用，设为最多一瓶。不得由 UI、主动技能或死亡复活偷偷调用。
- `GameState/WorldSession` 内只维护一个共享余额；不以组件局部状态作为权威。具体对象名可由 Codex 依据现有模型决定。

## 2. 分段实施

### Y1｜真实权威与失败保护

1. 编写定向核心 RED：新世界 1 瓶、正式双人有效一次每人 +100 绝对 HP、最大血量夹紧；在一人死亡时只治活体、不复活；两人全死、零瓶、满血、旧世界、敌人、克隆/非正式入口均不会扣瓶。
2. 实现核心余额、资格与提交函数；拒绝不可改变 HP、钱包、等级、技能CD、world id、审计/奖励或角色生命状态。
3. 反复 Y 请求不能从一个瓶里多次治疗；允许真实消费后余额 0 的第二次按下仅得到拒绝。
4. 与攻击中使用的冲突按用户“瞬间回血道具”的意图保持简洁：不要求暂停战斗，不取消已经接受的出手；**如果实际动作权威不能安全兼容，记录阻塞并做最小明确门控**，不可借机改黄金动作。

### Y2｜篝火唯一刷新与世界连续性

1. 首次合法篝火成功，将余额设为 1；已有 1 时仍为 1，绝不升到 2。
2. 篝火不合法、附近敌人追击、已经使用过该篝火时，余额与既有机制都不应变化。
3. 同一世界合法离区/继续、切人、角色死亡复活和全灭返场不重置瓶；显式确认全新测试世界再得到 1 瓶。
4. 保留 SK-02 现有模态和 Level，无论玩家是否使用 V，瓶的寿命与其无关。

### Y3｜真实输入与 PPT Y 槽

1. `KeyY` 单次 keydown→核心命令；实际键盘持续按住/repeat 不能连发；模态、文本输入、帮助、暂停、G轮盘、F瞄准、失焦等不触发。
2. 左上主角 Y 槽显示 `Y`、真实余量 `1/1` 或 `0/1`，全满/空瓶可有只读提示，不显示假计时或虚构素材。可以单击槽位按等价 Core 命令使用，前提是不会与场景 LMB 点击穿透混用。
3. 阿尔左下自由道具槽仍保持预留，不变成第二瓶；两人 HUD HP 变化准确，阿尔头像、六区坐标、体力和姿态显示不变。
4. 可用现有简洁圆环/burst 作为 SAMPLE 提示，避免为了这轮制作新 Spine 治疗动作；禁止改成开新面板。

### Y4｜定向 B 级验证与交接

- Vitest：新增 Y 核心、篝火、NR 世界、LT 死亡、HP 灰血；仅受影响小集。
- 构建：`game/npm run build`（依项目真实包脚本）；若共享类型影响 Action Lab，做一次构建烟测；不为单个道具机械重复所有历史浏览器。
- 浏览器：2～4 条自然键鼠剧本即可。重点是真实吃怪伤害→Y双人回血；耗尽后再按拒绝；合法篝火→刷新；Z切人、暂停/面板不穿透；1920 主尺寸与必要 1280 HUD 视觉抽查。
- 保留真实失败与针对性复测日志；区别自然伤害与测试夹具；原型阶段不做全面性能、截图像素签名和全历史塔防复跑。
- 技术 Gate 与用户手感 Gate 分开。交接清单明确 SAMPLE 100 HP、当前可控制角色均可 Y、单死使用、全满不消耗均待用户试玩认可。
