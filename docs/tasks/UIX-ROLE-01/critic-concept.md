# UIX-ROLE-01 概念独立评审

评审日期：2026-10-16。依据：原计划 v0.1、原 PPT 两页渲染、需求清单、plan.md、concept-01.png。仅评审概念，没有把拟实现功能当作已验证事实。

**结论：7.4/10，未达到概念阶段 8 分门槛，先返修概念。**

|维度|得分|依据|
|---|---:|---|
|需求符合度|2.3/3|四入口、商人仅商店亮、右侧 F 提示及移动锁定说明齐全；但视觉菜单围绕的是左侧两名队员，商人在右侧，目标归属不符合 PPT 的贴目标角色半环。芙蕾茜娅四项可选只有文字说明，未显示实际状态。|
|操作直觉度|2.0/3|菜单与商人的 F 提示跨过两名角色，容易误认目标。菜单已打开却同时出现 F 提示，虽写有“菜单打开前”，仍混合两个状态。“角色装备”最后一字折行，按钮不易扫读。|
|UI 布局与观感|1.4/2|保留实机场景，半环方向正确；但矩形文字按钮叠在弧形底板上，尚弱于 PPT 的四个紧贴半环的图形入口。容器标签压在 NPC 头部附近进一步削弱目标识别。|
|架构扩展性|1.7/2|计划将能力、提示、菜单和路由分离，具备可扩展设计；概念阶段没有代码证据，不给实现满分。|

## 必须返修

1. 以商人身体投影为菜单锚点，内弧面对商人，菜单与商人之间不夹入猎人/芙蕾茜娅。概念截图可将玩家和伙伴移到商人右下侧，避免遮挡并让关联明确。
2. 将“靠近提示”和“交互后菜单”分成同张图里的两个明确标注场景/局部，或主场景只画菜单、角落单独画提示态。菜单打开态不同时展示 F。
3. 四入口文字均保持单行；补可识别的商店、对话、礼物、人形装备图形。无需照搬参考美术，但按钮应沿弧排列，别让文字框溢出破坏轮廓。
4. 增加一个伙伴状态小图，展示四项可用，及主控伙伴时只有 Z 提示。这可以是同一概念图的小插图，无需额外制作完整方案。

## 实装时继续核查

- 屏幕边缘翻侧仍应围绕目标，而不是仅将菜单裁进屏幕。
- F 优先最近目标与可见提示必须一致；菜单锁移动但世界继续，不得留下移动键状态。
- 容器和 NPC 重叠时应能辨认选中的角色，旧容器标签不得压住菜单。
- 商店为角色独立库存，不能把伙伴后备当商店库存。

返修后重新评分；本次不是实装迭代，不计入最多三轮实装评审。
