## 0. 本轮目标与完成后的下一步

**本轮目标只有一个：让“我现在操作谁”在输入、镜头和 UI 上始终只有一个答案。**

新默认流程：

```text
明确切人输入
→ 新角色立即成为 DirectActor
→ 技能栏、机动资源和实控标记更新
→ 镜头平滑跟随新主控
→ 原角色转为离手 AI
```

不再要求：

```text
先选成 CommandFocus
→ 再靠 WASD / 左键 / 技能键猜测是否真正接管
```

保留显式选路、持续 MoveOrder、纯手动普攻、技能瞄准与真实动作生命周期。

**本轮通过用户试玩后，下一份计划直接返回 EC-10「简易战术指令轮盘」。** 不要求把旧 XC-01～XC-14 的每个编号逐一补完。动作研究、职业手感和演出质量仍有欠账，但不把它们全部设为轮盘开发的前置。

## 1. 依据、事实与本轮建议

### 1.1 用户已确认的方向

用户试玩发现：进入另一角色的指令模式时，持续移动或下意识再次按 WASD，并不代表自己决定真正换人。旧方案把普通动作输入兼作高层接管决定，造成反直觉。

已确认采用：

- 默认切角色直接进入实控，不再有必须经过的 Command 中间模式。
- 未实控角色由 AI 接管，不再让原主控长期停留在“仍叫 Direct，但只有防御托管”的特殊身份。
- 保留选路和持续移动目标。
- 保留技能本身需要的瞄准／确认；删除的是两套控制身份，不是删除所有 Aim。
- 不为了保住既有工程投入而继续给旧 Command 模式增加例外。
- 精确遥控队友不是当前必需项；不在本轮另做“按住式遥控模式”。未来确有需要时另行讨论。

### 1.2 本轮首测默认值／具体入口建议

以下是为完成本计划提出的具体默认规则，不冒充现有实现或新的长期制度：

| 项目 | 本轮建议 |
|---|---|
| 切人入口 | C 切换两名本体；1 为猎人、2 为本次伙伴；队伍头像点击使用同一切人请求 |
| 世界角色点击 | 沿用已有可控友方本体点击入口，但改成直接切人；整个点击只做切人，不追加普攻 |
| 持续移动 | 成功显式切人时，把未被模态／Aim 屏蔽的有效 WASD 持有方向交给新角色；不要求松开再按 |
| 切人慢动作 | 首测关闭“仅因切人而自动触发”的 1.5 秒慢动作；保留时间倍率基础设施和现有模态慢速 |
| 技能条 | 沿现有 Direct 技能条保持状态／快捷键展示，不新加第二套鼠标施法入口 |
| 选路 | 继续 F 一次性激活，左键确认，右键或 Escape 取消 |

这些默认值用于验证简化后的控制感，不顺带建立新按键设置菜单。若用户后续要求静止切人保留缓动，只调整慢动作策略，不恢复 CommandFocus 或隐式接管。

## 2. 范围锁：保留什么，退出什么

### 保留并复用

1. `controlledBodyId`、身份合法性查询、现有身体动作交接。
2. PathAim、导航合法性、鼠标确认独占、MoveOrder 的目的地与恢复逻辑。
3. Basic 手动起手／手动续段、短预输入、真实 Release、命中及取消反馈。
4. 技能 Target Type、InputStyle、Aim session、目标校验与唯一确认；技能实际执行器和资源系统。
5. Companion AI 的移动、索敌、普攻、避险与已有 Auto／Background 技能。
6. 镜头平滑、碰撞、Break、强制位移、伤害数字及已交付的基础出手声音。

### 从正常探索玩法退出

- 先进入 CommandFocus、再用动作键 Promote 的流程。
- Command 专属三技能准备面板、选路按钮及“指令／实控”双身份提示。
- 原 Direct 因关注另一角色而启用的专属有限防御托管。
- 以 CommandFocus 为权威的鼠标／键盘路由。
- 当前待开发的“Command 闪避／瞬影 UI”独立阶段。

### 本轮不做

不做轮盘本体、新版角色技能、新敌人、动作数值重制、Soft Target 深度改造、Micro Advance、正式 VFX/SFX 素材采购、完整技能 AI 权限、怪物知识、卡牌转型、Tower 物理删除。

不把本轮变成全仓库改名、所有共享模块拆分或大规模历史文档归档。代码只清理与新运行路径相关的分支；历史任务记录保留追溯。

## 3. 新的控制契约

### 3.1 只有显式切换能改变主控身份

`C`、`1/2`、队伍头像，以及保留的可控友方本体点击，统一调用一个明确的切人入口。

- C 根据当前 `controlledBodyId` 选择另一名可操控本体，不再 Toggle CommandFocus。
- 1／2 是绝对角色选择，不轮换、不推断。
- 选择当前已实控角色为 no-op：不重新初始化 AI，不清 CD，不刷新慢动作，也不撤销当前合法 Aim／Order。
- Clone、敌人、非本次队伍角色、离场或倒地角色不能通过人工切换成为 DirectActor。
- 队伍只剩一名可操控本体时，C 不反复变更状态。
- 动作键只作用于当前实控角色，绝不再因一个隐藏焦点改变控制对象。

切人本身不要求新角色立即能执行动作。它可能正在硬直、技能或闪避中；身份与 HUD 可以先切过去，身体是否能行动仍由真实动作状态决定，不能用切人绕过硬直。

### 3.2 切换必须一次提交，失败没有副作用

推荐逻辑顺序，不强制新增函数名：

```text
校验入口未被输入框／独占模态拦截
→ 校验目标本体可操控
→ 目标就是当前本体：no-op
→ 取消旧角色尚未确认的 Aim，令旧 token 失效
→ 清除不能跨角色转移的玩家攻击预输入与一次性按键请求
→ 撤销旧角色的持续玩家移动控制
→ 通过现有 handoff 交接身份
→ 撤销新角色的普通 AI 自主路线，但保留玩家 MoveOrder 与原子动作
→ 更新主控关联 UI／镜头目标
→ 对新角色提交仍有效的持续移动方向（如有且动作允许）
```

目标无效时，不先取消旧 Aim、不先清订单、不先放开旧角色。失能后的系统 fallback 继续独立处理，不伪装成玩家按了一次切人键。

### 3.3 没有隐形第二个“当前操作对象”

正常 Standalone 中：

```text
技能键对象 = 普攻对象 = 机动对象 = DirectActor
主技能栏对象 = 主控标记对象 = DirectActor
新建 PathAim / SkillAim 的 actor = DirectActor
```

被动查看 Clone 或详情可以保留 inspect selection，但它不能成为动作输入的第二权威。

## 4. 持续移动与一次性输入分开处理

这是本轮首要的真实试玩用例，不可只测“松开所有键再切人”。

### 4.1 按住 W 时切人

```text
猎人正在按 W 移动
→ W 仍按住，按一次 C
→ 阿尔立即成为 DirectActor
→ 阿尔接收同一有效移动方向
→ 猎人停止接收玩家 W，转为离手行为
```

禁止：

- 要求 W 松开再按第二次才能移动。
- 两人同时被同一组玩家 WASD 驱动。
- 第一次 C 只进入观察状态，下一次 W 才切身份。
- 按住 C 因键盘 repeat 在两角色之间高速往返。

这里继承的是**有效持有方向**，不是所有物理按下的键。被卡牌瞄准、输入框、窗口失焦或旧 Aim 明确屏蔽的按键不能被切人重新放行。

### 4.2 普攻、技能、闪避不跨角色重放

WASD 是持续状态；LMB、E/R/T、Shift 是一次性动作请求，两类不能共用继承策略。

- 切人只交接身份，不自动攻击、不自动释放技能、不自动闪避。
- 旧角色未消费的玩家攻击缓存清理，不交给新角色。
- 新角色原有 AI 动作可以合法结束，但不能把旧玩家请求当成它的新输入。
- 在 UI 上完成切人的 pointer 序列必须被消费；不能 pointerdown 切人后，pointerup 又让新角色普攻。
- 失焦、暂停后的恢复不重放期间积累的离散攻击／技能事件。

### 4.3 切人不重置动作资源

不改 HP、架势、技能 CD、技能 counter、机动 charges、攻击恢复时间和合法持续模式。已出手的箭、已生成领域、已经成立的伤害不能被回滚或重复结算。

身体处于不可中断阶段时，不清掉强制位移／跨层／落位状态来制造“立即响应”。仍按原子生命周期结束，再允许玩家动作；UI应能说明当前暂不可行动。

## 5. 离手 AI：接回既有能力，不顺便开放所有技能

### 5.1 权限切成两类

| 角色 | 普攻 | 普通战术移动／避险 | 技能 |
|---|---|---|---|
| 当前 DirectActor | 每段由玩家输入 | 由玩家操作，不启用旧 Command 防御托管 | 玩家请求＋既有 Auto/Background 机制 |
| 离手本体 | 按既有 AI 规则起手 | 正常 Companion AI；有订单时服从订单约束 | 保持当前已允许的 Auto/Background；不新增任意手动技能 AI |

“全面接管”指不再停留在有限防御身份，不代表本轮提前完成 EC-11 的 AUTO / RESERVE / MANUAL 技能策略。

### 5.2 交接时不是立刻抹掉动作

旧实控角色如有正在进行的合法动作，先按既有规则完成或合法中断；AI在可行动时从实际位置决策，不恢复一条早已过期的旧 AI 路线。

新实控角色不再接受新的 AI 战术移动、AI普攻或AI主动闪避；已经开始的不可安全覆盖动作允许完成，不瞬移截停。

### 5.3 退出 CommandDefense，但保留通用防御查询

`command-defense.ts` 的特殊触发和 normal exploration tick 可以退出；`defense-query.ts` 等通用威胁／安全位置能力不因名称相近就删除，离手 AI 仍需使用。

若迁移时状态里有旧 `commandDefense`，只撤销它拥有的普通路线，不把 MoveOrder、crossing、skillLanding 一起清空。清理一次旧状态后，正常流程不再生成该状态。

不要让“主控在 SkillAim”重新触发一种隐形防御托管；本轮没有批准这种新行为。玩家选择自己的技能方向时，离手伙伴继续 AI，正在瞄准的主控仍由玩家负责。

## 6. MoveOrder 与选路必须继续可靠

### 6.1 F 仍是一次性工具

无 PathAim 时没有被动路线预览；场景 LMB 不恢复旧点地移动。

```text
F → 预览当前实控者路线 → LMB 确认 → 签发 MoveOrder → 退出 Aim
```

RMB／Escape 取消 Aim；无效路点保留 Aim 和原因；下一段路径需重新 F。模态、已知地形、碰撞及当前动作就绪约束继续有效。

### 6.2 切走不取消已确认目标

```text
切阿尔 → F 去 A → 确认 → 切回猎人
```

阿尔保留自己的 Order ID、目的地和来源策略，AI在订单约束下行动。途中合法自动攻击／技能／被击退只暂停，结束后从实际位置继续。

直接切回阿尔但没有提交新动作，也不取消订单。新 WASD／攻击／技能／闪避真正成功提交后，才依原契约取消该角色旧订单。

**特殊但重要：**按住 W 切到有订单的阿尔时，身份切换本身不取消订单；随后继承的 W 如果成功形成玩家移动，则由这次实际移动取消阿尔订单。两步不能混成“所有切人都清订单”。

### 6.3 未确认 Aim 与已确认 Order 区分

- 切人时旧 Aim 取消，不能把未确认路点交给旧角色自动执行。
- Aim 原先暂停的已确认 Order 可恢复；不能把整个 Order 当作 Aim 临时数据删掉。
- 两角色同时存在订单的能力保留。
- 新 PathAim 只从 Direct 入口创建。旧 `source='command'` 的历史订单若仍存在，保留其原有安全策略，不在迁移时偷偷放宽。

## 7. 技能统一为当前实控角色的同一套输入

### 7.1 退出双模式 UI，不推倒技能执行器

移除正常游戏中的 Command 三技能面板与准备按钮。E/R/T 永远读取当前 DirectActor 的实际槽位和技能。

已有 `Target Type`、`InputStyle`、目标校验、session token、确认去重仍然保留。它们属于技能工具，不属于 Command 模式专有能力。

当前正式技能保持原有 Direct 行为：[R7][R11]

- Prayer/Ward/Bell/Pain/Sanctuary 等按既有即时请求执行。
- Snipe/Poison 按既有模式切换执行。
- Dance、Rain、Reap 的自动进入／退出或禁止手动行为不擅自改写。
- Hunt 不被顺手重做成鼠标定向新技能。

现有正式技能没有承接的 Direction／Point／Unit 框架能力，只保留接口和受控测试，不冒充已有完整正式技能内容。

### 7.2 某技能需要 AimConfirm 时

```text
当前实控角色按技能键
→ 创建其自身 SkillAim
→ Preview / Prelock
→ LMB 确认，RMB 取消
```

其间选择另一个主控：旧会话立刻失效，旧 sessionId 无法再次施放；新角色不继承旧目标、旧槽位或确认点击。

确认仍必须重新检查 actor、slot、skillId、profession、动作、资源、目标与 token。失败不扣资源、不假成功、不误取消订单；成功只提交一次真实技能。

### 7.3 准备／动作权限仍要正确

“删除 CommandReservation”不等于“所有动作在 Aim 期间都可以乱抢”。保留通用 Aim owner 与身体就绪判断：LMB 由 Aim 消费，角色动作未结束不伪造立即施法。

但不要仅为了保留旧 Command 专属测试，另造第二个隐藏焦点或隐藏模式。

## 8. HUD、镜头与点击事件一并收口

### 8.1 玩家看到的主面板只跟 DirectActor

至少统一：

- 当前实控名字／头像／高亮。
- 主要角色状态与三技能槽的技能名、图标、冷却和计数。
- Blink／Evade 的名称与真实资源。
- 当前 Aim 提示与演员归属。
- 镜头 Primary。

镜头可以平滑移动，但 HUD 绑定与输入对象必须在下一次正常渲染时同步更新，不能等镜头到位再改 UI。

不做正式 HUD 美术重制；沿现有布局作最小修改即可。原 `command-skills` / Command Path 按钮应退出正常界面，也不留透明点击层。

### 8.2 世界角色点击不得产生两次动作

同一次点击命中可操控友方本体：只切人；目标就是当前角色时 no-op。不能先切再由同一个 pointerup 补出一段 Basic。

PathAim／SkillAim 已开启时，场景 LMB 优先属于确认，不能因为点在伙伴模型上就偷偷换人。键盘 C／1/2 或明确头像按钮仍可以显式退出 Aim 并切人。

Clone 详情仍可以只读查看；查看不能改变当前技能快捷键对象。敌人和普通地面不属于切人入口。

### 8.3 慢动作首测

本轮建议不因切人自动生成旧 TacticalFocus，也不把查看角色作为时间倍率开关。

保留已有暂停、Build／卡牌等模态慢速和玩家当前基础倍率；不要硬写“任何取消都回 1×”，覆盖原有 2× 或更高优先模态。

未来轮盘可使用其独立的按住期间慢速。那与切人无关，不需要重建 CommandFocus。

不强制全局改名。推荐继续保留 `controlledBodyId` 作为单一权威，在其周围收口既有接口。

| 实际路径 | 本轮职责 |

## 12. 真实浏览器最少八类场景

夹具只固定地形、角色资源和敌人条件；控制身份、UI归属、施法或移动结果必须通过真实键鼠操作产生，不能直接给 `controlledBodyId` 写目标值来冒充切换成功。

### A. 持续移动时切换

猎人按住 W，点击／按一次切人键，不松 W。观察阿尔立即接到输入、技能栏同时切换、猎人自然进入离手行为。再保持斜向移动切回，不能丢键、双控或要求补按。

### B. 单次头像／世界角色点击

点击另一角色一次，只切人，不挥刀。点击当前角色无重置。PathAim 中点在伙伴模型附近仍优先解释成确认目标，不隐式切人。

### C. 切人后技能、机动对象正确

选择两名技能与机动资源明显不同的角色；C后使用E/R/T/Shift，核对资源确实变化在当前角色。另一人的模式、CD和计数不变。现有自动技能仍按既有规则，不为测试伪造第三个正式技能。

### D. 下订单后切回

阿尔 F 确认目的地，立即切回猎人。阿尔继续目标，途中有已交战敌人时可依现有 local auto 规则处理后继续。猎人手动普攻不取消阿尔Order。再无动作地切回阿尔，订单仍在；按W成功后才取消。

### E. 切换取消未确认会话

Direct PathAim 中尚未确认，切到另一角色：不产生幽灵目标；先前已有Order能恢复。SkillAim/token同样验证；目前正式技能不走AimConfirm的部分可用受控定义建立框架用例，但明确它不是新增正式技能。

### F. 真实战斗中的离手自保

用当前敌人Ability制造危险。切走原主控后，它可在现有AI范围和资源内移动／闪避，而不是继续受旧CommandDefense限制。切回后不能有残留AI路线抢玩家输入。不要要求AI每次无伤。

### G. 动作与资源不被切换利用

普攻释放前后、已生成箭／领域、闪避中、硬直中分别切换。验证不吞合法已提交动作、不重复伤害、不刷新恢复/CD、不退还已花资源。旧玩家缓存不能在切回时突然补刀。

### H. 连续操作与UI观察

真实正常遭遇中连续玩一段，包括走路、来回切人、普攻、技能、F选路、一次模态打开关闭。录屏／截图加状态读数，检查没有两套角色UI、没有隐藏Focus、没有误施法或越来越多的残留输入。

至少一次用自然操作跑上述组合，而不是所有场景都先松开键盘、暂停并等待界面稳定后再操作。

## 15. 本轮通过标准与返工上限

通过的重点不是动画终于完美，而是：

1. 任意时刻只有一个明确的实控角色；输入、主技能UI和镜头主目标一致。
