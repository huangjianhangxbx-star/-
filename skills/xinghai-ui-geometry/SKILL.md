# 星骸回廊 UI 几何描边 Skill (v0.2)

## 1. 任务优先级与边界

优先级从高到低：**用户本次硬要求 > 已明确确认的项目风格约束 > 可验证参考图观察 > 分析器候选结果 > 变体自由度**。参考图仅提供可观察的信息，不代表所有要素都应该复刻。来源为他人游戏截图时，应避免按原样提取可识别商用装饰和图标用于再发布。

默认只在独立工作目录生成输出，不修改游戏源码、Git 仓库、人工维护区、开发细则或参考原图。不自动安装 Photoshop、Python 依赖或第三方插件。生成文件并不意味着安装或注册了 Skill。

## 2. 硬性美术公式

**黑色底 + 异色纯色细边 + 简单几何；所有素材外部透明。**

- 底色纯黑/近黑，尽量不含贴图噪点。
- 边框最多数条单色细线；不加梯度、金属反光、明确光源、浮雕、裂纹、大量装饰。
- 技能框方形/菱形保持原家族；头像窗口保持**正圆**；血条始终是**横向长方形**。
- 不因生成更多变体就把圆变方、血条变异形或随机换色。
- 允许区别：线粗、内缩、轻切角、双线、少量刻度、小底座。
- 复杂手绘感觉应由几何边缘和后期精修少量体现，而不是通过随机纹理模拟。

已登记的可机读约束：`references/style-contract.json`。其他说明：`references/geometry-contract.md`。

## 3. 参考图处理：先观察，后推断

1. **观察原图（重要）**：先看用户实际提供的图，记录要保留的部分，例如“只参考边框形状，不参考图标、立绘或背景”。把用户明确要求与 AI 的建议分开。
2. **确定区域**：复杂 HUD 必须选取目标局部。`--crop x,y,width,height` 指裁剪区域。不要把整张游戏截图当成一个孤立框架。
3. **机器分析**：运行 `scripts/analyze_reference.py`，得到来源 SHA256、区域尺寸、主要中性色/高饱和色、颜色候选、简单形状候选和风险提示。
4. **核对结果**：机器不能从复杂截图可靠认出“圆环”“手绘风”或精确图层结构；不确定时明确提供 `--kind`、`--shape`、`--accent`。这些被登记为操作者输入，并且仍标为待用户审阅，不谎称由算法自动证实。
5. **硬风格过滤**：去除照片光感、裂纹、写实雕花和未指定的复杂装饰。只保留与项目规则兼容的信息。
6. **变体生成**：运行 `scripts/render_variants.py`，同类 3–5 个版本始终保留主类型、轮廓家族和主色。
7. **验证与交接**：运行 `scripts/validate_exports.py`，检查尺寸/Alpha/来源与变体差异；拿预览图给用户选择，未验收不能写为已批准。

**最便捷的一键入口**：

```bash
python scripts/run_pipeline.py \
  --input "<参考图.png>" \
  --kind skill_slot --shape square \
  --crop "30,145,385,360" \
  --accent "#7C7777" \
  --count 5 \
  --out "<新的空目录>"
```

若输入已是单一长条血条，通常只需：

```bash
python scripts/run_pipeline.py \
  --input "<血条参考.png>" \
  --count 5 \
  --out "<新的空目录>"
```

血条颜色及填充占比会从像素候选测量；没有可分辨目标时，流程会输出 `BLOCKED.txt`，而不是伪造完成。

## 4. 渲染结果

- `reference-analysis.json`：观察事实与明确标注的候选推断。
- `variants/vNN-名称/preview.png`：最终预览，RGBA，外部透明。
- `variants/vNN-名称/base.png`：基础黑色形状。
- `variants/vNN-名称/frame.png`：独立彩色细边。
- 血条还具有 `fill_full.png` 与 `fill_76pct.png`（历史文件名；内容百分比以每项 `metadata.json` 为准）。游戏里应使用 `fill_full.png` 进行水平裁剪实现动态血量，不要直接拉伸预览。
- `variants/vNN-名称/metadata.json`：真实尺寸、构图区、变体参数、来源哈希。
- `review-sheet.png`：一页对比全部生成版本。
- `validation.json`：自动验证通过项与保留问题。

三类默认尺寸：技能槽 256×256，圆头像框 512×512，血条 1024×96。可传 `--size WIDTHxHEIGHT` 更改，注意头像框与技能槽最好保持 1:1。

## 5. 能力界限

- **本 Skill 不包括大模型视觉推理 API。** 当前 Chat/Codex 的模型可以自己观察图片，并结合脚本测量和显式选区实现“参考 → 变体”；单独运行 Python 并不能自动理解任意复杂美术截图。
- 图像分类主要为宽高比、前景占比等启发式推测；无法保证任意图片的边界正确，需要复核。
- Photoshop CC 2018 尚未运行、连接或输出 PSD。这是下一阶段的独立能力。
- 不自动生成复杂角色、图标或高级手绘纹理。这些应另用专门的图形绘制/生成流程。
- 代码验证不等于用户美术验收。

## 6. 检验命令

项目根目录执行：

```bash
python -m pytest tests -q
python scripts/validate_exports.py samples --out reports/validation.json
python scripts/make_contact_sheets.py --samples samples --out contacts
```

安装依赖见 `requirements.txt`。可选 OpenCV 只用于连通组件候选；没有也可进行基础分析与渲染。

## 7. 如何让后续执行者接手

将本目录放入 Codex 能够发现的技能目录，或明确提供此 `SKILL.md` 路径作为任务输入。是否被客户端**自动识别/允许调用**必须在目标环境实际验证，不能仅因为文件存在就宣称已安装。
