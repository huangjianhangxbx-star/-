## 1. 本轮目标与完成定义

### 1.1 玩家可感知目标

> 玩家能看到准确的当前波／总波数；同一波中来自不同路线的多批敌人分别预告、交错出现；只有本波所有批次生成完且敌人处理完，才进入短暂整备并开始下一波。短关与长关使用同一套规则，但提供不同的构筑长度。整场结束、放弃本场、重试、完成副本和安全带出之间的区别清楚且实际正确。

完整闭环：

**选择／进入节点 → 准备 → 批次预告与生成 → 本波清理 → 波间整备 → 下一波 → 节点胜败／主动放弃本场 → 重试或副本地图 → 既有安全带出／副本完成结算。**

“波次 UI 做完”不等于完成；“只增加敌人数量”也不等于长塔防。批准的短／长样本、正常操作、状态保留、结算和回归都需完成后才转入第七轮。

不重做已经交付的双资源账本、携入、抽牌、变卖、职业技能或复制体系统；不新增正式牌池能力、局外养成、商店内容、复制体维持机制、完整探索、全队命令、体素地图逻辑、地图编辑器或引擎迁移。

不把网页关闭、刷新、崩溃、异常断线视为已经确定的放弃规则；不新增刷新存档、断线恢复或反作弊惩罚。仍只保证当前页面会话内的既有状态寿命。

## 3. 实际实现与本轮缺口

### 3.1 当前仍是“八个按时间触发的刷怪组”

`game/src/core/types.ts` 的 `Wave` 同时持有一条 `route`、`startAt`、`previewAt`、`count`、`spawned`、`interval`。`core/map.ts` 的默认配置仍是八组，数量为 2、3、4、5、6、7、8、10，总计 45；开始时间为 18、45、65、85、105、125、145、165。

`engine.ts:tick()` 遍历所有组，根据整场 `s.time` 生成敌人，当前组号也由绝对时间计算。它没有“当前波结束后才激活下一波”的完整推进流程。S4、S5、S9 支持此判断。

因此不能只把几组名字合并，或只改 HUD 分母。调度及状态边界必须改变。

### 3.2 预告与 HUD 也绑定旧结构

`view/scene.ts:updateWaves()` 直接筛选 `s.waves` 中处于 `previewAt <= time < startAt` 的条目，按旧 `id` 管理预告。`ui.ts` 的准备页写死“8 波递进”，战斗显示当前波和击破数，但还没有独立的波内批次与整备状态。S8、S10。

本轮需让界面读取调度层给出的有效预告，不能自己复制第二套刷怪时间计算。

### 3.3 结算已有基础，缺的是“波结束”和“节点结束”分离

当前 `finish()` 会清复制体、临场手牌、效果及动作，并做节点／副本结果。`enter()` 会重置技能、瞬影、地图结构和抽价。这两类处理不能拿来实现波间整备。S4。

第五轮 `abandon` 表示**放弃整个副本**，直接按失败清随身资源。长塔防所需的“放弃本场、消费重试机会”不能错误复用这个语义。应增加明确的节点失败原因／入口，保留原副本放弃功能。S4、S6。

### 3.4 去重已做好，但预设身份必须随新结构稳定迁移

当前敌人 `rewardKey` 由 `economy.serial + node + group + slot` 产生，经济模块按该键记录领取。它不依赖运行时 `enemy-*` ID。S4、S6。

多批次改造后必须保证：同一敌人重试获得相同奖励键，不同波／批的敌人不会因局部序号相同而碰撞；不能将本次尝试次数、出场时刻或临时数组顺序拼进持久领取身份。

### 3.5 一个明确的前置风险

T-010／T-011 都记录了旧角落接敌停滞：伊内丝在 `(2,7)`、部分敌人在约 `(3.065,8)`；旧基准有持续战斗不结束的复现。此问题本次未独立复现，不能预判根因。S2、S11。

**建议纳入本轮窄范围前置修复。** 新波次必须等待清敌，已知停滞会直接阻塞推进。目标只限恢复合法的接近、交战或返程，不重做整个寻路／空间系统。

不得用超时删怪、强行宣告清波、改胜利条件、扩大穿墙或取消接敌规则“解决”。应先复现和定位，再做小范围修正。

## 5. 开工前仅需确认的三组事项

以下推荐是草案，不能因它们出现在任务文件就视为已批准。执行端先核对是否有更新决定，已经回答的部分直接采用。

### R6-B1：关卡内容量和节点映射

**建议：**保留现有 `1 → 休息 2 → 3` 测试副本结构。节点 1 改为短塔防样本，建议 3 波；节点 3 改为长塔防机制样本，建议 12 波。每波通常 2—3 批，包含至少一波两路线交错和一波同路线不同批次。

先复用已有地图、路线、敌人类别和四人技能；节点 3 原有黑暗条件保留，不把它擅自取消，也不因此扩展光照系统。长样本“更长”主要用更多波次和资源投入曲线体现，不只是敌人血量整体翻倍。

3／12 是建议规模，不是已有用户要求，也不承诺其对应固定游玩时长。可以调整，但批准后短／长样本都要完成，不能交一个短关后把长关推到探索模块。

执行前建立小型内容表，列出：波 ID、批次 ID、路线、出现偏移、数量、敌人构成、强度、预告时长及该波验证目的。无需用户逐个批准每一个 HP 数字；在已批准的内容量和机制范围内按可调原型参数记录。涉及新敌人机制则另行确认。

必须区分“预期给玩家的选择”和“已经通过试玩证明”。正常资源回放只能验证可通关、资源正确，不能证明所有构筑均衡。

### R6-B2：整备与预告的操作／时间契约

**建议起点：**整备 5 个模拟秒；每批预告提前 5 个模拟秒；首波第一批暂保留当前 18 个模拟秒的开战缓冲，最后 5 秒显示预告。后续首批预告与整备可以重叠，不默认额外串行加出两段等待。

建议本轮不新增“立即开下一波”或无限整备按钮，避免提前发波绕过预告。暂停和 1×／2×仍沿现有机制。

整备仍为同一场塔防战斗：允许正常移动、健康回收／再部署、既有技能、培养、换装、抽卖；不能同职业换技能或洗点，不提供免费修复、回血、回满技能或资源奖励。

普通游戏模拟继续推进：濒死超时、技能窗口、自动充能、瞬影恢复、异常状态和自然到期效果仍按各自既有规则工作。自动箭雨空场时的窗口消耗等现有效果不因整备被暗改；菲奥蕾影庭例外也继续适用。暂停／模态／隐藏则一并停止模拟。

**清波不自动救援。** 仅整场节点真正结束时才执行已确认的塔防结算救援。波间还有濒死者并不阻止波次按已定计时推进，玩家仍可单独救援；该组合建议需在开工前明确采用。

### R6-B3：弃本场的入口与适用范围

长塔防“弃本场视为节点失败”已确认。本轮只需细化入口，并确认是否同样提供给短塔防和节点初始准备页。

**建议：**短、长塔防均提供“放弃本场（按节点失败）”；从已进入节点的准备页开始可用，避免用反复进退绕过节点进入次数／临场发牌约束。保持“放弃整个副本”单独入口。

确认界面清楚写出：本场失败、消费重试机会、是否还能留在副本、随身资源是否将全部损失。确认前的打开／取消不改变结果；模态阻断时间，取消后恢复之前的暂停／倍率，而非自动回到 1×。

重复点击或已经结束的尝试不得再次扣次数。水晶失败与主动弃本场走同一受保护的节点失败终结流程，但保留不同原因文本。不能显示“水晶已破碎”来描述所有主动放弃。

若弃长关后尚有重试，返回副本地图；此前已经开放的测试安全撤离仍按 T-011 条件可用。这是先承担节点失败后的既有路线，不是长关内部“通过几波即可成功撤离”。

## 6. 关键工程约束（实现建议，不能改变已确认玩法）

### 6.1 分离定义、运行时与领取身份

建议用嵌套 `WaveDefinition → BatchDefinition → SpawnEntry` 表达内容，以独立运行状态保存当前波、已生成数量、阶段和基准时刻。类型／文件名可由执行者选择；不要为了名称统一重写全部核心。

每个批次应有稳定 ID。不同波同名的局部批次必须用波 ID 组成唯一身份，或使用节点内全局唯一批次 ID。波序、路由、敌人模板和奖励身份分别负责各自职责。

敌人类别建议在内容表中明确，不继续仅依赖整场 `s.spawned % N` 隐式决定；否则修改早一批数量会连带改变后面所有批次构成。允许在内容生成时按确定规则生成清单，但运行中不要依赖“恰好先生成了几只”。

奖励键应保持第五轮的同副本同预设一次领取语义；去重账本不要在波切换／重试时清空。允许结构化迁移键格式，但须先明确同一运行会话中何时重新初始化，不能用格式改变再领一遍旧奖励。

### 6.2 单一波次调度入口

建议新增一个窄范围波次模块（例如 `game/src/core/waves.ts`，**此路径目前为建议新增**），或在合适已有模块中封装。负责生成计划、批次预告查询、清波判定与整备推进，供核心和界面共同读取。

整场 `s.time` 不随波切换归零；波内时刻另用波启动锚点／局部运行状态计算。这样不影响技能、已发回声、异常和账本的时钟。

不能在开局一次性把所有后续波都激活，继续按全局固定时间偷发。只在上一波合法完成后确定下一波启动时点；同一波不同批次允许独立时间偏移和重叠。

### 6.3 清波条件和事件顺序

- 当前波所有计划生成的单位都已生成；尚未到时的后续批次不能因为场上暂时没人就被跳过。
- 当前波相关敌人均不再在场。已击杀与已漏怪都能结束该敌人的在场状态，但漏怪仍扣水晶且不发击杀收益。
- 接敌、返程、受控或寻路中的活敌都不是“已经清除”。不把短暂无目标等价于死亡。
- 最后一波结束才执行整场胜利；最终同一步水晶归零时保持既有失败优先，避免一场既发成功又发失败。
- 不等待无限持续模式或所有友方临时效果清零才算清波；清波看敌人与待出批次，不能被常驻友方技能卡住。
- 保留既有到位／回收保护、伤害与濒死超时的有效先后关系，再进行波完成与整场胜败判断。新增流程不得回退为依赖单位数组顺序。

建议为每次战斗尝试添加唯一终结标记，覆盖自然失败、主动弃本场与胜利的重复调用；同一结果不能重复扣次数、入库或清理。

### 6.4 预告与画面

调度层提供预告列表，包含波／批身份、路由、预告开始和首次生成时间；场景只负责展示和插值。共享路线可以复用几何，但不能把两个不同批次的预告事件吞并。

至少区分：等待首波、本波待出批次、批次正在生成、清理剩余敌人、波间整备、最终结果。不要用“击破数/总敌数”代替“当前波/总波”。

多批同刻、两条路线重叠或复用时保持可读，不要求仅靠更多颜色区分；可使用批次标记和倒计时。预告时长按游戏模拟时间，暂停／减速／2×保持一致；减少动态效果时保留静态路线和时间信息。

### 6.5 不在波间调用节点初始化／清理

禁止在波切换时调用整场 `finish()`、`enter()`、`clearClones()`、`resetNodeSkills()`、`resetPersonal()`、`settle()` 或重置 `economy.draws`。

波间不重新发临场牌、不解锁已锁分支、不移除仍合法的影体、不清正常持续效果、不恢复水晶。不凭 `场上暂时无敌人` 切成探索非战斗权限。

真正节点结束则仍按既有规则清理：影体与其绑定牌、临场牌和待领项、节点动作／效果等。健康回收与濒死获救不能混淆。

### 6.6 当前旧测试如何迁移

`game/tests/map.test.ts` 明确断言八组及绝对开始时间，这属于本轮有意替换的旧契约。应新增／替换为批准内容表和清波推进的断言，而不是删掉测试来通过。

第五轮部分边界夹具通过清空 `s.waves`／`totalEnemies` 强制胜利。新调度接入后，应提供明确的空场或最终波夹具，避免仅改旧字段而残留另一份运行状态。

保留旧地图路由合法性、实际经济和前几轮操作测试。需要旧 45 敌人配方作历史回归时，可在新调度器下作为明确测试配置运行；不在正常游戏同时维持两套不同规则的调度器。
