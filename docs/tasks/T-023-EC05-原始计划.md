# 星骸回廊：T-023 / EC-05 Break 2.0 与强制位移实施计划 v0.1

> 日期：2026-10-05  
> 当前核对基准：GitHub `main@1c95f535bb4c0405f06f6be5bdfbbc1ef0137e07`。  
> 前置：EC-01～EC-04 已实现。用户反馈 EC-04 程序层面未发现问题，但仍有未梳理的设计问题；这些问题不视为最终解决，本阶段只处理与 Break 2.0 直接重叠的规则。  
> 状态：计划草稿，尚未实施、未写入仓库。

## 1. 本阶段目标

把当前架势系统从：

> 架势归零 → 下一次架势命中 → 0.6秒硬直

升级为：

> **架势归零 → Broken → 下一次有效架势攻击触发 Break Reaction → 真正硬直 + 可配置强制位移 → 撞墙时产生 Wall Impact / Wall Pin。**

目标体验之一：

```text
猎人把敌人架势打空
↓
阿尔强化箭命中Broken目标
↓
目标被强力击退
↓
撞墙
↓
Wall Pin / 钉墙眩晕
↓
形成输出窗口
```

本阶段不是全面重做技能，只建立 Break / Impact / Forced Motion / Wall Impact 的通用战斗语法，并给当前可玩内容一个真实验证载体。

---

## 2. 保留两段式 Break

第一击把架势打到 0：

```text
posture > 0 → 0
```

只进入：

> **Broken**

不自动硬直。

Broken 状态下再次受到：

```text
postureDamage > 0
```

才触发：

> **Break Reaction**

结果：
- hard stagger；
- 动作中断；
- 按攻击 Impact 产生强制位移；
- 若撞墙且该攻击允许 Pin，则 Wall Pin。

---

## 3. 修正 EC-04 与 Break 的直接冲突

当前 standalone enemy Telegraph 的有效条件中包含：

```text
enemy.posture > 0
```

因此敌人刚被打到 0 架势时，正在准备的 Telegraph 会直接取消。

EC-05 要修正为：

> **Broken 本身不是 hard control。**

所以：
- `posture == 0` 不能单独取消 AttackIntent；
- 真正 `Break Reaction / stagger > 0` 才取消 Telegraph；
- Break 后未结算攻击不得继续 Resolve。

这属于 EC-05 必须覆盖的交叉语义，不代表 EC-04 其他设计问题都已解决。

---

## 4. 己方 0 架势移动锁保留

己方：
- `posture <= 0` 仍禁止普通 locomotion；
- 不能基础 Evade；
- 可以沿既有规则原地攻击 / 使用允许技能；
- 再受正架势攻击 → Break Reaction。

敌人：
- 暂时不新增完全对称的 0 架势移动锁；
- 直到 Break Reaction 前仍可沿现有行为行动。

---

## 5. applyPosture 改为结构化结果

建议：

```ts
type PostureResult = {
  applied: number
  becameBroken: boolean
  breakReaction: boolean
}
```

用途：
- 区分“打空”和“真正Break”；
- 后续供FX、AI、技能、怪物知识、Setup/Payoff使用。

---

## 6. 基础硬直保持现值

继续使用：

```text
Break Stagger = 0.60s
```

Break hard-control结束后：
- posture恢复到最大值50%；
- 重新进入1.5秒自然恢复延迟。

stagger期间不重复触发Break，也不刷新。

---

## 7. 新增 Impact

攻击以后可以拥有独立于伤害的：

```text
Impact
```

Impact 不等于 HP Damage，也不等于 Posture Damage。

建议：

```ts
type ImpactSpec = {
  distance: number
  origin?: Pos
  direction?: Pos
  wallPin?: boolean
  wallPinStagger?: number
}
```

EC-05 首版只在：

```text
breakReaction == true
```

时消费 Impact。

---

## 8. Impact Weight

新增独立控制重量：

```ts
type ImpactWeight =
  | 'light'
  | 'medium'
  | 'heavy'
  | 'immovable'
```

不要从HP、模型大小或武器负重隐式推导。

首版映射：

### Light
- 普通 melee enemy
- ranged enemy

### Medium
- 猎人
- 阿尔
- 菲奥蕾

### Heavy
- 伊内丝
- enemy Heavy

### Immovable
- 当前正式单位暂无；
- 复制体首版建议视为 immovable，避免破坏既有“不可移动”契约。

---

## 9. 重量倍率

建议：

```text
Light      × 1.00
Medium     × 0.75
Heavy      × 0.40
Immovable  × 0
```

ImpactSpec 的 `distance` 表示：
> 对 Light 单位的基准位移。

---

## 10. ForcedMotion 是独立机制

新增：

```text
ForcedMotion
```

它不是：
- path；
- direct；
- follow；
- AI locomotion。

Broken目标虽然不能主动移动：
> 仍然可以被外力击退。

建议状态：

```ts
type ForcedMotion = {
  sourceId?: string
  direction: Pos
  remaining: number
  speed: number
  wallPin: boolean
  wallPinStagger: number
}
```

---

## 11. 强制位移速度

首轮建议：

```text
8 U / 模拟秒
```

例如1.6U击退约0.20秒完成。

不是瞬移。

---

## 12. ForcedMotion 优先级

只要存在 ForcedMotion：
- WASD不能覆盖；
- AI不规划；
- Follow不推进；
- 不开始新的普通移动。

hard stagger仍负责“角色不能行动”的战斗状态。

---

## 13. 强制位移碰撞

连续采样，不能：
- 穿墙；
- 穿障碍；
- 穿Barricade；
- 出地图；
- 跨layer；
- 穿其他 active body。

建议采样步长约：
```text
0.025～0.05U
```

撞到其他单位：
> 只停止，不做链式撞飞。

普通探索本体互穿规则不适用于 ForcedMotion。

---

## 14. Wall Impact

如果 ForcedMotion 因：
- 墙；
- 障碍；
- Barricade；
- 地图边缘

提前停止，创建：

```text
WallImpact
```

第一版：
- 有明显世界反馈；
- 可统计；
- 不额外造成HP伤害。

---

## 15. Wall Pin

只有：

```text
impact.wallPin == true
```

时，WallImpact 才升级成：

> **WallPinned**

效果：
- 停在墙前合法位置；
- hard-control延长；
- 显示“钉墙”；
- 提供以后技能/AI可查询状态。

建议总硬直：

```text
WallPin hard-control = 1.40s
```

使用：
```text
stagger = max(stagger, 1.40)
```

而不是反复累加。

---

## 16. WallPinned 状态

建议新增：

```text
Status kind: wallPin
```

或等价专用字段。

后续 EC-11 可直接利用：
- prefersWallPinned
- bonusVsWallPinned

Pin期间继续受击：
- 正常伤害；
- 不重复延长Pin；
- 不再次Break。

---

## 17. Break 打断 Telegraph

Broken敌人可以继续 Tracking / Locked。

但下一次有效架势攻击触发 Break Reaction 后：
- stagger生效；
- AttackIntent立刻取消；
- Telegraph消失；
- 不再Resolve。

这样玩家可以用Break主动打断敌方重击。

---

## 18. Active Evade

如果本次攻击本来会触发Break，但目标成功 Active Evade：
- 整次 Hit Miss；
- 不扣架势；
- 不Break；
- 不Push；
- 不WallPin。

沿 EC-03 / EC-04 的顺序。

---

## 19. 护盾与 Break

继续沿当前规则：

> 架势伤害发生在HP / shield之前。

所以即使HP伤害被护盾吸收，只要攻击真实命中并满足架势规则，仍可触发Break Reaction。

---

## 20. 特殊原子位移

以下不允许被粗暴 ForcedMotion 覆盖：
- crossing；
- skillLanding；
- 回镰身体滑行；
- 其他原子位置生命周期。

第一版：
> hard stagger仍生效，但若无法安全覆盖位置生命周期，则 suppress Impact。

必须保证角色不被推到非法位置。

Evade动作：
- Active window内 → Miss；
- window结束但动作未完时被Break → Evade中断，进入ForcedMotion。

---

## 21. 当前 basic attack 的原型 Impact

这些只是系统验证参数，不是最终技能平衡。

Light目标基准位移：

```text
猎人 basic           0.40U
阿尔 basic           0.45U
菲奥蕾 basic         0.30U
伊内丝 basic         0.75U

enemy melee basic    0.45U
enemy ranged basic   0.30U
enemy heavy basic    0.90U
```

再乘目标 ImpactWeight。

普通 basic Break：
> 默认不 Wall Pin。

---

## 22. 为什么普通Break也需要小位移

用户已经明确希望：
> 架势被打空后的下一击产生真正的硬直和位移。

如果只有少数技能能推：
> 普通Break仍然会退化成“原地停0.6秒”。

所以所有正式 basic Break Reaction 至少产生可见的小空间反馈。

---

## 23. 阿尔狙击作为高Impact验证载体

EC-05 不全面重做技能，只选一个现有攻击验证“Break → WallPin”。

选择：

> **阿尔开启狙击姿态后的主箭**

因为它最接近用户已经描述的“强化箭”。

当：
- snipe.enabled = true；
- 主箭非derived；
- 本次命中真正触发 Break Reaction；

建议：

```text
Impact基准：1.60U
wallPin = true
WallPin总hard-control = 1.40s
```

非Broken目标：
> 正常伤害/减速/贯穿，不打飞。

未撞墙：
> 只击退，不Pin。

撞墙：
> WallPinned。

derived贯穿 / echo：
> 不重复Pin。

---

## 24. Derived / 高频攻击

首版默认：
- rain微箭；
- poison爆发；
- echo；
- 多段派生；
- sanctuary等

不产生 ForcedMotion。

避免高频小攻击把目标连续推成弹球。

它们仍按现有架势规则参与是否触发hard stagger；是否给最小位移由实施时保持“非derived basic才有Impact”的清晰契约。

---

## 25. Enemy Heavy 作为玩家被推验证载体

enemy Heavy basic：

```text
Impact基准 = 0.90U
```

不WallPin。

例如：
- Broken阿尔/猎人 → 被推出明显距离；
- Broken伊内丝 → 位移更短。

用于验证系统对双方成立。

---

## 26. 伊内丝重量价值

同样的 Heavy 0.90U Impact：

```text
Medium目标：约0.675U
Heavy目标：约0.36U
```

因此伊内丝第一次能通过空间反馈体现：
> “更站得住。”

## 27. Break FX

本轮只做最小可读反馈：

### Became Broken
- 继续现有架势条Broken状态；
- 可加轻微破裂脉冲。

### Break Reaction
- 短冲击效果；
- 真实位移；
- hard stagger表现。

### WallImpact
- 碰墙点短burst。

### WallPin
- 短显示：
  ```text
  钉墙
  ```

不做正式钉墙动画资产。

---

## 28. 强制位移结束后的AI

ForcedMotion不是玩家命令，不自动刷新传统anchor。

但结束后：
- 当前AI task必须重新验证；
- 旧路径不能自动续走；
- enemy AttackIntent已经取消；
- AI从新位置重新决策。

不能：
> 被推飞 → 硬直结束 → 立刻沿旧路径折返。

---

## 29. WallPin 与架势恢复

WallPin期间 posture继续保持0。

只有最终 hard-control结束后：
> posture恢复50%。

不能基础0.6秒结束就先恢复架势、角色却仍被Pin。

# 31. HitOptions 扩展

建议：

```ts
type HitOptions = {
  ...
  impact?: ImpactSpec
}
```

resolveHit大致：

```text
Active Evade
↓
applyPosture → PostureResult
↓
如果breakReaction
  → staggerAction
  → applyImpact
↓
HP / shield / gray
```

保持当前“架势先于HP”的规则。

# 32. Break 与死亡

如果同一击同时导致：
- Break Reaction；
- HP归零；

死亡/濒死生命周期优先。

不能让dead/downed body继续由ForcedMotion长时间驱动到非法位置。

允许有短促Impact反馈，但第一优先是生命周期正确。
