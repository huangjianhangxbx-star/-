# LE-04 基础地貌编辑器与形色参考笔刷设计

日期：2026-11-03。状态：用户已确认双路线和职责边界；本稿是通宵实施计划的设计依据，尚未执行Unity开发。替代2026-11-02的“规则岩体套件＋端口＋雪岩融合”草案，不继承其12角色套件或跨线统一网格任务。

## 1. 已确认的产品边界

### A：基础地貌编辑器（本轮）

保留现有可用的台地、隆起、延伸、下压、悬崖及局部塑形。完善局部编辑性能、锚点与可调范围、便捷笔刷／区域上色，以及通用形色参考笔刷。

外部模型是生成参考，不是必须完整保形的构件。读取外形和普通RGBA分布，按目标格度重新采样／增减占据；允许缩放、各轴伸展和方向调整；与基础地貌按同一体积规则编辑。不同参考复用同一采样和融合流程，不为每个源写专用连接件、支撑或建筑语义。

参考形状不会理解任意物体设计含义，这符合用户预期。输入源中的“snow”等标签仅作来源记录；本线不执行雪帽暴露、覆盖转岩、雪层厚度或真实雪岩分层规则。参考白色只是白色。通用分色允许按高度／表面朝向／区域工作，但不因此宣称有具体地貌美术生成能力。

### B：用途专属搭建（后续独立方向）

房屋、屋顶、楼梯、桥以及真实雪岩分层等，使用有设计特征的源构件、剖面和专属规则。水洼／草地可作为环境工具，具体可采用水面／分布等方式，不强制全是预制件。此线另出实际对象的实施计划，本夜不做它的素材库或规则生成器。

A与B各自保有作者和Mesh，可以在同一个Scene按坐标、表面吸附和遮挡组合。两者不要求网格焊接、体积布尔或把B重新体素化到A中；对齐不等于融合。共享交互、保存／导出便利设施，不以共用整个世界体积组合器为前提。

## 2. 本夜希望交付的操作闭环

同一研究工程中实际操作：
打开／另存基础地貌 → 点击锚点 → 调X/Z各向范围和高度带 → 隆起／压低或延伸 → 笔刷涂色／区域填色 → 选一个参考源 → 改尺寸与方向 → 连续画出参考地貌 → 局部削减 → Undo/Redo → 保存重开 → FBX带色移交。

锚点精修与连续拖画是两种输入，不把连续画改成每一笔都必须额外弹窗确认。锚点模式有明确“应用／取消”，滑条变化只更新候选，不把每次变化做成一条历史。连续模式按下冻结基准，拖动收集轨迹，松手提交一次。

已有悬崖规则本轮保留可选，不强迫采用上一轮板件化候选，也不承担重新打造所有自然地貌美术的任务。

## 3. 当前事实与优化方向

当前没有逐体素GameObject。TerrainDocument以XZ可变尺寸叶格、顶高和塑形规则描述作者；TerrainSolidSurface在编译时保存竖向区间，CompilerV2输出暴露面和4m块。水平面仍多为逐叶格四边形，侧面只有有限连续合并，因此表面化已做，但共面合并与局部缓存不充分。

已测旧24m/28968叶格：长笔触松手完成约472—543ms、Undo601—617ms；带旧手放模型的一次普通编辑约341ms、主线程最大Tick154ms。后者是旧混合模型路径，不能直接作为新A-only优化百分比的分母。旧Core分配数据为同几何CPU对照；module managedBytes是堆差值，不能称总分配。

采用“压缩编辑数据＋局部分块缓存＋合并表面”。保留能编辑的体积／颜色真源，平时只显示表面；锚点仅激活局部数据，不每次从Mesh逆向体素化。闭合外壳可以重新体素化，但不必反复支付代价，也不能靠外壳恢复完整隐藏颜色、规则与历史。

平整同色面优先合并；不能跨颜色、法线、真实开口或不可恢复的拾取语义盲合。新模式允许三角划分变化，以真实表面覆盖、法线、颜色和逻辑归属等价验收；旧legacy模式保持原字节指纹。减少面数不代表必须改变外形、格度或把阶梯抹平。

## 4. 作者数据与兼容

在原LE01TerrainAuthor旁新增LE04TerrainState。旧TerrainDocument和已认可悬崖规则作为基础；新增稀疏局部体积覆盖、颜色层、参考库与笔刷设置。没有覆盖的区域按旧基础读取并复用缓存。

局部体积以最细0.0625m坐标的XZ列和带普通基础色槽的半开竖向区间描述：未编辑列不保存副本；首次编辑列读取实际基础实体作为当前值，之后该列的新完整区间列表成为权威。空列表表示已删空，不是“没有覆盖”，因此下压／擦除后旧基础不会冒回。操作只改所选高度带，列内其它高度区间保持。仅压缩受影响列，不把全场展开为3D数组。

多段区间用于中段加粗／局部凹入；本夜不建设通用SDF编辑器、任意3D雕塑、复杂洞穴网络或自动支撑系统。移除唯一支点等形成孤立悬空碎块时拒绝该候选并保留原提交，不用不明规则删远处结构。

颜色与形体分离：手涂覆盖优先于参考生成色，参考生成色优先于旧基础色板。颜色绑定作者局部体素区域／面向，不绑定易变的三角序号；重建相同表面保色，新暴露表面在手涂覆盖内继承其色，覆盖外用参考或基础色。整体移动作者时一起移动；本夜不承诺任意单块变形都携带全部表面花纹移动。

新文件kind=basic-terrain-v2，保留原terrain与新增volume/paint/references/settings；旧文件另存候选后采用，原文件不覆盖。未知schema拒绝，不能按旧字段读完再保存丢新层。

LE03旧混合terrain+placements继续旧路径显示与保存。不得自动拆旧mixed Mesh、吸收其独立件或把原件变参考。需要A工作副本时显式提取原基础作者，旧混合文件和构件原样保留；若无法安全另存就明确保留只读，不以兼容为名重写整套旧混合器。

## 5. 锚点与可调范围

首个实际可见命中确定锚点、法向、高度基准与作者revision；候选不能成为新采样基准，防止越画越高。侧面与顶面可选，在未释放前移动视角不改变已冻结位置。

本夜提供圆／椭圆范围及沿X/Z正负方向独立扩展，另设上下高度带。滑条只影响一次操作的候选，支持恢复默认和取消；显示实际可编辑范围和边缘衰减。允许接触面上直接操作，不在虚空固定平面误投。连续延伸到空地时使用显式工作平面，原遮挡不应被穿透。

后台重建halo只用于读邻接和封边，不扩大作者改动范围。范围外体积、手涂及独立物体不变；邻块仅因封边需要更新对应派生面，不整片墙同时选中。

## 6. 通用上色与分色

必做两种入口：
- 颜色笔刷：在实际可见表面连续涂，支持色板／取色、半径和高度限制。
- 区域填色：对当前锚点范围一键填色，可选全部可见面／顶面／侧面，并按高度带限制；不要求逐笔把大区域涂满。

颜色以明确操作提交，Undo/Redo／保存／Scene／FBX保持。几何重建不擦掉手涂；参考Add默认只给新增实体写参考色，不刷掉既有手涂，覆盖颜色需显式选项。界面提供“仅改颜色”而不改变形体。

顶/侧/高度分色是普通工具；本夜不增加Snow语义自动识别、不制作雪帽几何或专属雪岩材料。原有legacy雪岩主题不删除、不迁移，也不当成本轮新增能力。色板容量先限制256个稳定槽，超限明确提示；不得每个点增加一种近似色导致全场UV改写。

## 7. 通用参考笔刷

输入优先使用已认证.voxel.json和已有一次性认证Unity静态模型。沿用严格的真实占据与RGBA读取，不用源bbox填满；不额外建设对任意斜面、骨骼、非闭合源的通用修复器。源不满足条件明确拒绝，保留当前参考。源单位与目标格度分别记录，目标采样是参考生成，不声称精确保形。现有世界坐标预算保持，不把本夜优化宣称为无限大场景或分块流式加载系统。

导入一次编译为只读形状／颜色场。缓存key覆盖源几何/颜色hash、采样版本和设置，鼠标移动、拉滑条和重复落笔不反向读取Mesh或重复体素化；源文件不改。

参数：目标格度沿用.25/.125/.0625m；总体尺寸与X/Y/Z伸展各为0.5—3倍，最小尺寸至少一个目标格；水平朝向，是否带参考颜色、形状融合宽度和固定变化种子。放缩通过目标占据重采样，不对场景Prefab做Transform.scale。预算先限制一次局部候选最多65536个目标采样格；超预算不静默降低精度，提示缩小范围。

操作：增加／削减／颜色参考分开。增加对扫掠形状求并集，削减对当前实体求差；源空白不意味着主动挖穿已有地形。参考颜色只为明确写入范围分配普通RGBA，没有具体雪／岩行为。

连续笔画按弧长规范化重采样，同一折线分成10/200/2000段得到同一覆盖；移动速度和事件频率不决定体积。重复扫过同一区域不反复增高。融合只使用通用地貌规则及局部过渡，有限且可重复的变化由固定空间种子控制，不为每种源写特判，不按当前帧随机洗牌。精确源轮廓不是承诺；源码和来源指纹可追溯。

两个真实参考源足以验收本夜：不同不对称阶梯外形、不同普通配色分布。使用现有原创源或通过共享工坊API另存最小测试源，不制作B线雪岩套件。对照源模型、目标采样预览、不同尺寸、实际连续结果及颜色，不能用Prefab原样摆放截图冒充参考生成。

## 8. 显示、拾取、缓存和事务

新A编译不经过LE03Modules.ComposeForUpload同步全层组合。基础和局部覆盖一次得出最终A实体；按旧／新dirty并集更新块，空块必须提交清除。保持B及旧手放数据独立，不建设跨线世界统一网格。

共面合并后按命中位置＋法向查询逻辑列／面归属，不把大三角的一个boundaryKey当整面身份。必要时保留每块的可查询来源表；不能用nearest墙回退掩盖错误命中。

只复制变化块的快照；鼠标输入不深拷全世界JSON。后台求解和网格准备，主线程只上传准备资源；过时generation/revision的结果不得触碰作者、颜色或历史。一笔／一次锚点应用只一条Undo；已松手导航保留，未完成Esc恢复确切提交资源。滑条变动可合并中间预览，但最终值不得丢。

候选与已提交显示分清；分预算更新Collider时不把半个新作者写入文件。保存／导出等待稳定提交，打开和Undo后回填当前参数。当前未编辑的块复用同一Mesh对象，而不只统计“只输出几个块”。

## 9. 性能与验证目标（不是已有成绩）

基准保持原24m/28968叶格作者，主测A-only；局部半径1.5m、.25m格度。另测一次.125m与跨负坐标／4m块界，不用改变格度和源细节伪装优化。

预热5次后20次同类操作，冷导入单列：
- 输入P95≤2ms、最大8ms；含最终Mesh/Collider上传的主线程Tick P95≤8ms、最大33ms；
- 热预览P95≤150ms；松手／锚点应用完整完成P95≤300ms、最大600ms；
- 取消恢复≤16ms；Undo请求≤100ms、完整恢复P95≤500ms、最大750ms；
- 固定小源首次认证／本地构建目标≤1.2秒单列；大源预算拒绝不与小源混算；
- 同一次局部worker+main总托管分配目标≤64MB，分别测线程分配，不把堆差值当总分配；
- 平台夹具须显著减共面三角形（目标≥50%），曲折悬崖不强求同一比例；几何覆盖、法线、颜色和拾取归属保持，旧legacy全数组保持。

数值目标未达需继续定位和修复，不能只报Drag回调流畅。CPU测试不等于完整GUI帧率，物理鼠标体验与美术认可仍由实际使用反馈确认。

## 10. 通宵执行与保护

估算约6—8小时，随现有工程状态和失败定位变化；不是保证完成时间，也不是到时自动停工／休眠指令。具体顺序见实施计划。先获得稳定可用的性能／范围／上色闭环，再完成参考生成，不先花一夜建立巨大素材库。

用户批准执行后，小阶段自主推进，复核失败自行修，不逐项问意见。默认后台；不启动Tiny Glade、不占鼠标键盘、不操作或关闭正式ANKALUTE。只有一个临时QA工程，可恢复地清理且不留Hub记录。不保存／切换用户当前场景，WorkScenes／Recovery和旧交付hash保护。

任何失败保留上一通过版本，候选独立生成，源输入不改。代码源码范围核对后才应用同一研究工程；若正在打开的研究工程或并行修改无法安全应用，提供完整ready-to-apply候选和检查脚本，明确“待应用”，不悄悄关工程、不谎称已安装。真正的用户数据／环境阻塞才报告需要处理的事项；不因一般实现困难直接放弃。

不达完整目标时如实列明已通过、未通过和恢复点；未完核心项继续追踪，不把保底交付冒充整轮完成。可压缩的是说明页美化和更多展示源，不是正确性／保存／核心参考功能。收尾不休眠。Git远端不安全时本地源码归档，不强推或混入其它任务。
