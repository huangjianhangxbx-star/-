## 0. 本轮交付目标与执行边界

把目前“每个体素独立抽一个明暗值”扩展成真正可用的自动上色工具，并增加按表面朝向制作固定美术暗面的能力。

本轮包含两项可以独立开启、独立提交的功能：

| 功能 | 用户做什么 | 应当得到什么 |
|---|---|---|
| 区域色差 | 选择范围，选择按块或成片变化，调整尺度、幅度、比例 | 同一块内相对统一，块间或区域间有克制差异；不是棋盘噪声 |
| 美术暗面 | 选择“上亮下暗”或指定参考光向，调整压暗量 | 同一个体素不同朝向的面可以有不同明暗；底色与手绘源可保留 |

首版做“按朝向分档压暗”，不做真实遮挡阴影烘焙、全场景光照求解或 AO 烘焙。遮挡功能列在第 13 节，不得把它与朝向判断混称已经完成。

按 M0–M6 完成一轮可用闭环：算法、正式界面、持久化、保存重开、材质绘制、GLB/FBX 和便携 EXE。不能只出独立算法页面就宣布整体完成。遇到数据丢失风险或新设计分歧时仅停受影响步骤，说明差距。

当前用户只要求继续讨论/规划，不自动授权本会话实施。文件内 START_HERE 仅在用户明确转交为实施指令后生效。

## 1. 需求来源与建议分开

### 1.1 用户明确要求

- 逐格无条件色彩随机化对大多数模型只会产生杂乱，需要类似砖石之间不均匀但自然的色差。
- 需要时高效打破过于干净、整齐的外观，不依赖逐笔手绘整面墙。
- 需要理解体素颜色与贴图能否共存，不能因新增功能丢失已有绘画。
- 希望自动识别模型非受光面并进行色调压暗；用户尚未把“非受光面”限定为朝向、遮挡或环境遮蔽。

### 1.2 本计划的建议决策，不冒充用户已批准细节

- 将“区域色差”和“美术暗面”放在同一上色工具组，但不是同一个随机算法。
- 区域色差首版优先改现有体素底色；暗面使用独立按面参数，不能把一个格子整体变暗来代替侧面压暗。
- 新暗面功能默认关闭。提供轴向“上亮下暗”和“指定光向”两种预设；前者不引入明显左右单向光。
- 原有逐格随机保留为显式旧模式，不默认替换已有资产、不批量重新染色。
- 默认保护不透明手绘像素；“暗面同时影响手绘”作为显式选项，仍不改原始笔触值。
- 允许首版不自动识别未知砖缝：已有真实分块用作者分块，合并墙面用虚拟砖格，非砌体用成片色斑。
- 工具参数先标 SAMPLE，用户美术认可与技术测试分开。

### 1.3 当前截图的角色

包内 `references/current_color_noise.png` 是用户当前逐格随机的**问题示例**，不是理想效果图。门洞周围密集的小格明暗需要改善，不应被当作新算法要复制的目标。

## 3. 必须先分清的三类“暗”

| 现象 | 需要的判断 | 首版范围 |
|---|---|---|
| 表面朝向背离指定光向，或底面/侧面较暗 | 表面法线与作者参考方向的关系 | 本轮实现 |
| 朝向光源，但被拱顶、凸石或另一物体挡住 | 光线可达性、遮挡物、采样与阴影范围 | 后续独立模块 |
| 缝隙与内角因为周围包围较多而暗 | 环境遮蔽或艺术遮蔽规则 | 后续独立模块 |

不能把相机看不见的面叫作“背光面”；也不能只看视口截图的黑色像素来反推该修改哪些面。

同朝向的两个面，仅一个在拱顶下被挡住，首版朝向算法会给它们相同分档。这是明确限制，验收时必须用此反例说明，不伪称已求真实阴影。

“上亮下暗”是作者配色规则，不是完整光照模拟。它可以帮助风格化建模，但不能保证在任何游戏照明和旋转方向下都物理正确。

## 4. 区域色差：分组规则

### 4.1 模式一：按作者分块

仅当用户明确选中若干真正代表砖石/部件的对象时，用 objectId 对应成员作为分组。

- 一块砖含多个体素，所有成员使用同一个随机参数；不同原材质仍各自从自身底色变化，不统一涂成一个 RGB。
- 若当前模型“每个新格都是独立物体”，预览应提示“一物体一格，效果接近逐格随机”，建议改用虚拟分块；不能冒充已识别砖块。
- 墙体合并为一个对象后，首版不承诺恢复原砖缝。连通域也不是砖语义：相接的多砖墙可能只有一个连通域。
- 不根据当前贪心合面结果分组，避免颜色变化反过来改变下一次分组。

### 4.2 模式二：虚拟砖块

用于整面墙没有砖块身份但希望产生砌体色差的情况。参数：砖宽、行高、厚度、错缝比例、参考平面、图案原点/偏移。

- 以模型局部物理坐标生成砖行，按行偏移形成错缝；正确处理负坐标 floor/mod。
- 虚拟砖块只给已有格子分组，不挖砖缝，不填洞，不修改体素数量。
- 门洞切掉一块砖的中间，不应让余下部分突然重新抽色；组标识由原始坐标与参数确定。
- 允许预览分组边界/临时伪色，确认前可对齐已有几何。不能自动把所有墙角、拱券和非规则砌石识别成正确砖纹。
- 首版一次使用一个明确局部参考平面；墙角多面不能分别沿相机投影随机造成接缝。必要时先分别处理墙段，说明范围。

### 4.3 模式三：成片色斑

用于整块岩壁、石柱、地面与抹灰表面。

- 建议基于模型局部米坐标的低频相关场或受控区域划分，主要颜色变化跨越多个体素。
- 默认关闭单格高频细节；大区为主，少量中区，不能整片满铺等强度 Voronoi 彩色拼图，也不能只是模糊旧噪点。
- 场值收束为少数色阶、留出大面积不变区。提供尺度与变化比例；边界过碎时合并小岛，而不是反向增加几何。
- 三精度画布按相同物理尺度取样，换精度不自动把污色斑缩成四分之一；格中心离散取样差异属于量化限制。
- 首版在单个活动画布内编辑，不因共同物理取样而自动取得其他画布写权限。

### 4.4 随机稳定性与颜色幅度

建议拆开布局 seed、变色区域 seed、色差 seed，外面仍给一个简单总种子和“重新分布”。

- 幅度调节不改变哪些地方属于同一块。
- 比例由稳定区域哈希阈值筛选，增加比例不应让已有区域全部换色。
- 结构数量或尺寸改变可以改变分组，但只换色差 seed 不改变区域边界。
- 同一源、相同参数与 seed，输入数组排列变化不影响结果。不能用遍历每个体素时推进的单一随机流定义区域身份。

新色差建议使用线性 RGB 的受限相对增益，收束为 3–5 档；保持多数区域近原色。不要复用旧的“每个通道加减固定 0.02”作为新界面数值的唯一含义。

可用试验 gain 集合 `[1-a, 1-a/2, 1, 1+a/2, 1+a]`；变化比例、各档权重独立。a 的默认量只是 SAMPLE，先在深灰与中灰夹具上看效果。接近黑色/白色时要检查量化和截断，不把调整结果称为感知均匀。

第一版冷暖偏移可收在高级选项且默认零；若实现，必须定义颜色空间、色相环绕与灰色行为。无需引入第三方颜色库来堆更多参数。

### 4.5 结果保存与侧面固定色

区域色差首版通过已有事务写入选中体素的 color 与必要材质色槽，原始物理材质参数按来源保持。预览期间从冻结源重算，确认才改变源。一键撤销恢复本次修改。

不宣称第一版拥有无限可逆程序材质栈：提交后再次打开是基于当前颜色的新操作；支持撤销，不假装还能在任意后续编辑之后找回已丢弃的原始颜色。配方可保存为复现参数，但不能拿配方代替源快照。

当 `sideColor` 固定时，改变 cell.color 可能不影响侧壁。必须在预检提示，不允许用户拖很久而不知为何无变化。首版不偷偷取消全资产 sideColor；可提示用户显式切为“侧面继承体素”，或将真正按面区域着色列为后续扩展。用户未授权全局改色时保持非目标侧面原样。

新增色槽不得仅按 HEX 合并不同 roughness/metallic/alpha/emissive 等材质身份。若必要槽位超出实际预算，明确拒绝并提示降低色阶，不静默截断一半区域。

## 5. 美术暗面：同格不同面的自动压暗

### 5.1 两种预设

1. **上亮下暗**：局部 +Z 顶面保持原色，四个侧面一致轻压，底面稍深。便于可旋转复用资产，不强制左右单向光。
2. **指定光向**：作者设置从模型表面指向参考光源的单位向量；按各面朝向给 2–3 档压暗。

可以提供“一次读取当前主光方向”按钮，但只在点击时拷贝方向。日常旋转视口灯光、相机或切换预设不得自动重写模型。

不默认增加亮面高光：首版只压暗选中的侧/背光面，亮面保留，避免过曝；“色调”首版落实为保色相的明暗变化，暗部冷暖可后续加。

### 5.2 判定与公式（建议而非物理光照承诺）

源坐标 Z 向上，Three.js 展示坐标另有转换。使用规范化源面法线 n 和“表面→光源”方向 L：`d = dot(n, L)`。

- d 大：较朝向参考光，保留；
- d 约零：侧向，轻压；
- d 小：背向，较深。

例：阈值 +0.35/-0.35，三档线性乘数 `1 / (1-s/2) / (1-s)`，s 先限定为温和区间。0.35 与范围均为 SAMPLE，需调图，不是系统不可改硬规则。

若 n=(0,0,1)、L=(0,0,1)，顶面应 d=1；底面 d=-1。这条测试必须写，防止把光传播方向当作指向光源方向导致明暗反转。

首版原生体素只有六种朝向，主分类只需六个分档；不需要“AI 看图识别”。同一方向的凹槽底与外墙会是同档，不包含距离、遮挡或真实反射。

从源色计算一次线性压暗，再转 sRGB 显示/写 PNG。不可每次拖动参数都从上一次已经变暗的结果继续乘。

### 5.3 需要新增的最小按面数据

当前每格一个 color 与全局 sideColor 不能完整表达“这个格子只有右面暗”。不能为达到侧面暗而改整格色，也不能直接往手绘 paintSource 填满黑色像素。

推荐新增版本化、稀疏的按面暗面表（例如 `faceTone`，字段名为提案）：

```text
画布内：faceTone
  schema: xinghai-face-tone-1
  faces:
    "x,y,z,face": { gain: 有限0..1值, affectPaint: boolean }
  可选 recipe: 仅作说明/重算输入，不代替 faces 最终值
```

- key 用 canvasId 所属容器 + 整数 owner cell + face，与现有画笔键方向一致；不绑定三角形序号、临时 Mesh ID 或相机。
- gain=1 的中性面可省略；同一面重新应用暗面是**替换系数**，不叠乘旧系数。
- 清除暗面只移除该表对应条目，恢复现有底色与笔触，不删除原颜色。
- 同时保存开关/诊断信息的最小需求即可，不发展成通用图层编辑器。
- 更改当前底色后暗面仍作为相对效果生效；几何新露出的面默认不继承旧相邻面暗色。
- 若本地已有等价字段，复用实际权威；不要再创第二套相同职责结构。

schema 必须在所有适配器显式承接。不得为省事放宽未知字段检查；旧文件无字段时解释为无暗面，新数据让不支持版本明确拒绝，不能旧程序悄悄剥离后覆盖。具体升级采用项目真实现有版本机制，不在阅读计划时自动迁移全库。

## 6. 底色、手绘与暗面的合成契约

当前手绘源是“有像素时用这个不透明颜色，无像素时露出底色”，不是任意透明度 Photoshop 图层。本轮不得伪称已有透明笔刷。

定义：B = 由体素颜色和 sideColor 求得的底色；R(B) = 本次区域色差后的底色；P = 手绘颜色；M = 是否有手绘像素；S(C) = 按该面的 gain 压暗。

**默认保护手绘：**

```text
无手绘处 → S(R(B))
有手绘处 → P
```

**用户明确开启“暗面影响手绘”：**

```text
无手绘处 → S(R(B))
有手绘处 → S(P)
```

两种模式都不把计算后的 P 写回 paintSource。因此关掉暗面后恢复原笔触，反复开关不累计变黑。区域色差本轮仍只改底色，不对手绘像素进行随机染色。

整面被手绘完全盖住时，默认保护手绘会导致底色色差/暗面看不见；必须提示覆盖原因，不能为了“看见效果”偷偷改画。界面可提供“仅底色对照”，只临时隐藏绘画显示，不删除数据。

显示、吸色、缩略图与导出应复用可测试的合成函数。吸色区分作者最终色与原始笔触色时使用明确模式；绝不能默认吸到实时灯光阴影后又写回原色，造成越画越黑。

## 7. 视口光照、旋转复用与导出的边界

### 7.1 与 TOOL-012 的区别

- TOOL-012 是“怎么看”：视口灯光/灰模/原色/侧光，不写入资产。
- 本轮是“怎么给资产上色”：确认的区域色差、按面暗面会持久保存并进入成品。
- 灰模可按原契约临时忽略作者颜色；原色检查应显示完成的作者 Base Color，包括已保存暗面，但不含实时光照。要看真正底色需单独对照开关，不能混称。
- 受光模式中，美术暗面与实时光照可能叠加。保持暗面轻、可关，并分别显示“无光照作者色 / 正常受光”，不自动降低全局灯光掩饰过暗。

### 7.2 旋转不是自动重新照明

已保存的暗面是固定在表面的艺术配色：移动、复制、90°旋转后应随面一起走。不会自动追逐场景新灯光。

物体编辑旋转时，face 键和 owner cell 一起映射，gain 不重新抽取；场景实例旋转只旋转引用模型，不暗中改共享资产。确实需要重新按参考方向判定时，用户显式“重算暗面”。

偏向固定左上光的强暗面，转个角度可能与游戏真实照明矛盾。这是选用强定向烘色的取舍；不能保证任意复用方向都正确。可复用墙块先建议“上亮下暗”或轻微侧压。

### 7.3 导出

- 无手绘面：可用派生材质色或等效现有渠道表达 face gain；不能强迫每面生成满分辨率 PNG。面分组合并键须含最终样式。
- 有手绘面：按第 6 节合成到底色 PNG，再使用白色乘数，避免再次在材质/顶点色里重复应用底色和暗面。
- 不把实时视口阴影、AO、相机相关效果写进 PNG，也不把原生暗面表当成接收引擎必须理解的私有 shader。
- GLB→Blender→FBX 延用现有已受管路径，材质旁车和贴图依赖一起输出；保持 roughness、metallic 等已有适用契约，不为纯色差重置全部材质。
- 自包含原生/便携源保留可编辑数据。FBX 是当次合成的成品，工坊源改变后需重新导出，不承诺外部 FBX 自动更新。

## 8. 编辑范围、生命周期与保护

操作开始冻结：assetId、revision、canvasId、对象成员、体素范围、原色/色板、paint、faceTone 与参数上下文。源被其他编辑改变时使预览失效，不在过期结果上覆盖。

- 模式路由按当前实际工程：物体模式和编辑模式都可能建模；新增工具不得恢复此前已被用户否定的“物体模式禁用建模”限制。
- 区域色差按选定对象/当前合法选区作用；未显式选择整画布时，不把全部物体一起染色。
- 暗面目标是选定范围的实际几何表面，包含转动相机后才能看见的合法面，不受当前屏幕裁切决定。隐藏/锁定画布保持保护。
- 现有面遮挡判断、坐标转换和对象 cellKeys 优先复用；同格多个旧源层按现有权威维护，不能只改 visible cells 使撤销/重显后旧色复活。
- 预览不改源、不入历史；应用一次事务；取消恢复。右键旋转/中键平移/显示预设不触发重新随机或重写暗面。
- 临时输入 UI 焦点变化不能当作操作失焦而取消；沿实际程序窗口失焦策略处理，明确区分视口点击与应用失去焦点。
- 颜色源不变、幅度零、暗面全为中性等无变化结果不制造空历史。
- faceTone 必须随移动/90°旋转/复制粘贴/分离/合并画布/场景合并重映射，范围冲突沿当前覆盖规则一并解决。
- 原生保存重开、项目复制、另存、便携导入、回收恢复必须保留字段。
- 几何删除清理真正消失 owner；遮挡但保留的 owner 可保留暗面；新露面默认中性。岩体削切不能把无关暗面全清空。
- S 步进缩放等重采样，复用实际 owner 映射；无法定义正确结果时仅明确拒绝含暗面对象的该类变换并提供原因，不静默丢字段，也不把拒绝写成完整支持。

交互建议：`desktop/regional-color-panel.ts`、`desktop/face-tone-panel.ts`。只在既有入口接线，不继续把所有算法塞进大型 renderer 文件。

### M2｜区域色差

- 实现作者分块、虚拟砖块、成片色斑三种模式；旧逐格随机保持可显式选择。

### M3｜按面美术暗面

- 实现上亮下暗、指定光向、强度、2–3档、目标面范围、手绘保护、清除暗面。
- 可只看“受影响面”诊断；它不进入资产或最终导出。
- 验证同一体素亮面不变、侧/背面改变；不允许把整个 cell.color 改暗作为替代。
- 指定光向与视口主光独立；可一次复制光向，但镜头/灯光随后变化不重算已保存暗面。
- 重复相同应用不加深；改强度基于原色求一次；清除恢复底色与手绘源。

### M4｜正式保存、变换与材质共存

- 完成所有第 8 节生命周期与按面键映射；不是仅把字段写进 JSON。
- 作者底色色差、手绘、暗面开关三者互不破坏；画笔/擦除/吸色在新合成下语义明确。
- 源/临时预览/右侧预览/试摆/缩略图一致；未来新生成 Mesh 自动继承当前显示模式和作者色。
- 已有岩体、像素完美、根点和对象模式只做相关回归；不借机重构整个工程。

### M5｜导出与独立回读

- 真实 Blender 回读 UV、PNG、材质颜色和六面朝向，不只检查 FBX 文件头。
- 无手绘的面用合理材质分组，不填满手绘像素源；有手绘的面烘最终作者色，不重复乘色。
- 切换视口光照预设前后，源与导出语义保持一致。FBX 可含时间戳，不以两份字节哈希必须相同误判；比较几何/UV/材质/PNG 等实际语义。

## 11. 样例与验收矩阵

### 11.1 视觉样例

A：规则砖墙——一块砖由多格组成；对比纯色、旧逐格、按块区域色差。同砖内部不出现棋盘。

B：单一合并墙/门洞——虚拟砖格在门洞处只裁切分组，不填洞；可以对齐原几何，不宣称自动认识拱券砖。

C：岩壁——成片弱色差，远看统一，近看存在少量大中区域；和 TOOL-011 造型结构分别评价。

D：六面体——顶面保持、四侧轻压、底面较深；改成侧向 L 后只有面分档改变，几何不动。

E：部分与全覆盖手绘——白色纹样、未画底色、整面涂色各一块；默认保护与显式影响手绘两套结果、清除恢复。

F：遮挡反例——两个同向面，其中一个在拱顶下；朝向模式仍相同，明示首版不求遮挡。

### 11.2 定向验证

| 验收点 | 最小证明 |
|---|---|
| 分组正确 | 8×3×2 格一砖，全砖共享一次扰动；其他原材质不被同 RGB 覆盖 |
| 随机稳定 | 相同 seed 可复现；重排 cell 数组不变；幅度改变不换分组 |
| 稀疏变化 | 比例0无变化，比例递增保留原已选区域；缺陷区域不是全铺 |
| 多精度 | 相同米尺度，0.25/0.125/0.0625画布不变成不同风格碎噪点 |
| 颜色范围 | 深灰/中灰/近白量化与截断可控；新材质身份保持 |
| 侧色冲突 | sideColor 固定时明确提示，不偷偷改全局侧色 |
| 面向判定 | 六法线与 +Z、+X、斜向 L 的符号和档位正确 |
| 非相机依赖 | 转相机/切前后视图不翻转已保存暗面 |
| 幂等/清除 | 同参数再次应用不继续变黑；清除只去暗面 |
| 手绘共存 | 两种保护策略与导出 PNG 像素一致，paintSource 本身不改 |
| 几何不变 | 上色前后 cells坐标、体积、Root、归属等不变（颜色字段除外） |
| 生命周期 | 复制/移动/旋转/分离/合并/回收/保存重启/便携正确映射 |
| 岩体与新面 | 无关面效果不丢；真正新面中性；撤销恢复 |
| 导出 | Blender 真实回读材质/UV/PNG，无二次乘色 |
| 原始数据安全 | 取消/失败不改源；未选对象、锁/隐藏画布、保护区不动 |
| 灰模与原色 | 灰模观察不是新上色；原色显示作者色，不烘视口照明 |

默认 B 级模块验证：相关新旧算法测试、类型/构建、少量真实键鼠、存储及导出代表样例。不要全量扫描或重跑游戏本体/2D工坊/所有历史场景；存在真实共享风险才扩大。

## 12. 风险、非目标与真实交付状态

- 对象数不等于砖数；无语义砖缝自动识别不属于首版承诺。
- 全面不可逆“随机染脏”不能靠增加亮度上限补救；先解决尺度和保留区域。
- 按面暗面如果只作用到 base mesh，而手绘层仍填旧底色，会出现块状错色；统一合成是必要条件。
- 只给 exporter 增加字段却没给代理/复制/导入适配，会在用户下次编辑时丢数据；必须覆盖消费者。
- 当前手绘预算不适合把每个暗面转换成数百个手绘像素；独立稀疏面系数避免此浪费。
- 不添加可变透明画笔、全功能图层堆栈、材质节点编辑器、导入任意外部三角模型的自动识砖，或新全局纹理格式。
- 不擅自改变《开发细则》、人工原稿、原始参考图、无关游戏资源；参考图在工程测试中用隔离副本。
- 本计划不会保证“所有真实灯光下都一样好看”；烘色是美术决定，需要用户看普通受光/无光照两种结果。
- 若原生迁移或个别变换暂不支持，逐项列出，不把“能画出来”当成完成所有保存/导出链路。

## 13. 后续候选：真正被遮挡的面压暗（本轮不实施）

当按朝向功能稳定且用户明确需要拱顶下、石块背后等差异时，再单独制定遮挡任务。

候选：限定单资产内的几何与一个参考方向，对外露面采样；从面外微偏移起沿指向光源方向求交，避免命中自身；有限多个样本得到可见性，用少数档位压暗。

该功能需要明确：遮挡物范围、是否包含隐藏画布、透明材质怎样算、面内阴影是否需 texel 分辨率、偏移/采样与预算、几何改变如何使结果过期、旋转/场景拼装后是否重算。不能仅加一次 normal dot 就冒称完成。

AO 又是不同的多方向遮蔽问题，复杂度和效果另评；当前 viewport 凹槽增强也不自动变成资产 AO。
