## 3. 建议的原型内容规模

> 本节是**待用户确认的内容范围建议**，不是 v0.2 已承诺的数量，也不是具体技能效果定案。

建议保留现有四名角色，全部迁入能够表达“身份→职业→技能”的通用结构，并保留各自已有技能的现有行为。不要让新结构只适用于一个测试角色，而其他角色永远走一套冲突的旧逻辑。

新增构筑内容集中在**一名选定的非猎人本体**上，做一个完整示范内容包：

| 项目 | 建议规模 | 验证目的 |
|---|---|---|
| 职业 | 2 个真实不同的职业，对应本次携带且允许使用的武器 | 能切换职业，不把原武器与同职业影武器冒充两个职业 |
| 候选战斗技能 | 职业 A 为 2 个，职业 B 至少 1 个 | 既能验证同职业非战斗选技能，也能验证跨职业和充能保存 |
| 进阶 | 每个入选技能：基础态 + 至少 2 次线性提升 | 能测试逐阶购买、跳阶拒绝及不同进阶与分支组合 |
| 分支 | 每个入选技能 3 个候选分支，最多购买 2 个；每分支至少 2 级 | 能实际验证三选二锁定、不同技能独立名额和高等级覆盖 |
| 角色及资源 | 复用已有角色、动作、攻击和特效资源；具体适配先核对实际资源 | 不将本轮变成大规模角色美术制作 |
| 其他既有技能 | 接入新定义与运行接口，保留当前效果；未纳入内容包的新增构筑不伪装成完成 | 保证全队兼容，同时控制内容制作量 |

为什么不建议仅做“两个分支”？两分支可以测升级，但无法测“购买第二个后，第三个锁定”。若用户另行选择简化规模，应明确标出未验证的规则，不宣布完整三选二已交付。[S6]

具体选谁、两个职业是什么、三个技能分别做什么、每阶和每级效果如何变化，都未由现有来源决定。实施前先形成并确认内容表，至少包含：

`角色身份 / 职业ID / 对应武器 / 允许携带与使用条件 / 技能ID / 技能模式 / 基础效果 / 进阶效果 / 三个分支及覆盖效果 / 局外上限 / 各级费用 / 充能与持续时间 / 换出与升级时效果处理 / 动画及范围表现`。

在内容表尚未确认前，可以完成讨论和计划细化，不能凭“做技能树”自行创作一整套并当作用户定案。数值若获准交给执行者调参，应与机制和技能效果的批准分开记录。

## 4. 已确认规则：本轮不重新询问

### 4.1 配置、默认技能和限制

每职业有候选技能，同一时间装备一个战斗技能。E 调用它；猎人瞬影和收纳不占此槽位。每职业保存非战斗阶段选定的默认技能，首次未配置时采用系统默认。[S5][S6]

战斗中不能在同一职业内换技能或改选已锁定分支。允许购买当前进阶、首次购买尚可选分支和提升已有分支等级。跨职业换武器会进入该职业的默认技能及已有构筑；换出再换回不能绕开限制。

副本地图和探索脱战阶段允许更换职业默认技能；塔防波间整备、角色暂收影庭均不等于脱战。同一副本内的已买分支不洗点、不退款。

### 4.2 培养记录和购买

培养记录按“角色→职业→技能”分别保存。切技能／职业不清空、不退款；未装备技能的构筑效果不生效。新副本从技能培养最低状态开始，不重置角色的长期基础等级；离开整个副本清空本次培养，局外解锁保留。

进阶和分支各自逐级购买，暂不增加彼此交叉前置；各自受资金与局外解锁上限约束。首次购买某分支第一级才占名额，查看不占。一个技能选满两个分支后第三个在本副本锁定，不同技能独立计数。同分支高等级覆盖低等级，不默认把每一级再叠加一次。[S5][S6]

培养消耗生命力。金币与生命力不是同一种资产，金币不能在副本内代付技能培养。[S7]

### 4.3 换装与技能状态

战斗换武器只能使用本次携带且角色能用的武器，不另收费。原地短暂换装期间不能攻击或施法，受击不中断，主动移动取消；完成才切职业与默认技能。[S5][S6]

需要充能的技能开局／重入从空条开始。同技能升级保留自己的充能百分比；切职业分别保存各技能充能，未装备暂停，首次启用空条。

执行限时主动技能时换职业会中断旧技能并进入冷却。持续模式、已施加效果的去留由具体技能说明，不默认迁移给新职业。中断发生在换装开始还是完成、取消换装后的处理需要组合边界确认，见第 6 节。

生命上限实际变化时按该单位原有生命百分比换算；濒死、死亡和已获救禁用者不能因此恢复行动资格。

## 5. 源码差距与工程方向

本节是固定基准上的静态分析；提出的文件拆分是建议，并非声称仓库已经有这些模块。

### 5.1 当前实现不能只靠加几个等级字段扩展

| 当前实际实现 | 对本轮的影响 |
|---|---|
| `Unit.role` 同时参与技能分发、初始武器/属性、猎人/菲奥蕾生命周期与影庭特例 | 不可直接把 `role` 改成当前职业；需要稳定角色身份和独立职业/技能选择。 |
| `Unit` 主要只有一套 `skillCd / skillMax / skillTime / skillPulse` | 无法独立保存多个职业多个技能的充能及培养；必须明确唯一权威状态。 |
| `switchWeapon` 即时翻转 `weaponIndex`，没有换装阶段 | 需要真实换装开始、取消、完成过程及统一操作仲裁。 |
| 两件起始武器为原武器与其影武器，通常同属 `gun / blade / focus` 中同类 | 这不是已经存在的双职业系统；职业映射和携带列表需要真正的数据定义。 |
| `releaseAttack` 耐久耗尽后直接切 `weaponIndex=1` | 自动切影武器与新换装规则的关系必须确认，不能让它偷偷切职业、重置技能或修复耐久。 |
| `main.ts` 按 `hunter/fiorre` 决定 E 后清持续输入；`skill-ui.ts` 按 `guard/ranger` 决定切换模式 | 新职业和技能必须由技能定义提供模式及输入语义，不能继续凭原角色类型猜。 |
| `personal.ts` 单独推进菲奥蕾影庭技能，`engine.ts` 也推进技能计时 | 改为多技能后应有统一计时入口，防止重复推进、误推进未装备技能。 |
| `ui.ts` 的部分重建键只含单位ID/生命状态/武器序号；技能名和描述按 `role` 查找 | 同一对象升级或换技能后，按钮、说明、范围和价格必须真实刷新。 |
| `GameState` 有旧 `fragments` 与节点流程，没有完整局外解锁和本副本培养模型 | 要建立本轮需要的最小寿命边界，不能把节点重入当新副本，亦不能声称完整经济已存在。 |

源码定位：[S8]—[S13]。

### 5.2 最小职责划分建议

保留 Three.js + TypeScript/Vite、现有地图与 `command/step` 主流程，不引入新引擎、物理库、通用插件框架或全项目 ECS 重构。

建议的职责如下，文件名由实施者结合现有风格落实：

| 建议位置 | 职责 |
|---|---|
| `game/src/core/types.ts` | 身份、职业、武器实例、技能定义/运行态、培养、换装和命令类型。 |
| 拟新增 `game/src/core/skill-catalog.ts` | 已批准的技能、进阶、分支、价格和表现定义；集中可调，不散写在 UI。 |
| 拟新增 `game/src/core/progression.ts` | 本副本培养、局外上限、分支名额、合法购买及消费事务。 |
| 拟新增 `game/src/core/loadout.ts` | 默认技能配置、场景权限、换装状态和切换完成处理。 |
| 拟新增或按规模合并的 `game/src/core/skills.ts` | 当前技能解析、效果/时间推进、中断、属性重算及技能能力描述。 |
| `engine.ts` / `personal.ts` | 接入命令、时钟、生命状态、节点钩子；保留第二轮的保护顺序和输入效果。 |
| `main.ts` / `ui.ts` / `skill-ui.ts` / `style.css` | 当前技能操作和构筑视图；表现消费核心查询，不自行决定购买是否合法。 |
| `view/scene.ts` 及相关表现适配 | 必要的技能范围、动作和特效接入；保留 T-005 的位移动画与召影反馈。 |

不要求为表中每项都强制建一个文件；可以合理合并。需要的是职责和测试边界，不是文件数量。

### 5.3 数据寿命建议

| 数据 | 所属寿命 | 应如何处理 |
|---|---|---|
| 角色本体等级、基础属性、特殊身份、局外解锁上限 | 局外/角色长期数据 | 本轮读取并保留，不因新副本清空；不制作其完整获取流程。 |
| 本次携带武器、每职业默认技能 | 明确的配置记录 | 在允许阶段选择；是否跨副本保存默认偏好由内容/持久化范围确认。 |
| 各职业各技能进阶、分支等级与锁定名额 | 一次副本 | 节点失败或换节点保留；整个副本结束或建立新副本时按规则重置。 |
| 各技能充能、持续状态 | 单位自身的技能运行态 | 同节点切职业缓存；未装备暂停；节点重入重置需充能技能，不把缓存蓄满带入新节点。 |
| 换装中、输入保持、前摇、回收过程 | 当前动作 | 生命周期结束时正确清理；不能随本体展开赋给新复制体。 |
| 既有复制体配置 | 该复制体出生快照 | 本体之后改变不更新；复制体生命、充能与临时状态独立。 |

可以保留旧字段作为明确的临时适配视图，但不能同时拥有两套互相覆盖的技能计时或培养数据。UI、卡牌、影庭和战斗结算都应最终访问同一权威技能状态。

### 5.4 效果计算建议

从原始角色/武器定义、当前技能进阶、每个已选分支当前等级以及有效临时状态计算结果，不在每次刷新界面或切职业时重复 `+=`。

长期身份能力与职业技能分开；“菲奥蕾可在影庭恢复”不应只是某一治疗职业自带的效果。进阶与分支的组合应用顺序、施法期间升级生效方式及持续效果归属由已批准内容表说明，不能用一条“最后写入覆盖全部”隐式决定。

## 6. 本轮需要收束的边界

以下不是重新开启 Q1—Q77，而是针对第 5 节剩余内容和第二轮新组合。Codex 应先查已有对应决定；确有答案则引用，不重问。未确认之前，下述建议只用于讨论。

### R3-B1：内容包、上限与起始参数

**缺口：**具体角色/职业/技能、各阶效果、分支及其覆盖、局外上限、费用、换装时长和原型内容数量未由现有资料定案。

**建议：**采用第 3 节的小规模完整内容包；先交付技能内容表再实现。允许把价格、持续秒数等列为获准可调参数，但“新增什么机制”必须明确批准。至少一个入选技能应有可感知的进阶差异和两条路线的组合，不只让所有按钮加同一个攻击数值。

局外上限通过真实数据和界面显示接入；准备“部分锁定”和“已解锁”两组开发验证配置，不制作完整解锁商店或用全解锁掩盖限制。

### R3-B2：可配置/可购买的状态矩阵与界面行为

**已经确定：**副本地图和探索非战斗可以配置默认技能；塔防战斗/波间和收进影庭不能借机换同职业技能。战斗与副本内非战斗可以培养，已买分支不洗点。

**仍需确定：**首场 `briefing` 是否提供开战前配置；健康未部署者/影庭角色、濒死者、已获救禁用者分别能否购买；能否培养未装备技能；构筑面板是否触发慢速、是否阻断快捷输入；同职业非战斗换技能后充能如何保存。

**建议：**为首场准备和副本地图提供明确配置入口；战斗购买先围绕所查看本体当前职业/装备技能，扩大到其他技能时必须明确授权。构筑面板打开时清持续输入，遵循第二轮的暂停优先级；建议使用 0.1×观察而不是擅自增加自动暂停。濒死/已获救禁用状态无论是否允许购买，都不能解除行动限制。

不得把“在场没有敌人”“打开面板”“收进影庭”当作全队已经脱战。探索脱战在本轮只测试显式上下文输入，不实现第 9 节状态机。

### R3-B3：换装与动作冲突、耐久回退

**已经确定：**合法携带武器、原地短暂换装、期间不攻击/施法、受击不中断、主动移动取消、完成才切职业；限时技能换职业时中断并进入冷却。

**仍需确定：**限时技能在换装开始还是完成时中断；取消是否恢复旧施法；换装中 Q、救援、瞬影、跨层、重复换装或死亡怎么处理；同职业换另一件武器是否同样读条；旧影武器自动回退与换装的关系。

**建议：**成功受理换装时停止移动并中断旧限时技能，取消换装不恢复已中断施法；最终职业/武器/默认技能只在读条完成时提交。成功的主动移动或瞬影取消换装，失败请求不取消。跨层及回收中的请求采用明确、可复现的拒绝或替换规则，不能靠分支先后顺序碰运气。

建议将“耐久耗尽进入同职业影武器回退”与“玩家换为另一职业”分开：回退不重置构筑和充能，不免费修复耐久，也不视为获得新职业。是否保留立即回退必须由用户确认；既有机制不能静默删除。

### R3-B4：升级、技能效果和特殊身份的时间组合

**已经确定：**同技能升级保留充能百分比；未装备暂停；限时技能换出中断；持续模式/已施加效果需具体说明；普通影庭冻结、菲奥蕾例外已确认。

**仍需确定：**执行中升级对本次技能的伤害、时长和范围是否立即生效；狙击/毒刃等持续模式换出后的状态；已施加中毒/治疗等效果的归属；菲奥蕾影庭内是否只推进已装备技能；普通死亡/待部署与多技能计时的组合。

**建议：**已经发动的有限时技能采用本次施放快照，新培养影响下一次施放；纯充能期立即换算百分比。对持续模式单独列明生效策略，不硬套施放快照。未装备技能仍暂停，菲奥蕾只放宽“影庭内当前技能时间”的冻结，不默认让所有后台技能一起充能。此组合建议须确认，不把第二轮只含单技能的实现当作多技能答案。

属性上限变化严格按比例处理本体自身生命；已获救的身份限制继续优先。严禁因修复数值重新创建角色而丢失其伤势、耐久、回收资格或长期身份。

### R3-B5：真实支付与既有卡牌/复制体的过渡

**已经确定：**培养消耗生命力，金币不能代付；本体构筑变化不更新已有复制体；卡牌具体能力与限制仍暂缓。

**缺口：**当前工程仅有旧 `fragments`，新经济尚未制作；多技能结构下旧“余响”等卡牌的等效目标与兼容方式需要明确。

**建议：**本轮设一个局内消费入口，以现有 `fragments` 作为经批准的临时余额后端，界面明确为原型过渡资源；培养、旧抽牌和召影共用余额，不能再造独立的无限培养币。正式经济完成后替换这一后端。旧开局余额是旧原型测试配置，不因此成为新版免费启动资金的规则。

培养必须实际扣费、校验上限和名额，失败零变化。交易按预期当前等级处理，避免同一个过期请求重复扣费；连续合法购买下一级则应有清楚的新价格。

既有复制体需安全初始化新字段并保持出生快照；只补结构兼容、当前技能运行和禁止独立培养/换职业的权限边界，不扩展复制体内容模块，不改变旧费用。

旧卡牌维持批准的过渡行为。旧冷却牌对原单技能状态的操作如何映射到新装备技能需单列确认；不得擅自扩大成清空所有职业冷却，也不得重引此前未批准的“只限正在充能/满条禁用/排除瞬影”等新牌池限制。

### R3-B6：副本寿命与持久化范围

**已经确定：**节点重入不清培养；离开整个副本/新副本重置本次培养；局外解锁保留。

**仍需确定：**首场配置入口如何映射到现有流程；新副本和离开副本的原型验证入口；默认技能偏好是否跨副本保存；是否要求浏览器刷新后持久化。

**建议：**在现有 `enter` 等节点流程上保留本副本培养；建立明确的新副本/结束副本入口，使用已加载的局外配置启动新副本，允许开发场景验证退出清空，而不新增尚未设计的撤离点。新副本不能通过重新创建整份长期配置而伪造“保留局外解锁”。

本轮优先交付运行会话内的正确寿命与可复现测试；刷新恢复、异常退出及完整存档不默认纳入。需要持久化时单独批准具体范围，不能声称已有长期存档支持。

## 7. 顺序执行计划

下列是同一模块内部的顺序。每步完成必要的最小界面/验证，不把所有 UI 留到最后才发现无法操作；每步可以有独立提交，但不能将中间检查点宣布为整轮完成。

1. Codex 完成真实规范和 Skill 读取，核验本地分支、远端、未提交差异，以及 T-005 后是否又有新提交；不覆盖用户未提交内容。
2. 以本文第 6 节为清单收束本轮问题，形成内容表、操作权限矩阵、技能效果生效/中断矩阵和旧功能过渡表。已确认内容不重问。
3. 在用户授权保存计划后建立任务记录。当前任务目录已有 T-005；可建议下一号 `T-006-职业技能与构筑.md`，创建前再核对编号，不将“第三轮”误写成已存在的 T-003。
4. 获准实施后，运行并保留当前实际单元、构建和浏览器基线；旧失败单独定位，不用历史全绿替代。

完成条件：内容与授权足够实施；每个阻塞边界有用户决定或明确获准的参数选择范围。仍未确认的新玩法不得先编码默认方案。

### R3-01：身份、定义和运行数据迁移

1. 分离本体身份、特殊身份、当前职业、装备技能与武器实例。
2. 建立技能内容定义、局外上限、本副本培养和单位技能运行态；明确新副本/节点切换的不同作用域。
3. 将现有四名角色的现有技能接入新接口，保持原效果、角色死亡身份和基础能力。
4. 替换依赖角色名称的技能模式判定；UI/命令使用同一技能能力描述。
5. 为现有召影构造加入必要安全初始化，避免复制本体正在换装、回收、移动或施法的动作引用。

完成条件：未购买新培养时，原四名角色仍可正常战斗；身份不因职业切换被混淆。没有两套同时推进的技能时间。

### R3-02：默认技能与配置权限

1. 接入批准的携带武器、职业映射及候选技能。
2. 实现每职业默认技能选择、未配置时默认值，以及战斗锁定。
3. 接入批准的首场准备/副本地图配置入口；为探索非战斗提供显式上下文测试。
4. 验证波间、影庭、切职业再切回不能绕过限制；已购分支始终不能洗点。

完成条件：玩家能通过真实界面选择，且核心命令对非法配置同样拒绝，不只依靠按钮禁用。

### R3-03：培养购买与实际战斗效果

1. 实现进阶逐阶、分支逐级、首次购买占名额、三选二锁定、局外上限与资金约束。
2. 接入批准的支付后端；一次交易同时更新余额与培养，失败时二者不变。
3. 按内容表解析有效效果，保证高等级覆盖、跨分支组合及进阶兼容，不累加历史旧等级。
4. 接入价格、等级、上限、锁定原因和效果对比的最小操作面板。
5. 验证升级后伤害/范围/冷却等批准效果实际生效，而非只改变显示。

完成条件：一个完整技能能从基础状态培养到本轮批准上限，形成可操作的分支选择和可感知效果；后续扩展到整个批准内容包。

### R3-04：换装、充能缓存与中断

1. 即时翻转武器序号改为目标武器请求与换装状态，完成时提交职业及默认技能。
2. 实现已批准的开始/取消/完成、移动/施法/Q/瞬影/死亡冲突策略。
3. 分别保存各技能充能；同技能升级保留百分比，未装备暂停，首次空条。
4. 按每个技能说明处理持续模式和已施加效果；不向新职业泄漏旧模式或旧效果。
5. 处理同职业换武器、旧影武器回退和耐久关系，不绕过职业切换锁定。

完成条件：玩家真实完成 A 职业培养→换 B→再换 A，构筑和充能按规则恢复；取消换装不会出现武器、职业、UI各不相同的中间状态。

### R3-05：影庭、生命状态和副本寿命衔接

1. 统一技能时钟，保留普通影庭冻结和菲奥蕾已确认特殊身份；新组合按第 6 节批准结果实施。
2. 保留获救禁用、始动量、保护时点以及第二轮的同刻处理顺序。
3. 最大生命变化按比例转换，不改变生命状态资格。
4. 节点失败/重入保留培养并正确清空需重置的技能缓存；新副本清培养和分支锁定，保留局外上限/长期角色数据。
5. 验证已有/新召复制体的结构兼容与状态独立；接入旧卡牌等效操作，禁止跨对象污染。

完成条件：构筑不在换节点时丢失，也不在新副本免费保留；特殊角色和复制体不会因字段迁移串状态。

### R3-06：完整界面与反馈收尾

1. 完成配置和构筑视图：当前职业/技能、进阶、分支、价格、局外上限、不可操作理由、换装进度。
2. E、角色旁按钮、侧栏说明、范围预览统一读取当前有效技能，升级/换装后即时正确刷新。
3. 复制体仅显示其自身快照，不展示可用的本体培养或换职业入口。
4. 面板交互按批准的时间与输入规则；不遮断紧急回收或留下失焦持续移动。
5. 保留 T-005 最新头像/召影分离、直接移动动画和空间反馈；验证紧凑窗口、常用窗口、减少动态效果和纯鼠标路径。

完成条件：正常用户操作能完成整个内容包，不依赖修改调试对象。可调试查看不等于实际实现。

### R3-07：全模块验收与交接

1. 执行第 8 节验收矩阵，对失败明确区分本轮问题、既有问题和未获批准范围。
