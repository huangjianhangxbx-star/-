# 星骸回廊：T-027 / EC-09 Companion AI 2.0 实施计划 v0.1

> 日期：2026-10-06  
> 当前核对基准：GitHub `main@adc531249bc0d584ef0da4ed1b86b61f30db9acf`。  
> 前置：EC-01～EC-08 已实现；用户确认新一轮已提交并可继续。  
> 状态：计划草稿，尚未实施、未写入仓库。

## 1. 阶段目标

Standalone Exploration 战斗正式停止使用塔防式：

```text
Anchor + 2U Activity Radius + Return
```

改成：

> **Encounter 范围内自主作战的 Off-Control Body AI。**

这里的 AI 不只指“伙伴”：

- 玩家控制猎人 → 伙伴由 AI 接管；
- 玩家控制伙伴 → 猎人由同一套 AI 接管。

目标体验是：玩家切走后，另一名角色会从当前真实位置继续战斗、规避、换位和基础包夹，而不是返回旧部署点。

---

## 2. 范围锁

本轮做：

- Standalone 战斗 AI 与塔防/旧庭院 AI 分流；
- Encounter Combat Domain；
- 全 Encounter 自主移动；
- 基础目标选择；
- 武器/职业距离站位；
- Flank / Frontline / Peel / Retreat / Regroup；
- Telegraph 风险识别；
- AI 使用真实 Evade / Hunter Blink；
- 玩家命令完成后的自然 AI 接管；
- 现有 AITendency 转为新 AI 权重；
- Debug 与浏览器验收。

不做：

- EC-10 指令轮盘；
- EC-11 技能 Behavior Tags；
- AI主动使用 Prayer/Ward/Pain/Sanctuary 等手动技能；
- AUTO/RESERVE/MANUAL 策略UI；
- 怪物知识；
- 卡牌转型；
- Encounter正式重做；
- 新敌人。

## 3. 模式隔离

### Tower
继续旧 Anchor / Activity Radius / Brace / Return。

### 旧庭院
继续 Legacy Exploration AI。

### Standalone Battle
改用 Companion AI 2.0。

不要用“把 exploreRadius 从2改成999”这种方式绕过去。

---

## 4. Encounter Domain

扩展 `ExplorationEncounter`：

```ts
center: Pos
tacticalRadius: number
```

首轮建议：

```text
tacticalRadius ≈ 6.5U
```

Standalone 当前敌人生成本来就在 room.pos 周围约6U，因此这只是正式化现有房间战斗区域，不改地图几何。

实际 enemy 保留：

```text
encounterRoom / encounterId
```

不能通过名称字符串反推。

---

## 5. Active Encounter

一个 Encounter 视为 Active，当组内有敌人正在：

- pursuit；
- engagement；
- AttackIntent；
- EnemyReaction；
- 最近被 Party provoked。

若两组同时被激活：

> Domain 取并集。

敌人死亡 / return / 结束交战后退出 Active。

---

## 6. AI 不能自己拉下一组怪

AI 的自主战术目标点必须：

- 在 Active Domain；
- 路径不能穿过 Inactive Encounter 的可感知区域。

建议提供：

```text
pathSafeFromInactiveEncounters()
```

检查路径采样点是否进入未激活敌人的 detect + LOS。

如果没有安全战术路径：

> Hold，而不是自己开第二波怪。

唯一例外：

> **Regroup to DirectActor**

如果玩家自己主动离开当前房间，AI可以跟着玩家离开Domain。

## 7. 新状态

建议独立建立：

```ts
type CompanionIntent =
  | 'hold'
  | 'engage'
  | 'flank'
  | 'frontline'
  | 'peel'
  | 'retreat'
  | 'evade'
  | 'regroup'

type CompanionCombatState = {
  intent: CompanionIntent
  targetId?: string
  point?: Pos
  encounterRooms: number[]
  nextDecision: number
  committedUntil?: number
  hazardKey?: string
  hazardSeenAt?: number
  rejectReason?: string
}
```

避免继续把所有探索新语义硬塞进旧塔防 `AIState`。

---

## 8. 决策顺序

Off-Control Body 在 Standalone Battle：

```text
1. 玩家/强生命周期还拥有角色？
   → AI不抢

2. ForcedMotion / Stagger / Foreground Skill？
   → 等待

3. 紧急 Telegraph Hazard？
   → Evade / Move

4. 与 DirectActor 距离过远？
   → Regroup

5. DirectActor受到明显近身威胁？
   → Peel / Frontline

6. Active Encounter有目标？
   → Engage / Flank

7. 否则
   → Hold / Regroup
```

---

## 9. 更新频率与防抖

建议首轮：

```text
Normal Decision Interval ≈ 0.20s
Movement Commitment ≈ 0.35s
```

普通战术移动至少承诺约0.35秒。

只有以下情况可立即打断：

- Hazard；
- 目标失效；
- 路径失效；
- Break / ForcedMotion；
- 玩家接管。

防止 AI 每0.2秒左右横跳。

---

## 10. 玩家操作永远最高优先级

`controlledBodyId === unit.id` 时：

> AI完全让权。

鼠标明确移动命令：

```text
下达目标
→ C切人
→ 角色先完成玩家命令
→ 完成后AI从当前位置接管
```

关键变化：

> 目标点不是永久 Anchor。

WASD切走：

> 角色停在当前位置，AI从当前位置开始判断。

H/B：

> 继续作为旧过渡命令；PartyTask执行期间AI让权，完成后恢复AI2，不建立Anchor。

---

## 11. Regroup

建议：

```text
与DirectActor > 5.5U → 开始Regroup
距离 <= 3.5U → 结束Regroup
```

这是首轮参数。

AI可以在房间另一侧作战，不要求永远贴玩家。

---

## 12. Target Selection

只从：

- Active Encounter；
- 当前可见 / 已明确交战；
- active；
- 非 return

的敌人中选。

优先级建议：

1. 正在攻击/瞄准 DirectActor；
2. 正在攻击/瞄准 AIActor；
3. 正在施放 Ability；
4. Broken；
5. Time-to-Contribute；
6. 距离。

AI不能利用全图未知敌人信息。

---

## 13. Preferred Range

远程角色：

```text
≈ 当前武器射程 60%～85%
```

一般近战：

```text
≈ 武器射程 70%～95%
```

Shieldguard：

```text
≈ 0.75～1.20U
```

不是所有角色都跑到“刚好能攻击”的最近点。

---

## 14. Flank

EC-06 已有真实 Front/Side/Back。

基础 AI 可以理解：

> 某个目标 Back 有真实 Weakpoint。

首轮偏好：

- Ranger / 远程Hunter：明显偏 Side/Back；
- Scythe/近战：适度偏 Side/Back；
- Shieldguard：偏 Front/Side；
- Healer/Cantor：安全距离优先。

Flank只是评分偏好。

如果后方：
- 危险；
- 无路；
- 会开新Encounter；
- 太远；
- DirectActor急需保护；

AI必须放弃绕后。

---

## 15. Frontline / Peel

Shieldguard 在 Standalone 不再使用旧 Anchor Brace。

如果敌人正在压 DirectActor：

> 该敌人 Priority提高，AI更愿意进入 Front/Side 的近战位置。

本轮不加 Taunt。

Peel靠：
- 站位；
- 基础攻击；
- 架势贡献；
- Break机会。

---

## 16. Retreat / Risk

低HP或低Posture时：

> 高风险位置评分显著变差。

不是“HP<25%就永久逃跑”。

角色仍可以在安全位置继续战斗。

---

## 17. AITendency继续生效

- 默认：平衡；
- 保势：Posture低时风险惩罚更高；
- 救护优先：更靠近DirectActor、更愿意Peel；
- 规避优先：更重Telegraph/射程风险；
- 进攻积极：更愿意Flank、处理Broken。

不增加新UI。

---

## 18. Hazard Awareness

AI只读取：

- 可见来源；
- 已交战来源；
- 当前真实 AttackIntent。

不读取不可见敌人的未来攻击。

用：

```text
sourceId + startedAt
```

形成 hazardKey，记录：

```text
hazardSeenAt
```

建议真实反应延迟：

```text
≈ 0.18s
```

AI不能同帧完美躲红圈。

---

## 19. Safe Point

Hazard成立后，在周围采样：

```text
0.5U / 1.0U / 1.5U
```

候选必须：

- 可站；
- Active Domain内；
- 不进入Inactive Encounter；
- 不在即将Resolve的危险Area；
- 有合法路径。

同时考虑未来约1.0秒内多个可见Hazard。

---

## 20. 走位优先，闪避兜底

如果：

```text
timeToSafe < resolveRemaining - ~0.06s
```

则普通走出去。

走不及时：

### Companion AI
使用真实 EC-03 Evade。

### Hunter AI
使用真实 Blink。

必须：
- 有资源；
- 有合法安全方向；
- 当前动作允许；
- 确实存在即将命中的危险。

不能用 Evade/Blink 赶路。

---

## 21. Evasion接口需要拆分

当前玩家 `queryEvade()` 要求角色必须是 DirectActor。

EC-09建议拆成：

### Shared physical/resource eligibility
检查：
- charge；
- posture；
- stagger；
- foreground；
- 合法位移。

### Player command eligibility
额外检查：
- DirectActor。

### AI usage
不要求DirectActor，但必须是当前 Off-Control Body。

不要复制第二套闪避实现。

---

## 22. AI不是完美无伤

允许AI失败：

- 反应太晚；
- 没安全路径；
- 没Evade/Blink资源；
- 正在Foreground；
- 被Broken；
- 多个Area重叠。

这是正常设计。

---

## 23. Risk Score

新AI风险至少考虑：

- 即将Resolve的 Locked Area：极高；
- Tracking Area：高；
- Enemy basic range：中；
- Heavy近身：额外；
- 自身低HP/Posture：放大；
- Inactive Encounter detection：直接Reject。

---

## 24. Tactical Position Score

建议综合：

```text
Path Time
+ Range Band
+ Hazard Risk
+ Inactive Encounter
+ Party Separation
+ Direction Preference
+ Peel Value
+ AITendency
```

不要依赖大量硬编码 if/else。

---

## 25. 已能安全攻击就不要乱动

如果当前站位：

- 可攻击；
- range舒服；
- 无危险；
- 没有明显更优Flank；

AI应该：

> 停下来打。

不能因为“聪明”变成不停绕圈。

---

## 26. Broken / WallPinned

Broken敌人：

> 基础 Target Priority提高。

WallPinned敌人：

> 也可以提高基础攻击Priority。

但 AI 仍只用：

- basic；
- 已有Auto/Background技能。

不主动消耗玩家Manual技能。

---

## 27. 三技能与AI边界

EC-09 不做手动技能AI。

继续自动运行：
- Rain；
- Dance；
- Reap；
- Poison。

AI不主动按：
- Prayer；
- Ward；
- Pain；
- Sanctuary；
- Hunt等Manual技能。

原因：

> EC-11专门做技能Behavior Tags与AUTO/RESERVE/MANUAL语义。

不要提前写 `if skillName` 的技能AI。

## 28. Noncombat不变

探索脱战后：

> 继续 EC-02 的 DirectActor领队 + 另一人软阵型 Follow。

EC-09只替换：

```text

```

---

## 29. 入战/脱战/切人

入战：
> 当前Off-Control Body从当前真实位置进入AI2。

脱战：
> AI2清理，从当前位置进入followParty，不回Anchor。

C切人：
> 新DirectActor立即获得控制；旧DirectActor从玩家最终位置进入AI2。

ForcedMotion / WallPin结束：
> 从新位置完整重新决策。

# 33. 用户试玩重点

### AI是不是终于“不像塔”
伙伴是否敢于跨旧2U，在整个房间做合理事情。

### 聪明但不作弊
会躲红圈，但不是每次完美无伤。

### Flank自然性
阿尔偶尔自己找到Heavy侧后方应当是惊喜，而不是满场绕圈。

### Shieldguard保护感
伊内丝是否更像会主动“顶上去”。

### 切人交接
切走后角色是否从你留下的位置继续战斗，而不是回旧点。

### 是否过度移动
如果有安全攻击位还一直换位置，应优先调 commitment / improvement threshold。

### Manual技能缺失是否明显
如果移动AI已经聪明，但三技能几乎不会主动用，这正是后续EC-11要解决的问题，不在本轮硬编码。
