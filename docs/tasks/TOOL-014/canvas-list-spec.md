## 1. 已定位的问题，不再把它当作用户操作问题

### 1.1 空白画布框：显示层和数据筛选互相冲突

在 `desktop/workshop.ts` 的 `renderCanvasPanel()`：
- 物体模式创建 `#canvas-target` 下拉框作为绘制目标选择。
- 列表逐行调用 `modelObjectTools.canvasShown(canvasId)`；不符合就不创建行。
- 末尾再次设置 `list.hidden = objectMode`。

在 `desktop/model-object-tools.ts`：
- `canvasShown()` 以 `!objectMode` 为前提；物体模式下所有画布均被过滤。

在 `desktop/workshop-shell.css`：
- 新外壳又为 `#model-hierarchy #canvas-list` 设置 `display: block !important`。

结果就是：物体模式没有列表行，却强制显示列表容器；用户看到空框，只能从上面的下拉框切换。不能仅去掉一条 CSS 就宣布完成，必须同时解除“画布是否在列表中显示”和“当前允许编辑什么”之间的错误绑定。

### 1.2 合并入口重复维护一套选择

同一函数又建立 `#canvas-merge-controls`，在下方逐个创建 checkbox，再调用 `multi.mergeCanvases(ids)`。窄侧栏里标签换行、名称/单位挤在一起。应该使用列表已有的多选状态，不再让用户在第二份画布清单中重新选择。

### 1.3 截图 3 是窄工具条菜单，不是刚修过的顶部“建模命令”

最新 `WorkshopShell` 已给 `#model-commands-more` 的内容使用 Popover，并将内容锚定按钮下方。但 `workshop.ts` 的 `#viewport-mode-menu`、`#viewport-brush-menu` 仍是另一组工具条 details 菜单。

现有 `workshop.css` 还保留 `.model-mode-controls` 的绝对定位与 `z-index:24`；新外壳将 `.viewport-brush-toolbar` 移为单独的窄网格列，旧定位/叠层规则没有统一。截图显示模式栏盖住了展开菜单的第一项。

以上是静态源码定位；实际哪个元素在截图位置接收鼠标，实施时用真实窗口的 computed style、bounding rect 与 elementFromPoint 复现确认，不能只靠猜 z-index。

## 2. 目标界面：借鉴 SAI 的操作方式，不照搬二维绘画语义

画布页就是一个常驻、可滚动的列表。物体模式和编辑模式均能看到当前资产所有画布；隐藏或锁定的画布仍保留对应行。列表自身不得因为没有“可绘制对象”而变成空框。

### 2.1 列表行

- 行主体点击即切换当前画布，不经过下拉框。删除 `#canvas-target` 的重复入口；确有外部调用依赖时，先将调用改为明确命令，不保留两个用户可见的选择器。
- 一行包含显示开关、紧凑缩略图/画布标识、名称、格尺寸、锁定状态。名称过长省略，悬停显示全文，不能撑出侧栏。
- 当前绘制画布用边框或“当前”标识；多选行用背景高亮。两种状态视觉上分开，合并目标只能有一个。
- 双击名称或列表焦点下 F2 改名；输入状态保留原生编辑快捷键。
- 显示与锁定按钮只切换该行对应状态，不偷偷更改活动画布、不清除列表多选、不触发视口绘制。
- 删除优先放底部/右键，避免每行同时塞锁定、删除、大滑条等。有内容的删除需要明确目标且可撤销；不得删除最后一张画布或绕过锁定规则。
- 缩略图是列表辅助，不是首轮瓶颈。优先复用现有缩略逻辑或按需缓存；不每帧重建网格、不为每一行创建一个 WebGLRenderer。不能为缩略图延误“所有行可见且能点选”的修复。
- 拖动排序沿用原有顺序命令；拖动阈值内算点击，真正拖动后禁止尾随 click 切错画布。顺序不代表二维绘画的颜色叠加顺序，不新增混合模式。

### 2.2 移走不应常驻的内容

- “导入/导出便携源”属于资产操作，移至资产更多/文件入口并保留功能，不继续占画布列表上方高度。
- 新建尺寸选择放在“新增画布”的紧凑小菜单：0.25 / 0.125 / 0.0625 m，默认沿用当前画布规格。它是新画布规格，不是当前画布可随意修改的尺寸。
- 当前画布的透明度和位置在一个属性区显示，不在每行重复放完整滑条。
- “查看全部画布”保留为列表附近的紧凑取景命令；普通行切换不得调用它，不复位镜头。
- 固定标题、固定底部常用操作，只有行列表滚动；不要整个长侧栏套多层滚动。窄窗口抽屉也遵循相同结构。

## 3. 选择、编辑范围与输入：三种身份必须分开

采用独立的列表管理状态（字段名为建议，不是现有 API）：
- `activeCanvasId`：当前绘制目标，来自现有 CanvasSession；只有一张。
- `selectedCanvasIds`：列表管理多选，用于合并等批量命令，不等于物体选择。
- `rangeAnchorId`：Shift 范围选择起点。

建议交互：
- 普通单击：只选中此行并激活该画布。
- Ctrl 单击：增减列表选中项；添加时该行成为活动目标，移除活动行时在剩余选中行中按稳定规则补一个目标；无多选时回到现有活动画布，不偷偷删除对象选择。
- Shift 单击：按当前可见列表顺序选取连续范围，当前端点成为活动目标。
- 右键已选行：保留多选，打开“合并所选/复制/改名/删除”等；右键未选行：只选择该行后打开菜单，目标文案必须立即更新。
- 纯列表选择/切页不改模型 revision，不标记资产未保存，不新增模型写入历史。原有物体选择的历史语义保持，不借此重写全局撤销。
- Ctrl+A/C/V、Delete、F2 仅在画布列表持有焦点且不是文本输入时按画布语义处理。视口 Ctrl+J 仍合并物体，不能被画布列表的全局监听抢走。

**编辑模式不再过滤列表，但写权限不因此扩大。**
- 当前对象的内部编辑仍只允许修改其成员。
- 点击另一画布，需要切换目标时先走现有草稿处理流程；推荐安全退出旧物体的内部编辑、回到物体模式并切换绘制画布，同时轻提示。不可沿用旧 editObjectId 去操作新画布，不自动选中一个任意对象代替用户。
- 切换前有岩体/自动上色草稿，复用“应用/放弃/返回”。选择返回则活动行、多选、画布和镜头都保持旧状态，不能先改 UI 再取消。
- 隐藏或锁定画布允许查看属性；绘画明确禁用并说明原因，不自动显示、不自动解锁。
- 独立贴图窗口持有写租约时，列表可按现有规则展示；任何会换写目标、合并、删除、复制资产内容的动作必须遵循租约，不能绕开 `paintController.requireClosed()` 或等效保护。
- 点击切换应保留相机姿态与世界观察范围，按三种体素精度换算局部参考帧，不能把模型缩放跳动误当“切换成功”。

## 4. 合并画布：在列表里多选，直接执行

### 4.1 入口

移除下方整组 checkbox。选择两张以上画布时，底部“合并所选”可用，右键菜单提供相同操作。旁边明确显示“合并到：<活动画布名>”。用户通过点击/多选最后激活的行即可确定目标；必要时右键提供“设为合并目标”，不另常驻一个目标下拉框。

不要求用户再次在弹窗中逐张勾选。兼容且无冲突的合并可以一次完成。存在重叠覆盖时，显示一次简短确认：目标、来源顺序、重叠格数、覆盖者；取消不得产生部分修改。

### 4.2 复用现有语义，不改写用户资产

当前 `CanvasSession.mergeCanvases(ids, targetId)` 已要求相同体素精度、网格对齐、来源不锁定；保留并映射物体身份、paintSource 和 faceTone。

它先载入目标格，再按模型画布数组顺序合入其他选中画布，后合入覆盖此前同格；这不是“目标总胜出”。UI 必须把实际次序说明白，不擅自换成 SAI 的二维图层混色规则。

本轮要求：
- 合并目标必须在选中集合内；保留目标的 canvasId、名称、格尺寸和空间参考帧，更新成员来源而非创建无法追溯的新资产。
- 预检查指出具体不兼容画布与原因：精度不同、网格不对齐、锁定、当前租约/草稿等。不得为了“智能合并”自动改分辨率、重采样、解锁或静默跳过一部分来源。
- 隐藏画布参与合并时，说明合并后的可见性采用目标设置；不以“隐藏”冒充不会参与数据。其余行为遵循现有有效规则。
- 保留基础色、手绘、面暗色、物体成员与原点；不改变未选画布、资产 Root、其他资产。
- 只通过现有会话事务提交一次；禁止多次 remove/add 造成半合并。预检查与提交间版本变化则重新预检或拒绝，不能拿过期列表直接执行。
- 失败不变；Undo 一次恢复原画布/归属/颜色/手绘，Redo 一次得到相同结果；保存重开结果一致。
- 合并后列表只选中并激活保留的目标画布。不能把“合并画布”同时变成“合并所有物体”；需要合并物体仍走 Ctrl+J。

## 5. 修复截图 3：统一菜单的定位、层级和事件

### 5.1 需要覆盖的实际入口

优先复现 `#viewport-mode-menu`（方块图标的建模方式），再检查 `#viewport-brush-menu`、`#viewport-precision`、列表右键菜单及顶部建模命令。不能只测试最后一个已经修过的菜单。

### 5.2 修复要求

- 触发按钮不移动、不因展开而改变布局。只让菜单内容从按钮右侧/下方展开；靠近窗口边缘时翻转或限制在窗口内。
- 把相关菜单内容纳入一致的顶层弹出机制。优先复用现有 Popover，而不是给每一个旧容器不断添加更大的 z-index。
- 物体/编辑模式控件应有固定可用位置；若仍贴在视口上方，不得覆盖已打开菜单项目。顶栏、工具条及弹出内容各自只负责自己的区域，不为修一处全局提高所有工具的叠层。
- 一次只打开一个同级工具菜单；本工具菜单打开应关闭上一个同级菜单。嵌套菜单需要明确父子关系，不能一刀切把子项也关掉。
- Esc 优先关闭打开的菜单并归还触发器焦点；该次按键不清空选区，不取消无关的岩体/自动上色草稿，不关闭贴图窗口。
- 点击菜单项目不会穿透触发画布绘制、物体选择或拖轴。点击外部关闭时，对视口的那次关闭点击不要意外落笔；文本输入仍保留原生操作。
- 窗口缩放、DPI变化、层级抽屉展开、列表滚动时重新定位或关闭菜单，不留漂浮的旧坐标。
- 菜单最小间隙建议 4–8px；长菜单可滚动，不能超出可视范围。无需为此替换整个UI库或新增大型依赖。
- 迁到顶层后检查现有事件委派/草稿拦截：原先依赖 `closest('#app ...')` 的判断可能不再覆盖菜单节点。用共享命令调用和明确“这是工具菜单”标记处理，不能靠复制一套业务事件解决。
- 监听器与弹层随工作区释放；重复打开资产不积累 MutationObserver、全局事件或多份菜单。

技术依据：Popover 显示在浏览器 top layer，避免被普通父级 position/overflow 规则遮挡；定位仍需要按实际触发器测量和窗口边界处理，不是设置一个属性就自动对齐。参考 MDN：https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/popover 。当前 Electron 已使用 showPopover 的代码路径，但仍应以项目锁定版本实测。

## 7. 验收（B级定向验证，不新增全工坊重构门槛）

### 画布列表
- 1张、5张、32张：两种模式都能看到完整行列表；隐藏/锁定画布不消失。
- 普通单击切换，Ctrl多选、Shift连续选，当前目标标识准确；名称长/空画布时不破版。
- 0.25/0.125/0.0625 m之间切换保持观察位置；锁定不误绘制；输入框快捷键不执行画布删除。
- 新建/复制/改名/排序/删除至少各一次；不再出现重复绘制画布下拉或下方复选清单。
- 编辑对象作用域仍隔离；跨画布切换不沿用旧编辑对象；草稿“返回”保持原选择和内容。

### 合并
- 同精度对齐，非重叠与重叠各一组，明确目标和覆盖顺序；合并前后世界位置一致。
- 有 paintSource、faceTone、多个物体及集合的资产副本：合并、撤销、重做、保存重开均保留有效数据。
- 精度不同、偏半格、锁定、过期上下文、贴图写租约：明确拒绝且资产不变，不部分成功。
- 未选画布完全不变，Root不变；合并画布后仍保留独立物体身份。
