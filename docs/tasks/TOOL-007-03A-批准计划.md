# TOOL-007-03A：聪明选区与区域修改

这一轮的核心不是“把旧框选做漂亮一点”，而是正式把：

> **选区从一个 XYZ 长方盒，升级成一组精确的体素。**

这是整个后续 Clipboard、临时资产、印章 Brush 的基础。

现在旧实现本质还是：

```text
屏幕拖出 XY 范围
+
手填 Z Min / Z Max
↓
得到一个长方体 Bounds
```

而你真正要的是：

```text
我眼睛看到这些体素
↓
框住它们
↓
决定我要穿透几层
↓
具体哪些格被选中一目了然
```

所以 03A 要改变的是**Selection 模型和交互**，不是资产格式。

---

## 一、这轮我建议锁死的几个设计决定

| 项目 | 03A 采用 |
|---|---|
| 选区本体 | **精确体素坐标集合** `Set<voxelKey>` |
| 框选命中 | **体素中心投影进入框内才算候选** |
| 穿透方向 | **当前相机视线方向**，不是世界 Z |
| 穿透定义 | 按视线实际遇到的实体层数 |
| 默认深度 | 最前可见层，即 1 层 |
| 最大模式 | 全穿透 |
| 单格选择 | 支持 |
| 拖动刷选 | 支持 |
| 框选 | 支持 |
| 加选 | Shift |
| 减选 | Ctrl |
| 选区本身是否 Undo | **不进入 Undo** |
| 对选区做 Clear/Fill/替色 | **一次操作 = 一次 Undo** |
| 选择后自动退出选择模式 | **不退出** |
| 空间坐标显示 | 从 Selection Set 派生 Bounds，不再由 Bounds 决定 Selection |

最后这点非常重要。

以后应该是：

```text
Selection Set
    ↓
自动算出
Min / Max / Count
```

而不是：

```text
Min / Max
    ↓
强行认为里面全部被选
```

这样以后选：

```text
■ ■
  ■
■■■
```

复制出去就真的只有这些格，不会把中间没选的格一起带走。

# 二、选择工具拆成两个子工具

模块制作中的：

> **体素选区**

进入后出现：

```text
选择方式

[ 点选 / 刷选 ]
[ 框选 ]
```

不增加 Workspace。

### 点选 / 刷选

这是最适合局部精修的一种。

无修饰键：

> 按下时先清除旧选择，然后当前这一笔经过的真实体素全部加入。

Shift：

> 加选。

Ctrl：

> 减选。

因此可以直接：

> 按住鼠标在模型表面“刷”出我要的几块。

它必须用 007-02 已经验证过的**真实 DDA 命中格**，不能从 Greedy Mesh 的大面猜格子。

# 三、框选改成真正的“屏幕框选”

这一点直接按照你提出的思路。

框选不再要求：

> 鼠标必须先命中工作层某个 XY 格。

而是可以从视口空白处开始：

```text
┌────────────────┐
│                │
│    █████       │
│    █████       │
│                │
└────────────────┘
```

拖一个真正的二维屏幕矩形。

然后遍历当前已有体素：

```text
Voxel Center
↓
投影到屏幕
↓
中心进入矩形？
```

只有中心进入才算。

所以：

> 方块只有一个角碰到框 —— **不算**。

> 方块中心进入框 —— **算**。

框边界上的中心按“包含”处理，避免一两个像素抖动造成不稳定。

# 四、穿透深度不是 Z，而是“我看到的第几层实体”

这一项是这轮最重要的技术设计。

例如当前视角：

```text
Camera →

A  B  C  D
```

A 在最前。

穿透：

```text
1 层
→ A

2 层
→ A + B

3 层
→ A + B + C

全部
→ A + B + C + D
```

但这个“层”不是：

> 世界 X / Y / Z 增加 1。

而是：

> **从相机射向这个体素中心时，沿途遇到多少个实际占用体素。**

所以对每一个框内候选体素：

```text
Camera
   ↓ ray
[实体]
   ↓
[实体]
   ↓
目标
```

如果目标是第三个遇到的实体：

> Depth Rank = 3

当当前穿透深度是 2：

> 不选。

深度是 3：

> 选。

这样无论你：

- 正面看；
- 侧面看；
- 斜 45° 看；
- 从上方看；

“穿透两层”都还是视觉意义上的两层。

这比世界 Z Min/Max 强很多。

例如：

```text

深度 2  → 131 格
深度 3  → 168 格
```

右下角实时显示。

# 六、三种穿透状态

实际上 UI 只需要表达：

### 可见 / 1 层

只选第一层真实可见体素。

### N 层

精确穿过 N 层实体。

### 全部

所有：

> 体素中心投影落在框内

的格子全部选中。

所以以后从正侧面框一根墙：

> 全穿透 = 直接把整堵墙厚度一起选走。

而：

> 1 层 = 只拿表皮。

# 十一、区域修改的准确含义

这部分我建议现在定义清楚，避免 Codex 自己发挥。

### 替换颜色

只修改：

> 选中且当前仍存在的体素。

改成当前色板色。

必须保留：

> owner / 原有几何身份。

---

### 清除

删除所有：

> 当前选中的已有体素。

Selection Set 本身仍保留。

也就是说清空以后仍然可以看见：

> 这些位置曾经是我的选区。

---

### 填充

03A **不做“凭空框一个空房间然后全部填满”**。

这里只对 Selection Mask 工作。

Selection 应记住选择时这些坐标原本的体素身份。

所以：

```text
选择 20 格
→ 清除
→ 20格变空
→ 填充
```

可以按当前颜色把这 20 个格重新填回来。

原本仍存在的格：

> 保留 owner，换当前颜色。

已经被本次清除的：

> 恢复 Selection Snapshot 中的 owner。

这让：

> Clear → 看一看 → Fill 回来

成为非常安全的工作方式。

真正“大范围空白空间填实”仍然由现有三维/矩形工具解决，不让 03A 又制造一套建模工具。

# 十二、Selection 自己不进入 Ctrl+Z

这个也很重要。

例如：

```text
选了15格
↓
又加选5格
↓
Ctrl+Z
```

**不应该撤销“选择动作”。**

Ctrl+Z 仍然负责：

> 文档几何修改。

但是：

```text
选20格
↓
Clear
↓
Ctrl+Z
```

应该恢复被删掉的20格。

Selection 仍然保持20格。

这样操作逻辑最符合建模软件。


# 十七、性能策略

不能每移动 1 像素就同步做：

```text
25万格 × 复杂射线
```

建议：

> 每帧至多重新计算一次 Preview。

可以缓存：

```text
camera matrix
+
document revision
+
section state
```

不变时：

> 屏幕投影数据重复利用。

视线深度可以利用当前 DDA，必要时给：

> voxelKey + cameraState

做短生命周期缓存。

但 03A 不需要提前搞 WebWorker 大系统。

必须做三档实测：

```text
约 1,000 格
约 20,000 格
接近 240,000 格
```

要求至少：

- UI 不长时间冻结；
- 拖框 Preview 可取消；
- 大选择不会生成几十万个 Three Object。
