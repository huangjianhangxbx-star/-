## 1. 第一轮的完整目标

**保留地格搭建的场景，把单位部署、普通移动、跨层、索敌、命中、接敌和敌方追击改成一致的连续空间规则，并在现有塔防与最小探索交战验证场景中完成验收。**

玩家可见的主交付是：现有塔防中能够用鼠标在非格心位置部署和移动角色；预览、实际射程、墙体遮挡与接敌一致；敌人能按容量锁定、追击、脱离、返程和继续推进，而不是继续依赖旧的邻格阻挡。

“完整”按上述玩法能力验收，不按单一脚本或文件验收。修改输入、渲染、反馈和测试，是完成同一个模块所需的工作；不等于开始其他新功能。

v0.2 §2.2 已要求“优先攻击与自己接敌的合法敌人”。没有 §3 的接敌记录，就不能正确完成该优先级。反过来，接敌、追击和返程都依赖 §2 的距离、通行与跨层。因此两节共同组成首轮，内部可以分步骤实现，但不在完成一半时转去制作 §4 的 WASD、瞬影或影庭。

### 2.1 探索部分怎样验收，才不把首轮无限扩大

首轮制作一个**开发验证用的最小交战场景**，使用真实模拟模块和实际探索规则策略，不是用测试替身假装探索支持存在。可见敌人由测试场景显式提供，不引入未确认的视距和探索失目标返回设计。

该场景验证部署范围、敌人目标选择、容量溢出与复制体例外，范围到 §2、§3 为止。§3.3 的“复制体攻击不触发本体队伍战斗状态”，首轮验证事件／参与者分类的输出契约；真正队伍状态管理器的消费端集成，属于 §9。首轮不能宣称探索入战／脱战系统已经完成。

因此验收记录必须分别写：

- 空间与交战规则：在两种规则环境中的已测结果。
- 探索队伍状态及节点循环：未实施，留待第 9 节。

不能把“给未来留了字段”写成 §3.3 已实现，也不能为了宣称探索整体完成而提前加入第 9 节。

### 3.1 建议的技术边界

以下不是新增游戏规则，实施者可在不改变批准行为的前提下优化组织：

- 地形可继续用地格记录，导航也可使用格网辅助；最终落点、路径线段合法性、距离、命中和动态通行不能靠吸附格心维持。
- 一套权威逻辑位置负责移动、距离、命中和拾取映射。视觉插值只改善显示，不反向决定战斗。
- 地形可通行、单位可经过、终点可停留、可接敌、可命中应分别查询，避免一个 `walkable` 承担相互冲突的非对称规则。
- 接敌关系为可追踪数据，容量由关系校验；避免多处独立增减造成死亡、撤离或重入后容量泄漏。
- 场景模型和装饰不自行决定命中。用于射线遮挡的墙体／实体高台等逻辑数据，与地形表现有明确映射。
- 调试场景可以增加显示逻辑中心、身体轮廓、容量与敌人状态的开关；这是本模块的验证手段，不是新玩法。

可以考虑新增 `game/src/core/spatial.ts`、`navigation.ts`、`engagement.ts`、`targeting.ts`。这些均为**建议文件名，当前不存在的文件不能写成已建成架构**；只在实际职责需要时拆分，不引入全面 ECS、完整物理引擎迁移或全项目重构。

## 4. 实施前必须收束的边界

v0.2 §10 明确保留了身体占地、动态落点和跨层中断等专题。因此，下面不是重问 Q1—Q77，而是进入首轮时补上其实际触及的边界。

**本节建议尚未获用户批准。没有回答的条目不得由执行者按建议默认落地。可以先完成计划与影响分析，但不能把受影响实现称为设计已确认。**

### B1. 身体占地、区域边缘与动态终点

已确认：中心距离判定射程；落点需合法地形与己方最小间距；移动可过友方、不能穿活敌。

需确认：碰撞占地采用什么形状；部署区域与地形边缘按中心还是完整占地判定；濒死友方如何参与停留间距；多个单位同时选择相近落点时是否预留。

**建议**：原型使用可配置半径的圆形脚底占地，不使用 Spine 动画外形；部署／停留检查完整占地和明确的最小间距，跨层转换使用专门合法性检查。已接受的移动终点建立预留以避免多人争抢，但预留不阻挡友军经过；到达前再次核验，失效则停在合法处提示，不擅自挤开友军或传送到替代落点。

取舍：比仅检查中心更不容易出现身体穿墙和边缘悬空；也会影响狭窄道路宽度和可部署空间，必须在原地图上实际核对。圆形占地仅用于通行／停留，**绝不把射程改成圆边到圆边距离**。

### B2. 普通跨层中断与目标变化

已确认：消失完成前在出发点，之后在落点；无无敌；跨层期间不能普攻、主动施法或接纳新敌人；渐隐开始不自动解除已有关系。

需确认：跨层已开始后新的移动命令如何处理；逻辑切换前后落点失效或进入濒死时停在哪一侧；怎样结束表现，避免“半隐状态”遗留。

**建议**：跨层开始后的新普通移动只替换后续目的地，不瞬间打断已开始的跨层；主动技能请求直接拒绝而非偷偷排队。濒死或死亡立即停止移动，以当时权威位置处理生命周期并恢复可识别表现；若逻辑切换前落点已非法，保留出发侧并报告受阻，不强占落点。具体取消／续行策略须确认后才编写验收期望。

### B3. 接敌解除后的非超距分支

已确认：目标死亡、濒死、撤离、超追击范围或不可合法接近时释放容量；超追击范围后返程，返程不重接敌。

需要补定：v0.2 对“目标超追击范围”明确规定返程，但没有同等明确写出目标死亡／撤离后是统一返程，还是在原地重新选择对象；返程中的机会普攻也没有完整规定。

**建议**：塔防中原关系失效后统一返程，返程只移动／承受伤害与控制，不主动攻击新目标或建立新接敌；返回合法路线位置后再恢复判断。这个方案简单一致，但会影响防线被击破后的敌人节奏，因此不能由程序实现自行决定。探索失去全部目标后的返回行为仍属于 §10／§9 后续专题，不在此顺便定案。

### B4. 首轮验证配置及旧功能过渡

**配置部分**：需形成可复查的小表，至少包括地图尺度换算、身体半径／最小间距、接敌半径／容量、敌人容量需求／追击半径、移动速度、普通跨层时长、原型武器射程／实际命中形状／目标数量、逻辑障碍的遮挡属性。

这些参数与具体内容没有被 v0.2 全部锁定。建议允许实施者在批准的原型内容范围内给出一组集中配置的起始值并记录理由，再以测试和试玩调整；这项调参权限本身须确认。武器命中形状、目标数和墙／台缘遮挡属于规则或内容决定，不能全都伪装成任意调参。

**旧功能部分**：旧版救援、水晶撤离、道具、疾行卡、路障等会调用本轮更换的坐标接口，但其完整新设计不属于首轮。

建议先列出逐入口的过渡表，按下面原则核准：

| 入口 | 首轮建议 | 不能借机做的事 |
|---|---|---|
| 当前角色与技能 | 作为测试载体；按确认后的连续空间配置接入实际命中与预览；保留未被推翻的独立结算 | 增加职业、技能树或新技能库 |
| 复制体部署／战斗 | 接入连续落点、不可移动、塔防／探索目标差异；其余旧机制标注为过渡 | 把旧 20 碎片认定成新生命力价格，或假装新构筑快照系统完成 |
| 旧卡牌／道具的目标选择 | 统一使用单位身份与合法落点查询，避免要求目标站在格心 | 设计新牌池、涨价／变卖，或擅自给卡牌增加 v0.2 暂缓的限制 |
| 疾行、路障、救援、水晶撤离 | 逐项确认空间换算与兼容方式，保留可运行验证链；无法无歧义兼容的具体项先列阻塞，再决定验证入口范围 | 将旧疾行直接改名为瞬影；直接启用半套影庭；未经批准删除或关闭旧功能 |
| 波次、节点和资源 | 保持旧版过渡流程，仅修正连续路线到达、水晶触发及清理接口 | 做新波内批次、永久账户、副本奖励去重或整套结算 |

首轮的过渡行为不修改 v0.2 的新设计方向，也不能重新登记为最终规则。若为收敛验证范围而需要临时关闭某个入口，必须列出具体对象、影响和恢复所属模块，获得明确同意后再做，不能藏在“兼容性调整”里。

## 5. 顺序执行步骤

所有步骤属于同一个首轮任务。内部按依赖推进并持续保持测试可追踪；在整个首轮完成前，不转入下一模块的功能制作。

### R1-00：确认范围、补充边界、建立旧版基线

**输入**：本文范围，v0.2 §2—3／§10，B1—B4 的用户回答，实际本地工作树。

**工作**：接手方重新检查版本和未提交改动；核实 Skill；记录已确认与未确认的区别；形成边界决定表及旧功能过渡表。获得实施／验证授权后，再在本地记录旧版单元测试、构建、相关浏览器测试的结果。

**产物**：第一轮有效范围、已批准补充决定、配置表、基线验证记录及失配测试分类。任务编号在 `docs/tasks/` 中实际核对后分配，不凭本附件占用编号。

**闸门**：受影响的设计边界没有确认，不得自动采用本文建议。不能用“先实现再说”掩盖未知行为。

### R1-01：统一空间类型和查询契约

**主要位置**：`core/types.ts`、`core/map.ts`、`core/combat-config.ts`，以及按需新建的空间模块。

**工作**：分清地格索引与连续位置；定义权威表面／层级和跨层状态；提供地形、中心距离、身体占地、终点、障碍线段等查询；明确塔防与探索规则上下文，避免与旧 dark/hunter 变体混用。

**验证**：非整点位置能找到正确地形；中心距离使用水平欧氏距离；边缘与身体判定按 B1；层级不因显示插值提前改变；非法输入不写坏状态。

**完成条件**：后续代码可以调用共同查询，不再各自复制 `same()`／`Math.round()` 来决定不同规则。

### R1-02：做完部署、普通移动与跨层，并接通鼠标入口

**主要位置**：`engine.ts` 的部署／复制体落点／移动，导航模块，`main.ts`、`interaction.ts`、`view/scene.ts` 的拾取与基础路线反馈。

**工作**：路径可利用格网辅助，但终点保持连续；检查完整路径线段而非仅终点，避开活敌；动态障碍变化按 B1 重新规划／停止。跨层实现明确阶段、权威位置切换与 B2 中断策略。点击／拖拽及部署预览同步使用真实落点，非法请求无消费。

**验证**：在同一块地面上可以停在多个不同非格心位置；可经过友方但不能停入不合法间距；不能穿敌或穿墙；复制体与濒死本体无移动入口；相邻跨层可走、整台跳跃／穿独立墙不可走；跨层仍可受击。

**完成条件**：部署—选中—移动—停留—跨层这条链路，在浏览器里实际可用。此处不增加 WASD 或新键位。

### R1-03：实现接敌、容量与敌方行为

**主要位置**：`engine.ts` 的敌人移动／阻挡／目标判断、按需新建的接敌模块、单位生命周期清理。

**工作**：建立唯一接敌关系和容量核算；稳定选择最近合法且容量足够的对象；锁定、追击、释放和返程按照 v0.2 与 B3。塔防容量溢出继续路线，不能被友方身体额外堵死；追击区域中心在接敌时记录，不随敌人移动。恢复路线时尊重路线身份与未走进度，不擅自抄近路改变关卡路线。

探索策略实现真实差异：无容量仍可追击本体；复制体不进入主动候选，不因造成伤害被报复；已有接敌遵守锁定。复制体不成为“本体队伍遭遇”事件的触发者；范围伤害／环境效果不套主动索敌免选过滤。

**验证**：容量不重复扣／不泄漏；多个敌人需要容量不可拆分；同距重复执行可重现；开始渐隐不直接释放；返程不重接敌，受控后继续；两种模式的复制体行为确有差异。

**完成条件**：旧邻格 `block` 行为不再与新容量机制同时决定结果。死亡、濒死、离场、节点清理均清除失效关系。

### R1-04：完成连续索敌、实际命中、遮挡与攻击呈现

**主要位置**：`engine.ts` 的 `geometry/rangeTiles/canHit/skillRangeTiles`、攻击前摇／释放逻辑，按需新建的攻击查询模块，场景范围覆盖及角色方向表现。

**工作**：圆形索敌选出合法目标，再按武器命中形状与目标数结算；优先自己的接敌对象，再选其他最近合法敌人；己方不自动移动追击。对近战／远程和逻辑障碍使用同一合法性来源；高处也不能绕过墙体检查。范围预览、选中提示和命中结果来自同一查询。

保留普攻“出手才结算”的时序，技能不额外扣普攻耐久。连续逻辑朝向与正反面、左右翻转适配，不能继续仅在四个方向上搜索目标，也不要求新增全角度动画。

**验证**：斜向目标正确纳入圆形索敌；圆内第二个敌人不会仅因动画覆盖自动吃伤害；与自己接敌的合法目标优先于更近但未接敌的对象；远程高／低处都不能穿墙；大型单位按中心入圈判断；取消未出手攻击不扣耐久；跨层不能施法／普攻。

**完成条件**：不以“画出一个圆”代替连续命中改造；不能保留“圆形预览＋四向实际索敌”的混合逻辑。

### R1-05：完成本模块的所有调用方适配

**主要位置**：`main.ts`、`ui.ts`、`world-feedback.ts`、`view/scene.ts`，以及实际受影响的效果／动画调用方。

**工作**：移除本轮范围内以格点相等寻找单位、判断到达、确定卡牌目标、投影和高度的旧假设；修正连续路线预告、资源飞行起点和水晶到达触发；执行 B4 批准的旧功能过渡表。

保留与本轮无关的 UI 风格、素材和音频结构。范围／部署提示应提前给出有效或无效原因，提交时仍复核。卡牌／道具不会因为角色站在非格心位置而无法使用。

**验证**：鼠标两个移动入口结果一致；角色、头像、非格心目标能够正确被拾取；范围、路径与落点不漂移；变速／暂停不使模拟和视觉脱节；旧入口兼容结果逐项有记录。

**完成条件**：从玩家输入到权威状态再到画面与反馈形成完整闭环，没有仅在调试代码中才有效的主功能。

### R1-06：自动化、浏览器与试玩验收

**主要位置**：既有测试文件及按职责新增的空间、移动、接敌、攻击和浏览器用例。新测试文件名由实施者按实际职责确定，不假定本仓库已经存在。

**工作**：执行第 6 节矩阵；在原塔防地图完成一场可解释的交战／漏怪／结算验证；在最小探索交战场景验证差异。检查同一条件下的稳定性和相对性能，不凭未测数据许诺固定 FPS。记录已通过、失败、未测、暂缓和用户试玩结论。

**完成条件**：本轮新增／修改用例通过，相关构建和浏览器验证完成，旧基线失败有明确处置；所有批准范围均有证据，不用历史截图或旧测试替代当前版本验证。

本轮之后才进入 §4。若后续模块带来新的规则要求，可以正式扩充已有模块并补测，但不把本轮已知缺口藏到下一轮。

## 6. 验收矩阵

| 编号 | 场景 | 必须满足的结果 |
|---|---|---|
| A01 | 非格心部署、边缘部署、贴近友方／濒死者部署 | 按 B1 判断；预览与提交一致；非法不消费 |
| A02 | 点击与拖拽到同一非整点 | 到达同一合法位置，无自动吸附格心，无额外朝向确认 |
| A03 | 友方路径交叉、同时抢终点、动态终点失效 | 可经过友方；终点按 B1 分配／复核；无强推、错误传送或重叠穿墙 |
| A04 | 己方绕活敌，敌人移动进入路径，无路可走 | 不穿敌；可行则绕行，确无路停止并提示 |
| A05 | 相邻高低边界、独立墙、整座高台跨度 | 普通跨层只发生于合法相邻边界；地面敌人不获得相同权限 |
| A06 | 渐隐前／后受击、濒死、新移动命令、落点变化 | 逻辑切换点遵守 §2.1；其余按 B2；无无敌或悬空状态 |
| A07 | 跨层期间已有接敌与新敌人 | 不接纳新敌人；旧关系按正常合法性判断，不因开始渐隐立即清空 |
| A08 | 容量足够／不足、单敌容量大于余额、多个候选等距 | 整体接纳或拒绝；唯一关系；稳定排序；无超额占用 |
| A09 | 容量已满时其他敌人经过 | 塔防继续推进且可经过己方；不出现容量之外的无限身体堵路 |
| A10 | 锁定后第三方伤害更高、目标死亡／撤离／超距 | 不按伤害改目标；关系释放与后续行为按 §3、B3，无容量泄漏 |
| A11 | 敌人追击绕行、返程受击／眩晕 | 追击中心固定；返程不重新接敌、不回血；控制结束继续返程 |
| A12 | 圆内斜向目标、自己的接敌对象、无合法目标 | 按圆与命中形状分别判断；接敌合法目标优先；己方不自动追击 |
| A13 | 近战跨层、远程高低互射、墙后目标、大体型擦边 | 中心水平距离与高度／遮挡分开；高处也不能穿墙；范围提示一致 |
| A14 | 前摇取消、技能执行、一次攻击多个目标 | 未出手不扣耐久；技能不混算普攻；群体命中按批准的武器配置结算 |
| A15 | 探索本体容量满、复制体主动攻击、敌人范围伤害 | 溢出敌人仍可攻击本体；复制体不引发主动报复／本体遭遇事件；不因此免疫范围或环境效果 |
| A16 | 同一复制体分别置于塔防／探索规则环境 | 塔防不享有探索免主动索敌例外；探索候选过滤实际生效 |
| A17 | 探索部署与收纳参数 | 部署使用独立配置，不把未制作的收纳 UI 或完整影庭作为部署前提 |
| A18 | 非格心卡牌／道具目标、救援／撤离过渡入口 | 按 B4 的逐入口批准表可用或明确标注未开放；不存在未声明失效 |
| A19 | 普通移动／伤害／死亡／水晶到达／重入 | 现有塔防链路不因连续坐标卡死；接敌清理正确；一次死亡不重复发放单场奖励 |
| A20 | 可见范围、光源／黑暗旧变体、模拟暂停与慢速 | 仅完成本轮必要坐标适配；不把旧可见性当作新探索视野定案；确认未覆盖的部分独立记录 |

A15 涉及本体队伍事件的输出侧验证，不等于 §9 完整入战／脱战集成通过。A19 的单场死亡去重也不等于 §8“同副本重试同一预设敌人奖励去重”已实施。
