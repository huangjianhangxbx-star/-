来源角色的密集头发、刘海、衣摆、尾巴、长武器辅助骨与目标拓扑、长度和局部镜像方式不同，不按序复制。来源不同网格的 deform（`city/interact` 三通道、`common/talk1` 两通道）全数跳过；即使顶点数恰好相同也不能证明目标绑定兼容。来源 drawOrder 使用 68 个 slot 的偏移，而目标有 88 个，两个动作分别有 4/1 帧来源层序键，不能照搬目标。来源 9 个 transform 约束通道驱动专属 3D、发丝、裙摆和武器结构，均显式跳过。结果会缺少来源长发/衣摆/尾巴的动态和长武器外观；目标保留自己的皮肤，`common/talk1` 保持目标原层序，`city/interact` 则使用下述三个目标专用层序键，袖/手连续遮挡仍待 Spine 编辑器审阅。

### v3 候选质量深审（2026-10-25）

逐通道数量会低估跳过项的动态影响：`city/interact` 的 174 条跳过包含 1168 个键，其中 150 条通道有多帧；`common/talk1` 的 175 条跳过包含 1129 个键，其中 140 条有多帧。相对地，两条动作直接迁移分别只有 40/28 个键，另有 60/60 个键已写入候选但标为需要校准。这些跳过主要覆盖来源长发、刘海、裙摆、尾巴与武器的密集次级运动，目标画面因此明显更静；不可把“显式跳过”解释为“来源这些部位没有运动”。来源 `city/interact` 的 `headzuoyou2.translate` 还有 7 帧、眼部 deform 3 帧，目标的脸部方向及表情并未完整复现。

官方 4.3 runtime 对照帧表明 `city/interact` 在 0.1667 秒左手收于胸前、0.2167/0.4 秒伸出、0.66 秒收回；`common/talk1` 在 0→0.33 秒张手，0.7/1.5/3 秒维持谈话手势，4 秒复位。抽查帧未见骨链明显断裂或错误手形。v3 的 0.1833 秒源/目标帧（位于 0.18333334 秒层序键前）显示：来源左手在胸前可见，目标手较小且接近被胸甲或袖口遮挡；v3 目标没有对应层序键。后来补拍 0.184 秒（层序键后）和 0.2166 秒（下一键前）用于核对 v4 的准确过渡。0.2167 秒双方伸手可见，因此应在目标原工程的连续播放中集中检查 0.15–0.2167 秒手、袖、胸甲的前后关系。目标补层序键作为目标专用修正记账，不能计入已迁移的来源 drawOrder 通道。

这两条结果可作为**手势可辨的候选**：共享映射和实际手臂链已有证据。它们尚不足以判为计划的完整动作验收通过：根、肩、头、手腕等分别 12/13 条关键通道仍标为 `needs-calibration`；连续播放中手袖遮挡、脚接地及目标体型适配未完成验收；来源大量多帧次级运动缺失。优先在目标正式绑定上校正并记录这些通道，再以相同 skin/显示条件比较工坊候选和导回结果。若只补用目标原生头发、尾巴或衣物运动，需单独标记为目标本体补层，不可提升来源通道迁移数。对肩肘腕局部轴目前没有可凭数据安全批量修正的数值，因此保留原生键待编辑器视觉校准。

### v4 最小目标层序修正

为修正 `city/interact` 早期手势被目标胸甲或袖口遮挡的问题，在该动作配置的 `targetDrawOrderKeys` 加入三个**目标专用**键：0 秒使 `Z-Z_Lhand1` 和 `Z-Z_Larm2` 分别提高 16、14 个目标 slot 位；0.18333334 秒只保留左手提高 16 位；0.21666667 秒恢复目标默认顺序。该三段来自来源手/袖相对躯干的前后关系，并用目标原工程 `common/talk1` 对同一手袖 slot 的层序实践核对；偏移值是针对目标 88 槽重新确定，不是把来源 68 槽的偏移直接复制。`common/talk1` 的手袖无同类关键遮挡，配置不加目标层序键。

工坊现可保存并重载动作级 `targetDrawOrderKeys`，生成时核验目标 slot、整数偏移、目标位置碰撞和时间范围，迁移报告以 warning 另列“Target-authored drawOrder: 3 keys”；来源 `@drawOrder` 仍为 `explicit-skip`，两条动作的来源通道统计与 v3 相同。`make-v4-talk-interact.mjs` 从保存的 v4 配置走与桌面工坊相同的迁移器，产出 `candidate-v4-city_interact/`、`candidate-v4-common_talk1/`、两份 `report-v4-*` 及 `v4-talk-interact-manifest.json`；脚本核对其余目标数据不变。官方 4.3 runtime 的 city 0、0.1667、0.1833、0.2167 秒图与独立层序试验逐像素一致；0.184 秒键后手仍可见、0.2166 秒键前手在目标胸前侧、0.2167 秒恢复默认后与 v3 图 SHA-256 一致。talk 1.5 秒 v4 与 v3 图 SHA-256 一致。改动让早期手在目标画面可见，尚须原 `.spine` 工作副本连续播放确认袖口和胸甲过渡自然。

左手尺度另作隔离试验：来源 `hips12.scale.x` 在 0.15/0.1667 秒为 0.438/0.579，但其子手骨 `hips13` 为 `inherit=noScale`；目标 `Lhand` 则继承 `Larm2` 缩放，故 v4 在这两帧手较小。`review-city-handscale-20261025/` 的倒数补偿使 0.15 秒的目标手偏长、偏薄；`review-city-handscale-mild-20261025/` 的部分补偿只略微放大，未解决与胸部的相对位置。两组均只保留为忽略目录内的试验，未纳入 v4 配置或正式候选。来源/目标左上臂 setup 角约 -164.6°/-160.6°、前臂约 -1.4°/+0.2°，角差很小；大幅统一加角度偏移缺乏依据。目标原工程中应按 0.15、0.1667 秒姿态细调手的大小、位置并连续播放检查，右前臂 setup 角差约 86.4° 也须单独检查。

## 被淘汰的跑步与备选动作

初选 `run` 的旧 v2 候选、报告、试验截图仍留在忽略的 `work/SPW-02/proofs/`，仅作为研究证据，不是正式验收结果。`run` 来源右臂的 `YOU IK` 动画键省略 `mix`，官方 4.3 runtime 将该键按 mix1 读取；其肩到 IK 控制点约 442–459px，超过源上臂+前臂约 388px。用肩相对世界路径按目标臂长试采样（0.65/0.75/0.8 倍）时，目标右臂大多被身体/披风遮挡，不能形成可见双臂跑姿。用目标原生 `run` 补层的独立试验能带来右臂、头发、尾巴摆动，但这是目标原动作，**不可计入 rhiny 时间线迁移**；源腿步幅与朝向仍不够接近。故不把 `run` 列为本轮完成动作。

另试 `common/give_start`、`common/yes`。前者伸手可迁但与 `city/interact` 手势相近；后者的点头主要依赖未映射的来源头部 3D 控制，目标候选几乎不点头。`common/talk1` 的源/目标正式代表帧都能看出较长的反复抬手讲话姿态，且必要手形可对应目标已有附件，因此作为第二动作。目标原工程本来有同名 `common/talk1`，新输出独立命名，不覆盖目标原动画。

## 复现与验收边界

在工坊目录运行 `node --import tsx ../../work/SPW-02/proofs/make-v4-talk-interact.mjs` 可从保存的正式 v4 配置与官方导出重建两个逐通道报告、完整目标 JSON 候选和 manifest。`candidate-v4-city_interact/`、`candidate-v4-common_talk1/` 各有 `rozeul.json`、`rozeul.atlas`、`rozeul.png`。脚本逐一验证：删去新动画后，完整目标 JSON 与原目标导出在结构上完全相同，原有 110 条动画、skin、骨骼、约束及附件未被重写；SHA-256 与路径见 `v4-talk-interact-manifest.json`。v3 的生成脚本、报告与完整候选仍在原位置。

官方 `Spine43Preview`（Spine 4.3 runtime）通过 Electron 隐藏窗口渲染，无桌面鼠标接管。v4 新增 city 0、0.1667、0.1833、0.2167 秒及 talk 1.5 秒图，原 v3 的首、中、末代表帧继续保留在同一 proofs 目录。静帧显示左手伸出/恢复、谈话抬手和对应袖/手附件；右臂未见明显骨链折断，目标脚保持站姿。这些证据证明候选可在官方 runtime 求值，不证明来源外观完整、连续动态自然，亦不证明 `.spine` 原工程已经导回、改键、保存重开。最终技术状态与未完成事项见 [validation.md](./validation.md)。
