# 星骸场景工坊 Workshop-M2.0

默认进入四工作区：项目与资产、模块编辑、场景装配、发布。新项目使用独立场景与私有模块源；公共库取用为副本。保存制作源与发布冻结版本分开，发布到 releases/<publishId>，不会覆盖旧版本。

本地桌面 UX 修正版默认深灰暗色。场景装配右侧“可放入资产”区可切换当前场景资产/公共库，并直接选择、重载、搜索公共库、拖入独立副本。活动编辑器使用 Ctrl+Z 撤销、Ctrl+Shift+Z / Ctrl+Y 重做、Ctrl+S 保存；输入控件保留正常编辑。[UX修正与验证](docs/Workshop-UX.md)。

模块编辑中先点选/刷选或框选体素；Ctrl+C 复制精确选区，Ctrl+V 显示整块 Ghost，移动鼠标后左键放置，Esc 取消。选区面板的“移动选区”进入移动预览；X/Y/Z 的 ± 按钮可逐格移动，预览中可微调后确认。一次放置/移动可整体撤销；剪贴内容仅在当前模块会话内使用。

打开 `release/星骸地图工坊-Workshop-M2.0/星骸地图工坊.exe`，保留整个便携目录。可“打开项目”选择随包 `示例/工坊墓室`，或新建项目/场景、创建模块/选择公共库。模块支持体素、PNG比例参考和Root；装配支持Ctrl多选/Shift框选、批量操作、分组、轴拖动及GLB/水平PNG。0.25米体素，无实例缩放；隐藏组仍发布。

发布前保存草稿，选场景/模块及新版本身份。GLB无需Blender；GLB+FBX需要已有Blender5.1.2，必须保留完整FBX/材质/贴图组。团结安装随包 `星骸地图团结插件-Workshop-M2.0.unitypackage`，用 `Tools → Xinghai → 接收工坊发布包` 选择整个发布目录的manifest.json。新版独立接收；手改与包装升级先预检，不自动更新用户场景。

[完整验证与边界](docs/Validation-Workshop.md) · [团结接收/包装操作](adapters/tuanjie/README-Workshop.md)。源码：`pnpm build` 后 `pnpm start`；旧入口用 `pnpm exec electron . --workspace=legacy`。新包：团结WorkshopPackageProof.Export后 `node scripts/package.mjs --target workshop`。不运行默认Legacy打包覆盖已有M1.2目录。

## Legacy M1.2 使用说明（原路线保留）
# 星骸地图工坊 M1.2

独立 Windows 地图编辑器。固定 0.25 米体素，外部 GLB 资产与 PNG 贴花组合，导出 JSON 后由团结生成网格、碰撞与模块预制体。M1.1 增加了一张使用同一 JSON 源的独立塔防验证图；工具本身仍不提供正式寻路、掉落或运行时地图系统。

## M1.2 新功能

方形/圆形大笔刷、真实三维厚度与向下绘制；二维跨保护列跳过而保留整笔；普通地面/高台资格合一且只接受真实顶面。侧栏底部新增独立PNG比例参考、框选原生资产、同ID更新与带色GLB/FBX导出。参考PNG嵌入编辑源，默认不导出到游戏或模型。

先读 [M1.2操作与验证](docs/Validation-M1.2.md)。新便携目录与旧M1.1分开。FBX使用已安装Blender，导出的同名 .xhmaterials.json 及存在时的 .xhtextures 目录必须与FBX一起导入新版团结插件；不是只复制FBX一个文件。最终包附 示例/M1.2 的源、三份装配、GLB/FBX与比例参考。

## 启动与试用

1. 打开 `release/星骸地图工坊-M1.2/星骸地图工坊.exe`。这是便携目录，不需要 Node、命令行或网页服务；请保留整个目录。未做代码签名。
   `release/` 是本地构建产物，不随 Git 仓库上传。克隆仓库后可按下文源码命令运行；便携程序需在本机重新打包。
2. 点击“选择目录”，选择随包 `示例/资产库`；点击“打开”，选择 `示例/地台与事件.json`。要检查真实套件，选择随包 `真实资产/遗迹套件`，再打开 `示例/遗迹双路/遗迹双路.xhmap.json`。源码对应 `assets/ruins-m11` 与 `samples/tower-ruins`。
3. 左侧绘制，右侧预览。左键使用当前工具，右键旋转，中键平移，滚轮缩放。“复位”将全图放入镜头；“俯视”用于对齐绘制。
4. “地台”：顶面高度 0、厚度 2 表示占用 -2 与 -1 两层，即顶面在世界 0 米、底面在 -0.5 米。输入的高度和工作层单位是体素；模型位置与贴花尺寸使用米。
5. “三维”：工作层是该体素的底面。逐层搭出支柱和桥板；擦除使用当前面积与厚度范围。“剖切”隐藏当前层上方，便于检查桥洞，不修改实际几何。`示例/桥洞模块.json` 可直接试验。
6. 一笔一次撤销；Esc 取消未完成笔画；Ctrl+Z 撤销，Ctrl+Shift+Z 重做，Ctrl+S 保存。矩形分批处理期间 Esc 可取消。输入框内不截获这些编辑快捷键。
7. 顶面采用体素色板；侧面、底面可继承颜色或统一选固定色。左侧色环“作为画笔色”只影响后续绘制；“重染当前槽”会改动所有引用该槽的体素，并要求确认。无光照校色便于检查实际配色。“显示已有表面 Z”只标当前可见顶面。逻辑属性独立于颜色；普通地面和高台默认有基础部署资格，最终许可仍由游戏判断。
8. “表面搭积木”点顶面向上加、点侧面向旁边加、点底面向下加；擦除按当前面积与厚度沿命中面法线执行。属性、模型、事件和水平贴花只能附着已有合法表面，空白处不会放置。模型／事件选 GLB，贴花选 PNG，再点击地面放置。事件预览模型与事件注册键是两回事；`sample.switch` 是随验证工程提供的示例功能键。已放置列表点击移除；本期不提供实例属性编辑器，要改锚点或旋转请移除后重放。

旧图若含顶面 `deploy` 标签，打开后可点“迁移旧部署标签 · 另存副本”；原件保留。旧图若把可站立标签涂在侧面，工具会列出待人工修正的位置，不会静默迁移。

## 独立塔防验证图

`samples/tower-ruins/遗迹双路.xhmap.json` 是经过编辑器打开、修改、保存的源图；`tower-content.json` 只定义两条路线和波次。24 × 14 游戏单位，每单位由 4 × 4 个 0.25 米体素组成；首图限定每个游戏单位内顶面高度一致。游戏从正常携入界面的“地图工坊验证 · 遗迹双路”进入，保留原有角色、技能、经济和三波流程，不替换默认关卡。验证图不是正式地图玩法或美术定稿。

团结验证工程的 `Assets/TowerProof.unity` 含两个同源模块实例；其 FBX/PNG 副本在 `Assets/TowerAssets`，原艺术资产未改。真实资源来源和尺寸见 `assets/ruins-m11/SOURCE.md`。

## 保存、身份与资产重载

- “另存为”保留地图身份，适合备份同一模块；两个文件仍会更新同一个团结模块。
- “复制模块”生成新地图身份，随后保存才是独立新模块。内部实例ID在新模块命名空间中保留。
- 保存成功后旧文件留在同目录 `.bak`。保存前检测外部改动，有冲突时选择重新打开或另存，不无声覆盖。未保存关闭会询问；临时 `.writing` 文件不作为正式地图读取。
- 资产根目录保存 `.xinghai-assets.json`，应与资产一起保存。ID 不等于显示名、文件名或内容哈希。使用工坊的“改文件名”可保持ID；外部任意改名不能自动猜测身份。
- 源模型定位按钮只打开所在目录；用 Blender 打开 `.blend` 修改、导出同一 GLB/FBX，再点“重载”。完整有效导出才替换预览，损坏导出保留旧预览并提示。
- 可编辑资产默认单位为米、不自动缩放；自定义锚点输入源坐标 X,Y,Z 米，影响之后新放置的实例。色板与锚点均有明确输入，不根据名称猜规格。

## 团结接入

本次实测 **团结 2022.3.62t13_632f6144c187，Built-in 管线**。未验证 URP/HDRP，当前 Shader 不声称兼容那些管线；未安装或升级引擎。

最快验证：使用现有团结打开 `validation/TuanjieProject`，打开 `Assets/CompleteProof.unity`。工程里已经配好注册表和两个模块实例。`validation/build/MapProof.exe` 是独立运行验证程序，不依赖编辑器运行。

接入另一个工程：

1. 先在团结 Package Manager 中通过包名添加 `com.unity.nuget.newtonsoft-json`，本机验证版本 3.2.1。
2. 导入 `release/星骸地图团结插件-M1.2.unitypackage`，便携包根目录也附同名插件。也可复制 `adapters/tuanjie/Runtime` 与 Editor 的正式文件（见 `docs/AssetContract.md`）。不要复制测试 Proof 文件。
3. 把模型 FBX、PNG、功能 prefab 导入你自己的资产目录。桌面 GLB 只作预览；本期正式交换实测使用 Blender 的 `-Z Forward / Y Up` FBX 配方。
4. 在桌面点击“导出团结源”。团结菜单 **星骸地图 → 烘焙地图**，选择 JSON，创建/选择映射表。窗口列出需要的键；在映射表 Inspector 将模型资产ID绑定到 FBX，事件注册键绑定到功能 prefab，贴花ID绑定到 Texture2D。
5. 标准 Blender FBX 保持 `Blender Fbx Axes` 开启，插件做一次已验证的 180° 方向校正；团结原生 prefab 不处理。其他 FBX 配方先自行制成已对齐 prefab 再映射，不能混用导出约定。
6. 点击“校验并烘焙 / 更新模块”。生成在 `Assets/Generated/<mapId>/Module.prefab`。拖入组合场景可以放多份，各自事件状态与身份独立。不要手工编辑生成目录或模块内部；人工内容放在模块外层，源模型与功能 prefab 放在生成目录外。
7. 再次导出、烘焙会稳定更新资源；无变化则报告无变化。校验失败保留旧版本；中途异常回滚磁盘与内存，进程意外终止的恢复记录在该团结工程 Library 下，下次加载插件时恢复。`bake-report.json` 记录本次源修订和网格信息。

## 首期限制

- 单模块最多 25 万体素、1 万模型/事件实例和 1 万贴花；矩形最多 4096 列。是防卡死预算，不是游戏世界上限。
- 撤销最多 40 步，累计最多 100 万体素快照；较大地图可撤销步数相应较少。18.4 万体素文档的快照仍有约 0.2 秒开销，宜分成可复用模块。
- GLB/PNG 单文件最多32 MiB；GLB仅允许内嵌资源，不联网读取依赖。资产目录最多2万项、12层；常见非支持格式显示 unsupported。
- 平面贴花仅水平接收，暂无曲面投射；不支持任意缩放与非90度旋转。表面逻辑是数据，不代表游戏寻路已实现。
- 本期为 M1.2 工具；M1.1 独立验证图继续保留；M2 生产任务包、自动监听和正式游戏地图系统不在范围内。首版历史验证见 `docs/Validation.md`，M1.1历史检查见 `docs/Validation-M1.1.md`，本轮见 `docs/Validation-M1.2.md`，仓库内 A01–A36 详细对账见 `../../docs/tasks/TOOL-002-地图工坊M1.1.md`；用户操作手感与美术效果仍需实际试玩判断。

## 开发与复现

新工坊目前完成 Task1–4 的项目、模块和场景装配。源码构建后运行 `pnpm exec electron . --workspace=workshop`；默认启动仍是上述 M1.2 界面。装配页支持 Ctrl 点击多选、Shift 拖动框选、批量复制/删除/旋转/分组与轴拖动；一次批量操作可一次撤销。公共库条目拖进视口会建立独立本地副本。模块 Root 按几何相位对齐，PNG 比例参考留在模块编辑页。

可通过“打开项目”选择 `validation/workshop-task4c/tomb-project/project.xhproject.json` 查看已保存的十一实例墓室示例。验证见 [Task4报告](../../docs/tasks/TOOL-005-Task4-验证.md)。冻结发布、FBX/Blend 完整交换、新 Unity 接收与新便携包属于后续 Task5–9。

依赖精确版本记录在 package.json / pnpm-lock.yaml，使用 pnpm 11.25.0。安装目录配置在 pnpm-workspace.yaml，不改变全局设置。依次运行 `pnpm install --frozen-lockfile`、`node node_modules/electron/install.js`、`pnpm build`、`pnpm start`；Electron 下载缓存可设为本工具 `.cache/electron`。

`pnpm test` 跑核心测试；`tests/ui-smoke.mjs`、`tests/bridge-ui.mjs`、`tests/workflow.mjs`、`tests/asset-reload.mjs` 是真实 Electron UI 回放。它们只模拟系统文件对话框的选择结果，地图内容通过界面输入。测试目录都是本工具的 validation；不要用它们指向真实制作资产。
