## 0. 总原则与目标

**不是继续旧 SK-02 的固定三级样板，也不是把研究报告里的 1930 张候选卡直接登记成 1930 个可用技能。** 本轮应先将“原作研究事实”与“星骸希望采用的规则”分离，再把小黄、小蓝的可核实能力**完整分类提取**，建立适应单职业/单武器的组合能力运行时，最后接入真实 Q/E/R、V、被动清单与被动升级道具。

验收终态分三层，必须分别报告：

1. **资料完整性**：小黄与小蓝在指定 Build 中所有相关主动根、主动升级分支、被动／符文及其升级、招式替换和条件联动均有逐项清单、稳定来源 ID、可追溯证据；没有遗漏或把候选误记为可用。
2. **架构可组合性**：主动技能最多装 Q/E/R 三个；对应职业／武器的被动集合不设人为三格／五格上限；可持有暂时不生效的合法被动、后续装上对应主动时自然生效；真实触发可以改变伤害、状态、招式、连段、动画请求或派生效果；效果执行、暂停、死亡、失效、移除均有唯一权威。
3. **实际原型交付**：技能预选、每主动的三级二选一分支、V 升级、被动选择与一次专项升级都能通过正常 UI 操作、真实变更游戏状态。资料已证且已经实现消费者的项目才可标记“可玩”；未实现者允许作为研究目录展示，但不能冒充有效效果或暗中当成“无对应技能而暂不生效”。

### 0.1 用户本轮明确要求（USER_CONFIRM）

- 以《灰烬之国》**代码揭示的机制结构**为主要技术参照，先验证用户从表面观察到的规则是否与实际实现一致。
- 深入提取**小黄与小蓝全部相关主动、被动、主动升级、被动升级**，使其成为《星骸回廊》可组合的条目；保留“来源职业/武器”的归属，不默认为所有角色通用。
- 《星骸回廊》**不采用原作肉鸽随机抽取**：通过 UI 为当前武器＝职业选择 Q/E/R 主动技能，并配置各主动的第 1、2、3 级升级方向。
- 被动依当前武器＝职业的能力池选择；**底层不能有三／五固定槽上限**。玩家无需先拥有对应主动或普攻才能取得被动；条件暂不满足时保留，不冲突、不删除。

- 组合效果要能真正改变招式和连段、技能表现与结算，而不仅仅在面板上加数值。
- 两角色专属能力与**跨角色通用装备**是两种独立来源；普通装备可由通用行为（例如第 n 次普攻）触发效果，不能悄悄混入角色专属被动池。

## 5. 阶段 S1｜星骸能力架构：先做可组合语义，再做更多能力内容

### 5.1 身份与状态模型（建议结构，可按真实代码调整）

```ts
// 仅概念草图，实际签名以游戏核心为准
WeaponProfessionCatalog {
  professionId; weaponDefinitionId; sourceRoleId;
  activeDefinitions; passiveDefinitions; equipmentEffectRefs;
}
SkillDefinition { id; professionId; levels: [Level1,Level2,Level3]; baseAction; triggers; effects; sourceEvidence }
SkillSlotRuntime { slot: 'Q'|'E'|'R'; skillId|null; level: 0|1|2|3; chosenBranches: [Choice|null,Choice|null,Choice|null]; cd; action? }

```

关键约束：

- 定义（不可变）／出征配置／当前世界运行实例／一次动作 Accept 快照分开，**不能让 HUD 数字成为权威**。
- 《星骸》Q/E/R **各自独立技能 ID、冷却和 0～3 级**；在新职业样板中允许三个槽均配置。用户说“用 V 升级三次选定主动”按**每个已装主动最多三级**解释，不沿用旧 `WorldSession.activation.activeLevel` 作为两人共享等级；若正式含义不同，记录为小项并暂停影响部分，不擅自把全队同步升级当定稿。
- 被动存储为**可扩展集合**，运行时不依赖 `PreparedPassives=[3个固定ID]`、旧 HUD 三格或五格。数量可以按数据和运行验证增长，不做 O(n²) 全组合预计算，也不因性能误把持有上限设成 3/5。
- “没有对应技能仍能选”指**获取与持有合法**；被动未匹配时状态为 dormant、效果为零，后续对应主动或普攻出现时自动重新匹配；不是把未知／尚未实现消费者伪装成 dormant。
- 对每个被动 `upgraded` 只能从 false→true 一次，重复消耗请求拒绝。若原作证据表明同名多层/叠层不同，再在资料层登记，不替用户改当前样板规则。
- 身份始终绑定**武器／职业定义**，不把所有技能复制给猎人和阿尔通用。若需要在当前两位黄金角色上验证原作黄/蓝能力，先通过明确的**隔离实验职业／主武器定义**接入，**不擅自认定“小黄＝猎人、小蓝＝阿尔”**，不覆盖黄金动作。
- 通用装备 Proc 拥有独立 `equipmentInstanceId`，按通用行动事实触发，和角色专属被动实例分开结算。

### 5.2 条件效果与动作变更（必须支持，而非全数值乘法）

优先复用 `CombatEvent`、`ActionContext`、主命中/架势/体力与右手真实 `MainInstance`，按实际差异补最小可复用接缝：

| 层 | 需要支持的最小事实／操作 | 为什么 |
|---|---|---|
| 获取与安装 | `acquirePassive / removeSource / queryCanEquip` | 被动可自由获取，不绑当前 QER，来源移除可清理订阅 |
| 角色事实 | `ActionAccepted/AttackEmitted/HitConfirmed/FirstValidHitPerWave/ComboStep/ReloadCommitted/Death/AreaUnload` 中证据支持者 | 不能把按键、出手、伤害或首次命中混成同一个触发器 |
| 条件与调度 | 真实 SkillId、关键词/tag、身份、来源链、CD、延时、目标、概率与去重 | 不对应时 dormant，对应后才执行；防一击多次结算 |
| 动作修改 | ReplaceAction、AppendComboStep、ChangeHitbox、ChangeAttackCount、AlterProjectile/DerivedSkill | 真正允许被动改变普攻招式、段数和出招表现 |
| 执行结算 | 实际 HP/架势/状态/资源/弹夹和派生实体结算 | 不能只在详情页换描述 |
| 生命周期 | Cast 归属、已生成实体、退订/卸除、换武器、死亡、同世界离开继续 | 不重复激活，也不意外取消已产生的合法效果 |

组合规则必须有**确定性顺序和冲突报告**：被动安装资格不因为潜在效果冲突而拒绝；当多个效果都想替换同一招式/弹夹时，根据可声明的优先级、阶段和稳定身份产生唯一结果，未采用者也不凭“曾查询过”消耗。这个设计是《星骸》的安全改良，不假称与原作黄回调副作用逐字一致。基础招式与替换层的可逆关系必须可测；卸下一个被动不误删除其他被动建立的改造。

## 6. 阶段 S2｜QER、V 与一次性被动升级道具的真实 UI

### 6.1 配置界面

在现有装备/技能配置区域提供选择武器职业后：

- Q/E/R 三槽：当前职业的主动技能列表、可装／已装／槽冲突、Level0 基础技能、当前等级；允许清空与槽间换位。
- 每个主动的 Level1/2/3 方向**分别展示两个真实来源分支**。可在配置 UI 预选三层分支路线；当前世界按各级已经真实激活的方向生效，未激活层不提前给效果。已实施/已支付层不得仅改下拉框就逆向重写旧动作。
- 可滚动的**无硬槽数上限**专属被动清单，展示已持有、已升级、匹配中／目前条件未满足；不因没有对应主动而禁用获取按钮。
- 通用装备效果只显示在装备域，不在职业被动列表里给出“全角色通用”的假结论。

### 6.2 V 的新语义

- V 是**当前职业的主动升级入口**，操作对象必须是当前主控身体拥有的合法 `MainInstance`／QER 槽；展示每技能 `0/3—3/3`，独立逐级升阶。升级选择使用已预配的本级方向；未预选时以一个真实两选一 UI 让玩家做决定，不自动随机。
- 单次成功交易才增加**指定技能**一级；失败不扣费、不升级其他 QER 或另一角色；升级不会追改已经 Accept 的旧施法快照。
- 费用/资源来源**尚未获正式批准**，不得强行沿用 SK02 的双人一次性 `4/8/12` 或自动送付费资源。做可显式配置、界面写 `SAMPLE` 的开发测试支付门，记录候选方案；任何真实扣费需一次支付且唯一。
- V 模态冻结模拟并隔离 Tab/Z/F/G/QER/LMB/RMB 输入，Esc/失焦取消不重复提交；成功后能读取真正的技能等级与改变效果。

### 6.3 被动升级物品（与 V 主动升级分开）

- 在实验世界团队背包登记一个**仅用于验证**的物品 ID（例如 `sample-passive-insight`，名称及数量 SAMPLE）。
- 玩家通过被动管理面板选一个当前职业已获得且尚未升级的被动，点击“消耗 ×1 升级”；只有真正成功才唯一扣物品并改变此被动运行实例。已升级选项不再出现在**可升级候选列表**，但仍显示在持有列表里。
- 道具不足／旧请求／选错职业／重复点击／死亡或世界代次切换一律拒绝且不扣库存。不要与猎人 Y 瓶、阿尔自由道具栏及左副装备道具混同。
- 被动的升级**数据与真实效果**优先按 R2 已核原作条目；若原作无对应一次升级配置，只能先用明显标记的 SAMPLE 效果验证**升级接口**，不可给真实条目捏造“原作升级后的能力”。

**S2 闸门：**正常玩家路径能够连续完成“装配QER→激活一级分支→获得无对应技能的被动→装上对应技能后被动激活→用专用物品升级另一被动一次→再点拒绝”。真正在 MainInstance、战斗实体、HP/架势或连段里能看到变化。

## 7. 阶段 S3｜小蓝、小黄能力目录落地（分类型、按证据收口）

S3 的目标是实现**两人完整可追溯内容表与可组合消费者**，而不是“凑几个临时加伤”。建议按原作范型顺序扩展，并用已证四条代表链当首批基准：

1. **小蓝：**“破阵猛冲＋能量回复”测试实际首次有效命中和角色资源；“凿冰”测试指定普攻招式替换、动作/子技能/召冰效果。
2. **小黄：**“火箭弹射＋起跳爆炸”测试根 Skill ID 的攻击时附加与真实空间伤害；“精准装填／下一次上弹全迫击炮”测试一次换弹结果、弹夹归属与下一次右键行为。注意多个回调的副作用与顺序必须以星骸确定性机制处理，不把原作不安全点全盘移植。
3. 再按 **伤害/数值／资源／状态附加／投射派生／替换／Combo 增项／装备Proc** 分组覆盖小黄和小蓝其他已证条目。凡同一范型由不同数据定义即可支持的，不每项手写一套新状态机。
4. **全量对账**：每一条 R2 清单必须进入三种结果之一：`playable_verified`（真实效果可操作）、`imported_unresolved`（来源已核但消费者不足，清楚标为待实现）、`excluded_with_reason`（禁用/不属于本角色/数据不成立）。不允许一个未知能力作为“普通不生效被动”混到成功清单。

**重要的范围风险**：R2 可能揭示上百个角色符文、复杂派生物、完整骨架动画/弹丸/VFX等。全部资料清点是本大任务的硬目标；**全部运行效果实现**需要按真实数据量和来源缺口拆成交付子批，并明确剩余清单。Codex 不得在没解决特例/资产所有权之前声称“所有技能功能与画面一比一复刻”。用户再次选定批次前，可以完成已授权且有证据的通用范型和代表链，但不能借任务名无限扩大到完整动画素材生产、2D TileMap、独立 AI 或别的游戏系统。

## 8. 验证策略：重点证明组合正确，不重演最近的超长测试

这次架构本身有跨模块风险，**按阶段分级**：R0/R1/R2 以静态身份/数据审计为主；S1 与 S2 属 C 级风险对象但实行窄范围分模块验证，按细则对每个受影响高风险消费者专项覆盖；S3 各内容小批按轻量 B。不得因为是 C 级就每小步默认跑全部历史浏览器用例。

必要验收：

- 数据：小黄和小蓝候选、ban、各主动 1～6 分支、被动归属和消费者引用双向完整性；无假 ID、静默漏行、重复合并；证据等级可追溯。
- 核心：三独立 QER 等级与分支；被动持有不绑定主动；装备不同主动后重新求值；组合替换/连段追加真实改变动作结算；攻击时与有效命中触发分开；高频多子弹去重；同槽多被动冲突顺序、卸下清理；一次道具升级幂等与库存守恒；职业切换、Z 控制、死亡、同世界继续、新世界重置。
- 浏览器：默认**一条完整短流程**覆盖配置→出征→V 升级一个 QER→被动组合产生真实效果→耗道具升级一个被动→Tab/ESC/输入保护；必要时仅补一条小黄/小蓝不同动作类型的对照。角色受击与连段必须由正常点击及实际状态展示证明，不仅用调试脚本更改数值。
- 原作运行观察（OBS）：如果本轮无法启动原作或没有录屏，明确报告哪条规则只有 CODE/DATA；不能让本项目仿真结果反向证明原作确实如此。
- 跑小集测试与主 Vite 构建为默认；只在修改共享战斗核心、经济支付、世界生命周期且出现具体风险时扩展对应回归。严格区分**真实产品失败**与测试夹具失败，验证预算按 `design/开发细则.md` §7.1.1 控制；不得无限刷新过去几十项长流程。
