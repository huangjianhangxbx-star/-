# 0. 本阶段一句话目标

把已经存在的 `CommandFocus` 继续细分为两种状态：

```text
只是关注角色
→ AI照常自主行动

已经进入Path / Skill / Mobility Aim
→ 玩家正在准备一条明确命令
→ AI逐层让权，角色稳定下来等待玩家
```

也就是正式建立：

> **Command Reservation**

但本轮**不做真正的Path UI、Skill UI或Evade UI**。

---

# 1. 为什么 XC-03 必须独立做

T-029 已经正确实现：

```text
Direct Hunter
↓
Command Al
↓
Al仍然由AI正常行动
```

下一步必须解决：

```text
Direct Hunter
↓
Command Al
↓
玩家点“技能”准备瞄准
```

这时如果 Al 还继续 Flank / Regroup / Retreat / 换目标 / 自己侧步 / 自己再开Basic，玩家的鼠标瞄准原点会不停变化。

但如果只要点中 Al 就 AI 全停，又会产生“看一下角色，她就突然木桩化”的糟糕体验。

所以正式区分：

```text
CommandFocus ≠ Reservation
```

只有真正进入 Aim Session：

```text
PathAim
SkillAim
MobilityAim
```

才触发 Reservation。

# 3. Aim Session 的最小正式结构

T-029 已预留：

```ts
type ExplorationAimKind = 'path' | 'skill' | 'mobility'

type ExplorationAimSession = {
  kind: ExplorationAimKind
  actorId: string
}
```

XC-03 建议扩成：

```ts

  kind: ExplorationAimKind

  startedAt: number
}
```

暂不加入 skillId / slot / destination / direction / preview / targetId，这些分别留给 XC-04 / XC-09 / XC-10。

# 4. Reservation 不重复保存 phase

不要存第二套 `yielding / ready` 真相。

建议派生：

```ts
commandReserved(s,u): boolean
commandReservationReady(s,u): boolean
```

`commandReserved` 成立条件：Aim存在、Aim.actorId就是当前 CommandFocus、且该角色不是DirectActor。

`commandReservationReady` 在没有仍需完成的身体动作时为 true。以下状态仍算 yielding：

- existing attackPending；
- foreground skill；
- evasion action；
- forcedMotion；
- crossing；
- skillLanding；
- stagger / stun；
- 其它已Commit原子动作。

这些状态结束后自动变成 Ready，不另写 phase 字段。

# 5. Begin Aim API

建议新增：

```ts
queryBeginCommandAim(s, kind)
beginCommandAim(s, kind)
cancelCommandAim(s)
```

只能作用于当前合法 CommandFocus。DirectActor不能走 CommandAim 入口。

Engine Command 建议增加：

```ts
{ type:'beginCommandAim', kind:'path'|'skill'|'mobility' }
{ type:'cancelCommandAim' }
```

本轮不绑定普通UI，这些先作为正式核心入口和自动测试入口。

# 6. 暂时拒绝 Begin Aim 的旧高层玩家动作

为了不在 XC-05 MoveOrder 之前破坏旧玩家命令，本轮若角色正在：

- `ai.command === 'move'` 且仍有路径/目标；
- recall；
- partyTask；
- rescue；
- loadout / 明确换装通道；

则 Begin Aim 暂时拒绝。

原因：目前还没有“暂停玩家命令但保留真正Destination”的正式 MoveOrder 数据。XC-05完成后再放开。

# 7. 允许先进入 Reservation、等待结束的动作

以下动作可以先进入 Aim，但 Ready=false：

- attackPending；
- 已开始Foreground Skill；
- 已开始Evade/Blink；
- forcedMotion；
- crossing；
- skillLanding；
- stagger / stun。

玩家可以提前表达“接下来我要给这个人一条命令”，系统等待既有动作结束。

---

# 8. Begin Reservation 时立即停止的 AI 行为

只停止**AI自己拥有的、尚未Commit的决策与移动**。

## 8.1 Companion Tactical Movement

若 `u.companionCombat?.moving === true`：

- 清当前AI path；
- 清AI destination；
- `moving=false`；
- 不恢复旧路径；
- Debug可显示 command-reserved。

Aim取消后，AI从当前位置重新判断。

## 8.2 Noncombat Follow

若 `u.following === true`：

> 停止Follow路径，让角色稳定。

Aim取消后由 followParty 从当前位置自然重新规划。

## 8.3 禁止粗暴 clearMotion

Reservation不能通过 `clearMotion()` 一刀切，因为它可能破坏 attack lifecycle / crossing / skill landing / recall / 玩家命令。

---

# 9. 已经开始的 Basic

当前Basic仍使用旧 `attackPending`。

XC-03保守规则：

> **Aim开始前已经存在的 attackPending 允许正常Resolve一次。**

然后 Reservation期间禁止创建新的 attackPending。

例如：

```text
玩家点技能
↓
Al刚好已经挥出一箭
↓
该箭正常打出去
↓
Al不再自行开下一箭
↓
稳定等待玩家
```

XC-07 Basic Combo完成后，再精确区分Windup取消与Release后完成。

---

# 10. Reservation期间禁止新的自动 Basic

当前 engine 会在目标合法且 attackTimer<=0 时自动创建 attackPending。

增加统一Gate：

```text
commandReserved(s,u)
→ 不启动新的自动Basic
```

现有 pending 可以完成。

---

# 11. Reservation期间 AI Hazard 不再接管角色

当前 Companion AI 看到 Ability 会 Walk Avoid，必要时 Evade/Blink。

Reserved 时：

> 不运行 AI Hazard Avoidance。

所以 SkillAim中的Al不会突然自己侧步跑开。

玩家若发现危险，可以取消Aim、WASD直接接管、Shift接管，未来 XC-10 还可用Command Mobility Aim。

角色也可能因为玩家犹豫太久而真实吃招，这是合理的。

已经开始的 AI Evade 不取消，完整结束后 Ready=true。

---

# 12. Background / Auto Skill 的处理

## Background State 继续

例如：

- Snipe enabled；
- Poison enabled；
- Dance mode；
- CD / charge时钟；
- 已成立持续世界效果。

不因 Reservation 消失或冻结。

## 已经Commit的Foreground / Auto Run继续

已经真正进入 run 的动作允许完成。

## Reservation期间不启动新的Foreground Auto Action

例如 Reap 此刻满足自动发动条件：Reserved时不启动新身体动作；Aim结束后条件仍成立，再由正常运行时判断。

# 13. 推荐统一 Autonomous Start Gate

建议在 `exploration-control.ts` 提供：

```ts
autonomousBodyStartAllowed(s,u): boolean
```

对 Command Reserved actor 返回 false。

统一控制：

- 新AI tactical decision；
- 新AI movement；
- 新AI Basic；
- 新Foreground Auto action；
- 新AI Evade/Blink。

但不阻止：

- cooldown ticking；
- background mode；
- 已Commit action；
- status tick；
- damage；
- forcedMotion；
- death/downed。

# 14. Companion AI2 接入

`advanceCompanionCombat()` 在 Hazard 与新目标决策之前检查 Reservation。

Reserved 时：

- 不跑 avoidHazard；
- 不选新target；
- 不重规划；
- 不开始move；
- 若AI移动残留则撤销；
- 保留必要Debug信息。

# 15. Cancel Aim

`cancelCommandAim()` 只清 Aim。

必须保留：

- DirectActor；
- CommandFocus；
- 当前TacticalFocus状态（不重新启动）；
- Skill state；
- 其它战斗状态。

不恢复旧AI path。AI从当前位置重新决策，因为旧路径可能已经不安全或过期。

---

# 16. Focus切换 / Clear / Promote

继续沿T-029：

- Clear CommandFocus → Aim同时清理；
- Promote Direct → Aim同时清理；
- 切到另一个CommandFocus → 旧Aim取消，旧角色AI恢复；
- 新CommandFocus只是Focus，不自动Reserved。

# 17. Direct Action 是 Aim Escape Hatch

T-029当前 `inputAuthority==='aim'` 会阻止Direct Action。XC-03需要调整：

> Aim拥有鼠标确认权，但不能锁死Direct takeover键。

## WASD

```text
Command Al + SkillAim
↓
W
↓
cancel Aim
→ Promote Al
→ 同一次W开始移动
```

## E/R/T

```text
cancel当前Aim
→ Promote
→ 同一次Hotkey按Direct输入语义执行
```

## Shift

```text
cancel Aim
→ Promote
→ 同一次输入执行真实机动
```

## LMB

未来真实Aim存在时，LMB属于Aim Confirm，不作为Direct Basic escape hatch。本轮不实现LMB新语义。

# 18. Reservation Ready 查询

提供：

```ts
commandReservationReady(s,u)
```

Ready=false例如：

- attackPending；
- foreground skill；
- evade action；
- forcedMotion；
- crossing；
- stagger / stun。

Ready=true代表身体已经稳定，可以安全接受未来Confirm。
