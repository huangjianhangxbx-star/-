## 0. 一页结论：什么必须改变，什么绝对不动

这不是新建生图器，也不是再开发一个工坊。继续使用 **0.4.0 的样品定稿闭环**，只补两个跨阶段、可追溯的约束：

**约束 A｜资产空间形式契约（Form / View Contract）**：对草地和石质边界分别定义固定投影、方向、可见面、厚度、联通用途；它是素材生产硬规格，先于风格。首轮小样、风格收口、手修批准和正式 `materials.png / contour.png` 必须保持一致。**不能把 AI 首轮错误的三分之四透视锁成“必须保留”的厚度方向。**

**约束 B｜任务级风格压制策略（Style Pressure）**：`off / standard / extreme`，默认 `standard`。`extreme` 是用户可选的“强力回拉”候选预设：结构以黑线/暗块概括、局部材质以两个主要明暗块为主、禁止习惯性高光描硬边、暗部不精修、细碎破损从严删除。**不改写 L0/L1 已批准宪章、不全局替换石材 L2，也不强迫草地/金属等材质用同一颜色。**

**保留：**现有离线工作流、真实 PNG 字节和 SHA、用户手修回传与准确版本批准、0.4.0 的 47 合法状态/188 变体、九场景预览与结果验真；默认 Unity PPU 100；旧 ZIP/旧工程可读；经典联通和普通 PNG 入口；不联网调用图像 AI。

### 成功的用户体验

用户在工坊选择“草地平面联通”或“石质边界联通”，看到固定形式解释图，选 `标准 / 极端`，再导出小样 ZIP。AI 即使读不到本聊天，也知道不能自由改变相机角度。返回小样不对，用户选择“视角不合格：重新试制”继续迭代；视角对了才进行独立风格收口。用户最终人工批准具体版本后，正式生产任务包携带同一份形式契约、样品文件和压制档位。生成和导入的具体图层仍由现有编译器处理。

**不能声称的结果：**“指定了正交俯视”不等于内置 AI 每次都遵守；“极端压制”不等于会自动量化每个像素或确保成熟画师质感；47/47 拓扑通过不等于美术与 Unity Sorting 通过。以上结论分别立证。

## 2. 本轮目标、非目标和决策状态

### 2.1 明确目标（实施时必须满足）

1. 草地/平面地块与石质边界/墙体各有一个**不可自由解释**的空间形式模板；2×2 四形态样品是统一世界视角下的片段，不是四张不同摄影机角度的概念图。
2. 第一次导出小样 ZIP 前能看到“空间视角基准”可读摘要和一幅**原创形式引导图**。AI 的步骤说明、验收说明、正式包均由相同权威规范派生。
3. 增设 `off / standard / extreme` 风格压制档位，默认 standard；档位切换能真实改变导出的约束内容、任务身份/哈希和待验状态，而不是 UI 假切换。
4. 风格收口只允许更改表现方法；出现视角、物体结构或者面朝方向错误时，应有“**返回小样重新生成/修正结构**”的明确路径，不能用普通 style-refine 将错误结构合法化。
5. 样品批准页明确要求检查视角与资产用途；缺少用户批准不能启用正式生产。只为当前任务批准，不修改长期风格规则。
6. 旧 ZIP v1–v6 解析与历史样包不受新规则影响；已有 .cache 工程能恢复，不能自动被赋予新契约下的批准身份。
7. 使用最少量真实 AI 图像进行前后对照，实事求是记录其遵从程度；工具不可用时只验技术与任务包，并将视觉 Gate 保留待测。

### 2.2 不做

- 不重写 0.4.0 多贴片 / 轮廓数据格式、47 状态掩码和 188 变体编译算法；发现真正阻断新约束的问题才做**有证据的小修**。
- 不改 Unity 项目、游戏本体、不进行新一轮《地心归途》资源全面提取，也不声称已恢复原画师 PSD。
- 不训练/加载 LoRA，不接 ComfyUI、不在工坊内联网或集成 Chat API。
- 不增加木材、植物、金属等全新正式 L2 规则；不把当前参考图作为全材质固定色板。
- 不做“自动检测图片是否成熟二次元”或“自动判定两色阶”的伪准确功能；图像语义由人或支持图像理解的外部执行者做可复核判断。
- 不制作便携 EXE、重做普通素材入口或 3D 工坊。

## 3. 形式契约：把“相机角度”从风格喜好提升为素材硬格式

### 3.1 一套清晰的屏幕坐标定义

不要让 AI 自由选择“好看的 3/4 视角”。为本轮两族明确记录：

| 约束名 | 解释 |
|---|---|
| `screenX` | 画面向右为 +X；图像方向，不与 Unity 世界坐标混为一谈 |
| `screenY` | 画面向下为 +Y；在文档中标注与 Unity XY 世界的转换关系 |
| `projection` | 固定正交/平行投影（不画透视消失点、不使用广角） |
| `worldFrame` | 同组四样与正式全套都使用同一相机方向、同一方形逻辑格 |
| `allowedFaces` | 明确顶面/前立面/边接触面的允许范围 |
| `frontDirection` | “前立面”统一指**朝画面下方的可见面**，禁止每张样品自行换方向 |
| `forbiddenViews` | 禁止自由旋转物体、斜角陈列展示、三分之四透视、任意变换视觉地平线 |
| `gridIntent` | 2D 正方形网格自动联通，不是四张独立模型概念图 |

以上是本轮原创 **XH 生产契约候选**，不是对《地心归途》原作者绘制视角的考古认定。

### 3.2 模板 F-GROUND-TOPDOWN-v1（草地 / 平面地块）

**必须：**画面严格俯视地表，以 XY 平面为唯一主要绘制面；地面不能竖起、不能呈现 3D 土台底面、地平线或带镜头透视的独立草簇雕塑；一个逻辑格以方形平面占位。所有样例的纹理方向与照明偏向一致。

**可变：**局部草叶边缘、真实土色下层、外角/内角的边缘形状、草色大块变化。草叶允许有限伸出，但透明轮廓/下层相位必须服从后续编译约束。

**样品检查重点：**中心面积、边界、外角、内角一眼看出属于同一平面；不能把“边缘形态”误绘成一层有厚度的立体草台。

### 3.3 模板 F-STONE-EDGE-FRONT-v1（石质边缘 / 高差墙，候选）

**必须：**整个资产与顶面采用统一的正交空间基准；必要的厚度/悬垂只通过**固定朝屏幕下方的前立面暗块**表达。四种小样在同一坐标轴上构成面、前沿、外角、内角/孔洞的关系。不得像单独展示的 3D 石头一样从四个侧面任意观察、随意转 45° 或自由摆拍。

**可变：**顶面形状、石块分布、黑色接触线、前立面大暗块、有限的纵向断口，但结构变化不能改变全套镜头方向。

**不可擅定：**Unity 真正的 cap/body/underlay 层级、sorting axis 和石墙另一朝向如何遮挡；当前并未完成实际场景核对。这些不影响本轮锁定“**小样摄像机不能乱转**”，但在 UI 与 ZIP 中必须保留 `unitySorting: unverified`。

**失败例子：**一张像上方俯视岩台、另一张像面对正面岩墙、第三张斜向露出侧墙、第四张变成 3D 凹座——即便美术很好，也只能用于画风参考，不能当完整联通生产用的已合格结构样品。

### 3.4 四形态统一排布，新增“形式引导”而非强迫 AI 画网格

小样沿用四个代表角色，但把现有“可任意摆放”改为**2×2 固定语义区域**，每格的位置和观察坐标一致：

| 左上 | 右上 |
|---|---|
| ① 主体/中心面：不得倾斜 | ② 接边/前沿：只能露出允许的边缘或前立面 |
| ③ 外角：与①同一坐标系 | ④ 内角/孔洞：与②统一厚度与层级方向 |

为草地和石质分别生成一张原创 `view-guide.png`，示意允许可见的面、屏幕上/下/左/右、四样相互关系；**引导的箭头/边框仅存在于说明图，不画进返回样品**。工坊让用户在请求前预览“形式引导”和“材质/风格参考”，二者独立。

小样 PNG 当前允许 64–2048 边长、≤4MP，不因为当前 AI 偶发返回 1254² 就偷偷拉伸。**固定的是四块语义排布，不强行宣称像素分割已可由程序可靠判断**；若不能确定返回图片四区是否正确，人工 Gate 保留。后续确实需要自动裁切时另立任务。

### 3.5 对正式双层的适用方式

- `materials.png` 仍为标准的 4c×2c **面内材质贴片表**，不是四个自由视角的岩块插画；所有材质变化都从已批准的统一空间基准生成。
- `contour.png` 仍为 2c×c 的 **数值编码控制图**，不是供 AI 画黑线、阴影的“风格图”。R/G/B/A 区间与共享边必须严格服从现有协议。
- 风格压制只作用于小样及其后续**美术表现材质层**，不能把“高光少/黑线多”的描述误投到 contour 的 R/G 控制通道中。
- 改变投影或固定厚度方向，必须生成新的正式母版请求，并重新验证47态、188变体、九地图；不允许修正 metadata 假装旧 PNG 是新视角。

## 4. 风格压制：任务级三档策略（不修改正式宪章）

### 4.1 继承与覆盖顺序

1. **不可突破：**PNG 尺寸、格、PPU、透明要求、合法邻接、轮廓数据编码、Pivot、审批身份、固定视角和可见面契约。
2. **继续有效：**项目已批准场景风格 L0/L1 与符合材质范围的 L2。
3. **本次可选：**任务级 `stylePressure`。只能收紧表现方法，不能把已批准规则改成新长期规则，也不能更改格式硬规格。
4. **最新本轮意见：**自然语言描述及当前修稿意见，不能默默覆盖①和②。遇真实冲突，应标记失败或请求对这个任务的明确调整。

### 4.2 三档含义

| 档位 | UI 名称 | 规则 | 用途 |
|---|---|---|---|
| `off` | 无额外压制 | 不叠加额外压风格说明；**已批准项目基础风格仍有效** | 做 A/B 对照或已有样品满意 |
| `standard` | 标准压制（默认） | 沿用成熟手绘、结构概括、少量亮边与暗部停刻原则；允许按需、整体化的弱材质变化 | 日常样品与一般修稿 |
| `extreme` | 极端概括 / 黑线二阶（可选） | 用功能性黑线和深色块取代抛光式立体描边，局部每种材质以主体色＋暗色**两级主要块面**为主；禁止常规高光描硬边、碎纹理和暗面细刻 | 反复出现 AI 精修感、亮边过量时回拉 |

**“两阶”的精确定义：**“每种材质局部主要明暗组织尽量为两组大块面”，**不是**整张图 RGB 只能有两种颜色，更不是由程序对 PNG 进行硬量化或限制透明通道。一个物件可有多种材质主色，不应强迫草地与石材都变灰。黑色结构线/接触暗块允许作为形体语法存在，不被错误计入“第三级彩色高光”。

### 4.3 extreme 预设文字（可实际用于生成任务）

> 本次采用 **极端概括 / 黑线二阶**。请优先通过有目的的黑色结构线、近黑暗块和少量大中型色面解释形体、遮挡、接触、折转与破损。单一局部材质以主体色和一组暗色构成主要明暗关系；暗面直接合并成稳定大色块，不再在暗处补纹理或渐变。**禁止使用高光细线描绘硬边、轮廓或每个转角**；不得通过发白、均匀、整圈的亮色包边让形体显得精致。减少裂纹、铆钉、缺口、碎斑、次要切面和零碎折线；大中小元素比例经过设计，不为丰富画面堆小元素。黑线要说明结构，不能把每个部件都勾成统一粗黑外轮廓。保留材质辨识与必要体积，不用模糊、整体变脏、弱对比或儿童卡通平涂假装完成概括。首先遵守本任务已锁定的平面/墙体视角及连接格式；这条风格要求不能改变任何几何、格、相位或数值控制图。

此文为**待验证的候选任务预设**，不是本轮直接写进 L0/L1 的正式修改。若用户实验后希望调词，只更新预设版本和新任务，不改历史任务包。

### 4.4 两个特别容易产生误用的例外

- **高光问题：**`extreme` 禁止习惯性“描亮边”这种视觉语言；不等于所有自发光物/关键交互符号今后永远不得使用亮色。本轮草地/石墙不引入新的发光例外。`standard` 依正式宪章可少量使用靠近主体色、非连续亮边。
- **黑线问题：**“使用黑线”不是统一加粗描边；线可断，可与大片暗部融合，次要结构可省略。若极端档让画面变成儿童卡通、平面剪纸或粗黑图标，应列为失败，不能把细节减少误当艺术质量提升。

## 5. 各阶段如何真正落地（不改工作流顺序）

| 当前 0.4.0 阶段 | 新增行为 | 不能发生的情况 |
|---|---|---|
| 0 锁格式 | 同时锁 `viewContract`、`stylePressure`；界面显示两种模板各自的投影、固定方向示意与原因 | 只展示 UI，但导出 ZIP 漏字段 |
| 1 导出少量样品 | 小样 ZIP 附 2×2 语义模板、正交/可见面契约、压制档与四个角色；正式约束不得由用户描述覆盖 | 四张自由视角概念画被当合格小样 |
| 2 独立风格收口 | 精确绑定小样版本；在尺寸/布局/视角已合格前提下做风格修改，允许用户切 `extreme` 后重新申请 | “保留厚度方向”把**错误的**斜视结构固化 |
| 3 人工修图并回传 | 每次 PNG 原件、SHA、父子版本照常保存；人工可先修结构，再修色块，但批准前必须看形式核对清单 | 返回一张新角度图仍继承旧批准 |
| 4 人工批准 | 确认卡中并排显示真实图、模板身份、形式规则、压制档位、视角自查结果、原图 SHA；用户显式批准准确样品 | 程序根据短标签“通过”自动代用户审批 |
| 5 正式制作 | 携带获批 PNG、形式与压制快照、materials/contour 目标；样品只作画法基准，不把 2×2 小样误作为切片图 | 把 3D 小样按形状直接当已完成 Tile |
| 6 编译和回拼 | 继承 47/188/九地图/像素验真；额外展示“形式已人工核对/待核对”并保留 Unity `unverified` | 程序通过便显示“风格已通过/Unity可用” |

**错误视角的纠正通道：**在样品页提供“不符合形式，重新试制”的明确操作，沿当前任务与原因生成新 `sample-task`，可将失败样品作为内容上的**负向诊断**但不得把它升格正向参考；保存其版本与原因，生成新返回图后另存。不要复用 `style-refine-task` 假装完成结构矫正。若开发成本较低可复用既有“重新导出样品任务”入口，只需在 UI 文案和 ZIP 中保留错误说明，不强制新增状态枚举。

**改档位时的版本语义：**`viewContract` 与 `stylePressure` 都进入任务的已锁规格和 `specHash`。用户从 standard 切到 extreme，应显示“这将产生新的任务规范修订，使当前生成请求、人工批准和正式产物失效；历史原图保留”。不得静默改变之前已经批准的样品归属。更换回原模式也不能凭字段相同自动恢复旧批准；需要重新明确批准当前版本。为了避免不必要的误操作，UI 在样品批准后改档位要有明确确认。

## 6. 协议、版本与兼容设计

### 6.1 推荐新增字段

在新阶段唯一硬权威 `spec/asset-spec.json` 中（具体字段位置由 Codex 根据现有 `lockedSpec` 定义实现）：

```json
{
  "lockedSpec": {
    "viewContract": {
      "schemaVersion": "2dw-view-contract/1",
      "id": "F-STONE-EDGE-FRONT-v1",
      "projection": "orthographic",
      "screenX": "right",
      "screenY": "down",
      "cameraFrame": "shared-fixed",
      "surfaceMode": "top-with-fixed-front-face",
      "frontDirection": "screen-down",
      "forbidFreeCameraRotation": true,
      "status": "candidate"
    },
    "stylePressure": {
      "schemaVersion": "2dw-style-pressure/1",
      "id": "XH-SP-EXTREME-01",
      "mode": "extreme",
      "version": "0.1.0",
      "scope": "current-task",
      "catalogStatus": "candidate"
    }
  }
}
```

这是**提案形状**，不代表现有代码已有该数据结构。实现时必须把模板 ID 与素材类型校验关联：草地不能附石墙前立面契约，石材候选不隐式继承草地 `flat-top` 契约。不能任意允许客户端提交未知自定义枚举或借自由字符串扩展为新正式美术规则。

### 6.2 推荐采用新 ZIP 与规格版本以保护 v6

现有 `2dw-zip/6` 使用签名、原文件 SHA 和对派生提示词的**严格重建比对**。直接修改 v6 的 `prompt()` 或校验语义，可能使旧 v6 原样包不能重新通过验证。因此建议：

- 新产物使用 **`spec 1.5.0 / 2dw-zip/7`**（建议编号，若实施时已有 v7，必须先检查并选兼容的新版本）；
- 保留既有 v1–v6 独立验证派发逻辑、原样任务包字节、已签 v6 的内容/解析语义；
- v7 才包含 `viewContract`、`stylePressure`、`guides/view-guide.png`、`guides/view-checklist.md`、`style/style-pressure.md` 等由唯一权威派生的镜像；
- 原版 v6 工程在新版程序打开时，仍可作为**历史工程**恢复和查看批准记录，不能被自动标为符合新硬约束；用户明确选择升级到 v7 时建立新任务修订，标记历史批准已过期，但**不删除旧字节**；
- 遵守旧 ZIP/工程容量预算，新增图/字段后核对签名、压缩与安全预算，不放宽任意路径写入、PNG 尺寸验证、受信发行者检查。

若 Codex 实际验证存在更小的兼容方案，可在独立技术备注中解释，但**不允许改变旧 v6 校验结果或在旧任务上静默补一个“形式已验收”标签**。

### 6.3 权威关系与导出文本

`asset-spec.json` 是**唯一硬权威**。所有阶段的 Markdown 提示词、视角说明、风格压制规则、引导图索引从同一 spec 生成，不维护多份可能漂移的手写文件。v7 读取时重新派生对比，篡改单个 markdown、图像或元数据后即便重签 manifest 也须拒绝镜像不一致。

建议 ZIP 最小增量：

```text
spec/asset-spec.json                     # 唯一硬权威
asset-grammar/grammar.json               # 现有联通硬映射镜像
guides/sample-layout.png                 # 现有 / 升级为统一2×2布局说明
guides/view-guide.png                    # 新：该模板的坐标轴、合法可见面图
guides/view-checklist.md                 # 新：形式人工验收清单
style/style-pressure.md                  # 新：选定档位的任务级规则
prompts/task.md                          # 三阶段分别重组，含视角硬要求
input/...                                # style / formal 阶段已有确切 PNG
manifest.json                            # 校验完整性与阶段身份
```

不要求为新增几行文字复制整份既有 L0/L1，以免扩大 ZIP 和规则维护成本。

## 7. UI 交互要求：更好控制，不做更大的表单

建议在已有 **「样品到联通生产」** 的第 0 步及第 2 步完成，保持原 6 步导航：

1. 选草地或石质边界后自动显示只读 **「本模板视角」**：草地“严格正交俯视”、石材“统一正交顶面＋朝画面下方的固定前立面”。旁边可展开原创形式示意 PNG，标注“候选，待 Unity 实机层级验证”。首版对两族**不提供任意相机角度自由输入**。
2. 提供一组紧凑单选：**无额外压制 / 标准（默认） / 极端概括**；每档一行易理解的效果说明；不使用频繁弹窗或很长的多选问卷。
3. 在第二工序的风格收口区域显示当前模式、可调整，并将“用户希望改变的内容”当作本次偏移，不能覆盖硬格式。
4. 样品审核区域增加视角检查：**正确平面/厚度方向、四形态同世界相机、无自由透视、后续可用于联通生产**；用户点批准时显示这些项的“由用户确认”或“未检查”状态。不能伪称软件自动视觉识别。
5. 增加清晰入口“**视角不对，回到样品重做**”，保留错误版本和文本诊断，可导出新试制 ZIP。
6. 在任务包预览显示当前 `F-GROUND-TOPDOWN-v1` / `F-STONE-EDGE-FRONT-v1`、`XH-SP-STANDARD` 或 `XH-SP-EXTREME`，和其所控制的步骤；正式包显示批准身份与产物模式。
7. 不增加必须手填任务 ID、标题或重复选择额外字段。仍沿用自动 ID 和已存工程状态。

**UI 接入注意：**renderer 不读取任意 Windows 绝对路径；文件、剪贴板、签名和安全校验仍由现有 Electron 主进程负责。错误反馈不抹除原件或历史请求。

## 8. 真实 AI 提示词设计的推荐组合

### 8.1 预设必须是“先结构、后风格”

**小样阶段：**`任务目的 → 资产模板 → 坐标系/投影硬约束 → 四形态位置 → 已选内容/风格参考用途 → 已批准通用美术规则 → 压制档位 → 输出与验收`。避免先丢大段“成熟奇幻概念美术”等易诱发 3D 岩台的宽泛艺术词。

**风格收口阶段：**先检查或由用户确认“视角和形式已合格”；若不合格则返回试制而不是进入第二工序。对合格小样，保持正确视角、四区位置、连接意图、主要可见面和原尺寸，在现有图基础上执行所选档位；不为美化自行增加侧立面、透视或高光描边。

**正式生产阶段：**把精确批准样品当作视觉标准，视角契约仍是更高优先级。让 AI 画固定几张材质贴片/轮廓数值层，不是自由制作47个透视各异的素材。样品里如果残留不合规视角但人工误批准，任务报告应明确提出矛盾，不得悄悄沿用或自动替用户批准新结构。

### 8.2 可直接输出给 Agent 的硬视角片段示例

**草地：**

> 当前任务是 Unity XY 平面 2D 智能联通地面所需的绘制小样，**不是地形模型概念图**。统一正交俯视，屏幕 X 向右、Y 向下；只表现地面平面与合法的边缘透明/底层关系。四小样依固定2×2布局分别表达中心、边缘、外角、内角，保持同一相机、同一平面尺度、同一材质方向。禁止三分之四俯视、草土立体台、可见任意侧面、自由旋转或透视消失点。

**石质边界：**

> 当前任务是 2D 条件八邻连通石质边界／高差墙的绘制小样，**不是四件可以独立旋转展示的3D岩块**。所有图严格共享正交相机和屏幕网格坐标。可以画顶部石面与必要的暗面厚度，但所有前立面统一朝画面下方，侧面只在模板允许的边界位置作为接触暗块出现。中心、前沿、外角、内角必须像一个世界中的相邻部分；禁止每格自行变换相机、用三分之四视角、画自由岩台或任意露出四周立面。原作 Sorting 未实机确认，严格按随包提供的候选模板工作。

### 8.3 极端档的短提示追加

> 采用“极端概括 / 黑线二阶”，只保留主要轮廓、关键内部结构和大中型色块；以黑线/近黑暗块承担接触、遮挡、裂缝和转折。每种局部材质主要由主体色与暗色两组块面组成；暗面不再继续刻画。不得沿硬边铺设亮色描线，不画规则细碎折面、锈蚀斑、无意义小裂纹与均匀高光。绝不把结构绘制简化成粗黑统一描边的儿童卡通；保留成熟二次元手绘的材质识别和视觉主次。不得改变任何已锁定视角、网格、连通关系与控制图数值编码。

以上文案为可调整预设候选。Codex 应统一从版本化数据生成，不能把同一段文字分散硬编码在三处。

## 9. 实施阶段（M0–M9）

### M0｜接手、边界与基线（不改程序）

- 检查当前 `main`、本地工作树和共享记录的其它任务增量；先确认 0.4.0 的任务/结果 ZIP、v6 校验、状态机、风格继承和样品批准真的存在且可运行。
- 读取本轮相关 AGENTS / 开发细则 / 0.4.0 协议、对应测试。检查本机所选 Skill，读取真实说明；不可用如实登记。
- 对受保护文件、18 个旧 v1–v5 样包与本轮 v6 六样包记录 SHA。只对实际存在的文件建立基线，不编造不存在样包。
- 把用户要求与 AI 方案分开写入新任务记录。
- **M0 完成条件：**有可靠基准、可解释的任务边界，不存在未经授权文件改写。

### M1｜视角/形式契约与版本定义

- 编制两个原创候选 form contract 及可读描述；检查非法模板/可见面/厚度组合会 hard-fail，未知选项不回退成宽泛“斜视”。
- 给形式契约版本、ID、方向及状态，输出规范和 Prompt 同源。
- 先写失败测试：ground 出现 front-face 禁止；stone 必须统一 frontDirection；变更 viewContract 改变 specHash 与状态。
- **M1 完成条件：**仅替换描述不可能改动硬视角事实；两个模板互不串用。

### M2｜压风格档位注册与合法性

- 独立任务级 `off / standard / extreme` 预设；写清“off 不是取消项目批准风格”“extreme 两大明暗群而非全图双色”的解释。
- 新字段与已有 L0/L1、石材 L2 的继承关系可查询；不编辑已有批准 catalog。
- 测试更换档位对任务 hash、阶段镜像及旧批准的影响；不同材质不得继承石砖专用颜色/裂纹。
- **M2 完成条件：**三档能生成不同但互相不矛盾的可审阅文本，任务级候选不污染长期规则。

### M3｜v7 阶段包与签名向后兼容

- 在旧 v6 之外创建本轮新增规范版本/独立验证路径，保留所有既有 `sample/style/formal` 阶段机制。
- 新 ZIP 引导、方向图、说明、预设和三阶段 Prompt 均从唯一 spec 派生；严格对镜像、文件哈希、签名和身份做验证。
- 先做 v6 老包不变和 v7 篡改镜像红测，再实施新 adapter；恶意改 mode、方向、模板 ID/来源、图像后不得仅重签 manifest 混过。
- **M3 完成条件：**v1–v6 历史样包仍可读且字节不变，新 v7 任一核心字段篡改能被拒绝。

### M4｜小样阶段的 2×2 视角导引

- 草地/石质各绘制一张**原创简洁示意 PNG**：屏幕 XY、平/立面、厚度朝向、四形态位置。说明图与返图分离，禁止把说明线送作实际待生产绘画内容。
- 样品任务的形式/视角说明提前于风格说明，替换“画布可灵活安排”引导自由透视的旧表述；保持实际图尺寸预算合理。
- 提供“角度错误 → 重试小样”且保留父子与失败反馈的最小路径；不要求 AI 自动变出47个独立 tile。
- **M4 完成条件：**外部只读 ZIP 就能指出四个样品必须共享什么角度，能明确知道什么是失败。

### M5｜风格收口和人工批准 Gate

- 风格收口绑定正确的已选父图/SHA/版号/视角与压制档位；不能默认把原图错误厚度角度当必须保留。
- 在样品审核/批准入口突出形式检查提示和具体版本身份，压制模式变化明确使审批失效或进入新规格；用户可以退回小样重新试制。
- 不替用户自动“检查美术并批准”；红测覆盖手动修图、修改档位、切换旧版本、撤销/恢复与重开工程。
- **M5 完成条件：**标准与极端的返修任务明确差异，结构不正确时不能被暗中放行到正式阶段。

### M6｜正式包携带同一形式/风格快照

- `formal-master-task` 原样包含批准 PNG+唯一身份，附格式方向与压制档位的当前锁定快照；`materials/contour` 的尺寸、用途、编码和共享边仍按0.4.0。
- 数值 `contour.png` 不被美术高亮/黑线要求污染。缺层/错尺寸/非法Alpha与通道仍拒绝；切换内容导致旧结果陈旧。
- 保留真实47态、188变体、九地图/3×3和来源定位。若新任务未人工批准，禁止导出正式生产任务。
- **M6 完成条件：**能追溯“这套47张 Tile 用哪一张人工批准样品、什么视角、什么压制档位制作”。

### M7｜小范围桌面交互及技术回归

## 12. 风险与应对

| 风险 | 应对 |
|---|---|
| AI 无法保证同相机视角 | 图片引导＋硬提示词＋样品人工 Gate；不能以格式字段代替视觉验收 |
| “二阶”被理解为幼稚的纯矢量画 | 解释为两大块面层级，要求保留专业视觉信息主次和材质辨识，保存真实反例 |
| 黑线变成整圈均匀粗描边 | 明确结构性线条，不给每个零件统一描边；极端档也需人工审美 |
| 极端档误影响 contour 的数据通道 | 把风格作用域限制为小样与 materials；对R/G/B/A执行原有硬校验 |
| 提示词更改使已签 ZIP v6 无法验证 | 新协议独立派发；旧解析与 byte/hash 快照回归 |
| 改风格后原批准自动沿用 | stylePressure 纳入 specHash；任何更改显式作废当前 Gate，但保留旧图 |
| 单独四形态易产生自由构图 | 四区统一方向、世界坐标和可见面，禁止概念摆拍；出图仍须用户看 |
| 自动测试报绿但游戏中不自然 | 结构、视觉、Unity 三种状态分开；E01/E02 和 Unity 留待实测 |
| 同步提交混入其它并行任务 | 开工与发布前核对 Git diff，白名单选择性提交；禁止强推/Gitee |
