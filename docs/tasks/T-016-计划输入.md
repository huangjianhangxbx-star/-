# 2. T-016：队友自治稳定化

## 2.1 核心设计：从“位置评分器”变成“局部任务 AI”

保留现有评分，但评分不能再直接等于“下一步去哪”。角色先决定是否值得接手一件局部任务，再围绕该任务选位置。

建议阶段：

| 阶段 | 含义 |
|---|---|
| Hold | 守位，没有值得移动处理的问题 |
| Commit | 已决定接手某目标/支援事项 |
| Approach | 为该任务取得合法贡献位置 |
| Engage | 已经可以真正攻击/支援 |
| Settle | 事情刚结束，先原地观察 |
| Return | 确实空闲，才返回锚点舒适区 |
| Player | 玩家当前拥有控制权 |

这不是复杂行为树，只是一层短期任务状态。

## 2.2 可行性硬门槛

攻击目标只有满足以下条件，才允许驱动自治移动：
1. 目标有效且符合当前可见/索敌规则；
2. 在活动半径内存在至少一个合法候选点；
3. 到达该点后，按真实 `canHit / inWeaponRange / LOS / 高低层` 规则可以攻击目标；
4. 当前到该点存在合法路径；
5. 路径不会越出活动半径；
6. 不是只能更接近、但最终仍无法贡献的假机会。

关键改动：**“更接近敌人”本身不再具备驱动移动的资格。**

## 2.3 TTC / 可贡献窗口

对移动中的敌人做轻量预测：

`TTC = 到合法攻击位的预计移动时间 + 必要攻击前摇`

再估算敌人仍停留在本角色局部可攻击包络中的时间 `T_window`。

如果 `TTC + 安全余量 > T_window`，则放弃为了该敌人移动。

首版只处理稳定场景：静止/已接敌目标、沿路线匀速推进目标、明显离开职责区的目标；不做完整未来模拟器。

## 2.4 响应覆盖

响应覆盖只决定“谁值得为了这个目标移动”，不限制正常集火。

算作已有响应者：
- 当前原地就能合法攻击目标；
- 已对目标处于 Commit / Approach / Engage；
- 已明确接敌且具备攻击资格。

建议首版需求：

| 敌人 | 自治移动所需响应者 |
|---|---:|
| 普通小怪 | 1 |
| 重甲/大型怪 | 2 |
| 正在直接攻击该角色本人 | 允许本人额外响应 |

因此前排已能处理小怪时，后排无需为了同一只怪前冲；如果后排原地本来就能射中，仍可正常攻击。

## 2.5 任务粘性

接受任务后记录目标，并保持一段任务承诺。普通新目标不能每 0.35 秒让角色掉头。

只允许以下情况换任务：
- 当前目标死亡/离场/不可合法处理；
- 当前任务的响应需求已被别人满足，而本角色尚未产生贡献；
- 出现明显更紧急事件（被直接攻击、架势危急、关键支援对象）；
- 玩家下达命令。

现有 `interval / dwell / improvement` 继续保留，但降级为平滑、防抖和任务内重评参数。

## 2.6 目标失效立即停路

自治 Approach 期间目标死亡/失效时：
1. 立即清除剩余自治路径；
2. 停在当前合法位置；
3. 进入 Settle；
4. 不把旧路线走完；
5. 不立即回锚点。

这是解决“后发角色白跑”的核心之一。

## 2.7 Settle 战后观察

建议起始值：`0.8s` 模拟时间，可调范围约 0.6–1.0s。

Settle 期间：
- 停止无意义归位；
- 可以原地正常攻击；
- 可以接受新的高价值、真实可贡献任务；
- 不因为暂时没事就开始 Return。

这样上方敌人清除后，下方敌人很快进入时，角色会直接从当前位置响应，而不是先回中心再折返。

## 2.8 锚点舒适区

锚点仍是玩家战略意图，但不是必须精确踩回的像素点。

建议首版：

| 模式 | 活动半径 | 锚点舒适区 |
|---|---:|---:|
| 塔防 | 1.0 | 0.35 |
| 探索战斗 | 2.0 | 0.50 |

任务结束后已经位于舒适区，就直接 Hold；只有超出舒适区且 Settle 结束、没有新任务时才 Return。

Return 进入舒适区即结束，不继续追求精确锚点。

## 2.9 Return 为最低优先级

Return 可以随时被新的真实任务或玩家命令打断。

AI 不再把“回中心”当作一项强制完成的动作。

## 2.10 支援职业同样要求真实贡献

治疗/辅助为了友方移动时，也必须满足：
- 存在真正需要支援对象；
- 半径内存在合法位置；
- 到位后实际覆盖/支援结果会改善；
- 不需要 AI 未经批准自动释放关键主动技能。

“离队友近一点但仍然做不了任何事”不能驱动移动。

# 5. T-017：全屏战场与 UI 覆盖层化

## 5.1 新的唯一原则

> **游戏世界始终拥有完整 viewport。HUD 是覆盖在世界上的界面层，不拥有相机保留区。**

因此 UI 可以遮挡地图；后续 UI 美术再通过透明度、镂空、布局改善可读性。相机不再替 UI 腾空间。

## 5.2 当前要删除的旧假设

当前 `BattleScene.resize()` 中的：
- left HUD reserve；
- right reserve；
- top reserve；
- bottom reserve；
- `safeWidth / safeHeight`；
- 由 HUD 差值推导的 `offsetX / offsetY`。

这些都是 T-017 的主要移除对象。

## 5.3 塔防全屏 Fit

塔防仍尽量显示整张地图，但 fit 基于完整 `w / h`。

允许保留纯世界级 padding：
- 地图边缘留白；
- Spine 角色头部空间；
- 建筑高度空间。

这些 padding 不能读取 UI 尺寸。

塔防相机中心回到世界/地图中心，不因为底部 dock 偏上。

## 5.4 探索全屏 Projection

保留现有：
- 猎人跟随；
- 选中其他角色后的有限偏移；
- 平滑跟随；
- reduced-motion 行为。

仅修改投影范围：完整 viewport 决定真实可视世界。

## 5.5 UI pointer 边界

继续采用：
- HUD 根层 `pointer-events:none`；
- 真正交互控件 `pointer-events:auto`。

必须逐项验证：顶栏、卡牌、角色栏、技能、详情、背包、构筑、Dialog、Debug、世界技能按钮、回收/救援按钮。

UI 上操作不能同时点击到背后的地面/角色；透明非交互区域仍允许操作世界。

## 5.6 打开 UI 不改变镜头

以下开关前后，同一世界坐标的屏幕投影必须不变：
- 背包；
- 构筑面板；
- 角色详情；
- Debug；
- 卡牌变卖；
- Notice；
- 世界技能按钮。

战术慢速/暂停可以变化，镜头位置和缩放不能变化。
